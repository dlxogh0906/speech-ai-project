## 2. 표준발음 보정 — 자세히

### 2-1. 왜 필요했나

API 는 문장을 받아 실행 중에 KoG2P 로 정답 발음(표준발음)을 만든다. 맞게 읽어도 틀렸다고 나오는 헛지적의 **가장 큰 원인이 이 정답 발음의 오류**였다.

- 학습 문장 224문항 중 51문항에서 KoG2P 결과가 사람 라벨의 표준발음과 다르다.
- 이 51문항에서는 헛지적 발화가 70.0% 였다(나머지 문항은 13.2%).

### 2-2. 동작 순서

| 단계 | 하는 일 | 예 |

| ① 글자 고쳐 쓰기 | KoG2P 에 넣기 전에 발음대로 철자를 바꾼다 | 먹을 수 → 먹을 쑤 · 사건 → 사껀 · 희망 → 히망 |
| ② KoG2P | 문장 전체를 지금 API 와 같은 방식으로 돌린다 | |

### 2-4. 녹음에 맞춰 고르는 허용 변이

KoG2P 는 띄어쓰기를 무시하고 문장 전체에 동화 규칙을 건다(일을 누가 → [이를루가]). 그런데 표준발음은 구절마다 다르다.

- 생각 나세요[생강나세요] 는 단어 경계 너머로 동화한다.
- 밥 같이[밥가치] 는 동화하지 않는다.

둘 다 허용 발음이라 하나로 정할 수 없어서 녹음에 맞는 쪽을 고른다.

| 종류 | 예 (기본 / 변이) | 쓰나 |
|---|---|---|
| 경계 된소리·거센소리 | 밥 같이 [밥까치] / [밥가치] | 쓴다 — 효과가 가장 크다 |
| 경계 유음화 | 일을 누가 [이를루가] / [이를누가] | 쓴다 |
| 경계 격음화 · 기타 | 딱 하루 [따카루] / [딱하루] | 쓴다 |
| ㄴ첨가 | 힘든 일을 [힘드니를] / [힘든니를] | 쓴다 |
| 조사 '의' → [에] | 감사의 [감사의] / [감사에] | 쓴다. 거의 · 회의 · 주의 등 28개 낱말은 뺀다 |
| 비어두 '의' → [이] | 회의 [회의] / [회이] | 쓴다 |
| ㄷ 탈락 | 했습니다 [핻씀니다] / [해씀니다] | 쓴다. 된소리 ㄸ·ㅆ·ㅉ 앞만(ㄲ·ㅃ 앞은 학습자 오류일 수 있어 뺀다) |
| ㅎ 탈락 | 전화 [전화] / [저놔] · 결혼 — 어절 안 공명음 받침 뒤만 | 쓴다. 효과는 작다 |
| **경계 비음화** | 생각 나세요 [생강나세요] / [생각나세요] | **안 쓴다** |

경계 비음화를 뺀 이유가 있다.

- 사람 라벨이 오류로 적는 발음까지 받아들이게 된다.
- 고른 결과가 라벨에서 멀어지는 경우(45번)가 가까워지는 경우(26번)보다 많았다.
- KoG2P 가 원래 맞는 문항에서 재현율이 33.4% → 31.0% 로 떨어졌다.

## 3. 섞은 모델 — 자세히

### 3-1. 만든 방법

| 항목 | 내용 |
|---|---|
| 출발점 | 지금 서비스 모델 w2v-BERT `step_38000` |
| 추가 학습 데이터 | 같은 목소리로 만든 "맞게 읽기 / 일부러 틀리게 읽기" 합성 녹음 쌍 6,515개 중 검증을 통과한 5,452쌍 + 실제 학습 데이터 15만 줄 |
| 합성 문장 출처 | 학습 문장을 바꾼 것 515 · 외운 단어(한국어 · 공부 · 두부 · 사과 · 친구)가 든 Kspon 문장 1,500 · 그 밖의 Kspon 문장 4,500 |
| 일부러 넣은 오류 | 첫소리만(된소리·거센소리 ↔ 예사소리 등). 정답 라벨은 표준발음 보정(2절)으로 만들었다 |
| 합성 엔진 | Chatterbox · Qwen3-TTS 반반 |
| 쌍 검증 | 기존 모델로 들어 보고 두 녹음의 차이가 2.0 nats 미만(647쌍)이거나 받아쓰기 오류율이 35% 초과(124쌍)면 뺐다 |
| 가중치 | 실제 데이터 중 헷갈리는 쌍의 오류가 든 줄은 1.5배 |
| 학습 | 3,000 스텝 · 학습률 최대 5e-6(워밍업 후 감소) · 약 2.4시간 |
| 섞기 (WiSE-FT) | 가중치를 기존 모델 50% + 추가 학습 모델(step_3000) 50% 로 평균했다(`interp.json`) |

섞은 이유가 있다.

- 추가 학습만 한 모델은 오류를 더 잡지만, 맞게 읽은 자리를 틀렸다고 받아 적는 비율이 기준(+0.3%p)보다 많이 올랐다(+0.55~0.65%p).
- 반반 섞으면 그 상승이 +0.26%p 로 기준 안에 들어오고, 오류 잡는 효과는 대부분 남는다.
