# 정상 ㅆ 보존 학습의 후속 검증 — 2026-10-23

2026-10-23에 시작해 10-24 00시경 최종 감사·문서화를 마쳤다.

**같은 문맥의 정상 자료를 늘리고 정상 보존 손실을 강화해 두 모델을 학습했다. 헛지적은 줄었지만 실제 오류 검출도 줄어 주후보를 채택하지 않는다.**
새 화자 확인셋에서 정상 가중치 1→4 변경은 **오류 검출 3→0개, 정상 헛지적 4→1개**였다.
이전 RP 자료에서도 **오류 검출 9→4개, 정상 헛지적 31→19개**로 둘 다 감소했다.
운영 서비스·모델·설정은 변경하지 않았다.

[앞선 ㅆ→ㅅ 전용 검증](ㅆ에서ㅅ_전용_검증_2026-10-23.md)의 실패를 바탕으로 진행한 다음 실험이다.
이번 결과는 정상 보호 계수를 높이는 방법의 효과와 한계를 보여주며, 모든 정상 보존 학습 방법의 실패를 뜻하지 않는다.

## 1. 학습을 어떻게 바꿨나

공식 train의 사람 실제 발음 전사(TAG)로 1,536발화를 구성했다.

| 구성 | 발화 | 내용 |
|---|---:|---|
| 실제 ㅆ→ㅅ 오류 | 256 | 적용 가능한 초성 오류. 절반은 모음–ㅆ–ㅓ–ㅛ 문맥 |
| 같은 문항의 정상 | 768 | 오류 자료와 같은 문항에서 3배수, 전체 TAG=표준음 |
| 추가 정상 | 256 | 같은 대상 문항의 다른 정상 녹음 |
| 일반 정상 replay | 256 | 다른 문항의 정상 발음 보존 |

학습자는 1,380명, 한 화자 최대 4발화다. rank에 쓰인 오류 256자리/정상 1,024자리 외에
받침 뒤 213자리는 전체 전사 CTC 학습에만 기여한다. 정렬이 모호하거나 다른 자음인 자리를 rank 정답으로 바꾸지 않는다.

오류·목표 정상 자료의 문항은 `쏟아요`, `싸다`, `주시겠어요`, `않으셨어요`, `하셨어요`,
`왔어요`, `오셨어요`, `하겠어요`, `좋습니다`, `써`의 10개다.
평가 문항을 보호하므로 이전 RP의 `갔어요·했어요·었어요` 동일 어휘와 `쓰기·있어요` 문항은 학습에 넣지 않았다.
따라서 어미의 음소 문맥을 공유한 것이지, 실패한 평가 문장을 그대로 학습한 것이 아니다.

두 모델 모두 운영 계열 `w2vbert_synth_tense_v2/step_3000`에서 시작했다.

```text
L = CTC(전체 실제 전사) + error_rank + λ × normal_rank
λ = 1: 같은 자료를 쓰는 대조군
λ = 4: 학습·평가 전에 지정한 주후보
hinge = max(0, 2 + NLL(actual) - NLL(목표 한 자리만 반대로 바꾼 전사))
```

오류 rank는 표준 ㅆ/실제 ㅅ, 정상 rank는 표준=실제=ㅆ에만 쓴다.
양쪽 음소열에서 다음 소리가 모음이고, 표준음 기준 첫 자리 또는 모음 뒤인 곳으로 제한한다.
각 rank는 해당 자리 평균 뒤 전체 batch 평균이며, 정상 계수가 오류 항의 가중치나 분모를 바꾸지 않는다.

동일 초기 가중치·자료·seed·실제 batch 순서로 300회 갱신했다. LR 5e-6, warmup 20,
batch audio frames 384,000, accumulation 2, 24층 인코더와 헤드 전체 학습이다.
Dropout/LayerDrop/SpecAugment를 끄고 BF16 forward/FP32 CTC를 사용했다.
중간 checkpoint·가중치·표시 임계값을 평가 결과로 고르지 않았다.

## 2. 학습이 실제로 작동했나

두 모델 모두 600 microbatch에서 2,807발화 노출, 학습 1,536개 전원 노출을 확인했다.
초기 가중치·자료·실제 batch 순서 SHA256이 같고, 24층과 헤드의 갱신 검사도 통과했다.

| 학습 중 지표 | 정상 가중치 1 | 정상 가중치 4 |
|---|---:|---:|
| 정상 제약 미충족 노출 / 1,861 | 457 (24.6%) | 195 (10.5%) |
| 오류 제약 미충족 노출 / 470 | 400 (85.1%) | 450 (95.7%) |
| 마지막 40 microbatch 정상 rank 손실 | 0.01347 | 0.00249 |
| 마지막 40 microbatch 오류 rank 손실 | 0.03329 | 0.04712 |

정상 제약을 더 잘 만족하는 동시에 오류 보존 제약은 덜 만족했다. 이 표는 학습 자료의 결과이며 일반화 성능은 아래에서 따로 측정했다.
gradient clipping은 27/300→47/300회다. 손실 계수 4배가 실제 파라미터 갱신량의 정확한 4배를 뜻하지 않는다.

## 3. 평가 자료와 고정한 응답 조건

새 화자 확인 561발화와 이전 directional 자료 1,711발화를 합쳐 모델별 2,272개를 평가했다.
학습과 모든 평가 사이의 녹음·화자·문항·정규화 문장 겹침은 0이다.

새 확인셋은 이전 실험 화자를 제외한 192명·19문항이며, 공식 valid/test에서 확보한 실제 오류 49발화와
전체 정상 512발화다. **새 화자 자료이며 문항 자체는 이전에 사용됐다.** 기존 출발 모델의 과거 학습 노출까지 차단한 검증은 아니다.
이전 RP는 개발·재현 자료로 분리했고, 새 문항 검증이라고 부르지 않는다.

새 확인 561개 중 76개가 운영의 `low_speech` 검사로 거절됐다. 매핑 확인은 실제 오류 36/정상 540자리이며,
**정책 적용 문맥에서는 실제 오류 10/정상 468자리**다. 거절·표준음 불일치와 적용 범위 밖을 숨기지 않고 따로 기록했다.
적용 오류 10개는 8화자에 불과해 한 사례가 검출률 10%p를 바꾼다.

기존 `eval_sibilant_directional.py`와 어댑터를 수정하지 않았다. 기준 모델이 고른 표준음과 점수·다른 판정은 고정하고,
후보가 해당 초성 ㅆ를 확률 0.6 이상으로 ㅅ으로 들을 때만 지적한다. `.6`은 보정된 오류 확률이 아니다.
세 후보가 같은 baseline을 공유하며, 이전 1,711개 baseline의 전체 body·raw·거절 결과도 지난 실행과 동일했다.
현 저장소 운영 응답 코드를 GPU에서 실행했으며 NPU 배포 실측은 아니다.

## 4. 실제 응답 결과

먼저 새 화자 확인셋의 **적용 가능한 문맥**만 비교한다.

| 방법 | 실제 오류 검출 / 10 | 정상 헛지적 / 468 |
|---|---:|---:|
| 기존 운영 응답 | 0 | 0 |
| 이전 대조 학습 후보 | 4 | 12 |
| 이번 자료 + 정상 가중치 1 | 3 | 4 |
| **이번 자료 + 정상 가중치 4** | **0** | **1** |

이전 후보와 이번 가중치 1은 자료·rank 대상도 달라 정상 가중치만의 효과로 해석하지 않는다.
같은 조건의 **1→4 비교에서는 헛지적 3개와 실제 검출 3개가 함께 사라졌다.**
새 화자 확인에서 기존 운영보다 오류를 더 잡지 못했고, 정상 헛지적은 1개 추가됐으므로 사전 기준을 실패했다.

재사용 RP의 **매핑 확인 전체 ㅆ 자리**는 다음과 같다.

| 방법 | 실제 오류 검출 / 99 | 정상 헛지적 / 776 |
|---|---:|---:|
| 기존 운영 응답 | 2 | 8 |
| 이전 대조 학습 후보 | 15 | 36 |
| 이번 자료 + 정상 가중치 1 | 9 | 31 |
| **이번 자료 + 정상 가중치 4** | **4** | **19** |

적용 문맥만 분모로 잡으면 오류 47/정상 485자리이고 검출·헛지적 개수는 같다.
그 문맥의 4−1 차이 화자 bootstrap 95% 구간은 재현율 −18.2~−2.3%p, 헛지적률 −4.1~−1.2%p다.
새 확인셋의 같은 구간은 각각 −66.7~0%p, −1.46~0%p로 작고 불확실하다.
문장별 구간도 산출물에 따로 기록했으며, 두 군집을 동시에 고려한 일반화 구간은 아니다.

RS029 정상 67자리에서는 이전 후보 1개에서 이번 두 모델 모두 0개로 줄었다.
원어민 수락 506발화의 추가 ㅆ→ㅅ 지적은 두 모델 모두 0개다. 원어민은 사람 음소 정답이 없어 지적 부담만 측정했다.
기존 확인셋 재사용에서는 가중치 4가 오류 4/17, 정상 헛지적 0/176이었지만, 새 확인셋 실패를 대신할 수 없다.
RP에서 가중치 4의 기존 운영 대비 추가 헛지적 11개 중 9개는 정상 `쓰기`에 몰렸고, 추가 검출 2개는 RP002에만 있었다.
이 두 검출도 기존 모델이 이미 ㅅ로 인식했지만 화면에서 숨겼던 자리다. 새 화자에 남은 헛지적 1개는 정상 `있어요`였다.

## 5. 사라진 실제 오류를 확인했다

새 확인에서 가중치 1이 검출하고 4가 놓친 3개는 원본 TAG와 직접 대조했다.

| 문맥 | 사람 실제 전사 | 가중치 1 인식·확률 | 가중치 4 인식·확률 |
|---|---|---|---|
| 못 보셨어요? | ㅅ | ㅅ · 0.650 | ㅆ · 0.725 |
| 닮았어요? | ㅅ | ㅅ · 0.682 | ㅆ · 0.617 |
| 늦었어 | ㅅ | ㅅ · 0.807 | ㅅ · 0.508 |

두 자리는 모델이 실제 오류를 표준 ㅆ로 되돌렸고, 한 자리는 ㅅ 확률이 고정 표시 기준 아래로 내려갔다.
헛지적 감소도 ㅆ로 되돌리거나 ㅅ 확률을 낮추는 방식으로 일어났다.
가중치 4에만 새로 생긴 검출은 매핑 확인 정상·오류 자리 전체에서 0개였다.

따라서 **이번 정상 보존 강화는 지적을 줄이는 효과를 냈지만 정상과 실제 오류를 더 잘 가르는 목표는 달성하지 못했다.**
이 평가 결과에 맞춰 가중치나 표시 임계값을 다시 고르지 않았다. 이후 탐색에서도 이번 자료는 개발 자료로 관리해야 한다.
