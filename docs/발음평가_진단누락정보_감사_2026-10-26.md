## 1. 기반 모델의 자료 노출: 기존 설명에 오류가 있었다

단순한 source split 표시 대신, 모든 대상 UID를 M2의 train/valid/test TSV와 LTR 및 M3의 train TSV/LTR에 직접 대조했다.

| 자료 | 녹음 수 | M2 train 포함 | M2 valid 포함 | M2 test 포함 | M3 추가 학습 포함 |
|---|---:|---:|---:|---:|---:|
| D5 기존 TRAIN | 7,536 | 7,536 | 0 | 0 | 969 |
| D6 부분 전사 복원 자료 | 694 | **694** | 0 | 0 | 97 |
| D7 문맥 정상 자료 | 1,248 | **1,248** | 0 | 0 | 166 |
| CAL | 5,425 | 0 | 0 | 5,425 | 0 |
| 주평가 primary | 943 | 0 | 0 | 943 | 0 |
| 보호 488녹음 | 488 | 0 | **483** | 5 | 0 |

**“D6는 부분 전사여서 M2 학습에서 제외됐다”는 기존 모델 명세의 설명은 잘못됐다.** M2 매니페스트 생성기는 불명 표기를 버린 나머지 자모열로 LTR을 만들며, `dropped`가 있다는 이유만으로 발화 전체를 제외하지 않았다. D6·D7은 최근 국소 보조 학습의 완전 전사 선정에서 빠져 있던 자료를 복원한 것이지, M2가 전혀 보지 않은 새 녹음이 아니다. D5와 D6·D7의 `dropped` 보유 녹음은 각각 0/7,536, 694/694, 1,248/1,248이었다.

UID뿐 아니라 실제 M2 LTR도 대조했다. D6의694개·D7의1,248개 모두 불명 표기를 제거한 기존 실제음열(`legacy_actual`)과 M2 학습 타깃이 정확히 같았다. 근거는 `<A>/M2_partial_target_comparison.json`이다.

M3의 데이터 포함 여부도 양쪽 모두 일부씩 존재한다. 따라서 “기존/신규 출처”를 “기반 모델 노출/미노출”의 처치로 설명할 수 없다. 부분 전사·문맥·선정 방식의 차이는 여전히 교란 가능성이 있다.

여기서 **포함은 보존 학습 매니페스트의 포함 여부**다. M2·M3의 매 optimizer 업데이트별 UID 노출 로그를 확보한 것은 아니므로 개별 녹음을 실제 몇 번 학습했는지까지 증명하지 않는다. UID를 중심으로 한 일치이며, 전체 M2 원천의 모든 PCM 별칭을 이번에 새로 전수 비교한 것은 아니다.

### 보호 자료의 의미도 축소해야 한다

483개는 M2 체크포인트 선택에 사용한 valid에 속한다. 따라서 보호 488개를 **기반 모델까지 포함한 독립 미사용 최종 평가셋**으로 부를 수 없다. 최근 보조 모델의 학습·보정·채점에서 보류했다는 제한된 의미만 유효하다. 기존 보고서의 최종 평가 계획은 이 제한을 반영해 수정했다. 이번에는 UID와 분할만 조사했으며 해당 녹음에 모델을 실행하지 않았다.

## 2. CAL 미검출·헛지적 단계와 입력 거절

### 확정 오류 232개 전체의 배타적 단계 분해

| 관측한 단계 | 오류 수 |
|---|---:|
| 입력 거절 | **58** |

18건은 실제음이 TAG와 일치하고 자리 점수가 모두 60 이상이었다. ㅅ→ㅆ 6건은 인식 확률 .530~.598로 일반 세기 예외 .6에도 못 미쳤고, ㅆ→ㅅ 4건은 반대 방향 예외가 기본 운영에서 없었다. 나머지 8건은 제3음소 오류다. 이 결과는 표시 규칙의 기여를 보여 주지만, 문턱을 풀면 늘어날 정상 지적을 평가하지 않고 변경할 근거는 아니다.

126건은 기존 디코더에서 기대음이 나온 사례여서 **표시 문턱만 낮춰서는 새 지적이 생기지 않는다.** CTC의 연결 없음은 실제 자음이 물리적으로 없다는 증거와 구분한다. 보조 모델의 구간 관측 실패도 위 단계와 중복될 수 있어 별도 집계한다.

## 3. 운영 판정 규칙 명세

아래는 10월25일 원격 소스·실행 인자 확인과 일치했던 운영 경로다. 이번 감사에서 운영 서버를 재시작하거나 최신 원격 상태를 다시 확인하지 않았다.

| 단계 | 실제 동작 |
|---|---|
| 디코딩 | CTC 프레임 argmax → 연속 중복 합침 → blank 제거. 별도 beam search·언어모델 없음 |
| 기대 발음 | KoG2P + `canonical_fix`. 허용 변이는 같은 음향 로그확률의 비교로 선택 |
| 대응 | `edlib.align(..., task='path')`의 전역 편집거리 정렬 한 경로. 서비스의 한 경로와 감사의 모든 최적 경로 모호성 검사는 다름 |
| 인식 확률 | 그리디 토큰을 출력한 연속 프레임 중 해당 자모 확률의 최댓값. 발음 정확성의 보정 확률과 다름 |
| 자리 점수 | 기준음 CTC 강제정렬 구간의 margin GOP를 음소·위치별 보정. `p_error=sigmoid(a·margin+b)`, `score=round(100·(1−p_error))` |
| 보정 묶음 | `초성 ㅅ`, `초성 ㅆ`, `받침 ...`, `모음 ...`별 a/b, 없으면 `_global`. 모음별·개별 문항별 표시 문턱이 아님 |
| 일반 대치 표시 | 인식음≠기대음이고 점수<60일 때. 60 이상은 `uncertain:true`로 유보 |
| 세기 예외 | 초성 예사→된·거센소리, 인식 확률≥.6이면 점수60 이상이어도 표시. **ㅅ→ㅆ도 이미 포함** |
| ㄴ↔ㄹ 예외 | 초성·종성에서 확률≥.6이면 점수 문턱 예외. 운영 켬 |
| 삭제 표시 | 일반적으로 강제정렬 보정 점수<50일 때 표시. 점수/인식 결측과 통째로 빠진 글자의 별도 집계 처리 있음 |
| 기본 입력 길이 | .3초 미만 거절. 기본은 앞20초 분석. 긴 입력 거절 스위치는 꺼져 있음 |
| 음성 검사 | 에너지 기반30ms RMS, 임계 `max(최대RMS×.06, .0008)`. 음성 비율≥.30, 말한 시간≥`min(1.0,max(.2,.08×한글음절수))` |
| VAD 전처리 | 앞뒤 약.15초 여유, 중간 긴 침묵은 최대 약.5초까지 남김. 에너지 검출이지 유성/주기성 검출 아님 |
| 별도 거절 스위치 | `no_match`, `too_long`, `no_korean`은 해당 운영 확인에서 꺼져 있었음 |

꺼 둔 `--ss-rule`의 정의는 다음과 같다.

- ㅅ→ㅆ: 인식 확률 기준을 .6에서 **.5**로 완화한다.
- ㅆ→ㅅ: 확률≥.6이며 문장 처음 또는 바로 앞 기대음이 모음인 초성에만 점수 예외를 준다. 받침 뒤는 제외한다.
- 인식열이 기대음으로 복원된 자리에서 새 실제음을 찾아내는 모델은 아니다. 효과가 없어 운영에서는 꺼 뒀다.

0~100 자리 점수는 `(1−p_error)` 보정값이지 두 음소의 물리적 유사도나 객관적 발음 정확도 그 자체가 아니다. 삽입은 기본 자리 정렬에서 건너뛰고, 삭제 인식음/음소 점수는 `null`을 유지하는 경로가 있다. 단어·발화 점수는 이 표시와 별도로 집계한다.

## 5. 라벨 신뢰도: 확인한 내용과 아직 못 한 내용

공개 AIHub 설명에서 수동 발음전사·오류태깅·평가 라벨의 형식과 담당 기관은 확인했다. 그러나 **ㅅ/ㅆ 청취 판정의 세부 기준, 녹음당 독립 전사자 수, 불일치 조정 절차, 해당 대립의 평가자 간 일치도**는 이번에 읽을 수 있었던 소개 본문에서 확인하지 못했다. 첨부 가이드 다운로드 요청은 정상 접근 오류 응답이어서 내용을 확보하지 못했다. 문서가 존재하지 않는다는 뜻은 아니다. [공식 영어권 설명](https://aihub.or.kr/aihubdata/data/view.do?aihubDataSe=data&currMenu=115&dataSetSn=71469&topMenu=100), [중·일어권 설명](https://aihub.or.kr/aihubdata/data/view.do?aihubDataSe=data&currMenu=115&dataSetSn=71490&topMenu=100).

**현재 보고서의 `ambiguous/모호`는 청취자 불일치가 아니다.** TAG 실제음열과 LAB 기대음열의 최소 편집 정렬에서 여러 대응이 가능한 상태다. 추가 부분 전사 복원 자료에는 원천 라벨·시간 대응을 확정하지 못한 상태도 포함된다. 이를 사람 판정 신뢰도의 직접 측정값으로 사용하면 안 된다.

## 7. 통계적 불확실성

동일 화자의 자리들을 묶고, 전체 대상 화자를 복원추출해 분자·분모를 함께 재계산했다. 화자 수는 CAL401·primary495, 반복2,000회·seed20261026, percentile95% 구간이다. 각 정책의 출력은 고정했고 비교는 같은 추출 인덱스의 paired 차이다.

| 관측 결과 | 점 추정 | 화자 bootstrap 95% 구간 |
|---|---:|---:|
| CAL 기존 정확 검출20/232 | 8.62% | **4.83~12.64%** |
| CAL 기존 정상 지적93/7,189 | 1.294% | 0.967~1.655% |
| CAL 모음기준 후보20→23, 검출률 차 | +1.29%p | **0~+3.03%p** |
| 같은 후보 정상 지적93→92, 비율 차 | −0.014%p | −0.131~+0.099%p |
| primary 같은 후보25→27, 검출률 차 | +0.59%p | **−0.56~+1.94%p** |
| 같은 후보 정상 지적4→1, 비율 차 | −0.394%p | −0.894~0%p |
| 최신 native CAL20→20, 검출률 차 | 0 | [0,0]의 관측 차 |
| 최신 native CAL93→86, 정상 지적률 차 | −0.097%p | −0.173~−0.028%p |

작은 검출 차이의 일반화는 뒷받침되지 않는다. 다만 “기준 비율의 구간이 겹치니 모든 작은 차이는 잡음”이라는 판단도 정확하지 않다. **동일 사례의 paired 차이를 봐야 한다.** 최신 native의7개 정상 지적 감소는 고정 출력의 조건부 구간에서는0을 제외했다. 그러나 같은 CAL로 유보 정책을 정했고 반복 탐색도 했으므로 새 자료에서 확인된 효과는 아니다. 1% 한도 미달과 추가 검출0이라는 기존 탈락 판단도 그대로다.

이 구간은 문항 간 일반화·여러 모델 탐색·정책 선택의 낙관성·라벨 오류를 보정하지 않는다. `[0,0]`은 이번 출력의 차이가0이라는 뜻이지 모집단 차이가 정확히0이라는 증명이 아니다. 연구의1% 점 추정 한도와 모집단 FPR의95% 상한 보장은 서로 다른 목표다.

## 9. 원본 샘플레이트·기기와 학습 리샘플링

원본 표본화율은 준비 시 남긴 `_index.tsv`를 UID로 대조했다. 공개 설명의 대표 포맷만으로 실제 자료 전체를44.1kHz라고 적지 않았다.

| D5 | 6,703 | 692 | 38 | 71 | 23 | 9 |
| CAL | 4,758 | 538 | 54 | 48 | 27 | 0 |
| primary | 833 | 93 | 6 | 10 | 1 | 0 |
| D6 | 611 | 66 | 5 | 9 | 3 | 0 |

학습 음성 변환은 [resample_gold_16k.py](../tasks/pronunciation-assessment/scripts/data/resample_gold_16k.py)의 PCM 정규화·채널 평균·`scipy.signal.resample_poly`·PCM16 저장이다. 브라우저의 단순 선형 보간/표본 건너뛰기와 다른 경로다.

기존 `to16k()` 함수를 그대로 실행한44.1/48kHz 제어 시험에서1k·6kHz 크기는 약±.01dB로 보존됐고,9kHz가7kHz로 접히는 성분은 약−30.59dB였다. 대역 제한이 있으나 이상적인 완전 제거는 아니다. `<A>/resampling_audit.json`에6시험을 기록했다.

선언된 원본 음성 디렉터리 배치에서 재구성용 원본 WAV는0개였다. **이는 이 배치의 조사 결과이며 서버 전체에 원본이 없다는 주장이 아니다.** 과거 모든 원본→16k 변환을 이번에 다시 계산해 일치 확인한 것은 아니다. 녹음 기기 제조사·마이크별 분포는 기존 인덱스·파싱 메타데이터에서 확보하지 못했다. mono 여부나 online/offline을 기기 종류로 대체하지 않는다.

## 11. 점수 회귀기 M2→M3 정합성

**M3 특징으로 회귀기를 다시 학습한 것이 아니다. 기존 회귀기를 유지하고 모델 교체 후 검증했다는 기록이 있다.**

10월21일 보고서의 테스트 화자800명·통과26,390발화 비교에서, 기존 혼합 모델→M3 100%의 화자 PCC는 발음.681→.683·이해.711→.713·유창성.752→.752, 평균 점수는 대체로−.02~−.03점이었다. 점수 회귀기와0~100 보정은 유지했다. [해당 점수 검증](발음평가_개선_반영_2026-10-21.md#3-5-점수).

이는 기존 본 문항·테스트 화자 조건의 교체 영향 검사다. M3에 맞춘 재학습·새 문장/기기의 보정오차·서비스 하위집단별 점수 정합성까지 검증한 것이 아니다. 로컬 joblib과 최신 운영 NPZ 자산의 hash 동일성도 이번 감사에서 원격 재대조하지 않았다. 따라서 “회귀기 재학습 완료”도 “아무 검증 없이 그대로 사용”도 맞지 않는다.

## 12. 이번 감사 이후 바뀌는 판단

2. **자유 문장용 백본 선택은 여전히 미검증이다.** H0의 동일 문항·화자 분할, 실제 TAG, 원어민 replay·노출량·선택 규칙을 유지하고 백본을 바꿔 같은 seen 헛지적에서 unseen 헛지적과 오류 재현율을 비교해야 한다. 백본별 Stage1 한국어 지도학습 이력도 맞추거나 차이를 명시해야 한다. 이번 M3 분석과 M9 학습은 그 비교가 아니다.
3. H0 test는 이미 보고·분석에 사용됐으므로 새 최종 미사용 시험처럼 부르지 않는다. 미노출 문장·화자의 별도 확인 자료와 사람 청취는 아직 확보하지 못했다. 기존 사람 참여 불가 조건을 자동 라벨로 대체하지 않았다.
4. 대형 모델·새 손실을 채택하거나 음향 인코더가 유일한 원인이라고 결론내리지 않는다. CTC 점수는 음향·학습 편향을 함께 담으며 현재 결과는 “정렬/문턱만으로 해결”의 제한된 근거를 줄였을 뿐이다.

첨부 문서의 논문은 원문 초록·공식 출처를 확인했다. [CTC-GOP 2024](https://www.isca-archive.org/interspeech_2024/cao24b_interspeech.html)는 정렬 의존성을 줄이는 접근, [음운 지식 후보 제한 2025](https://www.isca-archive.org/interspeech_2025/parikh25_interspeech.html)는 후보 그래프 효율화에 해당한다. [Intent vs. Surface, BEA 2026](https://aclanthology.org/2026.bea-1.23/)는 영어 학습자 ASR의 의도 복원과 음향 근거 재순위화를 다룬다. 현재 한국어 M3에서의 개선을 증명한 논문이나 이번 구현의 동일성을 뜻하지 않는다.

### 15.2 비교 레시피와 평가 경계

기존 XLS-R Stage1은 마스킹과 배치/손실 경로가 달라 재사용하지 않는다. w2v-BERT도 공통 루프에서 다시 학습해 대조한다. 기존 H0 궤적은 참고로 남긴다. 음성 전단과 공개 사전학습 코퍼스는 백본의 일부이므로 결과를 순수 파라미터 수 효과로 해석하지 않는다.

- **궤적 비교:** 문턱을 움직이지 않은 greedy 판정에서 checkpoint별 seen/unseen 헛지적을 계산한다. 인접 checkpoint 구간 안에서만 같은 seen 헛지적의 unseen 차이를 보간하며 통계적 우월성으로 단정하지 않는다.
- **1% 정책 비교:** 기대 자모 강제정렬의 GOP margin으로 greedy 불일치를 선별하는 공통 오프라인 정책이다. seen 보정 화자의 정상에서 문턱을 정하고 별도 선택 화자의 seen/unseen에 그대로 적용한다. 1%를 넘으면 실패로 남기고 재조정하지 않는다. 이 표본의 분모로 예산을 계산하며 기존 CAL의71개 예산을 그대로 가져오지 않는다.
- **정확 진단:** 틀린 자리에서 다른 제3음을 지적한 것을 정답으로 세지 않는다. 점수를 못 낸 자리도 전체 분모와 관측 실패 집계에 남긴다. 전체·RS문장·엄격한 원어민 미중복·기대ㅅ/ㅆ를 별도로 출력한다.

## 16. H0 전체 음소 오류 감사 — 2026-10-27

**P0를 먼저 실행했다. 2k→4k unseen 헛지적 증가의 중심은 모음이며, 특히 ㅜ와 두 문항에 집중된다.** ㅅ·ㅆ만의 문제나 모든 새 문장에서 같은 크기로 악화되는 현상으로 설명할 수 없다. 같은 기대 음소·위치·뒤 모음 조건을 맞춰도 seen/unseen 차이는 남는다. 이 결과는 원인을 확정한 실험이 아니라 다음 표현·구간 진단의 범위를 정하는 탐색적 오류 감사다.

산출물 `<P>=/data/speech-ai/out/mdd/experiments/h0_phone_audit_2026-10-27_v1`. 본 절의 자리 집계는 `sites_v2/`이며 최초 집계 `sites/`도 보존했다. 기존 네 조건의 선택 역할 `sites.jsonl`에서 시작했고, 학습 갱신·문턱 재선택·test 평가·운영 변경은 하지 않았다. 삽입과 정렬 민감도는 원래 자리 파일에 전체 인식열이 없어서 같은 가중치로 선택 발화만 다시 추론해 별도 확인을 완료했다(§16.7).

### 16.1 분모·정의와 전체 음소 범위

네 조건 모두 동일한 seen 53,814자리(정상51,743·오류2,071), unseen 35,993자리(정상34,706·오류1,287)를 사용했다. unseen 오류는 실제 대치1,141·삭제146자리다. seen201문항·unseen9문항이며 음소별 정상/오류 수와 해당 문항 수도 별도로 센다. 원래 보고서의 greedy·보정 후 집계를 다시 계산해 모두 일치함을 확인했다.

- **정상 헛지적:** TAG 실제음=LAB 기대음인데 인식음이 다름. 아래 대치 화살표는 이 정상 자리의 `기대음=TAG → 모델 출력`이다. 실제 사람이 그 대치를 했다는 뜻이 아니다.
- **기대음 복원:** TAG는 오류인데 모델이 기대음을 냄.
- **실제음 오진:** TAG는 오류이며 모델도 기대음과 다르게 냈지만 실제 TAG 음소와 다름. 정확 진단과 분리한다.
- **정확 진단 후 유보:** 인식음은 TAG와 같지만 저장된 GOP 문턱에 걸려 경고하지 않음. 낮은 헛지적을 위한 필터의 관측 결과이며 구간 정렬이 잘못됐다는 인과 판정은 아니다.

CTC 사전의 특수 토큰을 뺀 **46자모 모두**를 [음소별 전체 표](</data/speech-ai/out/mdd/experiments/h0_phone_audit_2026-10-27_v1/sites_v2/phones.tsv>)에 남겼다. 정상·오류 분모, 기대음 복원·실제음 오진·정확 진단, GOP 유보·통과, 문항 수와 문항별 FPR 최소/최대/평균을 포함한다. [음소×문항 표](</data/speech-ai/out/mdd/experiments/h0_phone_audit_2026-10-27_v1/sites_v2/phone_items.tsv>), [위치·문맥별 표](</data/speech-ai/out/mdd/experiments/h0_phone_audit_2026-10-27_v1/sites_v2/groups.tsv>), [대치·삭제 혼동표](</data/speech-ai/out/mdd/experiments/h0_phone_audit_2026-10-27_v1/sites_v2/confusions.tsv>)도 별도다. 분모0은 성능0%로 채우지 않았다.

선택 unseen에서 기대음 표본이 없는16자모는 `ㅋ·ㅍ·ㅃ·ㅝ·ㅟ·ㅢ·ㅠ·ㅙ·ㅞ·ㄻ·ㄼ·ㅒ·ㄺ·ㅄ·ㄳ·ㄵ`다. 예를 들어 ㄱ→ㅋ 출력은 관찰할 수 있어도 정상 기대ㅋ 자리의 FPR은 이 unseen 셋으로 평가할 수 없다. **전체 사전을 집계했다는 것과 모든 한국어 음소·문맥을 검증했다는 것은 다르다.**

초성·중성·종성은 LAB의 평탄한 실제 발음 자모열에서 추론한 위치다. 철자 음절 위치·물리적 음향 경계와 같다고 가정하지 않는다. 뒤 모음은 해당 자리 다음에 처음 나타나는 모음으로 정의했다. TAG의 최소 편집 정렬에서 실제음 대응이 여러 가지인 자리도 표시하고, 임의의 한 라벨로 덮어쓰지 않았다.

| 모델 | 같은 문맥 구성으로 재가중한 seen FPR | 공통 문맥 unseen FPR | 차이 |
|---|---:|---:|---:|
| w2v-BERT 2k | 6.94% | 13.50% | +6.56%p |

이 절은 **문맥 구성 재가중**이다. §15.4의 **같은 seen FPR에 맞춘 백본 궤적 보간**과 다른 계산이며, 음소별 백본 우열을 같은 운영점에서 증명한 표가 아니다.

### 16.5 종성·음운 규칙 후보

| unseen 규칙 후보 | 정상 / 오류 / 정상 문항 | w2v-BERT 정상 헛지적2k→4k | XLS-R 정상 헛지적2k→4k |

### 16.7 전체 인식열 복원: 삽입과 정렬 민감도

각 조건에서 **동일 선택 발화9,250개를 다시 추론해 총37,000회** 실행했다. 고유 녹음37,000개를 새로 모은 것이 아니다. 기존 checkpoint hash를 확인하고, 복원한 전체 greedy 인식열을 기존 방식으로 canonical 자리에 대응시켰을 때 **네 조건의89,807자리씩 모두 기존 `sites.jsonl`과 정확히 일치**했다. 학습 갱신0회, `capture.exit=0`, 약25분51초다.

**삽입:** canonical 자리 사이 gap으로 별도 센다. seen은59,055gap 중 실제 삽입181개, unseen은40,002gap 중 실제 삽입106개·정상gap39,896개다. 다중 음소 삽입도 한 gap의 음소열로 비교하며 정확 진단은 삽입열 전체가 같아야 한다.

| 모델 | unseen 정상gap 헛삽입 / 39,896 | 실제 삽입 정확 진단 / 106 | 삽입은 찾았으나 음소열 틀림 | 삽입 미검출 |
|---|---:|---:|---:|---:|
| w2v-BERT 2k | 357 (0.89%) | 22 (20.75%) | 11 | 73 |
| w2v-BERT 4k | 196 (0.49%) | 15 (14.15%) | 10 | 81 |
| XLS-R 2k | 473 (1.19%) | 29 (27.36%) | 17 | 60 |
| XLS-R 4k | 298 (0.75%) | 24 (22.64%) | 15 | 67 |

2k→4k에서 헛삽입은 줄고 실제 삽입 보존도 줄었다. 앞서 본 삭제 출력 증가와 함께 읽어야 한다. 실제 TAG 전체35,970토큰에 대해 인식열 길이 합은 w2v-BERT35,703→34,587, XLS-R35,365→33,973으로 짧아졌다. 이것은 출력에서 확인한 변화이며 학습 목적함수가 길이 편향을 만든다는 인과 증명은 아니다.

gap의 위치는 기존 한 개 최소 편집 경로를 따른다. 삽입 신뢰도·GOP 문턱을 새로 만들지 않았으므로 **greedy 삽입 지표**이고, 일부 gap FPR이1% 미만이라고 전체 음소 서비스 목표를 통과한 것이 아니다. [gap 혼동표](</data/speech-ai/out/mdd/experiments/h0_phone_audit_2026-10-27_v1/sequence_audit/gap_confusions.tsv>)에 앞·뒤 자모와 실제/인식 삽입열을 보존했다.

**정렬 민감도:** canonical↔TAG, canonical↔인식열의 모든 최소 편집 경로에서 각 자리에 올 수 있는 음소값을 계산했다.

| 모델 | unseen 정상 헛지적 중 대응 음소값이 경로에 따라 달라짐 | 모든 최적 경로에서 대응 음소값이 고정된 헛지적 |
|---|---:|---:|
| w2v-BERT 2k | 917 | 4,338 |
| w2v-BERT 4k | 1,192 | 4,928 |
| XLS-R 2k | 1,424 | 4,567 |
| XLS-R 4k | 1,666 | 5,442 |

**‘경로에 따라 달라짐’을 ‘정렬 오류로 밝혀짐’으로 세지 않는다.** 다른 경로에서도 모두 틀린 음소일 수 있다. 반대로 대응값이 고정된 헛지적도 두 모델에서 증가하므로, 악화 전체를 최소 편집 경로의 임의 선택만으로 설명할 수 없다. 정상ㅜ의 대응값 고정 헛지적은 w2v-BERT329→773, XLS-R302→782다. 음향 구간의 물리적 정렬 문제는 이 편집거리 검사로 판정하지 못한다.

canonical을 거치면 실제음이 틀렸지만 TAG↔인식열의 직접 편집 대응에서는 해당 TAG 음소가 맞는 자리도 unseen43→39 / 60→39개 있었다. 이것은 부분적인 대응 방식 민감도이며 전체 인식열이 맞았다는 뜻은 아니다. 여러 자리의 가능한 음소값이 각각 겹친다는 사실만으로 모든 자리를 동시에 고치는 한 경로가 있다고 주장하지 않는다.

**전체 인식열이 TAG와 정확히 같은 경우**에는 이 결정적 자리 대응에서 음소 오진0건이었다. 그러나 그중 실제 오류를 GOP가 유보한 자리는 unseen w2v-BERT151→121, XLS-R156→131개다. 정확히 인식했으나 경고되지 않는 경로는 존재한다. 이 유보를 풀 때의 정상 헛지적 대가나 GOP 구간의 정확성을 이번 결과만으로 판단하지 않는다. [음소·위치별 정렬 및 유보 집계](</data/speech-ai/out/mdd/experiments/h0_phone_audit_2026-10-27_v1/sequence_audit/alignment_phones.tsv>)를 추가했다.

‘수리’는 전체 TAG 음소열이 정상인 동일475발화에서도 w2v-BERT의 `ㅅㅗㄹㅣ` 출력이86→420개, XLS-R49→327개로 늘었다. 이 부분은 자리 대응만의 착시가 아니라 **전체 인식열에서 확인한 수리→소리 변화**다. 실제 녹음의 독립 청취 결과는 없으며 문장 암기·음향 표현·라벨 중 어느 것이 원인인지 아직 확정하지 않았다. [정상 발화의 전체 인식열 혼동표](</data/speech-ai/out/mdd/experiments/h0_phone_audit_2026-10-27_v1/sequence_summary/normal_sequence_confusions.tsv>)에 모든 문항을 함께 남겼다.

### 16.8 기준열 변형과 다음 진단의 범위

저장 LAB에서 같은 RS012 문항도 `…ㅣㄷㄸㅗ…`183발화 / `…ㅣㄸㅗ…`131발화의 두 canonical 열을 가진다. RS017은 `…ㅁㅕㄴㅆㅣ…`와 `…ㅁㅕㄷㅆㅣ…`, `ㄴㅐㅣㄹ…`과 `ㄴㅐㅇㅣㄹ…`의 조합으로162/126/10/10발화의 네 종류다. 그 밖의7개 unseen 문항은 각각 하나의 canonical 열이다. [기준열별 분모·오류 표](</data/speech-ai/out/mdd/experiments/h0_phone_audit_2026-10-27_v1/sequence_audit/reference_variants.tsv>)에 같은 문항 안의 변형을 분리했다. 원본 LAB·전처리·허용 발음 중 원인을 확인하지 않은 상태에서 잘못된 라벨로 고치거나 평가에서 제외하지 않았다.

이번 P0에서 결정할 수 있는 다음 순서는 다음과 같다.

1. **P1 표현·구간 비교를 전체 음소로 진행한다.** 모음ㅜ→ㅗ·ㅗ→ㅓ, 모음 삭제, 초성 대립, 종성 대치·삭제와 연음 후보를 함께 유지한다. ㅅ·ㅆ 전용 판별부로 축소하지 않는다. 오류 표본이 없는 음소는 평가 불가로 남긴다.
2. **초기/중간/최종층×자동/다중 창/TAG 진단 구간**을 같은 TRAIN과 같은 크기의 경량 probe로 비교한다. 새 probe의 TRAIN 적합도를 성과로 쓰지 않는다. 실제음 판별 입력에 기대 자모를 주지 않고, TRAIN에서만 전처리·투영을 학습한다. 보정 화자에서 정한1% 문턱은 선택 seen/unseen에 그대로 적용하고 달성 FPR·정확 진단·관측 실패를 함께 보고한다.
3. **P2는 기준열과 보정 이전을 별도로 검증한다.** 시계ㅖ·두 문장의 LAB 변형·문턱 분해는 우선 검토 항목이다. 원래 라벨을 보존하고 독립 근거 없이 정상/오류를 재분류하지 않는다. 자동 구간과 TAG 구간의 차이는 물리 경계의 정답 비교로 부르지 않는다.
4. **P3 새 학습 목적함수 채택은 보류한다.** P0는 모음·문항 집중과 대응 민감도를 보여줬지만 인코더 중간층에 정보가 남아 있는지는 측정하지 않았다. [P1 설계 기록—미실행](</data/speech-ai/out/mdd/experiments/h0_phone_audit_2026-10-27_v1/P1_design_NOT_EXECUTED.json>)에 후속 비교 조건을 남겼다.

이번9문항은 반복 분석한 개발 자료다. 원어민 문자열도 겹치지 않는5문항의 §15.4 성능은 **valid 하위 집합**이며, 별도로 식별한 엄격 test5문항을 이번 네 조건으로 추가 채점한 결과가 아니다. 새로운L1·새 미사용 문장·독립 청취는 여전히 없으며, 현재 원인 가설과 후속 설계가 이9문항에서 생겼다는 점도 다음 결과에 표시해야 한다.

## 17. P1: 같은 녹음의 층별 표현·구간 진단 (10월27일 후속)

산출물 `<Q>=/data/speech-ai/out/mdd/experiments/h0_representation_diagnostic_2026-10-27_v1`. **P1 36조건의 학습·평가·검증 완료.** ‘수리’의 후기층 악화와 전체 음소의 정상 보호 실패를 구분해 아래에 기록한다. P0에서 관찰한 ‘수리’ 현상을 우선 사례로 삼되, 사전46자모와 삭제를 모두 출력하는 공통 probe를 사용한다. 음향 인코더와 기존 CTC 가중치는 고정한다.

### 17.1 고정한 비교 조건

| 항목 | 실행 조건 |
|---|---|
| 인코더 | 기존 통제 실험의 w2v-BERT/XLS-R 300M × Stage2 2k/4k |

원어민 replay에는 동일한 TAG 시간 감독이 없어 **이번 probe TRAIN에는 넣지 않는다.** 기존 인코더 학습의 replay를 제거하거나 바꾼 것이 아니다. TRAIN의 일부만 사용하는 고정 용량 탐침이며, 실패를 표현의 모든 정보가 없다는 상한 증명으로 쓰지 않는다. TRAIN 적합도는 실행 검사일 뿐 성공 지표가 아니다.

원시 TAG/LAB 정규화가 기존 타깃과 일치하는지 확인했다. 모호한 편집 대응, 여러 음소를 하나의 시간 구간에 적은 경우, 명시 구간 없는 삭제는 TAG 진단 입력을 만들지 않는다. 평가에서 해당 자리는 분모에 유지하며, 모든 구간이 있는 공통 자리 비교도 별도로 남긴다. TAG 시간은 물리적 경계의 독립 정답도 서비스 입력도 아니다.

‘수리’는 **동일한 전체 TAG 정상475녹음의ㅜ 자리**를 고정한다. 이 집합은 실제음이ㅜ 하나뿐이므로ㅜ/ㅗ AUC를 만들지 않는다. 실제ㅜ와ㅗ가 모두 있는 기대ㅜ 자리에서의 AUC를 따로 계산하고 표본·문항 수를 붙인다. 2k→4k의 같은 TAG 구간에서 cosine·상대 L2 변화와, **2k probe 및 전처리를 그대로4k 표현에 적용한 점수 변화**도 기록한다. 새 probe를 각각 학습한 결과와 같은 readout을 고정한 표현 변화를 구분한다.

### 17.2 실행 검사

두 백본 각각 실제 음성4개에서6·12·24층 추출을 native hidden-state API와 대조했다. 여덟 사례 모두 층별 표현과 CTC logits의 최대 차이가0이었다. 자동 구간의 TAG 독립성·모호한 대응·삭제 시간·프레임 시계·문턱 동점을 검사한 단위 검증6개도 통과했다. 전체 특징 추출에서도 조건마다18,030발화·191,327자리를 처리했고, 평가14,009발화의 기존 canonical 자리 인식값이 모두 일치했다. 네 조건의 음성 PCM·순서 hash도 같다.

실행 상태는 `<Q>/각조건/live_status.json`이며 `finished.json`이 생성된 조건만 완료로 센다. 병렬 실행 중 공통 상태 파일의 임시 이름 충돌로 XLS-R4k가3,300발화 후 중단한 기록은 보존했다. 임시 파일 이름을 프로세스별로 분리하고 원 checkpoint에서 해당 조건을 다시 실행했다. 미완성 특징은 probe에 사용하지 않는다. 실제 실행 소스 버전은 `<Q>/execution_source_provenance.json`에 구분했다. 완료 receipt의 소스 hash는 저장 시점 파일 hash여서 실행 시작 시점 소스와 혼동하지 않는다.

공통 TRAIN 감독은53,887자리·4,010녹음이다. 준비한4,021녹음 중11개는 확정 TAG 구간이 없어 probe 감독에 들어가지 않는다. 각 probe의 실제512,000회 draw는 고유53,884자리·4,010녹음을 포함하며 동일 배치 hash를 사용한다. 출력47개 중 감독0개는ㄳ·ㄵ·ㄺ·ㄻ·ㅄ·ㅒ, 극소 표본은ㄼ1·ㅙ4·ㅞ1이다. 이 음소들에 대한 부정 결과를 표현의 정보 부재로 해석하지 않는다.

TAG 구간을 만들 수 있는 선택 자리는 seen53,172/53,814·unseen35,684/35,993이다. unseen 오류는1,127/1,287개여서, TAG 비교의 관측 실패160개를 정상으로 바꾸거나 오류 분모에서 없애지 않았다. 원본 TAG 끝 시각이 녹음 길이를 넘는 구간49개의 최대 초과는4ms다. 실제 존재하는 프레임만 사용하며 음성을 늘리거나 라벨을 수정하지 않았다(`<Q>/tag_audio_boundary_audit.json`).

### 17.3 ‘수리’: 중간층의 실제ㅜ 신호가 최종층보다 남아 있다

전체 TAG가 정상인 동일475발화의 **ㅜ 한 자리**를 맞힌 수다. P0의 전체 음소열 `ㅅㅜㄹㅣ` 정답 수와 다른 지표다. 각 칸은2k→4k이며, 각 checkpoint의 같은 TRAIN으로 각각 학습한 선형 probe 결과다.

| 백본 | 층 | 자동 구간 | 다중 창 | TAG 시간 구간 |
|---|---:|---:|---:|---:|
| w2v-BERT | 6 | 408→427 | 392→418 | 415→406 |
| w2v-BERT | 12 | 382→412 | 366→412 | 375→366 |
| w2v-BERT | 24 | 370→36 | 366→45 | 255→17 |
| XLS-R300M | 6 | 311→320 | 317→328 | 384→387 |
| XLS-R300M | 12 | 356→343 | 353→351 | 400→370 |
| XLS-R300M | 24 | 426→275 | 431→204 | 396→197 |

w2v-BERT4k의 자동 구간에서 중간12층412/475(86.7%) 대 최종24층36/475(7.6%)다. TAG 구간에서도366 대17로 차이가 남는다. **이번 ‘수리’의 후기층 악화를 CTC 출력층 하나나 자동 구간 위치만의 문제로 설명하기는 어렵다.** 최종 표현에 새 probe를 학습해도 복구하지 못하지만, 같은 녹음의 중간 표현에서는 많이 복구한다. 다만 다른 녹음·다른 probe까지 정보가 완전히 사라졌다는 증명이나 학습 목적함수의 인과 효과는 아니다.

XLS-R도 최종층에서2k→4k 정답 수가 줄지만 감소 크기와 구간 효과는 다르다. 4k의 초기6층은 TAG 구간387개가 자동320개보다 많고, 최종층은 TAG197개가 자동275개보다 적다. **TAG 구간 또는 다중 창이 모든 층에서 우세한 패턴은 아니다.**

**같은 readout을 고정해도 변화가 보인다.** 2k probe와 TRAIN 평균/표준편차를 그대로4k의 같은 TAG 시간 구간에 적용하면, 최종층의ㅜ 예측은 w2v-BERT255→9, XLS-R396→116이다. 같은475개에서 `logit(ㅜ)−logit(ㅗ)` 변화 중앙값은−4.446/−4.245다. 같은 좌표의 표현 cosine 중앙값은.959/.973, 상대 L2 변화는.289/.232다. 표면적인 cosine 유사도만으로 판별 정보가 보존됐다고 할 수 없고, 고정 readout 실패만으로 정보 소실을 증명할 수도 없다. 각 checkpoint에서 새로 맞춘 probe와 함께 읽는다.

475개는 실제음이 모두ㅜ이므로 AUC는 `null`이다. 별도 unseen 기대ㅜ의 실제ㅗ21·정상ㅜ1,816자리(4문항)에서는 자동 구간 AUC를 계산했다. TAG 구간은 오류18·정상1,797자리이며 대상 수가 다르다. 예를 들어 최종층 TAG AUC는 w2v-BERT.860→.774, XLS-R.880→.888이다. **‘수리’ 정상ㅜ 정확도 하락과 전체 문항의 오류/정상 순위 AUC는 같은 관측이 아니다.** 문항 구성과 적은 오류 수 때문에 AUC의 작은 차이로 최고 조건을 고르지 않았다.

자동 구간은 ‘수리’에서 중앙값1프레임, TAG 구간은6프레임이다. 자동/TAG 중심 차이 중앙값은 w2v-BERT2k/4k40/40ms, XLS-R80/70ms다. XLS-R의 구간 미겹침은386→282/475개지만 모델의 출력 정답은 줄었다. **CTC 토큰 피크와 주석 구간의 불일치를 곧바로 물리적 정렬 오류 건수로 해석하지 않는다.** TAG 구간 평균은 CTC 피크 밖의 표현도 섞으므로, 이 구현을 모든 관측 방식의 성능 상한이라고 부르지 않는다.

### 17.6 이번에 좁혀진 가설과 완료 근거

- **후기층 표현 변화:** ‘수리’에서는 두 백본 모두 후기층에서2k→4k 이번 probe가 실제ㅜ를 맞히는 비율이 줄고, w2v-BERT에서는 중간층과의 차이가 크다. CTC 출력층 이전 표현까지 비교한 관측이다. 향후 중간층 실제음 감독·후기층 정보 보존을 통제 실험할 근거는 생겼지만 새 손실의 효과를 증명하거나 학습한 것은 아니다.
- **구간 관측:** TAG 구간과 다중 창으로 후기층 문제를 일관되게 복구하지 못했다. 단순 구간 교체만으로 해결된다는 근거가 없으며, TAG 주석 신뢰도와 평균 pooling의 제한 때문에 모든 정렬 개선을 기각하지 않는다.
- **정상 보호·문항 이전:** 중간층에서 일부 정상 음소를 복구해도 모든36조건이 unseen1%를 넘는다. 낮은 FPR, 실제 오류 정확 진단, 다른 음소의 기존 검출 보존을 함께 검증해야 한다.
- **현재 결정:** ㅜ 전용 보정기·중간층 probe의 서비스 채택과 추가 Stage2 장기 학습은 하지 않는다. 다음 학습 가설은 전체 음소를 유지한 중간 감독/후기 표현 보존이며, P2의 기준열·보정 이전 문제와 별도로 통제해야 한다. 이 문서에서 해당 학습까지 실행하지 않았다.

**실행 완료:** 4개 고정 인코더의18,030발화씩 특징 추출,36개 선형 probe×1,000회=36,000 optimizer 갱신을 완료했다. 인코더 갱신은0회다. `run.exit=0`, 후속 집계·검증도 종료코드0이다. 조건마다 P0의 선택9,250발화 전체 인식열까지 정확히 재현했다. 저장한36개 probe를 각각4,096자리에서 재로딩했을 때 logits 차이0이고, CAL 예산·선택 seen/unseen 정상/오류 집계가 원시 logits 재계산과 일치했다.

### 18.1 ‘시계’의 허용 발음은 일부만 설명한다

국립국어원의 표준 발음법 제5항 설명에는 ‘시계’의 [시계]/[시게]가 모두 허용된다. 따라서ㅔ 출력을 서비스에서 무조건 오발음으로 지적하는 기준은 적절하지 않다. **그렇다고 해당 녹음의 실제 발음이ㅔ였다고 확인한 것은 아니다.** TAG 실제음 일치와 규범적 허용 여부는 별개다. [국립국어원 설명](https://www.korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=216&qna_seq=302312).

| XLS-R4k | 255 | 178 | 102 | 24 |

**98.9~100%의 TAG 불일치를 전부 허용 발음 탓으로 지울 수 없다.** 특히 w2v-BERT4k는 대부분ㅐ이며, 인용한ㅖ→ㅔ 허용 규정을ㅐ까지 넓히지 않는다. 같은 정상 분모에서 해당ㅔ 경고만 제거하는 제한적 민감도 분석의 전체 unseen FPR은 w2v-BERT1.95→1.88% /4.82→4.72%, XLS-R1.88→1.88% /2.87→2.80%다. 네 조건 모두1%를 넘는다. 이는 보존 출력의 기준 호환성 점검이지 새 모델 성능·TAG 정확도 개선 결과가 아니다.

### 19.1 출발 상태와 통제 범위

출발점은 새 H0 통제 실험의 `w2vbert_stage2/step_2000.pt`다. **이 파일에는 모델·RNG·AMP 상태가 있지만 optimizer는 `None`이다.** 따라서 네 조건 모두 같은 AdamW 초기 상태로 재시작한다. 과거4k를 이어받은 것처럼 비교하지 않고, 새 B0를 효과 비교 기준으로 삼는다. 기존2k는 공통 출발점이며 기존4k는 역사적 참고값이다.

- 부모 RNG·AMP 상태를 새 모듈 생성 후 복원한다. 학습률은 기존40k tri-stage의2,001회 위치부터 이어간다(기반 최대LR1e-5, 첫LR5.05e-6). AdamW β(.9,.98)·eps1e-8·WD0·clip5, AMP, 마스킹 끔·LayerDrop .1을 유지한다.
- 원래 H0 전체1,761,083행을 사용한다. TRAIN 실제 타깃에는 사전46자모 모두 존재한다. 이는 각 음소의 충분한 오류 감독이나 라벨 신뢰도 검증을 뜻하지 않는다. `preflight_data.json`에 원어민/외국인 정상/오류별 전체 타깃 빈도와 실제 추가 노출의 빈도를 구분했다.
- 기존 처음8,000 microbatch를 재생해2k의 누적행·오디오 샘플·배치 hash가 모두 일치하는 것을 확인했다. 그 다음8,000 microbatch를 학습한다. 조건별 추가 노출은 **220,384행 = 외국인 정상118,340 + 오류79,612 + 원어민22,432**, 오디오12,449,115,378샘플(약216.13시간)이다. 복제 행이 포함돼 고유 녹음 수와 다르다.
- 전체누적4k의440,996행·24,893,215,091샘플·배치 hash도 기존 H0와 일치하도록 실행 말미에 검사한다. 합성 추가·ㅜ 전용 재표집·TAG 시간 감독은 없다.

### 19.2 네 조건과 사전 고정한 구현

| 조건 | 최종 예측 | 추가 학습 손실 | 학습 파라미터 수 |
|---|---|---|--:|
| B0 | 기존24층 CTC | 없음 | 580,544,370 |
| B1 | 기존24층 CTC | 0.3×12층 CTC | 580,597,668 |
| B2 | 12·24층 결합 CTC | 없음 | 580,546,419 |
| B3 | 12·24층 결합 CTC | 0.3×12층 CTC | 580,597,669 |

중간 표현은 HF `hidden_states[12]`이며 LayerDrop으로 해당 층이 생략된 경우도12개 층 슬롯을 지난 표현이다. 별도 LayerNorm 후50출력 CTC 헤드를 연결한다(46자모+기존 특수토큰). 중간 헤드는 부모 최종 CTC 헤드로 초기화한다. 최종·중간 손실 모두 발화별CTC NLL/타깃길이의 배치 평균이다. 추가 감독 헤드는 학습에 사용하며 기본 평가 출력은 최종 헤드다.

결합은 **`h24 + tanh(g) × LayerNorm(h12)`, 초기 g=0**인 단일 스칼라 잔차다. B3에서는 LayerNorm을 중간 감독과 공유한다. 확률적 혼합 계수나 음소별 게이트는 아니다. 추가 파라미터의LR은 기반LR의100배로 고정하며 같은 스케줄을 따른다. λ·층·결합 방식·추가LR 탐색은 하지 않는다. 네 조건의 최종 최초 출력이 같아야 하며, 평가에서는 기준 문장이나 실제 TAG를 인코더 입력으로 넣지 않는다.

이는 기존 방법을 바탕으로 한 단순 대조군이다. [Intermediate CTC, ICASSP 2021](https://arxiv.org/abs/2102.03216), [Self-conditioned CTC, INTERSPEECH 2021](https://www.isca-archive.org/interspeech_2021/nozaki21_interspeech.html), [inter-layer attention CTC, INTERSPEECH 2024](https://www.isca-archive.org/interspeech_2024/hojo24_interspeech.html)를 선행 근거로 둔다. 이번 스칼라 잔차가 마지막 논문의 attention 구현을 재현한 것은 아니며 신규 알고리즘 기여를 주장하지 않는다.

### 19.3 평가·실패 판정

**주 비교는 B3 4k 대 B0 4k로 고정**한다. B1·B2는 구성 요소의 효과를 분리하는 대조군,3k는 궤적 확인용이며 사후에 주 후보·주 checkpoint를 바꾸지 않는다.

- 기존 seen CAL 정상에서 모델·checkpoint별1% 문턱을 구하고 선택 화자의 seen/unseen에 고정 적용한다. 두 평가의 실제FPR≤1%, 전체unseen 정확 진단 재현율>B0를 함께 확인한다. 미달 수치를 `Recall @ FPR≤1%`로 부르지 않는다.
- 문턱을 바꾸지 않은 greedy 출력으로 공통2k와 B0 3k·4k 궤적을 만든다. 후보의 seen FPR이 관측 구간 안에 있을 때만 같은 seen의 unseen 차이를 보간한다. 범위 밖은 비교 불가다.
- 46자모·초성/중성/종성·문맥·문항별 정상/오류 분모와 기대음 복원·실제음 오진·정확 진단·GOP 유보를 보존한다. 표본0을 성능0으로 채우지 않는다.
- 실제 오류30개 이상인 unseen 음소 및 삭제/삽입 범주의 정확 재현율이 B0보다5%p 넘게 낮아지거나, 정상 gap 헛삽입이0.2%p 넘게 늘면 개발용 보호 기준 미달로 표시한다. 이 허용폭은 이번 탐색의 사전 기준이며 제품 목표나 모집단 비열등성 보장이 아니다. 희소 범주는 원시 건수와 한계를 남긴다.
- 전체 인식열을 함께 저장해 삽입 gap의 정확한 음소열 일치와 헛삽입을 계산한다. 이는 한 편집 경로의 greedy gap 지표로, 삽입용 보정 정책이나 생산 API 성능이 아니다. 정렬 경로 민감도도 별도 집계한다.
- 고정된 모델·CAL 문턱에서 화자와 문항의 paired bootstrap을 각각 계산한다. 학습 seed·CAL 재표집·다중 탐색을 보정한 확증 검정으로 해석하지 않는다. ‘수리’475발화의 회복은 진단 지표다.

‘수리’만 복구되고 다른 음소가 악화되면 전체 개선으로 채택하지 않는다. Fusion만 개선되면 추가 감독과 정보 전달의 효과를 구분한다. 인식 개선에도1% 조건을 못 맞추면 보정 이전 문제는 남는다. 모두 실패하면 데이터·문맥·라벨 감독을 재검토하며 임의의 보조 손실 추가로 이어가지 않는다.

기존9개 unseen 문항은 이미 반복 분석한 개발 자료다. **독립 신규 문장·화자 검증과 VAD·G2P·표시 정책을 포함한 실제 API 검증은 별도 미완료 조건**이다. 개발 기준을 통과해도 운영 교체를 자동 승인하지 않는다. P2의 원래 LAB/TAG는 그대로 유지한다.

### 19.4 실행 전 검증과 보존

실제 음성4개에서 네 조건의 초기 최종 logits가 기존 H0와 학습·평가 모드 모두 정확히 같고, forward 후 CPU/CUDA RNG도 일치했다. 본 배치 크기로 조건별2회 optimizer 갱신을 실행해 각 인코더 및 해당 추가 헤드/게이트 변경을 확인했다. 네 조건의 첫 최종 CTC loss와201행·12,379,677샘플 추가 노출·배치 hash가 일치했다. CUDA 최대 할당은 약24.2GiB였으며 모든 길이 배치의 상한 보장은 아니다.

### 20.5 해석: 중간 음소 증거는 남지만 최종 진단까지 보존되지 않는다

**B3에서는 중간 CTC가ㅜ를 맞혔는데 최종 CTC가 틀린 ‘수리’가323개다.** 이 가운데264개는 고정 probe도 동시에ㅜ를 맞혔다. 중간 CTC의 전체 `ㅅㅜㄹㅣ` 정답은320/475, 최종 CTC는28/475이며, 전체 `ㅅㅗㄹㅣ` 출력은108→433개다. 따라서 이 사례의 큰 차이를 canonical 자리의 편집 대응만으로 설명할 수 없다. 다만 특정 후기 층·최종 헤드·CTC 학습 목표 중 어느 하나의 인과 효과를 분리한 실험은 아니다.

같은 ‘수리’에서 TAG가 실제ㅗ인11개도 함께 봤다. B3 중간 CTC는10개, 최종 CTC는11개를ㅗ로 맞혔다. **중간 CTC의 정상ㅜ354개 복구가 실제ㅗ를 모두ㅜ로 바꾸어서 생긴 결과는 아니다.** 오류 표본11개·한 문항·기존 TAG에 대한 결과라는 제한은 유지한다.

**B3의 중간 표현 변화도 있으며, 이를 곧바로 정보 소실로 부를 수는 없다.** 동일 probe·동일 부모 구간의ㅜ 정답은 B0 417→B3 299, 같은 TAG 구간에 자동 probe를 적용하면372→293이다. 같은 B3 중간 CTC 판별기로도440→354다. 반면 같은 ‘수리’ 정상ㅜ475 대 실제ㅗ11의 probe 점수 AUC는.871→.877이고, 실제ㅗ 정답은5→8개다. `logit(ㅗ)−logit(ㅜ)` 중앙값은 정상ㅜ에서−1.798→−.462, 실제ㅗ에서1.092→3.426으로 둘 다ㅗ 쪽으로 이동했다. 분류 결과 악화와 순위 분리도 소멸은 같은 현상이 아니다.

동일 화자의 ‘수리’–‘소리’25쌍에서는 두 인코더 모두25쌍 전부에서ㅗ 녹음의 상대ㅗ 점수가 더 높았다. 하지만 두 모음을 모두 올바르게 분류한 쌍은19→15개다(전체 TAG 정상22쌍에서도17→14). 점수의 상대 순서와 실제 분류 결정이 다르며, seen ‘소리’ 대 unseen ‘수리’의 문항 차이까지 통제한 실험은 아니다. 이 작은 대조의 높은 AUC를1% 서비스 성능으로 해석하지 않는다.

**관측 구간과 판별기 이전의 상호작용도 크다.** 같은 자동 probe를 부모 구간→각 모델 자체 구간에 적용할 때 ‘수리’ 정답은 B0 417→159, B3 299→294다. 이 차이는 고정 판별기가 읽는 관측값에 민감하다는 증거이며, 물리적 음소 경계의 정답/오류 건수는 아니다. P1의 checkpoint별 새 probe와 다른 질문이다. 부모 구간을 서비스에서 사용하려면 부모 인코더도 실행해야 하므로 저장 구간의 진단 성적을 새 단일 모델 성능으로 부르지 않는다.

**전체 음소·삭제·삽입에서는 중간 CTC로의 단순 교체를 뒷받침하지 않는다.** B3의 실제 중간 헤드와 자체 최종 헤드를 비교하면 다음과 같다. 각 헤드의 seen CAL 문턱을 동결한 정책과 greedy gap을 구분한다.

이번 P4는 **중간 단계의 구별 신호가 일부 사례에서 최종 예측·저오탐 경고로 연결되지 않는 지점**을 확인했다. 동시에 중간 표현의 점수 이동, 구간 선택, 문항별 학습 노출과 보정 이전이 얽혀 있다. 중간 CTC를 더 붙이는 근거는 얻지 못했다. CTC와 별도의 음향 검증을 비교할 근거는 남지만, 다음 비교에서도 TRAIN 전용 참조·화자/문항 분리·전체 음소·삭제/삽입·고정 CAL 및 신규 확인 자료가 필요하다. 특정 모음의 AUC나 정상 ‘수리’ 복구만으로 모델을 고르지 않는다.

실행·검증: 두 인코더의 전수 추론28,018회(실행 점검 별도), 조건별136,577자리의 기존 최종 예측·GOP 완전 재현, 같은 원음/순서 hash, B3 중간 헤드 복원 차이0, TRAIN 전용 정규화 재계산 일치, 저장 출력16집계의 헛지적·정확 진단32값 독립 스칼라 재계산 일치를 확인했다. 단위 검증5개와 저장소 Python3.8 문법·지정 import22개가 통과했다. `extract.exit=0`, `run.exit=0`이며 새 학습 갱신0회다. 그림은 표준 plotting 도구로 생성하고 확인했다. 실제 서비스·사람 청취·새 독립 평가를 완료했다는 뜻은 아니다.

### 21.4 C0/C1/C2: 학습 전에 기여도 변경의 실체를 계산했다

사용자가 요청한 통제 중 음성·배치 예산을 정확히 맞출 수 있는 **발화 단위 CTC 손실 가중치안**을 TRAIN에서만 계산했다. 재표집으로 물리적 노출을 바꾼 실험이나 학습 결과는 아니다. 기존 B0의2k→4k 배치 목록을 재생해220,384행·12,449,115,378오디오 샘플과 누적 배치 hash가 실제 P3 기록과 같음을 확인했다. C1/C2를 학습했거나 음성을 새로 추론한 횟수는0이다.

| 설계 | 계산한 처치 |
|---|---|
| C0 | 기존 B0와 같은2k 출발점·Adam 초기화·2,000회 예정 구간, 모든 가중치1 |
| C1 | 외국인 정상/오류 발화 출처별로 문항 기여도를 평균의1.5배 이하로 제한. 동일 규칙을 모든 활성 문항에 적용하고 출처별 총 기여도를 유지 |
| C2 | 실제 TAG의 `자모×평탄한 음소열의 위치×좌우 자모` 빈도에 역제곱근 가중치. 자모·위치 안에서 정규화, 문맥 계수는[.5,2]로 제한한 뒤 발화 내 기하평균과 출처별 총량 정규화 |

기본 손실은 발화별 `CTC NLL/타깃 길이`의 microbatch 평균이므로, 문항 기여도에는 실제 `1/microbatch 발화 수`도 반영했다. 원어민 replay 가중치는1로 둔다. 물리적 정상/오류·화자·L1·길이·반복량은 동일하고 정상/오류 출처별 총 손실 계수도 보존한다. **가중 손실의 L1·화자 구성까지 같은 것은 아니다.** 최대 L1 비중 변화는 C1 .155%p·C2 .171%p이며 화자별 변화도 `<W>/contribution_shifts.json`에 기록했다. C2의 최종 발화 계수 범위.781~3.125는 문맥 계수 제한 뒤 출처 정규화까지 적용한 값이다.

예정 구간의 외국인 감독에는201문항·44자모·11,467문맥 셀이 있다. 전체 TRAIN202문항 중RP001은 이 구간 노출0이고, ㄳ·ㄵ도 해당 외국인 구간의 실제 타깃에 없다.0표본을 만들어 균형화하지 않았다. 삭제·삽입은 발화 타깃열을 통해 간접 영향을 받으며 별도 토큰 손실로 균형화한 것이 아니다.

### 26.3 고정 학습·평가와 파일럿의 의미

공통 Stage1 **10k(처음2k 인코더 고정)** → 공통 Stage2 **2k** → C0/λ=.3 각각 **추가2k**다. 조건별 출발 모델·RNG·AMP와 실제 배치 순서를 같게 하고, 두 조건 모두 AdamW를 새로 만든다. LR은 기존40k 스케줄의2,001회 위치부터 이어간다. 가중 손실은 `mean(w_i × CTC_NLL_i / target_length_i)`이며 가중치 합으로 다시 나누지 않는다. 사전 예정 모델 갱신은 공통12,000회+두 조건4,000회다.

각 조건의 관측 가능한 CAL 정상으로만1% 예산의 문턱을 정하고 내부·바깥 평가에 동결한다. 기존 RP 점수나9개 개발 문항의 성적을 후보·문턱 선택에 사용하지 않는다. 부분 주석의 전체 확정 정상/오류 분모를 고정하며, 주석 경계·불명 시간±40ms·인식 대응 모호·GOP 결측·삭제 anchor 불확실은 Coverage 감소로 남긴다. 이번 입력은20초 이내 전체 녹음이므로 RP의12초 core 경계 마스크를 적용하지 않는다. 삽입은 양쪽 대응이 확정된 내부 gap의 전체 음소열로 별도 평가한다.

내부 선택에서 후보의 관측 정상 FPR≤1%, 전체 확정 오류의 정확 진단>C0, 정상/오류 Coverage 각각≥C0를 함께 요구한다. 오류30개 이상인 음소·삭제·삽입의 정확 재현율 감소5%p 초과, 정상 gap 헛삽입 증가.2%p 초과도 중단 기준이다. 이 수치는 **개발용 연산 지속 기준**이며 제품의 모집단 보증은 아니다. 내부 파일럿 미달이면 같은 가중치 계열을 구제하는 재탐색은 하지 않는다. 바깥 평가는 실패 여부와 관계없이 그대로 보고한다.

파일럿 통과만으로 성공을 선언하지 않는다. 남은 fold1~4에서도 같은 후보·지원 기준을 해당 TRAIN에서 다시 확인하고 같은 계보·학습량으로 비교해야 한다. 5개 fold의 고정 결과·전체 음소·삭제/삽입·FPR·Coverage와 paired 불확실성을 함께 보고한다. 기존 자료의 개발 추정이며 새로운 독립 최종 확인셋은 아니다.
