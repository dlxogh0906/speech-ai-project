> 같은 자료에서 정상 손실 가중치를 1→4로 높이면 새 화자 오류 검출 3→0, 헛지적 4→1로 둘 다 줄어 주후보를 채택하지 않았다.

**전용 후보를 구현하고 1,711발화에서 비교했지만, 정상 발음의 헛지적이 늘어 운영 후보로 채택하지 않는다.**
새 RP 자료의 정답과 응답 위치가 일치한 자리에서 실제 오류 지적은 **2/99→15/99**, 정상 헛지적은
**8/776→36/776**이었다. 추가 검출 13개와 추가 헛지적 28개다. 운영 서비스·모델·설정은 변경하지 않았다.

[앞선 대조 학습](ㅅㅆ_대조학습_실험_2026-10-23.md)의 ㅆ→ㅅ 신호를 후속 확인한 결과다.
새 모델의 정보가 추가 검출에 기여하는 것은 확인했지만, 다른 문장에서 정상 발음을 보존하는 목표는 달성하지 못했다.

## 1. 무엇을 구현했나

기존 모델이 정한 표준 발음(canonical), 음소 점수와 기본 응답을 고정한 뒤, 추가 학습 모델의
ㅆ→ㅅ 판단만 기존 `SpeechSuperFormatter`의 `sz` 주석으로 전달하는 오프라인 어댑터를 만들었다.

- 기준: `w2vbert_synth_tense_v2/step_3000`.
- 후보: `ss_rank_2026-10-23/rank_normal/step_300`. 이번에는 재학습하지 않았다.
- 주후보: 초성 ㅆ 중 발화 첫 자리 또는 앞 음소가 모음인 자리만 검사한다.
- 기존 인식이 ㅆ/ㅅ이고 후보 인식이 ㅅ이며 해당 토큰 확률이 0.6 이상일 때만 지적한다.
  0.6은 기존 표시 예외의 값으로 추론 전에 고정했다. 오류 확률로 보정된 값은 아니다.
- 기존 모델의 삭제·다른 자음 치환은 보존한다. 양방향 `SS_RULE`은 켜지 않는다.
- 받침 뒤까지 여는 `broad`는 미리 지정한 진단용이다. 결과를 보고 주후보로 바꾸지 않았다.

기존 scorer·점수 보정·말소리 검사·VAD·표준발음 보정과 문서상의 운영 인자를 재사용했다.
GPU에서 현 저장소의 실제 응답 생성 코드를 실행한 것으로, 원격 NPU 실행 파일과의 동일성을 검증한 결과는 아니다.
호환 응답의 `errorType`/`actual_jamo`를 비교했으며, raw 전사·L1 조언·세션 기록까지 통합한 배포 구현은 아니다.

## 3. 실제 응답의 ㅆ→ㅅ 지적

다음 표는 모두 RP의 매핑 확인 자리다. '규칙만'은 추론 후 원인 분리를 위해 추가한 보조 비교이며,
같은 0.6·문맥 조건에 새 모델 대신 기존 모델의 인식·확률을 넣었다. 임계값 선택이나 독립 검증이 아니다.

| 방법 | 실제 오류 지적 / 99 | 정상 헛지적 / 776 |
|---|---:|---:|
| 기존 응답 | 2 (2.0%) | 8 (1.0%) |
| 기존 모델 + 표시 규칙만 | 6 (6.1%) | 28 (3.6%) |
| **새 모델 + 전용 규칙** | **15 (15.2%)** | **36 (4.6%)** |
| 받침 뒤까지 허용한 진단용 | 22 (22.2%) | 47 (6.1%) |

주후보가 적용될 수 있는 첫 자리·모음 뒤만 분모로 잡으면 오류 47/정상 485자리다.
기존 **2/47·8/485 → 후보 15/47·36/485**로, 재현율 4.3→31.9%, 헛지적률 1.6→7.4%다.

RP 전체 매핑 자리에서 변화량의 화자 bootstrap 95% 구간은 재현율 +6.7~+21.0%p,
헛지적률 +2.3~+5.2%p다. 문장 구간별 bootstrap은 각각 +5.8~+21.3%p, +2.1~+5.7%p다.
두 군집을 동시에 반영한 구간은 아니며, 부모 문단이 3개뿐이라 새로운 문항 일반화를 입증하지 않는다.

주후보 추가 검출 13개 중 3개는 표시 규칙만으로도 추가된다. 나머지 10개는 후보 모델에서만 추가되며,
기존이 ㅆ로 들었던 6개와 기존이 ㅅ로 들었지만 확률 0.6 미만이었던 4개다.
추가 헛지적 28개 중에서도 19개가 후보 모델에서만 추가된다. 단순 표시 문제와 모델 구별 문제가 함께 남아 있다.
규칙만 추가한 경우에도 별도의 진짜 오류 1개·헛지적 11개가 있어, 두 방법은 완전히 포함 관계가 아니다.

## 4. 어떤 문장에서 늘었나

아래는 부모 문단별 **매핑 확인 분모**다.

| 부모 문단 | 오류 / 정상 자리 | 실제 오류 지적 | 정상 헛지적 |
|---|---:|---:|---:|
| RP002 | 72 / 492 | 2→15 | 3→26 |
| RP003 | 10 / 159 | 0→0 | 5→10 |
| RP004 | 17 / 125 | 0→0 | 0→0 |

추가 검출 13개는 모두 RP002의 `갔어요`, `었어요`, `했어요` 계열에 몰렸다.
추가 헛지적도 이 계열에 23개, RP003의 `쓰기`에 5개가 생겼다.
추가 검출은 11화자·13발화, 추가 헛지적은 26화자·26발화에서 나왔다.
추가 헛지적 28자리 중 15자리는 발화 전체도 사람 전사상 정상인 녹음이었다.
RP004의 매핑 확인 142자리는 모두 받침 뒤여서 주후보 적용 대상이 없다. 변화 0을 성공으로 해석하지 않는다.

새 RS029에서는 정상 67자리 중 헛지적이 **0→1개** 늘었다(`있어요`).
원어민은 통과한 506발화의 초성 ㅆ 161자리에서 주후보의 추가 지적이 **0개**였다.
이 중 받침 뒤 63자리와 기존 인식이 다른 소리인 4자리를 제외하면 주후보 적용 기회는 94자리였다.
받침 뒤를 허용하면 **7개**가 추가됐다. 원어민 자료에 사람의 음소 정답이 없어 이 7개를 확정 헛지적이라고 부르지 않는다.

이전 확인셋은 실제 운영 입력 검사와 표준발음 선택까지 거치면 매핑 확인 오류가 17자리로 줄었다.
여기서는 1/17→6/17, 정상 헛지적 0/176→1/176이다. 앞선 greedy 7/64→17/64와 분모·측정 대상이 다르다.

현재까지 운영에 채택할 개선은 확보하지 못했지만, 추가 오류 검출의 위치와 정상 발음 손상의 위치를 같은 응답에서 확인했다.
