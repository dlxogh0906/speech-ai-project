핵심 발견

weighted F1의 함정정상 자리가 95.86%라서 전부 "정상"으로 찍어도 0.9384가 나온다. 0.9547의 실제 개선폭은 +0.0163이고, 오류만 보면 F1 0.43이다.
문장 암기학습 155만 발화가 287문장뿐이다(문장당 5,398회). 홀드아웃 실험에서 본 문장 weighted F1 0.9509 · 오탐 1.93% → 안 본 문장 0.8218 · 25.31%. 화자 일반화는 정상이다. 문장 다양성만 효과가 있었다(격차 −43%). w2v-BERT도 안 본 문항에서 헛지적이 2.95배로 늘었고, 학습률·층 고정·마스킹은 효과가 없었다.
약한 오류 종류step_38000은 삽입형의 74.6%를 놓치고 모음 F1이 0.37이다. 세기 차이를 표준으로 덮는다: ㅅ→ㅆ 88.6% · ㅈ→ㅊ 74.5% · ㄱ→ㅋ 63.6%. 20초가 넘는 입력은 출력이 빠진다.
SpeechSuper 비교같은 녹음 27건(정답 라벨 없음, 9월 26일 눈금 정리 전). 종합 82.9 대 84.9, 발음 93.6 대 94.7, 유창 66.3 대 92.1. 어느 쪽이 맞는지는 판정하지 않았다.
NPU 대 GPU앱 녹음 161건 중 157건의 인식 결과가 같고 점수 차이는 평균 0.007점. 모델 계산 중앙값 NPU 28 ms · GPU 34 ms(20초 입력은 429 ms · 45 ms).
발음 챌린지맞게 읽어도 MISS가 뜨는 비율: 학습 단어 2.2% · 처음 보는 단어 22%(느슨 판정). 엄격 판정이면 12.0% · 69.0%.

소음에 얼마나 버티나 (2026-10-08)

서비스 모델에 API와 같은 처리 경로로 외국인 발화 1,200개(사람 라벨)를 넣고 소음을 섞었다. dB는 말소리가 소음보다 얼마나 큰지다. 웅성거림은 부스·전시장, 저주파 소음은 기차·차량을 흉내 냈다.

  • 서버 성능(NPU·GPU)은 원인이 아니다. 현장에서는 휴대폰을 입에서 5~10 cm 안에 두거나 헤드셋 마이크를 쓰는 것이 가장 효과가 크다.

  • 브라우저·휴대폰 잡음 억제는 웅성거림에서 배경 말소리 받아 적기를 줄이지만(5 dB에서 46% → 11%), 틀린 소리를 짚는 능력은 되살리지 못한다.

남은 문제

큼

처음 보는 문장에 약하다

학습 문항이 226종뿐이라 모델이 문장을 외운다. 서비스 모델의 깨끗한 "안 본 문장" 성능은 아직 재지 못했다(문항을 빼고 다시 학습해야 한다). 검증된 처방은 문장 다양성이고, 사람 TAG 라벨링이 1순위다.

큼

현장 소음

웅성거림 10 dB부터 무너진다. "다시 녹음" 판정은 만들어 재 봤지만 API에 넣지 않았고, 소음을 섞은 추가 학습도 아직이다.

중간

검출력

재현율이 0.5 안팎이고 맞게 읽은 자리 헛지적이 2.2%(10문장에 두 번꼴)다. 삽입·모음·세기 차이가 약하고, 허용 발음('의' → [에])을 처리하지 않는다. 보정기는 서비스에 붙이지 않았다.

중간

점수

발화 1개로는 상관 0.43 수준이다. 세션(여러 발화) 기준이 문서마다 5발화·10발화·30발화로 다르다. 억양·강세·어휘·문법은 평가하지 않는다.

중간

운영

요청을 하나씩 처리하고 세션이 프로세스 메모리에만 있다. 모니터링이 없고 녹음 보관 기간이 정해지지 않았다. 앱 화면에 AI허브 출처 표기가 필요하다.

결정이 필요한 것: 서비스 모델 교체 여부, 고정 문장과 자유 문장 중 어디까지 지원할지, AIHub 데이터의 상용 범위, 말하기 평가 시작 여부.

남은 문제

큼

틀린 발음을 많이 놓친다

사람이 틀렸다고 한 단어 중 16%만 지적한다. 들린 그대로 받아쓰는 비율이 22%로 한국어 서비스(44%)의 절반이다. th(ð→d)는 판정을 못 하고, 모음 끼워 넣기(desk → 데스크)는 정확도가 낮아 숨겼다. 오류 규칙이 사람이 표시한 오류의 63%만 다룬다.

큼

한국인 기준 정답지가 없다

오류 판정 수치는 L2-ARCTIC 한국인 4명(상급 성인)뿐이고 개발에도 썼다. 037 음소 라벨은 기계가 만든 것이라 쓸 수 없다. 실제 앱 사용자(10대, 초급)에서 얼마나 맞는지 모른다.

중간

점수의 한계

문장 1개 상관은 0.6 수준이라 실력 판단은 여러 문장 평균으로 해야 한다. 운율이 발음과 상관 0.97이라 따로 주는 정보가 거의 없다. 유창성은 한국인 라벨이 없어 그대로다. 단어 점수(90점대)와 문장 발음 점수(70점대)의 눈금이 다르다. 강세·억양은 재지 않는다.

중간

현장 소음과 외부 비교

영어 쪽 소음 테스트는 아직 안 했다. 한국어에서는 웅성거림 10 dB부터 무너졌다. SpeechSuper 영어 비교는 권한이 없어 못 했다.

중간

운영과 법무

외부 접속·NPU 이식 전이라 앱 연결이 안 된다. 요청을 하나씩 처리하고 세션 점수 API가 없다. L2-ARCTIC(비상업)을 모델 선택에 쓴 점과 Kokoro 학습 데이터 출처는 법무 확인이 남았다.

다음 할 일

사람 라벨 만들기

한국어는 처음 보는 문장을 사람이 들은 발음으로 전사한다(파일럿 화면이 있다). 영어는 모델이 의심한 자리를 뽑아 맞음/틀림만 표시한다. 두 갈래 모두 정확도를 제대로 재고 판정 기준을 고치려면 이게 먼저다.

소음 대응

현장에서는 휴대폰을 입 가까이 두거나 헤드셋 마이크를 쓴다. 소프트웨어로는 "다시 녹음" 판정을 API에 넣고(한국어 API 변경은 승인 필요), 소음을 섞어 추가 학습한다. 영어 쪽 소음 측정도 남았다.

영어 앱 연결

외부 접속(토큰)을 열거나 NPU 서버로 옮긴다. 여러 문장을 모아 점수를 내는 세션 API를 만들고, 단어 점수와 문장 점수의 눈금을 맞춘다. SpeechSuper 영어 권한을 받으면 외부 비교도 한다.

정리와 확인

코드를 커밋하고 학습 순서를 저장소로 옮긴다. 골든 수치 회귀 테스트를 만든다. 법무 확인: L2-ARCTIC(비상업)을 모델 선택에 쓴 점, Kokoro 학습 데이터 출처, AIHub 데이터의 상용 범위. 앱 화면에 AI허브 출처를 표기한다.
