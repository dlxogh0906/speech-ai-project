# 국적 분류 서빙 개편 — 작업 정리 (2026-09-23 ~ 26)

기존 웹 서비스의 국적 분류를 이번 구성으로 바꿀지 판단하기 위한 문서다. 무엇을 바꿨고, 왜 바꿨고, 얼마나 좋아졌고, 무엇이 아직 약한지, 어떻게 교체하고 되돌리는지를 담았다.
세부 근거는 `tasks/nationality-classification/results/` 의 11~14번 문서에 있다.

---

## 1. 한 줄 요약

- **한국인이 외국인으로 나오던 문제를 고쳤다.** 원인은 모델이 "문장을 읽는 소리 = 외국인"으로 배운 데이터 구성이었고, 원어민 낭독 데이터를 넣어 해결했다.
- **외국인 국적 정확도도 크게 올랐다.** 웹마이크 문장 기준 상위 5개 정답률이 0.39에서 0.96으로 올랐다.
- **NPU 서버(Rebellions RBLN-CA25 ×8)에 올렸다.** 요청 1건 0.24초, 초당 약 32건을 처리한다.
- 공개 주소: `https://<NPU-funnel-주소>/read` (낭독 페이지) · `/predict` (API)

## 2. 무엇이 문제였나

### 2.1 증상
웹마이크로 재학습한 모델(run5)을 데모로 띄웠더니, **한국인이 노트북·폰 마이크로 말하면 미국 등으로 나왔다.**
같은 녹음을 기존 배포 모델에 넣으면 한국으로 나왔다.

### 2.2 원인 (확정)
- 학습 데이터에서 **한국인 음성은 전부 자유 대화**(KsponSpeech, AIHub 001)였고, **외국인 43만 발화는 전부 화면의 문장을 읽은 소리**였다.
- 그래서 모델이 "문장을 읽는 소리 = 외국인"을 배웠다.
- 공개 코퍼스 Zeroth-Korean(원어민 115명 낭독)으로 확인했을 때, run5 는 원어민 낭독의 **84%를 외국인으로** 판정했다.
- 채널(마이크) 차이도 일부 작용했다. 녹음 앞뒤 무음의 모양이 기기마다 달라 모델이 이를 단서로 썼다.

### 2.3 시도했다가 버린 것

| 시도 | 결과 | 판정 |
|---|---|---|
| 한국어에만 채널 증강 | 만든 증강 시험지만 맞힘. 실제 녹음은 1/6 | 폐기 |
| 모든 클래스에 채널 증강 | 실제 녹음 0/6 | 폐기 |
| 부스 잡음(군중 소리)으로 재학습 | 외국인은 좋아졌지만 한국인 최저 0.84로 하락 | 폐기 |
| XLS-R 2B(큰 모델) 미세조정 2 epoch | 웹마이크 top-5 0.75로 300m(0.87)에 13점 뒤짐 | 폐기 |

## 3. 이번 구성

### 3.1 모델 두 개

| 역할 | 모델 | 설명 |
|---|---|---|
| **주 모델** (국적 판정) | `zeroth` | XLS-R 300m KD 인코더(17층) + 선형 헤드, 41개 국적. 웹마이크 040~043 + 505 + 한국어(Kspon·001) + 한국어 채널 증강 + **Zeroth 원어민 낭독 22,263발화**로 학습 |
| **확인 모델** (한국인 안전망) | `deployed_gate` | 기존 배포 모델과 같은 가중치. 웹마이크를 학습하지 않아 "브라우저 녹음 = 외국인" 편향이 없다 |

### 3.2 처리 순서
1. **디코딩**: ffmpeg(5 이상)로 16 kHz 모노, 앞 12초. ffmpeg 4.2 는 아이폰 사파리 녹음을 첫 1초만 읽으므로 쓰면 안 된다.
2. **거르기**: 말소리가 1초 미만이면 추론하지 않고 400 `no_speech` 응답.
3. **무음 정규화**: 말소리 앞뒤 무음을 잘라내고 모든 녹음에 같은 작은 배경음(−64 dB)을 붙인다. 말소리 자체는 건드리지 않는다.
4. **주 모델**은 3번을 거친 음성을, **확인 모델**은 3번 전의 원본을 본다. 확인 모델에 정규화 음성을 주면 외국인의 짧은 발화를 한국인으로 부르는 버그가 있었다(1초 발화 84%).
5. **판정**
   - 확인 모델의 한국인 확률 > 0.9 이거나 주 모델 1위가 Korea 면 **한국인**.
   - 그 밖에는 주 모델의 국적. 1위 확률 < 0.45 면 `low_confidence=true`(화면에서 "다시 말해 주세요").
6. **화면 확률**: 한국인이면 두 모델 중 한국인 확률이 더 높은 쪽의 출력을 그대로 보여 준다. 외국인이면 주 모델 출력을 그대로 보여 준다. 숫자를 임의로 만들지 않는다.

### 3.3 API (기존과 호환)

`POST /predict` — multipart
- 필수: `audio` (webm/opus, mp4/aac, wav 등, 8 MB 이하)
- 선택: `consent`(`1` 이면 저장, `0` 이면 저장 안 함), `sentence_id`, `sentence`, `self_report`(`korean`/`learner`), `session`

응답 (기존 필드 유지, 새 필드 추가)

```json
{
  "top5": [{"label": "Korea", "prob": 0.9992}, ...],
  "native": true,
  "low_confidence": false,
  "gate_korea": 0.998,
  "sec": 4.2, "rms": 0.06, "gain": 1.0, "silence_norm": true,
  "encode_ms": 110, "total_ms": 240
}
```

- `native`: 1위가 Korea 인지. 화면에서 "한국어 원어민"을 크게 보여 줄 때 쓴다.
- `low_confidence`: 외국 국적인데 확신이 낮음. 결과 대신 재요청을 띄운다.
- 오류: 400 `decode_failed` · `too_short` · `no_speech` · `too_large`, 500 `server_decoder`

기타: `GET /health`(설정·상태), `GET /read`(낭독 페이지), `GET /`(기존 데모 화면)

### 4.3 실제 폰 녹음 (사내 테스트)
- 정상 발화 10개: 한국인 8개, 재요청 2개, 틀린 국적 0개.
- 한 문장 모드(가장 긴 문장) 4개: 전부 Korea 96~100%.
- 확률 표시 수정 전에는 "Korea 48% · 미국 48%"처럼 보이던 녹음이 있었고, 수정 후 한국인 판정 29개가 전부 96~100% 로 보인다.

- 전체 top-1 0.79 · top-3 0.93 · top-5 0.96
- 잘 맞힘(84% 이상): 일본, 베트남, 태국, 중국, 인도네시아, 스페인, 프랑스, 튀르키예, 루마니아, 이탈리아
- 약함(55% 미만): 미국(필리핀·영국과 혼동), 홍콩(중국), 카자흐스탄(러시아), 영국(미국), 인도·말레이시아(화자 수 적음)
- 틀릴 때는 대부분 모국어가 같은 나라끼리 헷갈린다. 사실상 "어느 언어권 말투인지"를 듣는다.

### 4.5 확률 보정
- 모델은 약간 과신한다. 70~95% 로 보인 구간의 실제 정답률은 5~14점 낮다.
- 온도 보정(T = 1.3)을 하면 보인 확률과 실제 정답률의 평균 차이가 5.1점에서 1.7점으로 줄어든다. **아직 서빙에는 적용하지 않았다.**
- 60% 를 90% 로 올려 보여 주는 식의 조정은 하면 안 된다. 60% 로 보인 판정의 실제 정답률은 60% 다.

## 5. NPU 배포

### 5.1 환경
- 서버: `npu-260923151650` (Rocky Linux 9.8, vCPU 32, RAM 503 GB, RBLN-CA25 ×8, 각 15.7 GiB)
- 접속: Tailscale (회사 tailnet), 호스트 이름 `npu` (<NPU-tailscale-IP>)
- 작업 폴더: `/root/nat_serve` (가상환경 `venv` Python 3.12 · `/opt/rbln_sdk` 의 rebel_compiler 0.10.2 · torch 2.9.1 · ffmpeg 7.0.2 정적 빌드 `bin/ffmpeg`)
- `/root/beaver`, `/root/nara` 는 이번 작업과 무관하다.

### 5.2 컴파일
- 기존 방식(fairseq TorchScript)은 컴파일러가 참/거짓 마스크 연산에서 멈췄다(`float32 vs bool`).
- 인코더를 **순수 PyTorch 로 다시 쓰고 마스크를 숫자로 바꿨다**(`country_classifier/npu_encoder.py`). 원래 모델과 출력 차 최대 5e-5.
- `rebel.compile_from_torch` 로 모델당 20초, `.rbln` 494 MB.
- 입력은 12초 고정 파형 `source` [1, 192000] 과 프레임 유효 마스크 `frame_valid` [1, 599] (1 = 유효).

### 5.3 검증
- 실제 시험 발화 300개: 정답률 CPU 0.880 · NPU 0.883, 1위 일치 298/300, 확률 차 평균 0.008.
- 사내 폰 녹음 17개: GPU 서버 데모와 판정 전부 동일.

### 5.4 속도

| 동시 사용자 | 처리량 | 지연 중앙값 | 95% |
|---|---|---|---|
| 1명 | 4.2건/초 | 0.24초 | 0.27초 |
| 8명 | 26.9건/초 | 0.23초 | 0.44초 |
| 16명 | 31.3건/초 | 0.42초 | 0.82초 |
| 32명 | 32.7건/초 | 0.87초 | 1.34초 |

- NPU 호출 자체는 58 ms. 나머지는 디코딩과 전처리다.
- NPU 호출은 한 프로세스 안에서 병렬로 안 돌아서, **처리 프로세스 8개**를 NPU 코어 8개에 나눠 띄운다(`NAT_WORKERS=8`). 한 프로세스면 초당 4.4건에서 막힌다.

### 5.5 GPU · CPU 와의 비교 (2026-09-26, 자세히는 `results/15_NPU_GPU_성능비교.md`)

| 구성 | 한 명 지연 | 최대 처리량 | 요청당 에너지 | 정확도 |
|---|---|---|---|---|
| GPU A100 | 0.10초 | 51.8건/초 | 4.7 J | 기준 |
| NPU · 12초 고정 · 8프로세스 (현재) | 0.23초 | 35.4건/초 | 11.6 J | GPU 와 1위 97.5% 일치 |
| NPU · 길이 버킷 · 16프로세스 | 0.18초 | **57.2건/초** | 7.2 J | 같음 |
| GPU 서버 CPU 16코어 | 1.6초 | 1.7건/초 | — | 같음 |

NPU 는 길이 버킷(4·8·12초) + 16프로세스로 바꾸는 것을 권장한다. 실험 서버가 NPU 서버 포트 8906 에 떠 있다.

**실제 저장 녹음 58개(사내 한국인)**: 새 구성은 GPU · CPU · NPU 판정이 100% 같다. Korea 50 · 재요청 3 · 다른 국적 4(모두 "정상 여부 미확인" 묶음) · 거절 1.
같은 녹음에서 기존 서비스(옛 모델 · 옛 설정)는 Korea 54 · 다른 국적 3. 한국인을 더 우선하려면 `KD_GATE_TAU` 를 0.5 로 낮추면 Korea 53 이 되고,
대신 외국인이 한국인으로 나오는 비율이 1.5% → 3.9% 로 오른다(`results/15_NPU_GPU_성능비교.md` 10절).

### 5.6 운영 명령

```bash
ssh npu                                        # Tailscale 경유 (GPU 서버에서)
bash /root/nat_serve/restart.sh [워커수]       # 재시작 (기본 8)
tail -f /root/nat_serve/serve.log              # 로그
```

주요 설정 (`run_npu.sh`)

| 환경변수 | 값 | 의미 |
|---|---|---|
| `NAT_BACKEND` | `rbln` | NPU 실행 (`onnx` 면 CPU) |
| `NAT_WORKERS` / `POOL` | 8 / 1 | 프로세스 수 / 프로세스당 세션 |
| `RBLN_DEVICES` | `0,...,7` | 쓸 NPU 코어 |
| `KD_GATE_TAU` | 0.9 | 확인 모델 문턱 |
| `KD_GATE_INPUT` | `raw` | 확인 모델은 원본을 본다 (바꾸면 안 됨) |
| `KD_SILENCE_NORM` | 1 | 무음 정규화 |
| `KD_GATE_MIN_SEC` | 1.0 | 최소 말소리 길이(초) |
| `KD_LOWCONF` | 0.45 | 재요청 문턱 |
| `KD_SAVE_DIR` | `/root/nat_serve/uploads` | 녹음 저장 위치 |
| `FFMPEG_BIN` | `/root/nat_serve/bin/ffmpeg` | ffmpeg 5 이상 필수 |

## 6. 기존 웹 서비스 교체 방법

1. **API 호환**: `/predict` 요청 형식과 `top5` 응답은 기존과 같다. 새 필드(`native`, `low_confidence`, `gate_korea`)는 무시해도 동작한다.
2. **백엔드 주소만 바꾸면 된다**: 기존 서비스가 부르던 국적 API 주소를 NPU 서버로 바꾼다. 지금 공개 주소는 `https://<NPU-funnel-주소>/predict` 다. 정식 도메인(예: `api.beavertalk.im`)을 붙이려면 앞단에 리버스 프록시를 둔다.
3. **화면 권장 사항**
   - `native=true` 면 "한국어 원어민"을 크게 보여 준다.
   - 외국인이면 1위와 함께 상위 3개를 보여 준다(상위 3개 안에 정답이 있을 확률 93%).
   - `low_confidence=true` 면 결과 대신 "조금 더 또렷하게 다시 말해 주세요".
   - 퍼센트를 크게 강조하지 않는다(4.5 참고).
4. **녹음 가이드**: 한 문장을 3~5초, 폰을 입에서 20~30 cm, 조용한 곳.
5. **개인정보**: 녹음을 저장한다면 동의를 받고(`consent=1`) 목적·보관 기간을 고지한다. 현재 낭독 페이지 문구는 "AI 모델 개선 연구에만 사용, 이름·연락처 수집 안 함, 만 14세 이상"이며 회사 방침과 맞춰야 한다.

| 인증 | 없음 | **없음** | 운영 전 API 키 등 인증 필요 (아래) |
| 요청 | `audio` 필드 하나 | 같음 (선택 필드 `consent` 등 추가) | 변경 불필요 |
| 성공 응답 | `top5` · `sec` · `encode_ms` · `total_ms` | 같음 + `native` · `low_confidence` · `gate_korea` · `rms` · `gain` · `silence_norm` | 변경 불필요, 새 필드는 선택 사용 |
| 라벨 | 41개 영문 | 같음 | 변경 불필요 |
| `prob` | 41개 합 1 | 합 1 (한국인이면 확신이 더 높은 모델의 분포) | 변경 불필요 |
| 짧은 음성 | 0.5초 미만 `too_short` | 같음 + **말소리 1초 미만이면 `no_speech`** | 1초 이하 짧은 대답은 거절됨 → "조금 더 길게" 안내 |
| 큰 파일 | 제한 없음 | 8 MB 초과 `too_large` (400) | 12초 음성은 수백 KB 라 영향 없음 |
| 처리 시간 | 약 0.1초 (GPU, 모델 계산 12 ms) | 약 0.24초 (NPU, 모델 두 개 + 무음 정규화) | 체감 차이 작음 |
| 동시 처리 | 측정값 없음 | 초당 약 32건 (8 워커) | — |
| 녹음 저장 | 안 함 | 기본 저장, `consent=0` 이면 저장 안 함 | 앱이 동의를 받지 않으면 `consent=0` 을 보낸다 |

**운영 전에 꼭 할 것**
- 지금 공개 주소는 **인증이 없다.** 누구나 호출할 수 있으니, 운영 앱에 넣기 전에 API 키 확인(예: `X-API-Key` 헤더)이나 정식 도메인 + 리버스 프록시 인증을 붙인다.
- 저장 기본값을 "저장 안 함"으로 바꿀지 결정한다. 지금은 `consent` 를 보내지 않으면 저장된다(기존 데모 화면과의 호환 때문).

### 되돌리기
- GPU 서버의 기존 서비스(포트 8905, 기존 모델)는 **손대지 않았다.** 문제가 생기면 백엔드 주소를 원래대로 돌리면 된다.
- NPU 공개 주소는 NPU 서버에서 `tailscale funnel --https=443 off` 로 닫는다.
