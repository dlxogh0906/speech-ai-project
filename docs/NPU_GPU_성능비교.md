# NPU vs GPU 추론 성능 비교 — 국적 분류 · 발음 평가

작성 2026-09-27. 같은 모델·같은 서빙 코드를 NPU 서버와 GPU 서버에서 돌려 **정확도 · 지연 · 동시 처리량 · 전력 · 메모리**를 비교했다.
자세한 표와 재현 방법은 각 task 의 원본 문서에 있다(7절).

## 1. 결론

- **정확도는 사실상 같다.** 국적 분류는 NPU 와 GPU 의 1위 판정이 97.5% 일치하고, 한국인 판정은 하나도 다르지 않다. 발음 평가는 실제 앱 녹음 161건 중 157건의 인식 결과가 같고, 점수 차이는 평균 0.01점 미만(5점 척도)이다.
- **한 건씩 처리하면 GPU 가 빠르다.** 국적 분류 요청 1건이 GPU 0.10초, NPU 0.18~0.23초다. 발음 평가는 짧은 발화에서 비슷하고(3.8초 발화 모델 계산 NPU 29 ms · GPU 33 ms), 길어질수록 NPU 가 느려진다(20초 발화 429 ms · 45 ms).
- **실제 앱 녹음은 짧아서 NPU 가 불리하지 않다.** 발음 평가 녹음은 무음을 자르면 중앙값 2.4초라 모델 계산이 NPU 28 ms · GPU 34 ms 다.
- **동시 처리량은 튜닝한 NPU 가 가장 높다.** 국적 분류 NPU(길이 버킷 · 16프로세스) 초당 57.2건, GPU 51.8건.
- **요청당 에너지는 GPU 가 약 1.5배 효율적이다.** 국적 분류 최대 처리량에서 GPU 4.7 J, NPU 7.2 J(가속기 보드 전력만).
- **운영 면에서는 NPU 가 단순하다.** GPU 서버는 학습과 같이 쓰여서 학습 중에는 추론이 크게 느려질 수 있다. NPU 서버는 추론 전용이다.

## 2. 장비와 측정 조건

| | NPU 서버 | GPU 서버 |
|---|---|---|
| 가속기 | Rebellions RBLN-CA25 ×8 (장당 15.7 GiB) | NVIDIA A100-SXM4-80GB ×1 |
| 호스트 CPU | 32코어 | 16코어 |
| 실행 | rebel 0.10.2 컴파일 모델(.rbln), 입력 길이 고정(버킷) | 국적: onnxruntime CUDA · 발음: PyTorch fp16 |

- 측정 클라이언트를 서버와 같은 기계에서 돌려 **네트워크 시간을 뺐다.**
- GPU 측정 때 GPU 사용률은 0% 였다(다른 학습이 돌지 않을 때).
- NPU 는 입력 크기를 컴파일 때 정한다. 짧은 입력은 가장 가까운 큰 크기(버킷)로 채워서 계산한다. GPU 는 실제 길이만큼 계산한다.

## 3. 국적 분류 (XLS-R 300m 증류 모델 + 확인 모델)

### 정확도 — 학습에 없던 화자 617개

| 구간 | GPU | NPU 12초 고정 | NPU 길이 버킷 |
|---|---|---|---|
| 한국인 대화 · 낭독 → Korea | 1.000 · 1.000 | 1.000 · 1.000 | 1.000 · 1.000 |
| 웹마이크 외국인 top-1 / top-5 | 0.712 / 0.930 | 0.726 / 0.933 | 0.716 / 0.933 |
| 505 외국인 top-1 / top-5 | 0.850 / 0.990 | 0.860 / 0.990 | 0.860 / 0.990 |
| 외국인을 Korea 로 잘못 판정 | 2.0% | 1.7% | 1.7% |

NPU 와 GPU 가 다르게 판정한 15개는 전부 외국인 경계 사례다(GPU 가 맞힌 것 6 · NPU 가 맞힌 것 7). 사내 실제 녹음 58개는 GPU · CPU · NPU 판정이 100% 같았다.

### 지연 — 한 명씩

| 구성 | 요청 p50 | p95 | 짧은 발화(4초 이하) p50 |
|---|---|---|---|
| GPU A100 | **105 ms** | 119 ms | 96 ms |
| NPU 12초 고정 (현재 운영) | 231 ms | 247 ms | 228 ms |
| NPU 길이 버킷 · 16프로세스 | 179 ms | 244 ms | 133 ms |
| CPU (GPU 서버, 참고) | 1,617 ms | 2,914 ms | 916 ms |

### 동시 처리

| 구성 | 최대 처리량 | 동시 16명일 때 p50 / p95 |
|---|---|---|
| GPU A100 · 1프로세스 | 51.8건/초 | 0.29 / 0.40초 |
| NPU 12초 고정 · 8프로세스 (현재 운영) | 35.4건/초 | 0.41 / 0.85초 |
| NPU 길이 버킷 · 16프로세스 | **57.2건/초** | 0.26 / 0.56초 |
| CPU (참고) | 1.7건/초 | 12.4 / 16.7초 |

- GPU 는 프로세스 1개가 가장 빠르다. NPU 는 한 프로세스 안에서 병렬로 돌지 않아 프로세스를 늘려야 한다.
- 실제 녹음(대부분 3~5초)으로 재면 NPU 길이 버킷 · 16프로세스가 한 명 0.17초, 최대 64.7건/초다.

### 전력 (가속기 보드만)

| 구성 | 대기 | 최대 처리량 때 | 요청당 에너지 |
|---|---|---|---|
| GPU A100 · 1프로세스 | 76 W | 242 W | **4.7 J** |
| NPU 12초 고정 · 8 | 115 W | 409 W | 11.6 J |
| NPU 길이 버킷 · 16 | 133 W | 411 W | 7.2 J |

## 4. 발음 평가 (w2v-BERT 2.0 CTC, 5.8억 파라미터)

NPU 에서 컴파일하려면 입력 길이를 64프레임(1.28초) 배수로 맞추고 어텐션 계산을 바꿔야 했다. 값은 원본과 같다.
운영 모델은 버킷 3개(3.84 · 8.96 · 20.48초)다.

### 정확도

원본(full precision) 기준 40개 클립:

| | 프레임 판정 일치 | 인식 자모열 완전 일치 |
|---|---|---|
| GPU fp16 (현 GPU 서비스 설정) | 99.98% | 38/40 |
| NPU | 99.74% | 35/40 |

실제 앱 녹음 161건을 서비스 채점 경로 전체로 비교:

| 비교 | 인식 자모열 일치 | 자리 판정 일치 | 판정이 바뀐 발화 | 점수 차이 평균 / 최대 (1~5점) |
|---|---|---|---|---|
| NPU vs GPU 서비스 | 157/161 | 99.93% | 3건 | 0.007 / 0.24 |
| GPU fp16 vs 원본 (기준 잡음) | 161/161 | 100% | 0건 | 0.001 / 0.07 |

- 달라진 4건은 모두 애매한 모음 하나가 바뀐 경우다(ㅏ↔ㅘ, ㅣ↔ㅡ, ㅣ↔ㅕ). 한국인 녹음 20개 클립은 NPU 도 전부 같았다.
- NPU 오차는 GPU fp16 보다 크지만, 제품 화면에서 구분될 수준은 아니다.

### 지연 — 모델 계산 1회

| 입력 길이 | NPU | GPU fp16 |
|---|---|---|
| 3.84초 | 29 ms | 33 ms |
| 8.96초 | 94 ms | 34 ms |
| 20.48초 | 429 ms | 45 ms |

실제 앱 녹음 161건(무음 자른 뒤 중앙값 2.4초 · 최대 7.1초):

| | 중앙값 | p90 | 최대 |
|---|---|---|---|
| NPU 모델 계산 | 28 ms | 53 ms | 94 ms |
| GPU 모델 계산 | 34 ms | 34 ms | 36 ms |
| NPU 서버 전체 처리 (`/speak` 1건) | 64 ms | — | 204 ms |

### 동시 처리 — NPU 서버, 프로세스 1개

| 동시 요청 | 처리량 | 응답 p50 | 응답 p95 |
|---|---|---|---|
| 1 | 15.5건/초 | 51 ms | 149 ms |
| 4 | 16.3건/초 | 195 ms | 344 ms |
| 8 | 16.3건/초 | 488 ms | 593 ms |
| 16 | 16.5건/초 | 961 ms | 1,314 ms |

- 한 번에 1건씩 처리해서 처리량이 초당 약 16건에서 멈추고, 동시 요청이 늘면 대기 시간만 늘어난다. 실패는 없었다.
- GPU 서비스도 같은 코드라 1건씩 처리한다. GPU 쪽 동시 처리량은 이번에 재지 않았다.
- GPU 서비스 문서에는 다른 학습이 GPU 를 같이 쓰면 응답이 **20초까지** 느려진다고 적혀 있다. 9/27 현재 GPU 서버는 다른 학습이 사용률 96% 로 쓰고 있다.

### 메모리

| | NPU | GPU |
|---|---|---|
| 발음 평가 서비스 1개 | 5.0 GiB (NPU 1장, 버킷 3개) | 약 2.9 GB |

NPU 는 버킷마다 가중치를 따로 올린다(버킷당 약 1.5 GiB). 버킷을 6개로 늘리면 9.0 GiB 다.

## 5. 해석할 때 주의

- **NPU 는 낮은 정밀도로 계산한다.** 그래서 확률이 조금 다르다(국적 1위 확률 평균 0.010 차이 · 발음 프레임 판정 99.7% 일치). 판정 결과에는 영향이 거의 없었다.
- **호스트 CPU 가 다르다.** 오디오 변환·정렬·채점은 CPU 에서 돈다. NPU 서버 32코어, GPU 서버 16코어다.
- **전력은 가속기 보드만 쟀다.** 호스트 전력은 빠져 있다. 발음 평가 전력은 재지 않았다.
- **네트워크 시간은 빠져 있다.** 실제 사용자는 업로드 시간이 더해진다. GPU 서버에서 NPU 서버를 부르면 Tailscale 중계를 거쳐 왕복이 약 0.1초 늘어난다.
- 국적 분류의 사내 실제 녹음은 1~2명 분량이다. 외국인 실제 녹음은 아직 없다.

## 6. 권장

1. **추론은 NPU 서버, 학습은 GPU 서버로 나눈다.** GPU 를 학습과 같이 쓰면 추론 지연이 흔들린다.
2. **국적 분류 NPU 운영본을 길이 버킷 + 16프로세스로 바꾼다.** 한 명 지연 0.23 → 0.18초, 처리량 35 → 57건/초, 정확도 변화 없음. 실험 서버(8906)에서 검증을 마쳤다.
3. **발음 평가를 여러 사용자가 동시에 쓰려면** 프로세스를 늘리고 세션 기록을 공유 저장소로 옮긴다.
4. 한 명 지연이 가장 중요하고 전용 GPU 가 있다면 GPU 가 더 빠르고 전력 효율도 좋다.
