# 설계 결정 — 왜 이렇게 했는가

나중에 "왜 이건 통합 안 했지?" 하고 다시 뒤집지 않도록 근거를 남긴다.

## 1. 두 task 의 오디오 전처리를 통합하지 않았다

겉보기엔 둘 다 "16 kHz mono WAV 로더"라 합칠 만해 보인다. 실제로는 요구사항이 다르다.

| | 국적 (`country_classifier/audio.py`) | 발음 (`mdd/mdd_eval.py:load_wav`) |
|---|---|---|
| 구현 | stdlib `wave` + `scipy.resample_poly` | 16 kHz 전제, 리샘플 없음 |
| torchaudio | **일부러 회피** (환경 충돌) | 미사용 |
| 정규화 | 없음 | `layer_norm` — **체크포인트마다 다름** |
| 실패 처리 | 조용히 skip, 배치 전체가 `None` 일 수 있음 | 예외 전파 |

억지로 합치면 두 파이프라인이 동시에 깨진다. `shared/` 에는 진짜 공통인 것
(경로 설정, fairseq 가드)만 뒀다.

**두 task 간 코드 import 는 0건이다** (AST 파싱으로 실측). 실제로 독립이다.

## 2. `outputs/` 를 저장소 밖에 뒀다

특징 캐시 7.6 GB + 예측 캐시 2.8 GB + 모델 2.4 GB. 저장소에 넣으면
`git status` 가 매번 이걸 훑고, VS Code 감시자가 OOM 으로 죽는다.

더 중요한 이유: **운영 중인 데모/API 4개가 같은 경로를 절대경로로 읽고 있다.**
옮기면 즉시 장애다. 그래서 `shared/paths.py` 의 기본값을 현재 위치로 두고,
다른 머신에서만 환경변수로 바꾸게 했다.

## 3. `deploy/` 를 task 와 동급으로 뒀다

운영 서비스가 `runs/demo`·`xlsr_infer_api`·`xlsr_loadtest_demo` 3곳에 흩어져 있었다.
학습/평가와 라이프사이클이 완전히 달라서(재기동·포트·터널 관리) 분리했다.

## 4. `mdd_demo.py` 를 라이브러리와 실행기로 쪼갰다

평가 스크립트 6개가 **데모 서버 파일을 import** 하고 있었다. 데모를 고치면 평가가
깨지는 구조였다. 로직은 `src/mdd/pipeline.py`, 서버는 `deploy/mdd-demo/app.py`.

## 5. 모듈 이름을 바꾸지 않았다

`mdd_eval.py` → `decoder.py` 처럼 의미에 맞게 바꾸고 싶었지만, `mdd_eval` 은
**20개 스크립트가 import** 한다. 이름까지 바꾸면 리팩터링 diff 가 커져서 회귀 원인을
분리하기 어려워진다. 패키지로 옮기는 것까지만 하고 이름은 유지했다.

## 6. 클래스 병합(31/13-class)을 하지 않는다

어족·권역으로 묶으면 macro-F1 은 오르지만 **제품이 답해야 할 질문이 바뀐다**
("이 사람 국적은?" → "이 사람 어느 권역?"). 과거 실험은 중단됐고 `archive/` 에 있다.
라벨은 61-class(+한국어=62) 원본 유지.

## 7. MDD 잣대로 gold 를 쓰지 않는다

gold(LAB)에는 **실현형(실제로 어떻게 발음했는지)이 없다.** 오류 태그와 1~5점만 있다.
gold 잣대로 재면 공식 0.96 모델조차 0.42 로 떨어진다 — 모델이 나쁜 게 아니라 잣대가 틀린 것이다.
**TAG(전문가 음소 전사)만 MDD 잣대로 쓴다.** gold 는 점수 라벨 출처로만 쓴다.

## 8. 공식 점수 팩(PCC)을 채택하지 않았다

액면 PCC 0.94 로 우리(0.66)보다 훨씬 높지만 **학습 화자 명단이 공개되지 않아**
우리 test 화자가 거기 포함됐는지 확인할 수 없다. 검증 가능한 조건에서 재보면:

```
자기 언어권 (화자 중복 의심)  0.938
가중치 4개 평균(수프)          0.565
다른 언어권 (미학습 보장)      0.330   ← 우리 0.662보다 낮음
```

화자를 외울 여지를 뺄수록 정확히 그만큼 떨어진다. 자체 방식을 채택했고,
결과적으로 추가 모델 0개 · 42 GB 절감 · 모국어 판별 불필요.

## 9. 설치(`pip install -e .`)를 필수로 하지 않았다

python 3.8 + pip<24.1 제약에서 editable 설치가 까다롭다. 대신 각 스크립트 상단에
5줄 부트스트랩을 넣어 **어디서 실행하든** 동작하게 했다. `pyproject.toml` 도 함께 두어
설치를 원하면 할 수 있다.
