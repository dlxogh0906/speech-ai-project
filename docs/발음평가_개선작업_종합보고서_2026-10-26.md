## 1. 결론: 유효한 방법이 나왔는가

**서비스의 헛지적을 줄이는 유효한 수정은 나왔다. 그러나 이번 집중 실험에서 ㅅ·ㅆ 실제 오류를 안정적으로 더 검출하는 새 모델은 아직 확보하지 못했다.**

성과는 다음 네 가지로 나눠야 한다.

| 구분 | 확인된 결과 | 적용·검증 상태 |
|---|---|---|
| 과거 운영 개선 | 표준발음 보정, 추가 학습 모델, 삭제·ㄴ↔ㄹ 표시 규칙 조합으로 정밀도·일부 오류 검출 개선 | 10월 17·21일 반영 기록 있음. 손실도 함께 발생 |
| 이번 탐색의 구체적 수정 후보 | ‘여덟 시’의 관측된 발음에 맞게 기준 발음을 선택하면 특정 헛지적이 크게 감소 | 실제 API 및 별도 NPU 프로세스 검증 완료. 운영에는 미반영 |
| 입력 품질 결함 수정 | 브라우저의 잘못된 다운샘플링으로 고역이 낮은 대역으로 접히는 현상 수정 | 로컬 두 데모 HTML 수정·제어 입력 검증 완료. 발음 검출 성능 향상은 미입증 |
| 이번 탐색의 음향 모델 개선 | 일부 자료에서 추가 검출 또는 헛지적 감소가 있었으나, 정상 보호·기존 오류 보존·보정 목표 중 하나 이상 실패 | 새 검출 모델 채택 없음. 운영 변경 없음 |

최신 인코더 학습의 탐색적 보정 결과는 **정확 오류 검출 20→20건, 정상 헛지적 93→86건**이다. 헛지적 감소는 관찰됐지만 입력 허용 정상 7,189자리의 1% 예산인 71건을 넘고, 추가 검출도 없어 채택하지 않았다.

따라서 “아무 유효한 방법도 없었다”는 표현도 부정확하고, “ㅅ·ㅆ 성능 개선에 성공했다”는 표현도 부정확하다. **기준 발음·입력 처리의 수정 근거는 확보했지만, 핵심인 실제음 구별과 서비스 검출 일반화는 해결하지 못했다.**

## 2. 무엇을 개선하려고 했는가

서비스는 대략 다음 단계를 거친다.

`기준 문장 → 기대 발음 생성 / 녹음 → 입력 검사·음성 구간 → 음향 모델 → 음소 대응·점수 → 사용자 지적`

ㅅ·ㅆ가 잘 안 잡히는 문제는 이 단계들에 걸쳐 있다. 기준 발음이 틀리면 맞게 읽은 사람을 지적하고, 모델이 실제 ㅅ을 기대한 ㅆ로 되돌리면 오류를 놓친다. 모델이 바뀐 소리를 인식해도 표시 문턱 때문에 지적이 안 나갈 수 있다. 자동 구간이 목표 소리를 포함하지 않으면 보조 모델도 다른 소리를 근거로 판단할 수 있다.

이번 작업의 목표는 **정상 발음 헛지적을 억제하면서, 실제로 바뀐 소리까지 맞게 알려 주는 오류 검출을 늘리는 것**이다. 음소 분류 정확도, AUC, TRAIN 성적만 올리는 것으로는 목표 달성이 아니다.

### 지표와 분모를 구분한 이유

| 용어 | 이 보고서에서의 의미 | 해석 제한 |
|---|---|---|
| 정확 오류 검출 | 오류 위치뿐 아니라 실제 바뀐 소리도 맞춘 지적 | 틀린 실제음을 알려 준 경고와 구분 |
| 정상 헛지적 | TAG상 정상인 자리에 나온 오류 표시 | 정상 전체와 입력 허용 정상의 분모를 함께 확인 |
| TRAIN 추가 정확 제안 | 기존 API가 놓친 오류에 대한 보조 모델의 학습 자료 내 제안 | 최종 API 응답 성능이 아님 |
| AUC·ABX | 점수 구별력·표현 유사도의 진단값 | 낮은 헛지적률의 서비스 검출률이 아님 |
| 측정 가용성 | 특징값이나 자동 구간을 얻을 수 있는 정도 | 측정한 소리가 목표 소리라는 보장도, 정확도 향상도 아님 |

최근 주요 TRAIN 비교는 원래 GT 14,002자리·자동 입력 13,741개를 사용했다. 감독 불명 입력 979개와 입력 없음 261자리를 보존했다. 지원 정상의 방향별 오제안 한도 33/54건은 학습 진단용이며 **서비스 전체 정상 1% 달성 기준과 다르다.**

전체 보정 자료(CAL)는 GT 8,894자리·자동 입력 7,276개다. 정상 전체는 8,652자리, 그중 판정 가능한 입력 허용 정상은 7,189자리다. 주평가는 GT 1,329자리·실제 오류 337개다. 이 보정·주평가 자료는 반복 탐색에 사용했으므로 미사용 최종 평가라고 부르지 않는다.

당시 `--ss-rule`은 효과가 없어 꺼 둔 상태였다. 이 운영 개선이 ㅅ·ㅆ 문제를 해결했다는 기록은 없다.

## 4. 이번 탐색에서 유효성이 확인된 수정

### 4.1. ‘여덟 시’ 기준 발음 선택 수정: 헛지적 감소 근거가 가장 구체적

기존 모델이 실제로 ㅆ를 인식했는데도 기대 발음 선택 때문에 ㅅ 기준으로 평가하는 경우가 있었다. 출처가 확인된 해당 시간 표현에 한해, **원래 인식이 ㅆ일 때 그 관측된 발음 기준으로 정렬·점수를 다시 계산하는 수정**을 구현했다.

이 처리는 모델의 실제음 인식열을 고치지 않는다. ‘여덟 시’의 모든 읽기를 무조건 허용하거나, 비슷한 단어 전체에 경음화를 확대하지도 않는다. 해당 표현의 단일 표준 발음이 정해져 있지 않다는 출처상의 제한도 남겼다.

운영 설정을 재현한 API 직접 비교에서 복합 평가의 정상 지적은 18→4건, 확대 평가에서는 71→24건으로 줄었다. 정확 오류 검출 수는 그대로였다.

별도 NPU6 프로세스에서 문제 표현과 정상 제어 370녹음을 비교한 결과는 다음과 같다.

| 해당 표현에 집중한 NPU 검증 표본 | 수정 전 | 수정 후 |
|---|---:|---:|
| 정상 헛지적 / 정상 346자리 | 330 | 6 |
| 정확 오류 지적 / TAG 오류 27자리 | 0 | 0 |
| 오류 자리에서 잘못된 실제음 지적 | 26 | 0 |
| 다른 음소의 API 응답 변경 | — | 0 |

실제 NPU 추론은 비교 요청당 1회이며 재계산 응답과 어댑터의 전체 응답 일치도 확인했다. **이것은 특정 기준 발음 결함을 고치는 유효한 후보다. 음향 모델의 ㅅ·ㅆ 구별 개선은 아니다.** 문제 표현을 집중 수집한 표본이므로 330→6을 전체 서비스의 감소율로 확대할 수 없다. 남은 6/346도 1%를 넘는다.

구현·별도 NPU 검증은 완료했지만 운영 앱 등록·프로세스 교체는 하지 않았다.

근거: `<R>/cv_observed_reference_v1/{direct_evaluation,adapter_validation_v2,npu_execution_v1}`. 특히 `npu_execution_v1/metrics/report.json`.

### 4.2. 브라우저 녹음 변환: 입력 결함 수정은 확인, 검출 이득은 미확인

기존 일반 데모는 48kHz 입력을 충분한 대역 제한 없이 16kHz로 줄였다. 시험에서 9kHz 음이 7kHz로, 10kHz 음이 6kHz로 접혔다. A/B 데모에도 같은 종류의 문제가 있었다.

WebAudio의 원래 표본화율을 WAV에 보존하고 서버 변환기가 대역 제한을 하도록 두 로컬 HTML을 수정했다. 제어된 Chromium 입력의 녹음·업로드와 서버 디코딩에서, 9kHz가 7kHz로 접히는 성분은 약 0dB에서 약 −61~−62dB로 억제됐다.

입력 변환 결함을 고쳤다는 근거는 있다. 다만 물리 마이크·다양한 기기·실제 발음 오류를 통한 성능 비교는 하지 않았다. 전송량과 변환 비용도 늘 수 있다. **운영 웹 반영과 ㅅ·ㅆ 검출 향상은 별도 미완료 과제다.**

## 5. 한국어 소리 특징을 어떻게 다루려고 했는가

핵심 관찰 단위는 **마찰 자음과 뒤 모음으로 이어지는 구간**이었다. 마찰의 세기 하나나 F0 하나로 ㅅ·ㅆ를 단정하는 접근을 피하고, 다음 정보를 함께 비교했다.

| 관측 대상 | 실제로 시도한 처리 | 확인한 한계 |
|---|---|---|
| 마찰 소음 | 대역 에너지, 스펙트럼 무게중심·평탄도, 고역 세부 형상, 시간 궤적 | 녹음 변환·자동 구간·뒤 모음에 영향을 받으며 단순 평균은 안정적인 추가 검출로 이어지지 않음 |
| 발성·주기성 | F0, H1-H2, 주기성, 유성 시작 주변 여러 창 | 초기 모음에서 측정 실패가 많음. 값이 나와도 다음 음절을 측정했을 수 있음 |
| 모음의 공명·상대 세기 | 초기/후기 모음, 상대 에너지, F0 없는 저주파 세부 스펙트럼 | 주기성이 약한 것과 모음 자체가 없는 것을 분리해야 함 |
| 자음→모음 전이 | 역할별 표현, 순서·위치·분산, 모음 기준 원음 관측 | 모델 역할 가중치와 CTC 시점은 물리적 음향 경계 정답이 아님 |
| 음소 문맥 | 뒤 모음, 발화 위치, 문항·자리별 정상/오류 대조 | 문맥만으로 라벨 비율을 예측할 수 있어 소리 대신 문맥을 이용할 위험이 있음 |

특히 ㅣ·ㅡ·ㅜ 조건을 따로 확인했다. 초기에 사용한 캐시에서는 ㅆ→ㅅ 지적이 뒤 모음 ㅏ에서 40/119였지만 ㅣ에서 2/211, ㅜ에서 5/283이었다. 문항과 위치도 함께 달라 **모음 하나가 원인이라고 확정할 수는 없지만**, 고모음을 별도 검증해야 한다는 근거였다.

초기 캐시의 CTC 자음 구간은 17,490자리 중 17,482자리에서 약 20ms 한 프레임이었다. 이를 실제 마찰음 길이로 해석하면 안 된다. 또한 **공명이 나타나기 시작하는 시점과 성대가 주기적으로 진동하기 시작하는 시점을 같은 사건으로 취급하지 않아야 한다.** F0가 안 나온다는 이유만으로 모음 삭제나 무성화를 확정하지 않았다.

이 구분은 평가 설계상 유효하지만, 구분을 구현했다는 사실이 검출 성능 향상의 증거는 아니다.

## 6. 실제로 학습했는가: 학습과 비교 내역

**실제로 여러 차례 모델을 학습했다.** 고정 음성 표현 위의 분류기만 바꾼 실험, 음향 인코더 층까지 바꾼 실험, 학습하지 않고 가설을 먼저 점검한 진단 실험이 섞여 있다. 전부 ‘모델 재학습’이라고 묶어서 보고하면 안 된다.

| 접근 | 실제 수행 내용·대표 결과 | 채택하지 못한 직접 이유 |
|---|---|---|
| 기존 음향 특징 + CTC | 분리 화자·문항에서 재학습. ㅅ→ㅆ AUC .880→.891이나 낮은 헛지적 구간 재현율 12.8→12.4% | AUC 증가가 목표 구간의 검출 증가로 이어지지 않음 |
| 파형 경계 재탐색 | 여러 초기 모음 창에서 F0·H1-H2 측정. 결측은 감소 | 같은 표본의 CTC+새 음향 AUC가 두 방향 모두 CTC 단독보다 낮음 |
| 문맥을 줄인 재추론 | 0.6/1.0/1.6초 음성을 같은 모델에 다시 입력 | 전체 발화 대비 안정적인 구별력 증가 없음 |
| 작은 mel CNN·비선형 판별기 | 실제음 분류 학습 및 CTC와 결합 | CNN 결합에서 오류 15개 추가 검출에 정상 지적 231개 추가. 선택한 표현·모델로는 부족 |
| 모음 조건·문맥 균형·대조 손실 | 같은 문항/자리/뒤 모음의 정상과 오류를 함께 학습 | 예비 추가 검출은 있었으나 확대 정상 자료에서 헛지적 증가 또는 한 방향 손실 |
| 모음 기준 실제음 판별 | 실제 API 주평가 정확 검출 25→27, 정상 지적 4→1 | 기존 TAG삭제 정확 검출 1개를 잃어 오류 보존 조건 실패 |
| 국소 CTC·실제음 음소열 학습 | 전체 보정에서 정확 검출 20→21·정상 지적 93→92인 중간 결과 | 검출 이득이 작고 1% 정상 보호 미달. 후속 학습도 개선하지 못함 |
| 기존 경고 재검토 | 전체 API 재생에서 보정 정상 지적 93→89, 정확 검출 20 유지 | 일부 자료의 헛지적 감소만 확인. 보정 1% 미달, 추가 검출 없음 |
| 시간 변화·원음 저주파·고해상도 분기 | 시간 표현·세부 스펙트럼·인코더 조합 학습 및 실제 API 대조 | TRAIN 이득이 보정에 전이되지 않거나 같은 정상 예산에서 검출 증가 없음 |
| 정상 상위 1% 집중 순위 손실 | 고정 표현 위 실제음 분류층 50,117파라미터, 각 300회 갱신 | 두 대조군보다 낮고 실제음 오제안 증가. 높은 TRAIN 성적만으로 통과시키지 않음 |
| XLS-R 300M→2B | 고정/마지막 2층 학습 4조건, 각 300회 실제 갱신 | 사전 후보 2B 마지막 2층 조건이 같은 TRAIN 기준 부모 564→523으로 감소 |
| 신규 오류 라벨 복원·추가 학습 | 전체 전사가 일부 불명확한 자료에서 확실한 국소 라벨만 복원·학습 | 새 오류만 추가하거나 같은 녹음 집합 정상까지 넣어도 방향별·대조군 조건 실패 |
| 기대 ㅅ/ㅆ별 분리 판별부 | 기존 오류 유지, 공유/분리×기존/신규 오류 4조건 학습 | 후보 합계 564→589지만 ㅅ 방향 240→191, 잘못된 실제음 3→4 |
| 정상/오류 자료 출처 교차 | 분리 판별부에서 오류 기존/신규×정상 기존/신규, 각 800회 갱신 | 신규/신규 587건으로 신규/기존 495건보다 회복했지만 기존/기존 709건 미달 |
| native HuBERT 마지막 2층 적응 | 조건부 판별부 100,234개와 인코더 14,175,744개 파라미터 학습 | 신규 자료 사전 후보 TRAIN 490건. 기존 자료 대조군의 이득도 후속 보정 검출로 전이 안 됨 |
| 고역 형상·시간 궤적 ABX | 고정 문맥·교차 화자에서 평균/형상/순서 대조. 별도 학습 전 진단 | 사전 진출 기준 미달. 이 방법 전체에 정보가 없다는 결론은 아님 |

이 표의 실험들은 평가 표본·모델·분모가 다르다. 서로 다른 행의 검출 수를 직접 순위로 비교하지 않는다. 개별 실험 안의 같은 조건 비교만 해석한다.

## 7. 안 된 원인은 무엇인가

### 7.1. 확인된 문제

**① 처음부터 잘못된 기준 발음으로 평가하는 사례가 있었다.**

‘여덟 시’ 수정은 모델 출력 자체를 바꾸지 않고도 지적을 줄였다. 해당 사례의 원인이 기대 발음 선택에 있다는 직접 근거다. 다만 전체 미검출 원인은 설명하지 못한다.

**② 자동 토큰 시점을 실제 소리 경계로 취급하면 특징의 의미가 달라진다.**

20ms CTC 피크를 자음 지속시간으로 보거나, 첫 주기를 모음 전체의 시작으로 보면 마찰·기식·약한 모음을 혼동한다. 여러 창을 넓혀 H1-H2 결측을 줄였을 때도 일부는 목표 모음 밖이었다. 측정 성공 증가가 정확도 증가로 이어지지 않은 중요한 방법상 제한이다. 이후 자동 구간과 TAG의 지지 여부를 구분했지만, TAG도 전문가의 물리적 경계 정답을 대신하지는 않는다.

**③ 일부 입력에는 학습시키려던 목표 자음이나 의도한 뒤 모음이 충분히 없었다.**

훈련 창과 원래 라벨 시간의 지지를 감사해 감독 대상을 제한했다. 관측 불가를 정답 정상이나 삭제로 바꾸지 않았다. 보정·평가에서는 이런 실패를 분모에서 빼지 않았다. 그러나 경계나 지지 마스크 수정만으로 검출 문제가 해결되지는 않았다.

**④ 정상/오류 개수를 맞춰도 음소 문맥까지 균형 잡히지는 않았다.**

복원한 새 오류 675개 중 같은 신규 녹음 집합의 정상 876개에서 완전 문맥 대조가 있는 오류는 248개뿐이었다. 문항·런타임 자리·기대 자음·뒤 모음·위치·모국어·UID F/M 코드를 맞춘 기준이다. 427개는 같은 문맥 정상 대조가 없었다. 모국어·F/M을 제외해도 152개는 없었다.

또한 음성을 쓰지 않고 문맥별 오류 비율만 이용한 화자 분리 진단에서도 새 자료 AUC가 약 .898이었다. 문맥이 오류 라벨과 강하게 연결돼 있다는 증거다. **모델이 실제로 그 지름길만 학습했다는 인과 증명은 아니지만**, 전체 클래스 균형만으로 부족하다는 구체적인 근거다.

**⑤ 높은 TRAIN 성적은 실제 소리 구별의 증거가 아니었다.**

같은 고정 표현 위 분류층에 실제음 라벨을 무작위로 섞어 학습시킨 용량 진단에서도 12,450/12,762, 즉 97.56%를 맞췄다. 이 크기의 분류층은 무의미한 대응도 외울 수 있었다. 최신 인코더 적응의 TRAIN 742건이 CAL 추가 검출로 이어지지 않은 결과도 일반화 문제를 보여 준다. 실제 라벨 모델의 모든 판단이 암기라는 뜻은 아니다.

**⑥ 헛지적을 줄이는 정책이 진짜 오류 경고까지 지울 수 있었다.**

모음 기준 모델은 주평가에서 정상 지적 3개를 줄이고 새 정확 검출 3개를 얻었지만, 기존 TAG삭제 정확 검출 1개를 잃었다. 목표 자음 연결이 없는 자리에서 기대음 확률이 높다는 이유만으로 정상 근거를 삼기에는 부족했다. 이 회귀 때문에 순증만 보고 채택하지 않았다.

**⑦ 기존 헛지적 전체가 보조 모델의 관측 범위에 들어오지 않았다.**

자음 토큰이 없거나 다음 모음 대응이 불명확하고, 입력 거절 또는 관측 지원 실패도 남았다. 경고를 확인하는 보조 분류기만 바꿔서는 관측하지 못하는 지적을 고칠 수 없다. 미연결 자음을 모음 기준으로 관측하는 경로도 시험했으나 앞의 삭제 회귀 등으로 채택하지 못했다.

### 7.2. 원인으로 단정할 수 없는 것

| 주장 | 현재 근거로 가능한 판단 |
|---|---|
| “모델이 작아서 그렇다” | 2B 확대는 고정 조건에서 실패했다. 크기가 유일한 원인이라는 근거 없음 |
| “학습을 안 해서 그렇다” | 마지막 음향 층의 기울기·가중치 변경을 확인했다. 다만 전체 인코더를 끝까지 학습한 것은 아님 |
| “새 TAG 라벨이 틀렸다” | 원문 라벨·시간 대응 검증은 했으나 새 독립 청취는 없음. 성능 저하만으로 라벨 오류를 단정할 수 없음 |

## 8. 같은 오류 문맥의 정상 자료 확보와 후속 학습 결과

최초 보고서에서는 아래 자료 준비와 사전 점검까지 완료했다. 같은 날 후속으로4조건을 실제 학습했으며, 결과는 이 절 마지막에 추가했다.

1. 전사 일부가 불명확해 최근 국소 보조 학습의 완전 전사 선정에서 통째로 제외됐던 TRAIN 원천 22,829발화를 조사했다. 불명 구간을 정상·삭제로 만들지 않고, 원래 TAG/LAB에서 국소 대응과 시간 근거가 확인되는 자리만 복원했다. **이는 M2 본학습 미노출 자료라는 뜻이 아니다.** 이후 매니페스트 대조에서 선정한 D6·D7은 모두 M2 train에 포함됨을 확인했다.
2. 원천 쌍 오류 728개 중 자동 관측에서 훈련 가능한 오류 675개를 확보했다. 지원 실패·입력 없음도 원천 분모에 남겼다. 새 사람이 만든 라벨은 아니다.
3. 같은 오류 문맥의 정상 발음이 있는 미관측 원천을 찾아 1,248녹음·1,124화자·27문항을 선정했다. 모델 점수로 고르지 않았다.
4. 원래 자동 음성 관측을 실행한 뒤에만 라벨을 붙였다. 원천 정상 3,107자리 중 2,851개가 런타임 대응·자음/모음 구간 지지를 통과했다. 나머지 정상 256개는 지원 실패 또는 입력 없음으로 보존했다.
5. 2,851개 전체에 대해 소스 라벨·런타임 대응·시간 겹침을 독립 재검사했다. 새 청취 검증을 한 것은 아니다.
6. 다음 4조건 학습 계획의 사전 검증이 종료 코드 0으로 완료됐다. 세 출처의 초기 예측이 기존 부모와 정확히 같고, 기존 오류·반복량·클래스 수 보존을 확인했다.

새 정상 풀에서 같은 완전 문맥의 런타임 지원 정상이 있는 오류는 **646/675개(95.7%)**다. 이전 248/675개보다 대조 가능 범위가 넓어졌다. 준비한 비교에서는 정상 고유 수를 ㅅ 297개·ㅆ 256개로 고정해 다음 네 조건을 비교한다.

| 조건 | 바꾸는 내용 |

## 9. 작업 방식 자체에서 부족했던 점

서비스 목표에 대한 새 검출 모델의 최종 성과는 아직 없다. 이 점과 별개로 작업 보고에도 문제가 있었다.

- 가설 점검, 코드·도구 구현, 재현 감사, 데이터 확보가 많이 쌓였지만 서비스 지표의 순개선은 그에 미치지 못했다.
- TRAIN 성적이나 일부 자료의 이득을 먼저 말하면 실제 서비스 개선이 진행된 것처럼 오해하게 된다. 최종 실패 조건과 미배포 상태를 먼저 밝혔어야 했다.
- 긴 탐색 문서의 앞부분에는 “진행 중”, “다음 확인” 등 당시 상태가 남아 있다. 최신 판정은 뒤의 완료 결과와 원본 결과 파일을 따라야 한다.
- 일부 후속은 TRAIN 결과를 본 뒤 대조군을 새 후보로 선택했다. 탐색적 절차임을 기록했고, 사전 계획을 통과한 확인 결과와 구분해야 한다.
- 기존 CAL·주평가를 반복 사용한 한계가 있다. 효과가 보여도 미사용 자료 검증 없이 일반화나 서비스 개선을 확정하면 안 된다.

재현 감사는 계산 오류와 가중치 혼용을 막는 데 필요했지만 그 자체가 사용자에게 제공되는 성능 개선은 아니다. **이번 집중 작업은 원인과 실패 범위를 좁혔고 수정 후보를 만들었지만, 투입 시간에 상응하는 새 오류 검출 성과는 아직 내지 못했다.**

## 10. 남은 일과 완료 판단

우선순위는 다음과 같다.

1. **헛지적 결함 수정:** ‘여덟 시’ 관측 기준 수정은 검증된 제한 범위를 유지해 운영 적용 후보로 별도 검토한다. 마이크 변환 수정은 실제 클라이언트·물리 기기와 지연을 확인한다. 둘 모두 새 ㅅ·ㅆ 검출 모델의 성과와 분리한다.
2. **학습 자료 가설 검증:** 준비했던4조건은 후속 실행했고 사전 후보가 탈락했다. 해당 구성은 실패로 기록한다. 자유 문장용 백본 판단에는 H0 분할·노출량·평가를 맞춘 별도 비교가 필요하며, 현재 작은 분류부 TRAIN 결과를 대신 사용하지 않는다.
3. **서비스 응답 검증:** 사전 후보가 양방향 TRAIN·대조군 조건을 통과한 경우에만 전체 CAL에서 정상 보호·추가 검출·기존 오류 보존을 검사한다. 이후 실제 API의 음소·단어·발화 집계와 주평가·회귀·NPU를 검증한다.
4. **최종 일반화 검증:** 보호한 488녹음은 최근 보조 모델로 채점하지 않았지만 M2의 valid483개·test5개다. 따라서 시스템 전체의 독립 최종 평가로 사용한다는 기존 계획을 철회하고, 보조 모델에서 보류한 범위의 탐색 확인으로 한정한다. 시스템 전체의 독립 검증에는 기반 모델 선택·반복 탐색까지 피한 별도 자료가 필요하다. 이 묶음의 쌍 오류도16개뿐이다.

독립된 새 복수 청자 판정과 전문가 경계 확인은 아직 없다. 현재 사람 참여가 어렵다는 조건에서 기존 TAG로 가능한 작업을 진행했으며, 이 한계는 모델 점수나 자동 대응으로 대체해 해소됐다고 처리하지 않는다.

완료는 “새 모델을 만들었다”가 아니라, **정상 헛지적 목표·기존 정확 오류 보존·실제 바뀐 소리의 추가 검출을 분리 자료와 최종 API에서 함께 만족하고, 적용 비용과 운영 경로까지 확인한 상태**로 판단한다. 현재는 이 조건을 만족하지 못했다.
