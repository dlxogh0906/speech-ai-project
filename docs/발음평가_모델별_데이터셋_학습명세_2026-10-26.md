## 1. 기존 문서와 이 문서의 차이

기존에도 [발음평가 모델·학습·API 구성](발음평가_모델_학습_API_구성_2026-09.md)이 있었다. 9월 기준의 w2v-BERT 학습·데이터·API 명세다. 10월 합성 추가 학습은 [10월 17일 반영 문서](발음평가_개선_반영_2026-10-17.md), 최근 ㅅ·ㅆ 모델은 [탐색 기록](ㅅㅆ_구분_개선_탐색_2026-10-23.md)에 나뉘어 있었다.

이 문서는 **어떤 원본 모델에서 출발해 어떤 자료로 어느 부분을 어떻게 학습했는지**를 한곳에 모은다. 전체 작업의 성과·실패 원인은 [종합 보고서](발음평가_개선작업_종합보고서_2026-10-26.md)를 참고한다. 과거의 모든 소규모 진단 가중치를 전수 나열한 목록은 아니며, 운영 계보와 최근 핵심 학습군을 명시한다.

값의 근거는 다음처럼 구분한다.

- **확인값:** 저장 config·데이터 통계·실행 스크립트·실제 학습 결과에서 확인한 값. 실행 스크립트만으로 모든 기본값의 실제 사용까지 보장하지 않는다.
- **레시피:** 학습 소스에 정의된 설정. 원 실행 인자와 연결되지 않는 값은 실제 실행값으로 단정하지 않는다.
- **미확인:** 원 실행 명령 등 근거가 부족한 항목. 코드 기본값으로 빈칸을 채우지 않는다.

아래에서 `<O>=/data/speech-ai/out/mdd`, `<C>=/data/speech-ai/corpus/checkpoints`, `<R>=<O>/analysis/sibilant_transition_2026-10-24`다. 운영 NPU 경로는 원격 서버 경로이며 로컬 체크포인트와 구분한다.

## 2. 모델 계보와 역할

### 운영 주 음향 모델 계보

```text
facebook/w2v-bert-2.0
  → KsponSpeech 한국어 CTC 적응: w2vbert_stage1/step_10000
  → 외국인 실제 발음 TAG + 원어민 replay: w2vbert_stage2/step_38000
  → 합성 정상/오류 쌍 + 실제 replay: w2vbert_synth_tense_v2/step_3000
      ├─ 이전 모델과 가중치 50:50 평균: 10월 17일 반영
      └─ 추가 학습 모델 100%: 10월 21일 반영 기록
```

마지막 모델의 원격 경로는 `/root/pron_serve/ft3000_2026-10-19/model_hf`다. 이는 10월 25일 읽기 전용 운영 확인 기록에 따른 것이며 이 문서 작성 중 실시간 재확인한 상태는 아니다.

### 최근 보조 판별 모델 계보

```text
team-lucid/hubert-base-korean 공개 가중치
  → 6·12층 특징 + TRAIN 전용 PCA256 + 실제음/구간 판별부
      ├─ 표현 고정, 실제음 분류층만 추가 학습
      ├─ 기대 ㅅ/ㅆ별 분리 판별부 학습
      ├─ 마지막 음향 2층 + 분리 판별부 학습
      └─ 같은 오류 문맥의 정상 자료 비교: 4조건 학습 완료, 사전 후보 TRAIN 탈락 (§11)

XLS-R 300M / XLS-R 2B 원본 가중치
  → 각자 TRAIN 전용 PCA256 + 같은 크기의 판별부
      ├─ 음향 인코더 고정
      └─ 마지막 음향 2층 학습
```

**HuBERT와 XLS-R 2B 실험은 운영 w2v-BERT 모델을 교체한 것이 아니다.** 기존 서비스 응답을 기준으로 국소 실제음 판별을 추가할 수 있는지 본 오프라인 실험이다. 현재 새로 채택한 ㅅ·ㅆ 보조 모델은 없다.

루트 README의 `mdd_tag_all_native`·`tag_all_lar` 등 XLS-R 300M 계열은 이전 시스템이다. 이 모델들의 성능·데이터 수를 현재 w2v-BERT 계보에 섞지 않는다. 이전 계보는 [task README](../tasks/pronunciation-assessment/README.md)와 [가중치 안내](WEIGHTS.md)에 남아 있다.

## 13. 재현과 기록의 남은 제한

학습 재현은 체크포인트 이름 하나로 끝나지 않는다. **원본 가중치·데이터 manifest/라벨·원음 hash·분할·배치 순서·학습 코드·실행 설정·후처리 정책**을 함께 고정해야 한다. 최근 실험은 각 protocol의 SHA 목록, 저장 가중치, 점수와 audit를 보존했다. 무결성과 재학습 일치는 성능 개선 자체의 증거가 아니다.

최근 M6~M9의 실행 형식은 `source tools/env.sh` 후 다음과 같다. 기존 출력은 덮어쓰지 않는다.

```bash
"$PY" tasks/pronunciation-assessment/scripts/train/<해당_학습_스크립트>.py \
  --protocol <보존한_protocol.json> --out <새_출력_폴더> --stage fit
```

`fit`은 protocol에 연결된 사전 검증 파일과 원본 자산을 요구한다. 새 환경에서 사전 검증을 다시 만들면 그 경로를 바인딩한 별도 protocol이 필요하다. 같은 fit 출력에 `--stage audit`를 실행하는 모델군은 독립 재학습·복원을 비교한다. M8은 해당 전용 학습·감사 명령을 원래 실행 기록에서 따라야 하며 이 공통 CLI로 실행하지 않는다.

아직 완전한 단일 재현 패키지로 묶이지 않은 부분은 M3의 최초 명령 전문, 일부 과거 실행의 코드 기본값 확정, 원격 점수 자산과 로컬 파일의 최신 동일성이다. 확보한 자료와 미확보 항목을 구분해 남겼으며, **미확인 항목을 추정으로 채워 ‘완전 재현 가능’이라고 표시하지 않는다.**
