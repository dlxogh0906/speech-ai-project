## 1. 국적 분류

### 1.1 어느 모델인가

- **가장 좋은 모델은 300m 전체학습이다** (`$NATIONALITY_OUTPUTS/webmic_kd/full_encoder_spk811/full_300m/best.pt`, step 16k, 결과 27).
  - 화자 ID 8:1:1 로 나눈 test 로 쟀다. 학습 · 선택에 쓰지 않은 화자 1,390명, 19,680발화다.
  - 결과 27~42 에서 시도한 모델(2B, 손실 · 증강 · TTS · 음성변환 · LID · 운율 등) 가운데 웹 전체 성능이 가장 높다. 나머지는 같거나 낮았다.
  - 대안은 **LoRA · 행 균등 · 300m 에서 이어**(결과 28)다. 중간 국가 top-5 가 오르는 대신 머리 국가와 웹 전체가 조금 내려간다. 클래스별 값은 표 맨 오른쪽 열에 같이 뒀다. 등급 A 는 8개국으로 300m 전체학습(10개국)보다 적다.
- **지금 앱(NPU 서버)에 붙어 있는 모델은 이것과 다르다.** 결과 24(10-05) 기준으로 `run_zeroth` + 확인 모델 게이트다.
  - 같은 test 에서 run_zeroth 는 웹 문장 top-1 0.776 · top-5 0.959 로 머리 국가 성능이 이 모델과 같다.
  - 다만 꼬리 국가 0.453 은 믿기 어렵다. 학습 목록이 남아 있지 않아 test 화자를 봤을 가능성을 배제할 수 없다(결과 27 §5.4). 아래 표가 "학습에 없던 사람"에게 기대할 수 있는 값이다.
- 300m 전체학습은 서빙 중인 KD 모델과 구조가 같다(300m 17층 + 선형 헤드). 기존 ONNX 내보내기 경로를 그대로 쓸 수 있다. 아직 내보내지는 않았다.

앱에서 쓸 수 있는지를 클래스마다 매겼다. 시험 화자가 5명 이상일 때만 매겼다.

- 5문장 합산은 앱에서 5문장을 읽게 하는 경우에 해당한다. top-1 정밀도는 "모델이 그 나라라고 답했을 때 실제로 그 나라 사람인 비율"이다.
- 웹 문장 시험 화자가 5명 미만이고 131 읽기 시험 화자가 5명 이상이면 131 로 매겼다(태국 · 미얀마). 131 은 녹음 환경이 웹마이크와 다르다.
- 판단 불가인 17개국도 관측값은 대부분 top-1 0~0.3 이다. 시험 화자가 0~4명이라 등급을 매길 수 없을 뿐, 쓸 수 있다는 근거는 없다.

### 1.5 앱 · 웹에서 쓸 만한가

**조건부로 쓸 수 있다.** 이렇게 쓰는 것을 권한다.

- **결과는 top-5 후보로 보여 준다.** 1문장이어도 머리 국가는 top-5 0.95 다. 1위 하나만 단정하면 머리 국가도 4명 중 1명은 틀린다(1문장 top-1 0.75).
- **3문장 이상 읽게 한다.** 1 → 3문장에서 top-1 이 0.777 → 0.841 로 오른다. 단어 하나(2~3초)는 top-1 0.30 이라 쓰면 안 된다.
- **1위를 단정할 때는 보정한 확신도 문턱을 건다.** valid 에서 정한 문턱 0.57 이면 발화의 71% 에 답하고 그중 0.91 가 맞는다. 나머지는 "후보 5개"로만 보여 준다.
- **등급 C · 판단 불가 나라(22개국)는 1위로 단정하지 않는다.** 이 나라 사람에게는 대부분 이웃 나라나 큰 나라가 1위로 나온다. 화면 문구를 "가장 가까운 억양" 정도로 두는 편이 안전하다.

**test 수치보다 실제 앱에서 낮게 나올 수 있는 이유:**

1. **녹음 묶음 단서.** 웹마이크 데이터는 수집 묶음(web040~043)마다 나라 구성이 다르다(8~24개국). 모델이 틀릴 때 같은 묶음 나라로 가는 비율이 80% 인데, 무작위라면 51% 이다. 모델이 묶음의 녹음 조건을 일부 알아본다는 신호다. 앱에는 이런 묶음이 없다. 이웃 언어 나라가 같은 묶음에 몰려 있기도 해서, 이 몫이 얼마인지는 이 자료로 가를 수 없다.
2. **잡음.** 결과 29 §6.6(같은 모델, 화자당 3발화 2,984개)에서 깨끗할 때 top-1 0.775 다. 생활 잡음 10 dB 에서 0.677, 연주곡 10 dB 에서 0.625, 주변 말소리(4명) 10 dB 에서 0.526 이다. 카페 · 길거리 녹음은 크게 떨어진다.
3. **한국인 원어민 — 10-26 실제 녹음으로 확인했고, 이 모델 혼자로는 안 된다(§2.4 끝).** 한국 클래스는 스튜디오 · 낭독 녹음으로만 배웠다.
   - 서버에 저장된 한국인 노트북 · 폰 녹음 34개 가운데 한국 1위는 원본 2개, 무음 정규화 19개뿐이었다. 대신 대부분 미국으로 나왔다.
   - 앱에 붙은 모델(run_zeroth + 무음 정규화 + 한국인 게이트)은 같은 녹음을 한국으로 맞혔다. 이 모델을 올릴 때도 게이트를 앞에 둬야 한다.
   - 유튜브 점검(결과 25, 옛 모델)에서는 한국어가 유창한 외국인 대회 발표자 8명 중 7명이 '한국'으로 나왔다.
4. **문장.** 웹 시험의 읽은 문장(RS)은 학습 화자도 읽은 같은 75문장이다. 자유발화는 0.754 로 읽은 문장(0.789)과 큰 차이가 없어, 문장을 외운 몫은 작아 보인다.
5. **기기.** 웹마이크 데이터의 기기 · 브라우저 종류는 시험에서 따로 나눠 보지 못했다.

실제 앱 녹음(NPU 서버가 저장 중)으로 재는 것이 가장 정확한 확인이다. 다만 사용자 녹음이라 명시적인 허락이 있어야 쓸 수 있다.

## 2. 사투리 분류

### 2.1 어느 모델인가

- **가장 좋은 모델은 EAT-L + XLS-R 2B 앙상블이다** (`/data/speech-ai/out/dialect/content_grouped_full_20261015/`, 10-16 완료).
  - 규칙: EAT 의 1위가 표준어면 표준어로 답한다. 아니면 EAT 와 XLS-R 의 지역 확률을 0.5 : 0.5 로 섞어 1위를 고른다.
  - XLS-R 2B 는 48층 중 마지막 8층을, EAT-L 은 마지막 4블록을 학습했다. 학습 창 597,505개(약 1,242시간), 3 epoch, 증강 없음이다.
  - 학습 전에 정해 둔 후보 8개 가운데 valid macro-F1 로 골랐다.
- 클래스: 강원 · 경상 · 전라 · 제주 · 충청 · 표준어 후보. 단위는 3~12초 창 하나다.
- 데이터: 지역 5개는 AIHub 71517(강원 · 경상) · 71558(충청 · 전라 · 제주) "중 · 노년층 방언, 1인 발화 질문에 답하기"다. 라벨은 거주 지역이다. 표준어는 다른 코퍼스(AIHub 537 화자 인식용, 짧은 명령어 낭독)에서 왔다.
- **split**: 화자 ID 를 기준으로, 같은 녹음 파일을 공유하는 ID 끼리 묶어 나눴다. 화자 · 파일 · 음원 지문 겹침은 0 이다.
  - 문장(대본)이 split 사이에 겹치는지는 확인하지 않았다. 앞선 답변에서 "문장이 안 겹친다"고 한 것은 틀렸다. 이 split 의 "content" 는 같은 음원 파일이라는 뜻이다.
- **봉인 test(5,820창)는 10-26 사용자 요청으로 한 번 열어 채점했다(§2.2).** 앙상블 규칙은 valid 로 이미 고른 것을 그대로 썼고, test 를 보고 바꾸지 않았다.

### 2.3 앱 · 웹에서 쓸 만한가

**아직 못 쓴다.** 수치는 높지만 앱 환경을 대표하지 않는다.

1. **표준어 클래스가 코퍼스 단서로 맞히고 있을 가능성이 크다.** 표준어는 다른 코퍼스의 짧은 명령어 낭독이라 1.00 이 나온다.
   - 다른 코퍼스(AIHub 71349)의 일반 표준어 낭독 8명 · 96창을 넣었더니, 이전 EAT 모델 둘이 표준어라고 한 것은 9창 · 5창뿐이다. 나머지는 대부분 강원 · 경상이었다.
   - 최종 앙상블로는 이 확인을 안 했다. 하지만 표준어 판정을 같은 계열의 EAT 가 한다.
   - 앱 사용자 대부분은 표준어 화자일 것이다. 이들 상당수가 강원 · 경상으로 나올 위험이 크다.

**쓰려면 필요한 것** (순서대로):
