# ㅅ·ㅆ 실제 오류 대조 학습 실험 — 2026-10-23

> 후속 [ㅆ→ㅅ 전용 응답 검증](ㅆ에서ㅅ_전용_검증_2026-10-23.md)을 완료했다.
> 새 RP 자료에서 실제 오류 지적은 2/99→15/99로 늘었지만 정상 헛지적도 8/776→36/776으로 늘어 채택하지 않았다.
> 아래의 greedy 인식 신호를 실제 서비스 개선으로 확정하지 않는다.

## 결과

**사전 목표인 낮은 헛지적률에서의 양방향 검출 개선은 달성하지 못했다. 운영 교체 후보로 채택하지 않는다.**
다만 실제 정상·오류를 함께 대조한 후속 모델의 **ㅆ→ㅅ greedy 인식**에서 추가 검증할 신호가 나왔다.
별도 화자 확인셋에서 실제 오류 인식은 7/64→17/64, 정상 헛인식은 2/229→3/229였다.
이는 +10개 검출/+1개 헛인식이며, 문항 bootstrap 구간은 0을 포함한다. 서비스 화면 검출 개선으로 확정하지 않는다.
반대 방향 ㅅ→ㅆ는 헛인식이 4→15개로 늘어 전체 모델 교체를 뒷받침하지 않는다.

선별한 실제 녹음으로 일반 CTC 추가 학습을 했을 때 전체 음소 오류 감소는 첫 평가와 별도 화자 확인에서 모두 나타났다.
하지만 이 사실 역시 목표 ㅅ·ㅆ 검출 성공과 구분해야 한다.

## 1. 질문과 실험

[앞선 탐색](ㅅㅆ_구분_개선_탐색_2026-10-23.md)에서 제안했던 실제 전사 대 표준 복원 전사 학습을 직접 실행했다.
출발 모델은 운영 계열 `w2vbert_synth_tense_v2/step_3000`이며, 24층 인코더와 출력 헤드 전체를 학습했다.
운영 모델·서비스에는 반영하지 않은 오프라인 실험이다.

첫 비교는 기존 모델, 일반 CTC 추가 학습, 오류 자리 대조 학습의 세 가지다.
같은 초기 가중치·자료·배치 순서·300회 갱신을 사용하고 손실 함수만 바꿨다.
첫 평가 결과를 보고 정상 자리에도 대조 손실을 더한 확인 실험을 한 번 추가했다.
이 후속 선택은 첫 평가를 참고했으므로, 확인에는 첫 실험의 모든 화자를 제외한 별도 녹음을 사용했다.

|---|---:|---:|---:|---:|---:|
| 학습 | 768 | 128 | 128 | 446 | 228 |
| 임계값 보정 | 512 | 6 | 1 | 623 | 177 |
| 첫 평가 | 512 | 64 | 64 | 317 | 239 |
| 후속 확인 | 493 | 45 | 64 | 303 | 229 |

- 학습은 공식 `train.tsv/ltr`에 속하는 실제 사람 전사만 사용했다. 오류 256발화, 같은 문항 정상 256발화,
  그 밖의 정상 replay 256발화이며 선택한 768개 전사가 원본 학습 라벨과 일치함을 확인했다.
- 오류 발화는 표준/실제 전사 길이가 같고 **모음 앞 ㅅ↔ㅆ 한 자리만 다른 경우**로 제한했다.
  정상 발화는 전체 전사가 일치한다. 복합 오류·불명확한 편집 정렬은 포함하지 않는다.
- 0.5~12초, 16kHz mono PCM16을 사용하고 오디오를 잘라 전사와 불일치시키지 않는다.
- 첫 학습·보정·평가의 화자·문항·정규화 문장·녹음 교집합은 모두 0이다.
  추가 확인은 첫 실험에 나온 1,525화자와 모든 녹음을 제외했다. 학습·보정과의 문항 분리도 유지했다.
- 출발 모델은 예전에 이 문항들을 학습했다. 여기서 보장하는 분리는 **이번 추가 학습**에 대한 것이다.
  별도 확인 녹음도 과거 프로젝트의 모든 탐색에서 미사용이었다고 보장하지 않는다.
- 보정용 정상 ㅆ 177자리는 1% 꼬리 임계값을 안정적으로 추정하기에 작다. 실제 평가의 헛지적 수를 함께 기록한다.

## 3. 학습 설정

일반 CTC는 실제 전사 음소열의 NLL을 전사 길이로 나누어 발화 평균한다.
오류 대조 항은 실제 전사에서 목표 오류 자리 하나만 표준으로 바꾼 반대 후보와 비교한다.

```text
hinge = max(0, 2 + NLL(actual) - NLL(counterfactual))
L_error_rank = 발화평균(오류자리평균(hinge / 전사길이))
L = CTC(actual) + L_error_rank
```

오류 없는 발화는 오류 대조 항에 0을 기여한다. 두 후보는 같은 forward의 logits를 쓰고 양쪽 모두 gradient를 유지한다.
불가능한 CTC 경로를 0으로 바꾸지 않으며, 인접 반복 음소를 고려한 최소 프레임 수와 finite loss를 검사한다.

정상 보존 후속에서는 실제 전사의 **정상 ㅅ/ㅆ 자리**를 반대로 바꾼 후보도 추가한다.
`L_normal_rank`를 별도로 평균해 더하므로 기존 오류 항의 가중치는 줄이지 않았다.

공통 설정은 LR 5e-6, 20회 warmup 후 최종 0.1배까지 선형 감소, 300회 갱신, gradient accumulation 2,
batch audio frames 384,000, seed 20261023이다. Dropout·LayerDrop·SpecAugment는 끄고,
BF16 forward/FP32 master weight·CTC를 사용했다. 580,544,370개 파라미터를 학습했다.
첫 두 모델은 600 microbatch에서 같은 순서로 2,948발화를 보았고, 전체 학습 768발화가 모두 포함됐다.
배치 노출 SHA256과 초기 가중치 SHA256이 같으며, 모든 24층과 헤드의 파라미터 변경을 확인했다.

## 4. 첫 비교 결과

1차 점수는 표준 음소로 CTC 정렬한 구간의 `대안 음소 최대 logP − 표준 음소 최대 logP`다.
정상 보정 자료에서 헛지적 목표 1%의 임계값을 모델·방향별로 정하고 평가에는 그대로 적용했다.
이는 전체 운영 화면의 오류 필터까지 재현한 수치가 아니다.

| 모델 | ㅅ→ㅆ 검출 / 오류 64 | 정상 ㅅ 헛지적 / 317 | ㅆ→ㅅ 검출 / 오류 64 | 정상 ㅆ 헛지적 / 239 |
|---|---:|---:|---:|---:|
| 기존 | 7 | 2 | 9 | 2 |
| 일반 CTC 추가 학습 | 6 | 1 | 3 | 0 |
| 오류 대조 학습 | 8 | 2 | 5 | 0 |

ㅆ 오류 한 자리는 모든 모델에서 정렬/CTC 점수가 생성되지 않았다. 최종 비교에서는 해당 자리도 미검출로 세어
오류 분모를 64개로 유지했다. 개별 `report.json`의 점수 유효 표본 분모 63과 구분한다.

오류 대조 학습의 기존 대비 ㅅ 검출 증가는 1개뿐이며 문항 bootstrap 1,000회 재현율 차이 95% 구간은
−11.1~+16.0%p다. ㅆ는 4개 줄었다. 헛지적도 달라졌으므로 검출 수만으로 구별 능력의 인과적 악화를 단정하지 않는다.
그럼에도 사전 목표인 **헛지적 증가 없이 두 방향의 실제 오류를 더 잡기**는 달성하지 못했다.

임계값 없이 모델의 greedy 음소 전사 자체를 보면:

| 모델 | 실제 오류를 반대 음소로 보존 / 128 | 정상 자리의 ㅅ↔ㅆ 헛인식 / 556 | 전체 음소 오류율 | 비ㅅ·ㅆ 치환·삭제율 |
|---|---:|---:|---:|---:|
| 기존 | 20 | 3 | 4.51% | 3.13% |
| 일반 CTC 추가 학습 | 31 | 13 | 3.54% | 2.10% |
| 오류 대조 학습 | 52 | 40 | 3.65% | 2.18% |

대조 학습은 실제 오류 보존을 늘렸지만 정상 발음도 더 많이 뒤집었다.
일반 CTC의 전체 인식 오류 감소는 이 표본에서 관찰한 별도 결과이며, ㅅ·ㅆ 검출 성공이나 운영 전체 성능 개선은 아니다.

보정 목표 5%도 계산했지만 기존 모델의 ㅆ 실제 평가 헛지적률이 20.9%에 달했다.
따라서 이를 '동일한 헛지적률에서의 검출 비교'라고 표현하지 않는다.

## 5. 정상 대조 항을 추가한 별도 확인

첫 비교에서 늘어난 정상 헛인식을 줄일 수 있는지, 정상 녹음에서도 실제 음소가 반대 음소보다 높은 확률을 받도록
`L_normal_rank`를 추가했다. 학습 자료·초기 가중치·300회 갱신과 나머지 설정은 그대로다.
확인 자료는 앞서 평가하지 않은 화자의 493발화이며, 모델 출력 없이 라벨과 고정 문항 분할만으로 골랐다.
학습·보정 파일은 첫 실험과 바이트 단위로 같다. 학습 노출 순서 SHA256도 앞의 두 학습과 같으며,
전체 24층 및 헤드 갱신 검사를 통과했다.

보정 자료에서 목표 헛지적 1%로 정한 임계값을 적용한 결과:

| 모델 | ㅅ→ㅆ 검출 / 오류 45 | 정상 ㅅ 헛지적 / 303 | ㅆ→ㅅ 검출 / 오류 64 | 정상 ㅆ 헛지적 / 229 |
|---|---:|---:|---:|---:|
| 기존 | 4 | 4 | 7 | 4 |
| 일반 CTC 추가 학습 | 1 | 1 | 1 | 1 |
| 오류 대조 학습 | 1 | 0 | 1 | 1 |
| 오류 + 정상 대조 학습 | 2 | 0 | 6 | 2 |

후속 모델은 헛지적을 줄였지만 기존보다 실제 오류도 적게 잡았다. 따라서 사전 목표는 통과하지 못했다.
이 확인셋에서는 점수 결측·CTC 정렬 실패가 없었다.

보조 지표인 greedy 전사에서 **ㅆ→ㅅ**만 보면 다음과 같다.

| 모델 | 실제 오류 인식 / 64 | 정상 ㅆ를 ㅅ으로 헛인식 / 229 |
|---|---:|---:|
| 기존 | 7 | 2 |
| 일반 CTC 추가 학습 | 7 | 2 |
| 오류 대조 학습 | 18 | 7 |
| 오류 + 정상 대조 학습 | 17 | 3 |

정상 대조 항을 더하면 오류 대조만 했을 때보다 헛인식은 7→3개로 줄고 실제 오류 인식은 18→17개로 거의 유지됐다.
기존 대비 오류 인식 +10개의 화자 bootstrap 재현율 차이 95% 구간은 +7.46~+25.8%p지만,
문항 12개를 재표집한 구간은 0~+29.0%p다. 두 bootstrap은 각각 별도 군집 단위의 탐색적 구간이며
새 문항 일반화나 다중 군집 불확실성을 모두 보장하지 않는다.

**ㅅ→ㅆ**는 기존 8검출/4헛인식에서 후속 28검출/15헛인식으로 바뀌어 헛인식 증가가 컸다.
따라서 유망한 보조 신호는 ㅆ→ㅅ 방향으로 한정한다. 이를 보고 방향별 모델을 섞어 배포하는 것은
추가 설계와 검증이 필요한 새로운 방법이며 이번에는 실행하지 않았다.

확인셋 전체 PER은 기존 3.98%, 일반 CTC 2.88%, 오류 대조 2.88%, 오류+정상 대조 2.90%였다.
비ㅅ·ㅆ 치환·삭제율은 각각 2.36%, 1.40%, 1.45%, 1.48%다.
일반 인식 개선은 반복됐지만, 이는 엄격히 선별한 493발화의 결과로 운영 전체 성능에 대한 주장은 아니다.

이번 결과로 정한 우선순위는 다음과 같다.

1. 오류 대조 손실만 강화하는 방식은 이번 설정에서 제외한다. 검출 증가와 함께 정상 헛인식이 크게 늘었다.
2. 실제 정상/오류 균형 자료와 정상 대조 제약은 **ㅆ→ㅅ 전용 후보**로 남긴다. 채택하려면
   새로운 문항에서 정상 헛지적과 화면 검출을 함께 검증해야 한다.
3. 작은 보정셋의 1% 임계값이 다른 문항에서도 같은 헛지적률을 유지한다고 가정하지 않는다.
   현재 보정용 정상 ㅆ 177자리와 문항별 분포 차이가 판정의 제약이다.

## 6. 산출물과 검증

실험 폴더는 `$MDD_OUTPUTS/analysis/ss_rank_2026-10-23/`다.

- `protocol.json`, `confirmation/protocol.json`: 각 단계의 평가 전에 고정한 설정과 판단 기준.
- `data/`, `confirmation/data/`: 학습·보정·평가 JSONL과 표본 집계·분리 검사.
- `preparation_provenance.json`, `data_preparation.md`: 원본 manifest/TAG 자료·해시·제약.

- `confirmation/eval_*/`, `confirmation/comparison.json`: 별도 화자 확인 결과.
- `run_pilot.sh`, `confirmation/run_confirmation.sh`: 실제 실행 명령. 출력 덮어쓰기는 거절한다.
- `source_snapshots/`, `confirmation/source_snapshots/`: 각 단계의 코드 사본.

저장소 진입점은 `scripts/data/prepare_sibilant_rank_pilot.py`,
`scripts/train/train_sibilant_rank_pilot.py`, `scripts/eval/eval_sibilant_rank_pilot.py`다.
모두 `tasks/pronunciation-assessment/` 아래에 있다.

CTC 손실과 rank gradient 부호·비활성 hinge·정상 replay 가중·불가능 반복 경로를 CPU 검증했다.
정상 대조 항은 오류 항의 gradient 크기를 바꾸지 않고 실제 정상 음소 방향으로 작동함을 독립 검토했다.
Python 3.8 저장소 검사에서 문법 496개·라이브러리 import 22개가 통과했다.
기존 기본 XLS-R 체크포인트 경로 부재 안내는 이번 w2v-BERT 실험과 무관하다.
