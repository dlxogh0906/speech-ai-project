# 발음평가 API 명세서 (운영 서버 기준)

작성 2026-11-03. 운영 중인 NPU 발음평가 서버(8932번 포트)의 코드와 실행 설정을 읽고, 같은 코드·같은 가중치로 문장 녹음 2개를 직접 채점해 확인한 내용이다. 이전 명세 `deploy/pronunciation-demo/API.md`(2026-09-26 개정)에서 바뀐 점은 §12에 모았다.

| 항목 | 운영 값 |
|---|---|
| 서버 | `https://<발음평가 호스트>` (443 → 내부 8932) |
| 모델 | M3 `w2vbert_synth_tense_v2/step_3000` (= `ft3000_2026-10-19`), Rebellions NPU 컴파일본 |
| 실행 인자 | `--canon-fix --del-score-max 50 --liquid-rule --ask-token --save-dir …` |
| 켜진 것 | 표준발음 보정, 빠진 소리 50점 규칙, ㄴ↔ㄹ 예외, 토큰 인증, 녹음 저장, 요청 기록 |
| 꺼진 것 | 입력 거르기 3종(`no_match`·`too_long`·`no_korean`), ㅅ↔ㅆ 예외(`--ss-rule`) |

## 0. 결론: 기대 발음과 들은 발음이 같이 나가는가

1. **나간다.** `/sent.eval.kr` 응답의 `result.words[].phonemes[]`에 자리마다 **기대 발음**(`alpha`·`alpha_jamo`)과 **모델이 들은 소리**(`actual`·`actual_jamo`)가 짝으로 들어간다. 정상 자리, 애매 자리, 오류 자리 모두 같다. 소리를 빠뜨린 자리는 `actual`·`actual_jamo`가 `null`이고, 기대 발음에 없는 소리를 더 냈으면 그 글자의 `words[].inserted`에 들어간다.
2. **문장 전체를 한 줄로 담은 칸은 `/sent.eval.kr`에 없다.** 기대 발음 문자열(예: `[마시따]`)도, 들은 발음 문자열도 따로 오지 않는다. 앱이 `phonemes`를 순서대로 이어 붙여 만든다(§10, 코드 포함). 데모용 `/speak`는 문장 전체 자모열(`canon_jamo`·`pred_jamo`)을 따로 준다(§11).
3. **`actual_jamo`는 모델이 받아 적은 그대로다.** 확실하지 않아 숨긴 자리(`uncertain: true`)도 들은 소리를 그대로 싣는다. 학습자에게 "틀렸다"고 보여 줄 자리는 **`errorType`이 붙은 자리만**이다.

## 1. 엔드포인트

| 메서드 | 경로 | 용도 | 인증 |
|---|---|---|---|
| POST | `/sent.eval.kr` | **문장 채점(앱용)**. SpeechSuper `sent.eval.kr` 호환 | 필요 |
| POST | `/word.judge` | 발음 챌린지 단어 판정. 후보 단어 1~4개, 녹음 저장 안 함 | 필요 |
| POST | `/speak` | 데모 화면용 진단 + 세션 누적 | 필요 |

## 2. 인증

토큰은 아래 넷 중 아무 방법으로 보내면 된다. 값은 운영 서버의 토큰 파일에 있고, 이 문서에는 적지 않는다(개발팀에 문의).

```
Authorization: Bearer <토큰>
X-API-Key: <토큰>
폼 필드 token=<토큰>
쿼리 ?token=<토큰>
```

없거나 틀리면 `401 {"error": "인증 실패 — 토큰이 없거나 틀리다", "code": "unauthorized"}`.

## 3. 요청 (`/sent.eval.kr`)

| 필드 | 필수 | 뜻 |
|---|---|---|
| `audio` | 예 | 녹음 파일. 필드 이름이 달라도 첫 번째 업로드 파일을 쓴다 |
| `refText` | 예 | 채점 기준 문장(학습자가 읽어야 할 문장) |
| `tokenId` | 아니오 | 그대로 `recordId`로 되돌려준다 |
| `userId` | 아니오 | `_meta.userId`로 되돌려준다. 없으면 `guest` |

두 가지 형식을 받는다.

- **간편 방식**: 위 필드를 폼에 그대로 넣는다.
- **SpeechSuper 방식**: 폼 필드 하나(이름 무관)에 SpeechSuper의 connect/start JSON을 통째로 넣는다. 서버는 `start.param.request.refText`·`tokenId`와 `start.param.app.userId`만 읽는다. `applicationId`·`sig`·`timestamp`는 받되 쓰지 않는다.

```bash
curl -H "Authorization: Bearer $TOKEN" \
     -F audio=@rec.wav \
     -F 'refText=이 빵 달콤한 게 진짜 맛있다.' \
     -F tokenId=tok-1 \
     https://<발음평가 호스트>/sent.eval.kr
```

## 4. 오디오 제한

| 항목 | 값 |
|---|---|
| 권장 형식 | WAV · 16 kHz · 1채널 · 16bit. 변환 없이 바로 읽는다 |
| 그 밖 형식 | webm/opus·mp3·m4a 등은 서버가 ffmpeg로 변환한다 |
| 최소 길이 | 녹음 전체 0.3초 이상 |
| 최소 말소리 | 말한 시간이 **기준 문장 음절당 0.08초**(하한 0.2초, 상한 1.0초) 이상이고, 말소리 비율이 30% 이상 |
| 최대 길이 | **앞 20초만 채점**한다. 운영에서는 `too_long` 거절이 꺼져 있어 20초를 넘으면 나머지는 버린다 |
| 문장 | `refText`의 한글 글자만 채점 단위(`words[]`)가 된다. 숫자·영문은 한글로 풀어 보내는 것을 권장 |

## 5. 오류 응답

| HTTP | `code` | 뜻 | 운영 |
|---|---|---|---|
| 401 | `unauthorized` | 토큰 없음·틀림 | 켜짐 |
| 400 | `no_audio` | 오디오 파일이 없음 | 켜짐 |
| 400 | `decode_failed` | 오디오를 읽지 못함 | 켜짐 |
| 400 | `too_short` | 녹음이 0.3초 미만 | 켜짐 |
| 400 | `no_reftext` | `refText`가 비어 있음 | 켜짐 |
| 400 | `low_speech` | 말소리가 모자람(§4) — 다시 녹음 안내 | 켜짐 |
| 400 | `no_match` | 기준 문장 소리와 들은 소리가 거의 다 다름(잡음·음악 녹음) | **꺼짐** |
| 400 | `too_long` | 말소리가 20초 초과 | **꺼짐** |
| 400 | `no_korean` | `refText`에 한글이 없음 | **꺼짐** |

`low_speech` 본문 예(11음절 문장이라 최소 말한 시간 0.88초):

```json
{ "error": "말소리가 거의 없다 (말한 시간 0.4초 · 소리 비율 12%) — 마이크에 가까이서 또박또박 다시 녹음할 것",
  "code": "low_speech",
  "audio": { "voiced_ratio": 0.12, "voiced_sec": 0.4, "min_voiced_ratio": 0.3, "min_voiced_sec": 0.88 },
  "speech_s": 0.4, "min_speech_s": 0.88, "voiced_ratio": 0.12, "min_voiced_ratio": 0.3 }
```

꺼진 세 코드는 앱이 처리할 준비가 되면 서버 인자로 켠다. 지금은 `refText`에 한글이 없으면 200에 점수 칸이 비어서 나간다.

## 6. 응답 구조 (`/sent.eval.kr`, 200)

### 맨 위

| 필드 | 뜻 |
|---|---|
| `refText` | 보낸 기준 문장 |
| `recordId` | 보낸 `tokenId` (없으면 `null`) |
| `result` | 점수와 글자별 판정 |
| `_meta` | 점수 해석 안내, 처리 시간, 오디오 정보. 무시해도 된다 |

### `result`

| 필드 | 뜻 |
|---|---|
| `overall` | 0.6 × 발음 + 0.2 × 유창성 + 0.2 × 이해도. 없는 값은 빼고 남은 것끼리 비율 유지 |
| `pronunciation` | 글자 점수의 평균(= 음소 점수 평균). 사람 점수 예측이 아니다 |
| `fluency` | 말 속도·쉼만 보는 규칙 점수(발음과 독립) |
| `rhythm` · `comprehensibility` | 발화 1개에서는 **`null`** (운영은 `--utt-comp` 꺼짐). 이해도 참고값은 `_meta.comprehensibility_utt` |
| `words[]` | `refText`의 **한글 글자마다 하나** (이름은 words지만 단위는 글자) |

### `words[]` (글자)

| 필드 | 뜻 |
|---|---|
| `word` | 글자 하나 (철자 기준) |
| `readType` | 글자 판정. 0 정상 · 1 빠뜨림 · 2 다르게 읽음 · 3 오독 · 4 소리 더 넣음 (§7) |
| `score` | 그 글자 음소 점수의 평균. 오독이면 0 → `null` |
| `phonemes[]` | 그 글자에 속한 기대 발음 자리들 |
| `inserted` | (있을 때만) 기대 발음에 없는데 모델이 들은 소리 `[{"actual_jamo": "ㅡ"}]` |

### `phonemes[]` (기대 발음 자리)

| 필드 | 뜻 |
|---|---|
| `alpha` | **기대 발음** 자리의 KoG2P 기호(예 `pp` = ㅃ, `nf` = 받침 ㄴ) |
| `alpha_jamo` | **기대 발음** 자리의 한글 자모 |
| `position` | `초성` · `중성` · `종성` (기대 발음 기준) |
| `pronunciation` | 자리 점수 = (1 − 그 소리가 틀렸을 확률) × 100. 들은 소리가 없으면 `null` |
| `actual` | **모델이 들은 소리**의 KoG2P 기호. 빠뜨렸으면 `null` |
| `actual_jamo` | **모델이 들은 소리**의 한글 자모. 빠뜨렸으면 `null` |
| `errorType` | (오류로 표시할 때만) 오류 유형 (§7) |
| `uncertain` | (애매할 때만) `true` — 들은 소리는 달랐지만 확실하지 않아 지적하지 않는 자리 |

`0`점은 숫자로 보내지 않고 `null`로 보낸다. `null`은 "0점이거나 판정하지 못함"이다. 평균은 0을 넣어 구한 뒤에 바꾼다.

### `_meta` 주요 칸

| 필드 | 뜻 |
|---|---|
| `ms` | 서버 처리 시간(밀리초) |
| `audio` | 앞뒤 무음 자르기 정보 `{orig_sec, voiced_ratio, sec, trimmed, cut_sec}` |
| `raw_human_1to5` | 사람 점수(1~5점) 예측 원값 `{pron, comp, flu}`. 별점으로 쓸 때 이 값 |
| `fluency_human` | 사람 유창성 점수 예측을 백분위로 바꾼 값(참고용) |
| `comprehensibility_utt` | 발화 1개 이해도(참고용, 상관 0.433) |
| `userId` · `request_style` | 보낸 사용자 ID · 요청 형식(`simple` 또는 `speechsuper:<필드명>`) |
| 나머지 문자열 칸 | 점수 해석 안내문(`scale`·`flagged_rule`·`score_pcc_utt` 등) |

## 7. 판정 규칙

### 자리(phoneme) 판정

| 상황 | 응답 | 화면 |
|---|---|---|
| 들은 소리 = 기대 발음 | `actual_jamo` = `alpha_jamo` | 정상 |
| 다른 소리, 자리 점수 60 미만 | `errorType` 붙음 | **틀림** |
| 다른 소리, 자리 점수 60 이상 | `uncertain: true` | 지적하지 않음 |
| 첫소리 예사소리(ㄱㄷㅂㅅㅈ)를 짝 된소리·거센소리로 들었고, 그 소리 확률 0.6 이상 | 점수 60 이상이어도 `errorType` | **틀림** |
| 첫소리·받침 ㄴ↔ㄹ로 들었고, 그 소리 확률 0.6 이상 | 점수 60 이상이어도 `errorType` | **틀림** |
| 들은 소리 없음, 강제정렬 점수 50 미만 | `actual: null` + `errorType: "음운탈락"` | **빠뜨림** |
| 들은 소리 없음, 강제정렬 점수 50 이상 | `actual: null` + `uncertain: true` | 지적하지 않음 |
| 글자 하나가 통째로 안 들림 | 그 글자 자리를 **한꺼번에** 판정: 강제정렬 점수 평균 50 미만이면 모두 `음운탈락`, 아니면 모두 애매 | — |
| 기대 발음에 없는 소리를 더 냄 | 그 글자의 `inserted` | 지적하지 않음 |

### `errorType` 값

| 값 | 조건(기대 → 들은 소리) |
|---|---|
| `모음오류` | 어느 한쪽이 모음 |
| `경음화` | 예사소리 ↔ 짝 된소리 (ㄱ↔ㄲ, ㄷ↔ㄸ, ㅂ↔ㅃ, ㅅ↔ㅆ, ㅈ↔ㅉ) |
| `격음화` | 예사소리 ↔ 짝 거센소리 (ㄱ↔ㅋ, ㄷ↔ㅌ, ㅂ↔ㅍ, ㅈ↔ㅊ) |
| `비음화` | ㄱ·ㄷ·ㅂ·ㅋ·ㅌ·ㅍ를 짝 비음(ㅇ·ㄴ·ㅁ)으로 |
| `유음화` | ㄴ ↔ ㄹ |
| `음운탈락` | 소리를 빠뜨림 |
| `초성` · `종성` | 위에 해당하지 않는 자음 오류. 자리에 따라 둘 중 하나 (예: ㅃ→ㅍ, ㅉ→ㅊ는 `초성`) |

`음운첨가`는 코드에 있지만 `/sent.eval.kr`에서는 붙지 않는다. 더 낸 소리는 `inserted`로만 나간다.

### `readType` (글자 판정)

| 값 | 조건 (위에서부터 먼저 맞는 것) |
|---|---|
| 1 빠뜨림 | 그 글자 자리가 모두 빠뜨림으로 판정됨 |
| 3 오독 | 글자 점수 20 미만이고 틀림·빠뜨림 자리가 있음 (`score`는 `null`) |
| 2 다르게 읽음 | 틀림 또는 빠뜨림 자리가 하나 이상 (애매 자리는 세지 않음) |
| 4 소리 더 넣음 | 틀린 자리는 없고 `inserted`가 있음 |
| 0 정상 | 그 밖 |

### 기대 발음은 어떻게 만드나

`refText` → KoG2P(표준 발음 규칙) → **표준발음 보정**(KoG2P가 틀리는 곳 고침: 먹을 수[머글쑤], 사건[사껀], 중요[중요], 희망[히망], 빠졌네요[빠전네요]) → 허용 발음이 여럿이면(우리의 → [우리의]/[우리에]) 녹음에서 나올 확률이 더 높은 쪽. `alpha_jamo`는 이 결과다. 소리 없는 초성 ㅇ은 자리에 없고, ㅙ·ㅞ는 ㅗ+ㅐ·ㅜ+ㅔ 두 자리로 나뉜다.

## 8. 문장 예시 ① — 틀린 곳이 있는 녹음 (전문)

- 기준 문장: **이 빵 달콤한 게 진짜 맛있다.**
- 녹음: AIHub 외국인 한국어 녹음, 학습에 쓰지 않은 화자
- 사람이 들은 정답(TAG): 빵의 ㅃ을 **ㅍ**, 짜의 ㅉ을 **ㅊ**으로 읽음. 나머지는 표준 발음대로

### 기대 발음과 들은 소리 대조

| 문장 전체 | 자모 | 음절로 합치면 |
|---|---|---|
| 기대 발음 (`alpha_jamo`) | ㅣㅃㅏㅇㄷㅏㄹㅋㅗㅁㅎㅏㄴㄱㅔㅈㅣㄴㅉㅏㅁㅏㅅㅣㄸㅏ | [이빵달콤한게진짜마시따] |
| 모델이 들은 소리 (`actual_jamo`) | ㅣ**ㅍ**ㅏㅇ**ㅌ**ㅏㄹㅋㅗㅁㅎㅏㄴㄱㅔㅈㅣㄴ**ㅊ**ㅏㅁㅏㅅㅣㄸㅏ | [이**팡탈**콤한게진**차**마시따] |

| 글자 | 기대 → 들은 소리 | 자리 점수 | 응답 | 사람 정답 |
|---|---|---|---|---|
| 빵 | ㅃ → ㅍ (초성) | 12 | `errorType: "초성"` · 글자 `readType: 2` | ㅍ — 일치 |
| 달 | ㄷ → ㅌ (초성) | 84 | `uncertain: true` (점수 60 이상, 들은 소리 확률 0.599 < 0.6) | ㄷ — 숨긴 게 맞음 |
| 짜 | ㅉ → ㅊ (초성) | 52 | `errorType: "초성"` · 글자 `readType: 2` | ㅊ — 일치 |

모델은 세 자리를 다르게 들었고, 그중 확실한 두 자리만 틀림으로 표시했다. 두 자리 모두 사람 정답과 같다.

### 응답 전문

`recordId`는 보낸 `tokenId`다. `_meta.ms`는 로컬 GPU 실행 값이다(§13).

```json
{
  "refText": "이 빵 달콤한 게 진짜 맛있다.",
  "recordId": "example-6",
  "result": {
```

## 10. 문장 전체 발음 문자열 만들기 (앱에서)

`/sent.eval.kr`에는 문장 단위 문자열 칸이 없으므로 아래처럼 만든다.

1. 기대 발음 = 모든 `words[].phonemes[].alpha_jamo`를 순서대로 잇는다.
2. 들은 소리 = 같은 순서로 `actual_jamo`를 잇되 `null`은 건너뛰고, 글자마다 `inserted`의 `actual_jamo`를 그 글자 뒤에 붙인다. `inserted`는 글자 안의 정확한 위치를 주지 않으므로 근사다.
3. 자모열을 음절로 합친다. 초성 ㅇ이 빠져 있으므로 모음으로 시작하면 ㅇ을 넣고, ㅗ+ㅐ → ㅙ, ㅜ+ㅔ → ㅞ로 다시 합친다. 띄어쓰기 정보는 없다.

```python
CHO = "ㄱㄲㄴㄷㄸㄹㅁㅂㅃㅅㅆㅇㅈㅉㅊㅋㅌㅍㅎ"
JUNG = "ㅏㅐㅑㅒㅓㅔㅕㅖㅗㅘㅙㅚㅛㅜㅝㅞㅟㅠㅡㅢㅣ"
JONG = ["", "ㄱ", "ㄲ", "ㄳ", "ㄴ", "ㄵ", "ㄶ", "ㄷ", "ㄹ", "ㄺ", "ㄻ", "ㄼ", "ㄽ", "ㄾ", "ㄿ", "ㅀ",
        "ㅁ", "ㅂ", "ㅄ", "ㅅ", "ㅆ", "ㅇ", "ㅈ", "ㅊ", "ㅋ", "ㅌ", "ㅍ", "ㅎ"]
MERGE = {("ㅗ", "ㅐ"): "ㅙ", ("ㅜ", "ㅔ"): "ㅞ"}

def compose(jamo):
    js, k = [], 0
    while k < len(jamo):
        if k + 1 < len(jamo) and (jamo[k], jamo[k + 1]) in MERGE:
            js.append(MERGE[(jamo[k], jamo[k + 1])]); k += 2
        else:
            js.append(jamo[k]); k += 1
    out, i = [], 0
    while i < len(js):
        c = js[i]
        if c in JUNG:
            on, v = "ㅇ", c; i += 1
        elif i + 1 < len(js) and js[i + 1] in JUNG:
            on, v = c, js[i + 1]; i += 2
        else:
            out.append(c); i += 1; continue
        coda = ""
        if i < len(js) and js[i] in JONG[1:] and not (i + 1 < len(js) and js[i + 1] in JUNG):
            coda = js[i]; i += 1
        out.append(chr(0xAC00 + (CHO.index(on) * 21 + JUNG.index(v)) * 28 + JONG.index(coda)))
    return "".join(out)

def sentence_strings(result):
    exp, heard = [], []
    for w in result["words"]:
        exp += [p["alpha_jamo"] for p in w["phonemes"]]
        heard += [p["actual_jamo"] for p in w["phonemes"] if p["actual_jamo"]]
        heard += [x["actual_jamo"] for x in w.get("inserted", [])]
    return compose(exp), compose(heard)

# 예시 ① → ("이빵달콤한게진짜마시따", "이팡탈콤한게진차마시따")
```

들은 소리 문자열에는 애매 자리(예시 ①의 달 → 탈)도 들어간다. 화면에서 틀림으로 강조할 곳은 `errorType`이 있는 자리만이다.

## 11. 다른 엔드포인트 응답

### `/speak` (데모·세션용) — 문장 전체 자모열을 준다

요청: `audio`, `sentence`, `country`(선택), `id`(세션 ID, 기본 `default`). 응답 칸:

| 필드 | 뜻 |
|---|---|
| `canon_jamo` · `canon_phone` | **문장 전체 기대 발음** 자모 배열 · KoG2P 기호 배열 |
| `pred_jamo` · `pred_phone` | **문장 전체 들은 소리** 자모 배열 · KoG2P 기호 배열 |
| `sites[]` | 기대 발음 자리마다 `{i, canon, pred, j, verdict, prob, canon_ph, pred_ph}`. `verdict`는 `일치` · `다름` · `삭제`, `prob`은 들은 소리의 확률 |
| `feedback` | 국적을 주면 그 나라 학습자에게 흔한 오류 교정 안내 |
| `scores` | 사람 점수(1~5) 예측 `{pron, comp, flu}` |
| `summary` | 세션 누적 요약(10발화부터 유효, 30발화 권장) |
| `vad` · `sec` · `rms` · `ms` | 무음 자르기 정보 · 녹음 길이 · 음량 · 처리 시간 |

예시 ①의 녹음을 `/speak`로 보내면 `canon_jamo`는 ㅣㅃㅏㅇㄷㅏㄹㅋㅗㅁㅎㅏㄴㄱㅔㅈㅣㄴㅉㅏㅁㅏㅅㅣㄸㅏ, `pred_jamo`는 ㅣㅍㅏㅇㅌㅏㄹㅋㅗㅁㅎㅏㄴㄱㅔㅈㅣㄴㅊㅏㅁㅏㅅㅣㄸㅏ이고, `다름` 자리는 ㅃ→ㅍ(prob 0.914), ㄷ→ㅌ(0.599), ㅉ→ㅊ(0.742) 셋이다. `/speak`는 화면 지적 규칙(60점·0.6)을 적용하지 않은 원래 판정이다.

### `/word.judge` (단어 챌린지)

요청: `audio` + `targets`(후보 단어 1~4개; 여러 번 보내거나 JSON 배열·쉼표·줄바꿈으로 묶어도 됨). 응답:

```json
{ "targets": [ { "target": "…", "canon_jamo": [...], "pred_jamo": [...],
                 "mismatches": [ { "i": 0, "expected": "ㄲ", "heard": "ㅋ", "kind": "다름" } ],
                 "n_mismatch": 1 } ],
  "pred_jamo": [...], "voiced_sec": 0.6, "sec": 1.2, "truncated": false, "device": "…",
  "ms": { "prep": …, "forward": …, "post": …, "total": …, "request": … } }
```

맞음·틀림 등급은 주지 않는다(허용 불일치 수는 웹이 정한다). 녹음은 저장하지 않는다. 오류 코드: `too_short`(0.12초 미만) · `low_speech` · `no_audio` · `decode_failed` · `no_targets` · `too_many_targets` · `unauthorized`. 6초가 넘으면 앞 6초만 보고 `truncated: true`.

## 13. 이 문서의 예시를 만든 방법

- 운영 서버에는 요청을 보내지 않았다(운영 요청은 녹음이 저장된다).
- 운영 서버의 코드 폴더와 점수 파일을 그대로 복사하고, 같은 가중치(`model.safetensors`·`config.json`·`jamo_vocab.json`의 sha256이 운영본과 일치)로 GPU 서버의 로컬 포트에서 운영과 같은 인자(`--canon-fix --del-score-max 50 --liquid-rule`)로 띄워 채점했다. 시작 로그의 설정 줄도 운영과 같았다(인증·녹음 저장만 끔).
- 운영은 NPU 컴파일 모델로, 이 예시는 GPU로 돌렸다. 점수 숫자가 1~2점 다를 수 있다.
- 녹음은 AIHub 외국인 한국어 데이터의 테스트 화자 녹음이다(앱 사용자 녹음은 쓰지 않았다). 오디오는 이 문서에 넣지 않는다.
