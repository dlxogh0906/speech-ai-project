# 한국어 발음 평가 API (SpeechSuper `sent.eval.kr` 호환)

비버톡 자체 엔진으로 문장 발음을 채점한다. **SpeechSuper 와 요청 형식이 같고, 응답도 같은 모양이다.**

```
https://api.speechsuper.com/sent.eval.kr    →    http://<서버>:8932/sent.eval.kr
```

요청은 기존 코드 그대로 보내면 된다. 응답에서 **두 곳만 다르다** — 실제로 비교해 확인한 차이다.

| | SpeechSuper | 우리 |
|---|---|---|
| 글자 점수 위치 | `words[].scores.pronunciation` | `words[].score` |
| 음소 표기(`alpha`) | 한글 — 게다가 **낸 소리**가 섞여 있다(학→ㅏㄱ) | KoG2P 기호(`k0`) = **내야 할 소리**. 한글은 `alpha_jamo` |

작성 2026-09-23 · 개정 **2026-09-26**(문장 점수 눈금을 백분위로 변경 · §6) · 문의: 개발팀



---

## 1. 엔드포인트

| 메서드 | 경로 | 용도 |
|---|---|---|
| POST | `/sent.eval.kr` | 문장 발음 채점 |
| GET | `/health` | 서버 상태 |
| GET | `/speechsuper.html` | 브라우저 확인용 화면 |

Content-Type 은 `multipart/form-data`.

## 2. 인증

넷 중 아무거나 쓰면 된다.

```
Authorization: Bearer <토큰>
X-API-Key: <토큰>
폼 필드 token=<토큰>
쿼리 ?token=<토큰>
```

토큰이 없거나 틀리면 `401 {"code": "unauthorized"}`.

## 3. 요청

### ① SpeechSuper 방식 (기존 코드 그대로)

multipart 에 **오디오 파일**과 **JSON 덩어리**를 함께 보낸다.
JSON 이 담긴 필드 이름은 무엇이든 된다(`text`·`params`·`data`…) — 값이 JSON 이고 `start`/`request` 를 품고 있으면 찾아서 읽는다.

```json
{
  "connect": { "cmd": "connect", "param": { "sdk": {...}, "app": {...} } },
  "start": {
    "cmd": "start",
    "param": {
      "app":   { "userId": "guest", "applicationId": "...", "timestamp": "...", "sig": "..." },
      "audio": { "audioType": "wav", "channel": 1, "sampleBytes": 2, "sampleRate": 16000 },
      "request": { "coreType": "sent.eval.kr",
                   "refText": "안녕하세요 만나서 반갑습니다",
                   "tokenId": "tok-1787908617-26108" }
    }
  }
}
```

읽는 값은 셋뿐이다 — `request.refText`(채점 기준 문장) · `request.tokenId`(→ `recordId` 로 되돌려준다) · `app.userId`.
**`applicationId`·`sig`·`timestamp` 는 받되 쓰지 않는다**(우리 인증은 위 토큰 하나).

### ② 간편 방식

```
audio=@rec.wav
refText=안녕하세요
tokenId=tok-1
```

### 오디오

| 항목 | 값 |
|---|---|
| 권장 | **WAV · 16 kHz · 1채널 · 16bit** (그대로 읽어 가장 빠르다) |
| 그 밖 | webm/opus·mp3·m4a 등도 받는다(서버에서 변환, 약 150 ms 추가) |
| 길이 | 20초까지 채점(초과분은 버린다) · 말소리 1초 이상 필요 |

### 예

```bash
curl -H "Authorization: Bearer $TOKEN" \
     -F 'text={"start":{"param":{"app":{"userId":"guest"},"request":{"refText":"안녕하세요","tokenId":"tok-1"}}}}' \
     -F audio=@rec.wav \
     http://<서버>:8932/sent.eval.kr
```

## 4. 응답

```jsonc
{
  "refText": "안녕하세요",
  "recordId": "tok-1",              // 보낸 tokenId 그대로
  "result": {
    "overall": 98,                  // 0.6·발음 + 0.2·유창 + 0.2·이해
    "pronunciation": 99,            // 음소 판정 기반 (= 글자 점수 평균)
    "fluency": 96,                  // 말 속도·쉼으로 매긴다 (§6)
    "rhythm": null,                 // 발화 1개로는 보내지 않는다 (§6)
    "comprehensibility": null,      // 같은 값 — 세션(5발화+)에서만 나온다
    "words": [
      {
        "word": "안",               // 글자
        "readType": 0,              // 0정상 1누락 2대치 3오독 4삽입
        "score": 98,                // 글자 점수 = 아래 음소 점수 평균
        "phonemes": [
          { "alpha": "aa",          // 내야 할 소리 (KoG2P 기호)
            "alpha_jamo": "ㅏ",      // 같은 소리, 한글 표기
            "position": "중성",      // 초성 · 중성 · 종성
            "pronunciation": 97,    // 점수 = (1 − 틀렸을 확률) × 100
            "actual": "aa",         // ★ 실제로 낸 소리 (없으면 null = 빠뜨림)
            "actual_jamo": "ㅏ" },
          { "alpha": "nf", "alpha_jamo": "ㄴ", "position": "종성",
            "pronunciation": 42, "actual": "ll", "actual_jamo": "ㄹ",
            "errorType": "유음화" }  // ★ 오류 유형
        ],
        "inserted": [ { "actual_jamo": "ㅡ" } ]   // ★ 없는 소리를 넣은 경우(있을 때만)
      }
    ]
  },
  "_meta": { ... }                  // 신뢰도·기준 설명. 무시해도 된다
}
```

★ 표시는 SpeechSuper 에 없는 항목이다. 모르는 키는 무시하면 된다.

### 음소 기호

`alpha` 는 KoG2P 기호다. 같은 자모라도 **자리에 따라 기호가 다르다**.

| 자모 | 초성 | 종성 |
|---|---|---|
| ㄱ | `k0` | `kf` |
| ㄴ | `nn` | `nf` |
| ㅂ | `p0` | `pf` |
| ㅁ | `mm` | `mf` |

모음은 `aa`(ㅏ) `vv`(ㅓ) `oo`(ㅗ) `uu`(ㅜ) `ii`(ㅣ) `ee`(ㅔ) 등.
한글로 쓰려면 `alpha_jamo` 를 그대로 쓰면 된다.

### 오류 유형(`errorType`)

`초성` · `종성` · `모음오류` · `경음화` · `격음화` · `비음화` · `유음화` · `음운탈락` · `음운첨가`

## 6. 점수를 읽는 법 (중요)

### `0` 은 보내지 않는다 — `null` 로 온다 (2026-09-26 변경)

**모든 점수 칸은 `0` 대신 `null` 로 온다.** `overall`·`pronunciation`·`fluency`·`rhythm`·
`comprehensibility`·`words[].score`·`words[].phonemes[].pronunciation` 전부 같은 규칙이다.

| 오는 값 | 뜻 |
|---|---|
| 1~100 | 채점된 점수 |
| `null` | **0 점이거나, 그 자리를 판정하지 못했다**(인식된 소리가 없어 `actual_jamo` 도 `null`) |

앱에서는 `null` 을 숫자 0 으로 바꾸지 말고 `—` 같은 빈 칸으로 그리면 된다(데모 화면이 그렇게 한다).

**평균은 `0` 을 그대로 넣어 구한 뒤 마지막에만 `null` 로 바꾼다.** 즉 0 점 자리가 있으면
그 글자·문장 점수는 실제로 내려가고, 화면에 그 자리만 빈 칸으로 보인다. 0 점을 평균에서 빼면
점수가 부풀려지므로 그렇게 하지 않는다. 다만 **인식된 소리가 아예 없는 자리(`actual_jamo: null`)는
평균에서 제외한다** — 같은 자모가 잇달아 나거나 파열음이 뒤 소리에 먹히는 자리가 많아
(측정: 누락 37건 중 19% 가 같은 자모 연속) 0 점으로 세면 정확히 읽은 사람이 깎인다.

유효한 점수가 하나도 없으면 상위 칸도 `null` 이다. 마이크 입력 부족·오디오 해석 실패 등은
점수가 아니라 HTTP 400 오류로 온다(위 오류 응답 규격).

### 믿을 수 있는 것

| 항목 | 근거 |
|---|---|
| `words[].phonemes[].pronunciation` | **(1 − 틀렸을 확률) × 100.** 검증셋 179만 자리에서 **맞게 발음한 자리의 97.3% 가 80점 이상**, 90점 이상 구간의 실제 오류율 1.2% |
| `words[].score` · `result.overall` | 위 음소 점수의 평균. 같은 기준 |
| `readType` · `actual` | 실제 발음과 대조한 판정. 자리 단위 판별력 AUC 0.937 |

→ **화면 게이지와 통과 기준(80↑)은 `overall` 과 글자 점수로 잡을 것.**

### 조심할 것

| 항목 | 문제 |
|---|---|
| `fluency` | **말 속도·쉼만 보고 매긴다**(2026-09-26 변경 · 아래 설명). 발음 판정과 섞이지 않는다 |
| `rhythm` · `comprehensibility` | 발화 1개에서는 **`null`** 이다. 사람 채점과 상관 0.433 뿐이라 내보내지 않는다 — `/session` 으로 5발화 이상 모아 쓸 것(모으면 0.691) |
| 참고값 | `_meta.fluency_human`(사람 유창성 점수 예측) · `_meta.comprehensibility_utt`(발화 1개 이해도)로 원래 값도 같이 간다. 화면에 쓰려면 위 신뢰도를 감안할 것 |

### 네 칸의 관계 (2026-09-26 변경 — 눈금이 바뀌었다)

```
pronunciation = 음소 점수 평균 = (1 − 틀렸을 확률) × 100     (= 글자 점수 평균, 검증된 값)
fluency·이해도 = 사람 점수 예측값의 **학습자 분포 백분위**
overall       = 0.6·pronunciation + 0.2·fluency + 0.2·이해도
```

**네 칸 모두 "80점 = 학습자 상위 20%" 로 읽는다.** 이전에는 5점 만점 비례(`예측÷5×100`)였는데,
사람 채점 평균이 3.30/5 이고 회귀 모델이 확신 없을 때 평균으로 붙어서 **잘 읽어도 76점이 천장**이었다.
순서는 그대로 두고 눈금만 폈다.

| 녹음 | overall | 발음 | 유창 | 이해 | (이전 눈금) |
|---|--:|--:|--:|--:|---|
| 정확히 읽음 | **98** | 99 | 96 | 99 | 93 / 99 / 83 / 86 |
| 정확히 읽음 | **98** | 99 | 95 | 98 | 92 / 99 / 83 / 81 |
| 일부러 틀림 | **58** | 94 | 8 | 2 | 75 / 94 / 47 / 46 |

사람 점수 예측 원값(1~5)은 `_meta.raw_human_1to5` 로 그대로 보낸다 — **별점으로 쓸 때는 이 값**을 쓸 것.
`overall` 가중치를 바꾸려면 `_meta.scale` 의 식을 보고 앱에서 다시 계산해도 된다.
백분위 표가 없는 서버에서는 예전 5점 비례로 물러난다(`_meta.scale.utt` 로 어느 쪽인지 알 수 있다).

### `fluency` — 속도·쉼으로 매긴다 (2026-09-26 변경)

이전에는 사람이 매긴 유창성 점수를 예측한 값이었다. 그런데 **AIHub 채점에서는 발음이 틀리면
유창성도 낮게 매긴다** — 세 칸끼리 상관 0.84(화자 단위 0.90), 발음 4.5점 이상 발화에서 유창성
3점 미만은 0.0%. 그 라벨을 예측하니 「또박또박 읽었지만 틀리게 읽은 녹음」의 유창성이 한 자릿수로
떨어졌다(SpeechSuper 는 같은 녹음에 92~98점). 특징에서 발음 관련 항목을 전부 빼도 그대로였다
(2.88 vs 2.80) — 모델이 아니라 **라벨 정의**가 그렇다.

그래서 유창성만 **조음속도·쉼 비율·최장 쉼·쉼 빈도** 네 가지로 따로 계산한다. 기준은 사람이
유창성 4.5점 이상을 준 발화 4,887건의 분포이고, 느리거나 쉼이 많으면 깎는다(빠른 것은 깎지 않는다).

| | 사람 라벨과 상관(발화/화자) | 발음 2.0 이하 발화 평균 | 발음 4.5+ 평균 |
|---|--:|--:|--:|
| 지금: 속도·쉼 규칙 | 0.441 / 0.678 | 82.9 | 97.0 |
| 이전: 사람 점수 예측 | 0.610 / 0.762 | (발음과 같이 떨어진다) | — |

상관은 낮아졌지만 **발음과 독립된 정보**가 된다. 기준표는 `$MDD_OUTPUTS/score_phoneme/fluency_rule.json`
(`scripts/score/fit_fluency_rule.py` 로 재생성). 예전 방식으로 돌리려면 그 파일을 치우면 된다.

### `rhythm` 칸

**리듬 점수는 우리 엔진에 없다.** 이 칸에는 이해 가능성을 넣었지만, 발화 1개에서는 신뢰도가
낮아(상관 0.433) **`null` 로 보낸다.** 세션 점수(`/session`)에서는 값이 나온다.
발화 1개 값이 꼭 필요하면 서버를 `--utt-comp` 로 띄우면 된다.

### 틀린 곳 표시 — `errorType` 이 붙은 자리만 (2026-09-26 변경)

전사(받아쓰기)와 점수(강제정렬 확신도)는 따로 계산돼서 어긋날 수 있다. 실제로 「ㅕ 를 ㅓ 로 들었다」고
표시하면서 그 자리 점수가 90 인 경우가 나왔다. 그래서 **전사가 달라도 그 자리 점수가 60 이상이면
오류로 표시하지 않고** `"uncertain": true` 만 남긴다. 178만 자리 실측 근거:

| 지적 방식 | 정밀도 | 재현율 | F1 | 지적 수 |
|---|--:|--:|--:|--:|
| 전사만 (이전) | 0.474 | 0.518 | 0.4948 | 74,340 |
| **전사 + 점수<60 (지금)** | **0.557** | 0.319 | 0.4058 | 38,970 |

F1 은 내려가지만 **틀렸다고 잘못 말하는 횟수가 절반으로 줄고** 화면의 모순이 사라진다.
놓치는 오류는 늘어난다 — 재현율 0.52 → 0.32.

**틀린 곳 표시는 `errorType` 이 있는 자리로 할 것.** `uncertain: true` 자리는 "들린 소리는 달랐지만
확실하지 않다"는 뜻이므로 지적하지 말고, 필요하면 옅게만 표시한다. `actual`·`actual_jamo` 는
두 경우 모두 들어간다.

## 7. 성능·제약

| 항목 | 값 |
|---|---|
| 응답 시간 | **약 0.7초**(3초 발화, GPU 전용일 때) · 모델 추론 자체는 43 ms |
