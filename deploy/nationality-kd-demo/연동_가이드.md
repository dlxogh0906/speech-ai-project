## 한눈에

1. 사용자가 **문장 수(1 · 3 · 5)** 를 고르면, 그 수만큼의 짧은 문장을 **한 단락**으로 보여 준다.
2. **한 번** 녹음한다. 목표 길이는 5 · 15 · 25초다. 최소 길이 3 · 9 · 15초보다 짧으면 판정하지 않고 다시 읽게 한다.
3. `POST /predict_long` 에 녹음 파일(`audio`)과 문장 수(`parts`)를 보낸다.
4. 응답의 `top5` 로 결과를 보여 준다. `n < parts_requested` 면 "짧게 읽어 정확도가 낮을 수 있다"고 알린다.

**녹음 저장 (2026-10-09~)**: NPU 서버는 실사용 오판 분석을 위해 들어오는 녹음과 판정 결과를 저장한다(서버 안 접근 제한 폴더). 응답에 요청 번호 `rid` 가 붙으니, 이상한 결과는 `rid` 로 알려 준다.

## 0. 기존 `/predict` 연동에서 바꿀 것

이미 `POST /predict`(파일 1개)로 붙여 둔 경우, 바꿀 것은 아래 다섯 가지다.

| | 기존 `/predict` | 새 `/predict_long` |
|---|---|---|
| 주소 | `POST /predict` | `POST /predict_long` |
| 요청 필드 | `audio` | `audio` + `parts` (= 화면의 문장 수 1 · 3 · 5) |
| 판정에 쓰는 길이 | 앞 12초만 | 앞 60초까지 문장 수만큼 나눠 합산 |
| 녹음 저장 | 품질 분석용으로 저장한다(2026-10-09~, `consent` 와 관계없음) | 품질 분석용으로 저장한다(2026-10-09~) |
| 응답 | `top5` · `native` · `low_confidence` … | **`top5` · `native` · `low_confidence` 는 같다.** `n` · `parts_requested` · `voiced_sec` · `per_part` 가 더해진다 |

- **문장(글)은 프론트에서 자유롭게 바꿔도 된다.** 모델은 문장 내용을 받지 않고 억양만 본다.
  - 다만 문장 수와 길이가 정확도를 정한다. 1문장은 약 5초, 3문장은 약 15초, 5문장은 약 25초를 읽게 한다(3장).
- **3문장 글을 그대로 `/predict` 로 보내도 결과는 나온다.** 하지만 앞 12초만 판정해 정확도가 약 80% 다. `/predict_long` 으로 3구간 합산하면 83% 다.

## 1. 서버 주소

| 서버 | 주소 | 용도 | 상태 |
|---|---|---|---|
| **NPU 서버 · 서울 직통 (권장)** | 서버 담당자에게 따로 받는다(웹·앱 서버 환경변수로만 보관) | **운영(웹·앱 서버에서 호출)**. 토큰 필요. 동시 처리 8개 | 사용 가능(2026-10-05). 3문장 왕복 p50 약 0.68초 |
| NPU 서버 · Funnel (예비) | https://<NPU-funnel-주소> | 예비 경로와 테스트 화면 `/multi`. 토큰 없음 | 사용 가능. 직통보다 약 0.3초 느리다 |
| GPU 데모 | https://<GPU-funnel-주소>:8443 | 개발·테스트용 예비 서버. 동시 처리 2개 | 사용 가능. API 동일 |

- **주소는 코드에 박지 말고 설정값(환경 변수 등)으로 둔다.** 개발 중에는 GPU 데모, 운영에서는 NPU 를 쓴다. 두 서버의 API 는 같다.
- **서울 직통 주소는 토큰이 필요하다.**
  - 헤더는 `X-API-Key: <토큰>` 또는 `Authorization: Bearer <토큰>` 이다.
  - `/health` 만 토큰 없이 열린다(연결을 미리 열 때 쓴다).
  - 토큰과 주소는 **웹·앱 백엔드의 환경변수에만** 두고, 화면 코드·문서·저장소에는 적지 않는다.
- **Funnel 예비 주소와 GPU 데모는 인증이 없다.**
- **서버는 예고 없이 재시작될 수 있다(보통 1분 이내).** 재부팅이나 비정상 종료 때는 자동으로 다시 뜬다. 재시도 1회와 "잠시 후 다시" 안내를 넣는다.

## 2. API — `POST /predict_long`

### 요청 (`multipart/form-data`)

| 필드 | 필수 | 설명 |
|---|---|---|
| `audio` | 필수 | 녹음 파일 1개. 형식은 webm(Opus) · m4a/mp4(AAC) · wav · mp3 · ogg 등 ffmpeg 가 읽는 형식이면 된다. 최대 8 MB 이고, 앞 60초만 쓴다 |
| `parts` | 선택 | 나눌 구간 수 = 화면의 문장 수(1 · 3 · 5). 1~10, 기본 3 |

### 서버가 하는 일

1. 16 kHz 모노로 바꾸고 앞 60초를 쓴다.
2. 같은 길이로 `parts` 구간으로 나눈다.
   - 구간이 3초보다 짧아지면 구간 수를 줄인다. 예: 3문장인데 5초면 1구간.
   - 구간이 12초를 넘으면 구간 수를 늘린다. 예: 1문장인데 20초면 2구간.
3. 말소리가 1초 미만인 구간(긴 쉼)은 건너뛴다.
4. 구간마다 판정한 뒤 합친다(log 확률 평균). 한국인 원어민 판정 보정을 적용한다.
5. 녹음과 판정 결과를 품질 분석용으로 저장한다(2026-10-09~). 응답에 요청 번호 `rid` 를 붙인다.

### 응답 200 (실제 응답 · 베트남 화자가 3문장을 이어 읽은 20초 녹음)

```json
{
  "n": 3,
  "parts_requested": 3,
  "sec": 20.57,
  "voiced_sec": 19.7,
  "top5": [
    {
      "label": "Vietnam",
      "prob": 0.998
    },
    {
      "label": "Indonesia",
      "prob": 0.0019
    },
    {
      "label": "Thailand",
      "prob": 0.0001
    },
    {
      "label": "Cambodia",
      "prob": 0.0
    },
    {
      "label": "China",
      "prob": 0.0
    }
  ],
  "per_part": [
    {
      "label": "Vietnam",
      "prob": 0.9857,
      "start": 0.0,
      "end": 6.9
    },
    {
      "label": "Vietnam",
      "prob": 0.999,
      "start": 6.9,
      "end": 13.7
    },
    {
      "label": "Vietnam",
      "prob": 0.9994,
      "start": 13.7,
      "end": 20.6
    }

  "gate_korea": 9.056154522113502e-05,
  "native": false,
  "low_confidence": false,
  "encode_ms": 96,
  "total_ms": 258
}
```

| 필드 | 뜻 |
|---|---|
| `n` | 실제로 판정에 쓴 구간 수 |
| `parts_requested` | 요청한 구간 수(`parts`) |
| `sec` / `voiced_sec` | 녹음 길이(최대 60) / 그중 말소리 길이, 초 |
| `top5` | 합산 결과 1~5위. `label` 은 영어 국가명(부록 A), `prob` 는 0~1 |
| `per_part` | 구간별 1위와 구간 시각(`start`, `end` 초). 화면에 안 보여 줘도 된다 |
| `native` | 1위가 `Korea` 다 = 한국어 원어민으로 판정했다 |
| `low_confidence` | 외국인 판정인데 1위 확률이 0.45 미만이다. "확신이 낮다"는 안내를 권장한다 |
| `gate_korea` | 한국인 판정 보정 모델의 Korea 확률(디버그용) |
| `encode_ms` / `total_ms` | 모델 계산 시간 / 서버 전체 처리 시간(ms) |
| `rid` | 요청 번호(2026-10-09~). 오류 응답에도 붙는다. 이상한 결과를 서버 담당에게 알릴 때 이 번호를 같이 준다 |

**`n < parts_requested` 인 경우**: 녹음은 길어도 중간에 말을 멈춘 경우다. 이때 정확도는 1문장 수준으로 떨어진다(5장). 결과와 함께 "글을 끝까지 읽으면 더 정확하다"고 안내한다.

### 오류 (본문 `{"error": "...", "code": "..."}`)

| HTTP | `code` | 뜻 | 권장 안내 문구 |
|---|---|---|---|
| 400 | `too_short` | 0.5초 미만 | 녹음이 너무 짧아요. 글을 끝까지 읽어 주세요. |
| 400 | `no_speech` | 말소리가 없음(무음이거나 너무 작음) | 목소리가 잘 안 들려요. 마이크를 가까이 하고 다시 녹음해 주세요. |
| 400 | `decode_failed` | 오디오가 아니거나 깨진 파일 | 녹음을 읽지 못했어요. 다시 녹음해 주세요. |
| 400 | `too_large` | 8 MB 초과 | 녹음이 너무 길어요. 다시 녹음해 주세요. |
| 422 | — | `audio` 필드 없음(개발 오류) | — |
| 500 | `server_decoder` | 서버 설정 문제 | 잠시 후 다시 시도해 주세요. |
| 401 | `unauthorized` | 서울 직통 주소에서 토큰이 없거나 틀림(설정 오류) | 잠시 후 다시 시도해 주세요. (서버 로그로 확인) |

## 3. 화면 흐름 (참고 구현: https://<GPU-funnel-주소>:8443/multi)

- **문장 수**: 1 · 3 · 5 중에서 고른다. 기본은 3.
  - 문장이 많을수록 정확하고, 대신 오래 읽어야 한다(5장 표).
- **글**: 부록 B 의 이야기 8개(각 5문장) 중 하나의 **앞 N문장**을 한 단락으로 보여 준다.
  - 문장을 바꿔도 되지만, 너무 짧은 문장(인사말 등)은 피한다. 짧을수록 정확도가 떨어진다.
- **녹음 길이**:

| 문장 수 | 목표 | 최소 (이보다 짧으면 판정하지 않고 다시 읽게) |
|---|---|---|
| 1 | 5초 | 3초 |
| 3 | 15초 | 9초 |
| 5 | 25초 | 15초 |

- 녹음은 최대 60초에서 자동으로 멈추게 한다.
- **결과**
  - 1위와 확률, 그리고 5위까지 막대를 보여 준다. 정답이 5위 안에 있을 확률이 1위 정답보다 훨씬 높다.
  - `low_confidence`, `n < parts_requested` 이면 안내 문구를 함께 보여 준다.
  - `native: true` 면 "한국어 원어민 같아요" 같은 표현을 쓴다.
- **표현**: 국적을 단정하기보다 "억양이 가장 가까운 나라"로 보여 주는 편이 정확하다(5장 나라별 차이).

## 4. 녹음 설정

**웹 (브라우저)**
- **https 에서만 마이크가 켜진다**(localhost 제외).
- `getUserMedia({ audio: true })` 를 기본값 그대로 쓴다. 정확도는 이 설정으로 쟀다.
- `MediaRecorder` 형식은 `isTypeSupported` 로 고른다.
  - Chrome · Android 는 `audio/webm;codecs=opus`, Safari · iOS 는 `audio/mp4`.
- 녹음이 끝나면 마이크 트랙을 `stop()` 한다. iPhone 은 마이크가 켜진 채로 재생하면 소리가 수화기 쪽으로 작게 나온다.
- **웹 페이지가 브라우저에서 직접 부르려면 서버에 그 웹 도메인이 등록돼 있어야 한다(CORS).**
  - 등록하지 않은 도메인은 브라우저가 응답을 막는다.
  - **NPU 에는 로컬 개발 주소가 등록돼 있다**: `http://localhost:3000` · `http://localhost:5173` (127.0.0.1 도 같다).
  - **운영 웹 도메인은 알려 주면 등록한다**(서버 재시작 1분). GPU 데모 서버에는 아직 CORS 를 등록하지 않았다.
  - 웹 백엔드(서버)를 거쳐 부르거나 앱(iOS · Android)에서 부를 때는 CORS 가 필요 없다.

**앱 (iOS · Android)**
- 모노, 16 kHz 이상(44.1 · 48 kHz 그대로 괜찮다), AAC(m4a) 64 kbps 이상이나 WAV(16-bit PCM)면 된다.
- 앞뒤 무음 정리와 16 kHz 변환은 서버가 한다. 녹음을 따로 자르거나 가공할 필요는 없다.

## 5. 정확도 (실제 서비스와 같은 처리 기준)

| 문장 수 | 1위 정답 | 5위 안 정답 | 녹음 길이(중앙) |
|---|---|---|---|
| 1 | 73% | 94% | 약 7초 |
| 3 (한 번에 읽기 → 3구간) | 83% | 97% | 약 17초 |
| 5 (한 번에 읽기 → 5구간) | 85% | 98% | 약 28초 |

- **측정 조건**
  - 학습에 쓰지 않은 외국인 약 1,000명(36개국)의 AIHub 웹마이크 녹음이다. 화자 1명 = 1표로 셌다.
  - 한 번에 읽는 방식은 같은 문장들을 이어 붙여 재현했다. 문장을 따로 녹음해 합산한 것과 정확도가 같았다.
- **한국인 원어민 77명은 100% 한국**으로 나왔다. 외국인을 한국인으로 잘못 판정하는 비율은 2~3% 다.
- **짧게 읽으면 떨어진다.** 1구간으로 판정할 때 4초 미만은 64%, 4~5.5초는 74%, 9~12초는 80% 다.
- **나라별 차이가 크다**(`tasks/nationality-classification/results/22_국가별_성능_정리.md`).
  - 잘 맞히는 나라: 베트남 · 일본 · 인도네시아 · 중국 · 프랑스 · 스페인 · 튀르키예 등. 3문장이면 대부분 90% 를 넘는다.
  - 약한 나라: 영국 · 홍콩 · 콜롬비아 · 인도 · 불가리아 · 말레이시아.
  - 같은 모국어 나라끼리 헷갈린다. 예: 중남미 → 스페인, 영어권끼리, 튀르키예어를 쓰는 불가리아인 → 튀르키예.
  - 칠레 · 키르기스스탄 · 네팔 · 파키스탄은 학습 데이터가 거의 없어 거의 맞히지 못한다.
  - 방글라데시 · 에티오피아 · 르완다 · 잠비아는 시험 데이터가 없어 성능을 모른다.
- **실제 폰·부스 녹음은 다를 수 있다.** 마이크와 소음 조건이 달라서다.

## 6. 예제 코드

**curl**

```bash
# 개발: GPU 데모 · 운영: https://<NPU-funnel-주소>
curl -X POST https://<GPU-funnel-주소>:8443/predict_long -F "audio=@reading.m4a" -F "parts=3"
```

**웹 (JavaScript)**

```js
const API = BASE_URL + '/predict_long';   // BASE_URL: 개발 https://<GPU-funnel-주소>:8443 · 운영 https://<NPU-funnel-주소>

// 녹음: start() 뒤 사용자가 다 읽으면 stop()
const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
const mime = ['audio/webm;codecs=opus', 'audio/mp4'].find(t => MediaRecorder.isTypeSupported(t)) || '';
const rec = new MediaRecorder(stream, mime ? { mimeType: mime } : undefined);
const chunks = [];
rec.ondataavailable = e => e.data.size && chunks.push(e.data);
rec.onstop = () => stream.getTracks().forEach(t => t.stop());   // 마이크 끄기 (iPhone 재생 음량 문제)
rec.start();

// 판정: parts = 화면의 문장 수(1·3·5). 녹음 길이가 최소(3·9·15초)보다 짧으면 부르지 말고 다시 읽게 한다
async function judge(blob, parts) {
  const fd = new FormData();
  fd.append('audio', blob, blob.type.includes('mp4') ? 'reading.m4a' : 'reading.webm');
  fd.append('parts', String(parts));
  const r = await fetch(API, { method: 'POST', body: fd });
  const j = await r.json();
  if (!r.ok) throw j;                         // j.code: too_short · no_speech · decode_failed · too_large · server_decoder
  return j;                                   // j.top5[0].label · j.n < j.parts_requested 면 "짧게 읽음" 안내
}
```

**iOS (Swift · URLSession, iOS 15+)**

```swift
func judge(fileURL: URL, parts: Int, baseURL: String) async throws -> Data {   // baseURL: 개발 GPU 데모 · 운영 NPU
    var req = URLRequest(url: URL(string: baseURL + "/predict_long")!)
    req.httpMethod = "POST"
    let boundary = UUID().uuidString
    req.setValue("multipart/form-data; boundary=\(boundary)", forHTTPHeaderField: "Content-Type")
    var body = Data()
    func add(_ s: String) { body.append(s.data(using: .utf8)!) }
    add("--\(boundary)\r\nContent-Disposition: form-data; name=\"parts\"\r\n\r\n\(parts)\r\n")
    add("--\(boundary)\r\nContent-Disposition: form-data; name=\"audio\"; filename=\"reading.m4a\"\r\nContent-Type: audio/mp4\r\n\r\n")
    body.append(try Data(contentsOf: fileURL))
    add("\r\n--\(boundary)--\r\n")
    let (data, _) = try await URLSession.shared.upload(for: req, from: body)
    return data                                    // JSONDecoder 로 해석. 400 이면 code 확인
}
```

## 7. 운영 · 보안 참고

- **인증이 없다.** 공개 주소라 남용이 걱정되면 토큰을 붙일 수 있다(발음 평가 NPU 서버와 같은 방식).
- **녹음 저장 (2026-10-09 변경)**
  - NPU 서버는 `/predict_long` · `/predict` 로 들어오는 녹음 전부와 판정 결과를 저장한다. 실사용 오판(예: 특정 국적이 다른 나라로 나오는 문제)을 분석하기 위해서다.
  - 저장 위치는 서버 안의 접근 제한 폴더다. 보관 기간은 정해지는 대로 알린다.
  - 사용자 안내(개인정보 처리방침 등)에 "녹음이 품질 개선을 위해 보관될 수 있음"을 넣는다.
  - 새로 붙일 때는 **1문장도 `/predict_long` (`parts=1`)** 을 쓴다.
- **처리 시간** (업로드 시간 별도)
  - NPU 는 구간마다 12초 고정 모델을 부른다. 1구간 약 0.25초, 3구간 약 0.7초, 5구간 약 1초다.
  - GPU 데모는 0.2~0.5초다.
  - 요청 제한 시간은 15초 이상으로 둔다.
- **다른 엔드포인트**
  - `/predict_multi` 는 문장마다 따로 녹음한 파일 여러 개를 받는다.
  - `/predict` 는 파일 1개의 앞 12초만 본다.
  - 정확도는 `/predict_long` 과 같거나 낮아서, 새로 붙일 때는 권하지 않는다.
