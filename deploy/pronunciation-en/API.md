# 영어 발음 평가 API (한국어 API와 같은 형식)

한국인 학습자의 **영어** 문장 발음을 채점한다. **요청·응답 형식이 한국어 API(`sent.eval.kr`)와 같다.**
앱에서는 아래 셋만 바꾸면 된다.

- 주소
- `refText`에 넣는 영어 문장
- 음소 기호 표시

```
한국어:  http://<서버>:8932/sent.eval.kr
영어:    http://<서버>:8952/sent.eval        (같은 처리: /sent.eval.promax · /sent.eval.en)
```

## 1. 한국어 API와 다른 점

**필드 이름, 위치, 0→null 규칙, 오류 코드는 모두 같다.** 다른 것은 다음과 같다.

| | 한국어 | 영어 |
|---|---|---|
| `phonemes[].alpha`, `actual` | KoG2P 기호(`k0`) | ARPAbet 소문자, 강세 숫자 없음(`th`, `iy`) |
| 사람이 읽는 표기 | `alpha_jamo`, `actual_jamo`(한글) | `alpha_ipa`, `actual_ipa`(IPA: `θ`, `iː`) |
| `position` | 초성, 중성, 종성 | 모음, 자음 |
| `errorType` | 초성, 종성, 모음오류, 경음화 … | 모음오류, 자음오류, 음운탈락. 한국인 대표 오류면 ★`errorRule`(`f_p` …)과 ★`errorHint`(`"f → p"`)도 붙는다 |
| 지적 규칙 | 받아쓰기가 다르고 **점수 < 60** | 점수 < 문턱, **또는** 한국인 대표 오류 자리에서 그 한국인식 소리로 들리고 근거가 충분할 때(§3) |
| 덧붙인 소리 | `words[].inserted` | 지금은 내보내지 않는다(정밀도가 낮아서, §3) |
| `comprehensibility` | 세션에서만 나옴 | 항상 `null`(영어에는 없음) |
| `rhythm` | 이해 가능성 | 운율(prosody) 예측. ⚠️ 유창성과 상관 0.98이라 사실상 같은 값이다(§5) |
| 추가 필드(모르면 무시) | — | `result.integrity`, `speed`, `pause_count` · `words[].scores`, `span` · `phonemes[].phoneme`, `sound_like`, `span`, `stress_mark`(사전 강세이며 들은 강세가 아니다), `actual_src`, `errorRule`, `errorHint` |

추가 필드는 SpeechSuper 영어(`sent.eval.promax`)와 같은 이름이다.
**`readType`은 우리 코드(0~4)를 쓴다.** SpeechSuper 영어의 코드와 숫자가 다르므로 섞지 말 것.

## 2. 요청

한국어 API와 같다. 둘 중 아무거나 쓰면 된다.

**① SpeechSuper 방식.** multipart에 오디오와 JSON 덩어리를 넣는다. JSON 필드 이름은 무엇이든 된다.

```bash
curl -F 'text={"start":{"param":{"app":{"userId":"u1"},"request":{"coreType":"sent.eval.promax","refText":"I think the weather is nice today.","tokenId":"tok-1"}}}}' \
     -F audio=@rec.wav  http://<서버>:8952/sent.eval
```

**② 간편 방식.**

```bash
curl -F audio=@rec.wav -F 'refText=I think the weather is nice today.' -F tokenId=tok-1  http://<서버>:8952/sent.eval
```

- 읽는 값은 `refText`, `tokenId`(→ `recordId`로 돌려줌), `userId` 셋이다.
- 오디오는 **WAV 16 kHz 1채널 16bit를 권장**한다. 그대로 읽어 가장 빠르다.
  webm, mp3, m4a, 다른 표본율도 받는다(서버에서 변환하며 수십~150 ms가 더 든다).
- **30초까지 채점한다.** 넘는 부분은 버린다.
- `refText`의 숫자("3", "1,000", "3.14", "50%", "$5"), 축약형("don't", "can’t"), 악센트("café")도 받는다.
  - 화면의 단어는 원문 철자 그대로 돌려준다.
  - 문장부호는 무시한다. 영어가 아닌 글자(한글 등)는 빠진다.
- 인증: 서버를 `--token`으로 띄우면 `Authorization: Bearer <토큰>`, `X-API-Key`, 폼 `token`, `?token=` 중 아무거나로 보낸다.

## 3. 응답

아래 값은 형식 설명용 예시다.

```jsonc
{
  "refText": "We call it bear",
  "recordId": "tok-1",
  "result": {
    "overall": 77,            // 0.6·pronunciation + 0.2·fluency + 0.2·rhythm (한국어 API 와 같은 비율)
    "pronunciation": 75,      // 한국인 학습자 사람 '조음' 점수(AIHub 037, 5점 만점) 예측 — 사람 4점 ≈ 80
                              //   (8952 는 2026-10-14부터 표시 눈금 gentle: 40 + 0.6×이 값 → 사람 3·4점 발화 평균 80 · 87)
    "fluency": 82,            // 속도·쉼 기반 유창성 예측(speechocean762, 0~10) ×10
    "rhythm": 77,             // 한국인 학습자 사람 '운율' 점수(AIHub 037) 예측 — 눈금은 pronunciation 과 같다
    "comprehensibility": null,
    "integrity": 100,         // 읽은 단어 비율(%)
    "speed": 188,             // 분당 단어 수
    "pause_count": 0,         // 단어 사이 0.3초 이상 쉼
    "words": [
      { "word": "bear", "readType": 2, "score": 71,
        "scores": {"overall": 71, "pronunciation": 71},
        "span": {"start": 156, "end": 184},          // 10 ms 단위
        "phonemes": [
          { "alpha": "b",  "alpha_ipa": "b", "position": "자음", "pronunciation": 99,
            "actual": "b", "actual_ipa": "b", "phoneme": "b", "sound_like": "b", "span": {...} },
          { "alpha": "eh", "alpha_ipa": "ɛ", "position": "모음", "pronunciation": 94, "stress_mark": 1,
            "actual": "ae", "actual_ipa": "æ", "errorType": "모음오류",       // ← 틀린 곳(한국인 대표 오류)
            "errorRule": "eh_ae", "errorHint": "ɛ → æ", "actual_src": "pair" },
          { "alpha": "r",  "alpha_ipa": "ɹ", "position": "자음", "pronunciation": 30,
            "actual": null, "actual_ipa": null, "sound_like": "-", "errorType": "음운탈락" }
        ]
      }
    ]
  },
  "_meta": { ... }            // 기준 설명. 무시해도 된다
}
```

### 틀린 곳 표시 — `errorType`이 있는 자리만 (규칙 v2, 2026-10-06)

다음 둘 중 하나면 `errorType`이 붙는다.

1. **음소 점수가 문턱 아래**일 때
   - 현재 문턱은 **77.3**이다. 맞게 발음한 소리 중 **3%만** 걸리게 잡았다(speechocean762 학습 데이터, 화자 단위 교차 예측).
   - 현재 값은 `_meta.flag_rule`에 있다.
2. **한국인 대표 오류**일 때
   - 대상: θ→s, f→p, v→b, r↔l, z→s, ɪ↔iː, ɛ↔æ, oʊ→ɔ 등
   - 조건: 그 자리에서 받아쓰기가 그 한국인식 소리였고, 근거(우도 차)가 오류 종류별 문턱을 넘을 때
   - 점수와 상관없이 붙는다. 이때 `errorRule`(예: `f_p`), `errorHint`(예: `"f → p"`), `"actual_src": "pair"`가 함께 온다.
   - 화면에서는 **"f를 p로 발음했어요"** 처럼 보여 주면 된다.
   - **ð→d는 판정하지 않는다.** 맞게 읽은 ð와 d로 읽은 ð가 소리로 구분되지 않는다.

`actual`(들린 소리)과 `actual_src`:

| actual_src | 뜻 | 화면 |
|---|---|---|
| `pair` | 한국인 대표 오류로 판정한 소리 | "f를 p로 발음했어요" |
| `asr` | 받아쓰기로 들린 소리 | 들린 소리로 보여 줘도 된다 |
| `unclear` | 점수는 낮은데 무엇으로 냈는지 근거가 없다. `actual`은 표준 기호이고 `sound_like`는 `"?"` | **"부정확"** 으로만 표시하고, 들린 소리는 보여 주지 말 것 |

- `uncertain: true`
  - 뜻: 한국인 대표 오류 소리로 들렸지만 근거가 문턱 아래라 지적하지 않은 자리다.
  - 지적하지 말고, 필요하면 "~처럼 들렸을 수 있어요"처럼 옅게 표시한다.
  - 대표 오류가 아닌 불일치는 보여 주지 않는다. 예를 들어 맞게 읽은 the의 ð→d다. 근거가 약해 틀린 힌트가 되기 때문이다.
- **모음 삽입**(book → 부커)은 지금은 내보내지 않는다(`words[].inserted` 없음, `readType` 4 없음).
  - 받아쓰기의 삽입 정밀도가 약 0.27로 낮아서 맞게 읽은 단어에도 붙었다.
  - 검증 장치를 만든 뒤 다시 켠다.
- `readType`의 뜻은 한국어와 같다: 0 정상, 1 누락(모든 소리를 빠뜨림), 2 대치, 3 오독(점수 20 미만), 4 삽입.
  오독 단어의 `score`는 한국어처럼 `null`(0점)이고, 문장 `pronunciation` 평균에도 0으로 들어간다.
- `span`은 **보낸 녹음 기준** 시각(10 ms 단위)이다. 서버가 앞뒤 무음을 잘라 채점해도 원래 녹음의 위치로 돌려준다.

### 0점은 `null`

한국어 API와 같은 규칙이다. 모든 점수 칸은 0 대신 `null`로 온다. 평균은 0을 넣어 계산한 뒤에 바꾼다.

## 4. 오류 응답 (한국어 API와 같은 규칙 · 영어에만 있는 코드는 ★)

| HTTP | code | 뜻 |
|---|---|---|
| 401 | `unauthorized` | 토큰이 없거나 틀림 |
| 400 | `no_audio` | 오디오 파일이 없음(`audio` 필드를 먼저 보고, 없으면 첫 파일) |
| 400 | `no_reftext` | `refText`가 비었거나 읽을 영어 단어가 없음 |
| 400 | `too_short` | 녹음이 0.3초 미만이거나, **문장에 비해 녹음이 너무 짧아** 맞춰 볼 수 없음 |
| 400 | `low_speech` | 앞뒤 무음을 뺀 녹음에서 말소리가 0.3초 미만이거나 10% 미만 — **다시 녹음하도록 안내** |
| 400 | `decode_failed` | 오디오를 해석하지 못함 |
| 400 | ★`reftext_too_long` | 단어 60개 또는 음소 240개 초과 — 문장을 나눠 보낼 것 |
| 503 | ★`server_busy` | 채점 중 서버 자원 부족(GPU 메모리 등) — 잠시 뒤 다시 |

- 영어는 한 단어 문장("Hello")도 받으므로 말소리 기준이 한국어(1.0초)보다 낮다.
- 녹음 끝을 늦게 눌러 뒤 무음이 길어도 거절하지 않는다.
  서버가 앞뒤 무음을 0.5초만 남기고 잘라서 채점한다.

## 5. 점수를 얼마나 믿을 수 있나

**① 중국인 화자 데이터 기준**(speechocean762 test 2,500문장, 사람 점수와의 상관)

| 항목 | 지금(한국인 기준 점수기) | 이전(speechocean762 점수기) | 공개 모델 GOPT |
|---|---|---|---|
| `overall` | 0.732 | 0.756 | 0.742 |
| `fluency` | 0.783 | 0.783 | 0.753 |
| `rhythm` | 0.746 | 0.761 | 0.760 |
| `pronunciation` | 0.706 | 0.640 | — |
| 단어 `score` | 0.618 | 0.618 | 0.533 |
| 음소 `pronunciation` | 0.655 | 0.655 | 0.612 |

- 오차가 ±0.05 정도라 **GOPT와 같은 수준**으로 본다. 한국인 기준으로 바꾼 뒤에도 그대로다.
- 사람 평가자끼리의 일치도는 음소 0.555, 단어 0.602, 문장 0.675다.

**② 한국인 기준(AIHub 037 한국인 학습자 882명 · 2만 6,444문장, 사람 점수와의 상관) — 2026-10-10 재보정**

문장 점수를 037 사람 점수(조음·운율, 평가자 2명 평균)로 다시 맞췄다. 수치는 모두 **학습에 없던 화자**에서 쟀다(화자 5겹).

| 항목 | 이전(speechocean762 기준) | **지금** |
|---|---:|---:|
| `pronunciation` vs 사람 조음 — 문장 1개 | 0.41 | **0.61** |
| 〃 — 화자도 문장도 처음 | 0.46 | **0.59** |
| 〃 — 같은 화자 5문장 평균 | 0.63 | **0.83** |
| `overall` vs 사람 조음·운율 평균 — 문장 1개 | 0.52 | **0.64** |
| `rhythm` vs 사람 운율 — 문장 1개 | 0.49 | **0.64** |
| `pronunciation` 분포 | 96 ± 3 | **76 ± 18** |

- 사람 조음 점수별 `pronunciation` 평균: 1점 37 · 2점 51 · 3점 66 · 4점 79 · 5점 89.
  이전에는 91~97 사이에 다 몰려 있었다.
- **표시 눈금 gentle**(서버 `--display-scale gentle`, 2026-10-14 제품 요청으로 8952 기본): 발음·운율 = `40 + 0.6 × 위 값`.
  같은 표로 1점 62 · 2점 71 · 3점 80 · 4점 87 · 5점 93, 분포 76 ± 18 → 86 ± 11. 상관(판별력)은 같다.
- `fluency`는 037에 유창성 라벨이 없어 그대로다(speechocean762 예측 ×10).
- 그래도 **문장 1개 점수는 상관 0.6 수준**이다. 실력 판단은 여러 문장의 평균으로 할 것(5문장이면 0.83).
- **잠근 외부 검증**(037 SPK 말하기 평가 — 학습에 없던 화자 879명 · 자유 발화 5,188건, 사람 점수는 말하기 전반 1개):
  `overall` 0.51 → **0.57**(화자 평균 0.71 → **0.77**), `pronunciation` 0.42 → **0.57**(0.62 → **0.78**).
  잣대가 달라 절대값보다 이전 대 지금으로 읽는다. 다섯 과제 모두 올랐다.
- `rhythm`은 사람 운율 점수 예측이지만, 037 사람 점수에서 조음과 운율이 거의 같이 움직여 `pronunciation`과 상관이 0.97이다.
  이전에는 `fluency`와 0.98이었다. 강세·리듬·억양을 따로 재지는 않는다.

**③ 틀린 곳 표시(`errorType`) — L2-ARCTIC 한국인 4명, 사람 주석, 단어 단위**

| | 이전 규칙(v1) | 지금(v2) |
|---|---|---|
| 지적한 단어 중 실제 오류 | 68% | 66% |
| 실제 오류 단어 중 지적한 비율 | 8% | **16%** |
| 맞게 읽은 단어를 지적한 비율 | 1.5% | 3.4% |
| 맞게 읽은 소리에 무엇이든(지적·힌트) 붙은 비율 | 3.5% | **1.8%** |

오류 종류별로, 사람이 들은 오류를 **같은 소리로** 지적한 비율이다.

| 오류 | v1 | v2 |
|---|---|---|
| θ→s | 11% | 50% |
| r→l | 14% | 43% |
| v→b | 0% | 37% |
| ɛ→æ | 1% | 29% |
| ɪ→iː | 0% | 23% |
| ɝ→ʌ | 7% | 17% |
| oʊ→ɔ | 6% | 14% |
| z→s | 1% | 6% |
| ð→d | 판정 안 함 | 판정 안 함 |

- L2-ARCTIC은 규칙과 모델을 고르는 데에도 썼다(개발용). 화자도 4명(상급)뿐이다.
  실제 앱 사용자(10대, 초급 포함)에서는 달라질 수 있다.
- `stress_mark`는 사전에 적힌 강세다. 학습자가 실제로 강세를 어디에 뒀는지는 아직 재지 않는다.
- `rhythm`은 `pronunciation`과 상관이 0.97이라(② 참고) 별개 정보가 거의 없다. 강세, 리듬, 억양은 아직 평가하지 않는다.
