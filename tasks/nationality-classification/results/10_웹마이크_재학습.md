## 방법 — 배포 모델에서 출발하고, 옛 지식은 자기 증류로 지킨다

2B 교사가 이 서버에 없어서 **배포 모델 자신**을 교사로 썼다. 목적은 성능을 끌어올리는 것이 아니라,
새 데이터를 배우는 동안 옛 지식(505 · 한국어 · 041/043)을 잃지 않는 것이다.

1. **배포 ONNX → PyTorch 복원**(`scripts/export/onnx_to_torch_kd_encoder.py`)
   - 학습 체크포인트가 이 서버에 없어서 ONNX 에서 가중치를 되돌렸다.
   - 상수 접기로 이름을 잃은 가중치는 소비 노드의 위치로 모듈을 정했다.
   - 위치 → 모듈 대응은 **KD 때 동결된 0~11층이 원본 300m 과 값이 같다는 점**으로 확정했다.
   - 원본과 달라진 텐서는 12~17층뿐이었고, ONNX 와의 출력 차이는 최대 1e-4 였다.
   - 되돌린 체크포인트를 다시 수출하면 배포 ONNX 와 실발화 top-1 이 15/15 일치했다.
2. **교사 신호**(`experiments/webmic_kd_signals.py`): 학생과 같은 입력(앞 8초)에서 logits · pooled · margin 을 뽑았다.
3. **학습**(`experiments/webmic_kd_train.py`): 층 12~17(75.6M 파라미터)만 학습했다.
   - 라벨 행의 손실: `(1−w)·CE + w·T²·KL`, `w = 0.3·margin·[교사 top1 == 정답]`.
     교사가 틀린 행(040 미국 → 유럽 국가 등)은 증류를 끄고 정답만 배운다.
   - 라벨 없는 131 행의 손실: `T²·KL + 0.5·(1 − cos(학생 표현, 교사 표현))`.
   - 배치: 길이 버킷을 쓰고, 한 스텝에 작은 배치 4개를 묶는다.
   - 최적화: lr 1e-5 · cosine, **가중치 EMA 0.999**(평가와 저장 모두 EMA 가중치).
   - run3 에서 늘어난 22만 행은 교사 신호 없이 CE 만 썼다. 기존 신호는 `audio_path` 로 재사용했다(`--reuse_only`).

## 앱 입력 권장 — 발화 길이·포맷

같은 test 를 발화 길이로 나눈 문장·자유발화 top-5(배포 → 새)다. 길이보다 **문장이냐 단어냐가** 더 중요하다.

→ **4초 이상의 문장**을 말하게 하면 top-5 0.96 수준이다. 단어 하나는 0.5~0.6 이다.

업로드 포맷 영향. 문장 발화 3,000개(화자 778명)를 먼저 해당 포맷으로 인코딩한 뒤, 서버와 같은 방식으로 디코드했다.
차이는 같은 발화 쌍의 화자 부트스트랩 95% 구간이다.

| 업로드 포맷 | top-1 | top-5 | Δtop-1 | Δtop-5 |

| wav 16 kHz | 0.782 | 0.956 | — | — |
| m4a (AAC 64 kbps) | 0.775 | 0.954 | −0.007 [−0.016, +0.002] | −0.002 [−0.006, +0.002] |

→ 압축 포맷으로 올려도 유의한 차이가 없다. m4a 는 파이프로 못 읽는 경우가 있어서 AAC 스트림(ADTS)으로 대신 쟀다.
서버는 임시 파일로 디코드하므로 m4a 도 그대로 받는다.

- **131 라벨의 효과는 작다.** 웹 단어와 웹 문장 top-1 이 조금 올랐을 뿐이다.
  - 131 자체는 run3 와 같다. run3 가 이미 배포 모델(131 라벨로 학습됨)을 따라 배워 131 을 알고 있었기 때문이다.
  - run4 는 131 베트남어·미국 화자를 131 에서 한 번도 못 본 상태라 131 에서 떨어졌다(베트남 top-1 0.72, 미국 0.51).
    run5 에서 회복했다(0.91 · 0.89).
- **꼬리 국가는 거의 그대로다.** 웹 문장 top-5(run3 → run5):
  - 오른 국가: 미얀마 0.50 → 0.54, 이란 0.58 → 0.71, 몽골 0.88 → 0.89, 미국 0.94 → 0.95

- **131 test 수치는 모든 모델이 낙관적이다.** 배포 모델은 옛 split 으로 131 화자 약 80% 를 학습했고,
  나머지 모델은 모두 배포 모델에서 출발했다. 오염 없는 131 평가는 이 서버에서 할 수 없다.

  - 네팔(3명)은 0.43 이다.

## 주의

- **041·043 수치는 두 모델 모두 낙관적일 수 있다.**
  배포 모델은 옛 split 으로 041·043 화자의 약 80%를 학습했는데, 그 명단(`speaker_split.json`)이 이 서버에 없다.
  새 모델도 배포 모델에서 출발했으니 같은 영향을 받는다.
  **040·042 는 배포 모델이 본 적 없는 화자라 이 문제가 없다**(문장 top-5 0.940 · 0.975).
- **040~043 은 모두 온라인 녹음이고, 데이터셋마다 모국어권이 다르다**(040 영어권 · 042 중·일 …).
  녹음 조건과 국적 집합이 함께 바뀌므로, 앱 실녹음(휴대폰·주변 소음)에서의 정확도는 따로 재야 한다.
  다른 조건의 녹음인 131(휴대폰 앱)에서는 그룹 정확도가 유지됐다.
- **131 은 라벨이 없다.** 그래서 배포 모델과의 top-1 일치율(0.907, 기타 그룹 0.845)과,
  그룹명 기준 정확도(일본어 → Japan 등)로만 봤다. 131 기타(EX) 그룹 화자의 국적별 정확도는 알 수 없다.
- **꼬리 클래스**는 test 화자가 0~2명이라 클래스별 수치를 믿기 어렵다.
  해결책은 화자를 더 모으는 것뿐이다(README "이 트랙의 결론").
- **비음성 입력도 거절하지 않는다.** 잡음 게이트는 무음만 거른다.
  대역 제한한 합성 잡음을 넣으면 새 모델은 한 국적에 확률 0.99 이상을 준다(배포 모델도 마찬가지). VAD 가 필요하다.
