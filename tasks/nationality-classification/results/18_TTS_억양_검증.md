# 18 — 오픈소스 TTS 로 외국인 억양 한국어를 만들 수 있나 (2026-10-01)

**결론: 지금 수준으로는 약한 국가의 학습 데이터로 쓰기 어렵다.**

- **모국어 음성을 참조로 한국어를 생성하는 방식(새 화자를 만드는 실제 활용 방식)**
  - Chatterbox 는 억양 신호가 없다(lift 1.0).
  - Qwen3-TTS 도 신호가 약하다. 의도한 국가의 top-1 은 0.14 이고, 62% 가 한국인으로 판정된다.
- **실제 외국인 화자의 목소리를 그대로 복제해도 억양이 크게 약해진다.** 같은 사람·같은 문장 기준 top-1 이 실제 0.86 → 합성 0.19(Chatterbox) / 0.29(Qwen3-TTS) 로 떨어진다.
- **원인: 합성 음성이 한국어를 너무 정확하게 발음한다.** whisper 문자 오류율(CER) 중앙값이 실제 외국인 녹음 0.071, 합성 0.000 이다. 억양의 단서인 모국어 특유의 발음 오류가 사라진다.

## 1. 설정

- **TTS 모델** — 둘 다 한국어를 지원하고 로컬 A100 에서 돌렸다. 외부 API 는 쓰지 않았다.
  - Chatterbox Multilingual 0.1.7 (MIT).
  - Qwen3-TTS-12Hz-1.7B-Base (Apache-2.0). ICL 모드(참조 음성 + 참조 문장)로 썼다.
- **판정 모델**: `run_zeroth` (현재 최고 국적 모델).
- **조건 A — 시험 화자 복제**
  - 대상: 중국·일본·베트남·미국·인도네시아·러시아의 시험 화자 각 8명(학습에 없던 사람).
  - 각 화자의 한국어 녹음 1개를 참조로, 그 사람이 실제로 읽은 다른 문장 4개를 생성했다.
  - 같은 문장의 실제 녹음과 짝지어 비교했다(192쌍).
- **조건 B — 모국어 → 한국어**
  - FLEURS dev(CC-BY 4.0)에서 언어당 모국어 음성 8개를 참조로 골라, 한국어 문장 3개씩 생성했다(언어당 24개).
  - 대상: 위 6개국 + 약한 국가 4개(태국·말레이시아·인도·홍콩) + 한국어 원어민(대조군).
- **품질 확인**
  - whisper-large-v3-turbo 로 생성 음성을 받아 적어 문자 오류율을 냈다.
  - 길이가 비정상인 출력은 seed 를 바꿔 다시 생성했다(최종 0건).

## 3. 해석

- **억양의 핵심 단서가 합성 과정에서 사라진다.** 합성 음성은 원어민처럼 정확하게 발음한다.
- **음질(깨끗한 채널)만의 문제는 아니다.**
  - 똑같이 깨끗한 합성 음성인데도 한국으로 판정된 비율이 A 에선 6%, B 에선 48~62% 다.
  - 스튜디오에서 녹음한 외국인 낭독(505)도 top-1 0.90 으로 잘 맞힌다.
- **이 데이터를 약한 국가 학습에 넣으면 생길 수 있는 문제**
  - 억양 대신 "합성 음색 → 그 나라" 같은 지름길을 배울 수 있다.
  - 원어민처럼 들리는 음성을 외국 라벨로 가르치게 되어, 한국인 판정이 흔들릴 수 있다.

## 6. 추가 — Qwen3-TTS VoiceDesign (2026-10-18)

실제 화자를 복제하지 않고 **글 설명으로 새 목소리**를 만드는 VoiceDesign(`Qwen/Qwen3-TTS-12Hz-1.7B-VoiceDesign`, Apache-2.0)도 같은 방식으로 쟀다.

- 설명: 성별 · 나이 · 음색 · 속도 · 말투에 더해 "한국어를 제2언어로 배웠고 {약한/뚜렷한/강한} {모국어} 억양으로 말한다". Korea 는 원어민 설명.
- 41클래스 × 목소리 6 × 문장 4 = 984발화. 문장은 AIHub 131 낭독 문장(valid · test 화자가 읽은 문장 제외).
- 판정 `run_zeroth`, 문자 오류율 whisper-large-v3-turbo.
