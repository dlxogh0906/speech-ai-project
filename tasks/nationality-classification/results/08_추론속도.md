# 08 — 추론 속도 (2026-08-06)

서비스 탑재 판단용 실측. 6초 발화 · A100 80GB ×1 · CPU 16코어(AMD EPYC 7H12).

⚠️ **벤치마크는 단독 실행으로 재야 한다.** 여러 개를 동시에 돌렸다가 값이 4~25배
부풀려진 적이 있다(2B CPU 21,254 ms → 실제 1,832 ms). 아래는 전부 단독 실행 기준이다.

재현: `scripts/eval/bench_latency.py` · `bench_capacity.py` · `bench_batch_matrix.py`

## ① 발화 1건 응답 시간

| 모델 | 형식 | 장치 | 응답 | 실시간 배수 | 서비스 |
|---|---|---|--:|--:|:-:|
| 2B | 원본 | GPU | **25 ms** | 237배 | ✅ |
| 2B | 원본 | CPU | 1,832 ms | 3.3배 | ⚠️ 느림 |
| 300m | 원본 | GPU | **12.8 ms** | 467배 | ✅ |
| 300m | 원본 | CPU | 473 ms | 12.7배 | ✅ |
| **300m** | **ONNX** | **CPU** | **276 ms** | 21.8배 | ✅ **현재 배포** |
| 300m | ONNX | GPU | — | — | ❌ provider 없음¹ |
| KD | 원본 | GPU | **12.9 ms** | 464배 | ✅ |
| KD | 원본 | CPU | 444 ms | 13.5배 | ✅ |
| **KD** | **ONNX** | **CPU** | **285 ms** | 21.1배 | ✅ **신규 후보** |
| KD | ONNX | GPU | — | — | ❌ provider 없음¹ |

¹ `onnxruntime` 이 CPU 빌드다 — `get_available_providers()` 에 CUDA 가 없다.
GPU 로 돌리려면 `onnxruntime-gpu` 를 별도 설치해야 한다.

**ONNX 가 원본보다 1.7배 빠르다**(CPU 276 vs 473 ms). 그래서 배포는 ONNX 다.

**KD 는 현 배포본과 속도가 같다**(285 vs 276 ms) — 구조가 동일(300m 17층 절단)하다.
**정확도만 오르고 비용은 0이다.**

## ③ 배치 처리량 (GPU 최대 역량)

| 모델 | 장치 | 배치 128 | 배치 256 | GPU 메모리 (128 / 256) |
|---|---|--:|--:|--:|
| 300m | GPU | **344 건/초** (0.37초) | 58 건/초 ⚠️ | 17.1 / 33.5 GB |
| KD | GPU | **343 건/초** (0.37초) | 58 건/초 ⚠️ | 17.1 / 33.5 GB |
| 2B | GPU | 143 건/초 (0.89초) | 47 건/초 ⚠️ | 20.5 / 36.9 GB |
| 300m | CPU | 2.6 건/초 (50초) | 2.6 건/초 (99초) | — |
| KD | CPU | 2.6 건/초 (50초) | 2.5 건/초 (100초) | — |
| 2B | CPU | 0.7 건/초 (183초) | 0.7 건/초 (354초) | — |

**배치 256 에서 GPU 가 무너진다.** 발음 모델까지 네 모델 전부 47~58 건/초로 수렴한다.
구조도 과제도 다른데 같은 값이 나오는 걸 보면 모델이 아니라 **런타임 문제**다. 메모리는
33.5/80 GB 로 여유가 있어 용량 문제도 아니다. cuBLAS 워크스페이스 고갈이나 할당자
단편화로 추정하지만 **원인 확정은 못 했다.** → **배치는 128 이 상한이다.**

**300m/KD 가 2B 보다 2.4배 빠르다**(344 vs 143 건/초). 층이 17 vs 31 이라 당연하다.

**CPU 에서는 배치가 무의미하다.** 128 이든 256 이든 발화당 385~393 ms 로 같다.
코어가 이미 꽉 차서 묶어봐야 나눠 쓸 뿐이다.

## ④ ONNX 는 배치가 안 된다

```
배치 2 → INVALID_ARGUMENT : Got invalid dimensions
```

`batch=1` 고정으로 수출됐다. 위 배치표의 300m·KD 는 **원본 PyTorch** 기준이다.

**재수출할 이유는 지금 없다.** CPU 에서 배치가 무의미한 게 원본으로 증명됐고(128배
키워도 1.2배), 현재 ONNX 단건(3.6 건/초)이 PyTorch 배치(2.6 건/초)보다 이미 빠르다.
`dynamic_axes` 재수출이 의미 있는 건 **GPU 서빙으로 갈 때**이고, 그러려면
`onnxruntime-gpu` 설치가 같이 필요하다.
