# 27 — XLS-R 인코더 전체 미세조정: 300m vs 2B · 클래스 불균형 보정 (2026-10-20)

**결론: 모델을 키워도, 클래스 비율을 맞춰도 학습 화자 15명 이하인 "꼬리" 국가는 살아나지 않는다.**

- **병목:** 꼬리 국가는 클래스 비율이 아니라 학습 화자 수가 모자란다. 이미 1,600~3,800행씩 있지만 화자가 5~15명뿐이다.
- **2B:** 300m 과 같은 레시피로 학습한 2B(인코더 약 6배)는 전체 성능이 같다. 중간 국가(화자 16~100명)만 조금 낫고, 단어 발화는 조금 못하다.
- **불균형 보정:** 세 방법 모두 꼬리를 못 살렸다.
  - 행 균등(모든 클래스를 1,008행으로)은 중간 국가를 가장 크게 올리지만 머리·전체를 크게 잃는다.
  - 손실 가중(적은 클래스에 큰 손실 가중치)은 얻는 게 없다.
  - 사후 로짓 보정은 전체를 조금 내주고 국가 평균을 올리는 가장 싼 교환이다.
- **국가 평균 최고:** run_zeroth 를 빼면 **2B + 사후 보정**이다. 웹 문장 국가 평균 top-5 가 0.661 → 0.701 로 올랐다. 300m + 사후 보정(0.688)과는 차이가 작다.
- **run_zeroth:** 꼬리 성적이 훨씬 높지만, 출발 모델의 학습 목록이 없어 test 화자 누수를 배제할 수 없다(§5.4).

수치를 읽는 법:

- **시험지:** 모든 수치는 test 한 장(`test_koraug_zeroth.csv`, 19,680발화 · 1,390명)에서 나왔다.
  - test 화자는 학습에 쓰지 않았다.
  - test 는 체크포인트 선택에도, 보정값 결정에도 쓰지 않았다(둘 다 valid).
- **신뢰구간:** 95% 구간은 화자 부트스트랩 1,000회다. 시드는 모델마다 1개라, 학습 무작위성은 구간에 들어가지 않는다.
- **2B 는 최종이다.** valid 최고점이 끝까지 step 16,000 이었고, step 34,000 에서 멈췄다. 표는 그 체크포인트를 체인의 표준 평가(bf16 · 240초 배치)로 잰 값이다.
- **평가 정밀도:** 평가는 bf16 이다. 2B 를 fp32 로 다시 재도 집계는 거의 같다(웹 top-5 0.889 → 0.888). 발화 단위로는 흔들린다(§6).

- **이름:** 학습 방법을 그대로 적었다.
  - 전체학습: 인코더 전 층을 학습했다(LoRA 아님).
  - 행 균등: 모든 클래스를 가장 적은 클래스(방글라데시)의 행 수 1,008 로 줄인 목록으로 학습했다.
  - 손실 가중: 행은 그대로 두고, 손실에 클래스 가중치 N/(C·n_c) 를 줬다.
  - 사후 로짓 보정: 학습은 그대로 두고, 추론 로짓에서 τ·log(학습 클래스 비율)을 뺐다.
- **구간:** 꼬리 · 중간 · 머리는 학습 화자 수로 나눈 웹 문장(단어 제외) 국가 평균이다.
- **국가 평균:** 국가마다 정확도를 내고 그 평균을 낸 값이다. 국가 수에 비례해 작은 국가도 같은 무게로 센다.
- **웹 전체:** 발화 평균이다. 그래서 큰 국가가 좌우한다.

## 3. 학습 방법

### 3.1 공통 레시피 (300m · 2B 같게)

- **백본:** 음성인식으로 미세조정하지 않은 사전학습 원본 XLS-R 이다.
  - 300m: 17층까지 자른다(약 0.24B).
  - 2B: 31층까지 자른다(약 1.46B).
  - 층은 배포 모델 · 9/24 2B 실험과 같다. 파라미터 수는 체크포인트 크기로 셌다.
- **분류기:** 그 층 출력을 발화 길이로 평균 → ±50 클립 → 표준화 → 선형층(41클래스).
- **학습 범위:** 트랜스포머 전 층 · 위치 합성곱 · 특징 투영 · 층 정규화.
  - 파형 앞단 CNN 특징 추출기만 고정한다(wav2vec 2.0 미세조정 관례).
  - 사전학습 손실 전용 모듈(quantizer 등)은 쓰지 않는다.
- **초기화(LP-FT):**
  - 먼저 인코더를 고정한 채, 클래스별 같은 수로 뽑은 2만 행으로 표준화 값과 선형층을 맞춘다.
  - 그다음 전체를 학습한다.
- **최적화:**
  - CE 손실(클래스 가중치 없음), AdamW(weight decay 1e-4)
  - 학습률: 인코더는 300m 3e-5 · 2B 1e-5, 분류기는 1e-3
  - warmup 1,000스텝 → cosine(최저 10%), 가중치 EMA 0.999, bf16, 기울기 clip 5
- **입력:**
  - 학습 때 8초로 자른다(평가는 12초).
  - 길이 버킷 배치(64초 · 24발화) × 누적 4 = 업데이트 한 번에 음성 약 256초.
  - 최대 5 epoch(≈ 87k 스텝).
- **학습률 고르기:** 부분 데이터(30% 행 · 1 epoch)로 비교했다. valid 기준은 다음과 같다.
  - 300m: 1e-5 → 1.457, 3e-5 → 1.525
  - 2B: 3e-6 → 1.505, 1e-5 → 1.538
- **체크포인트 선택:**
  - 2,000스텝마다와 epoch 끝마다 valid 로 평가한다.
  - 기준 = 웹 top-5 + 웹 국가 평균 top-5.
  - 가장 좋은 EMA 가중치를 저장하고, 10번 연속 안 오르면 멈춘다.
  - test 는 그 체크포인트로 한 번만 추론한다.

| 행 균등 (`imb_capmin`) | 모든 클래스를 가장 적은 클래스(방글라데시)의 행 수 1,008 로 줄임 | 41,328 · 7,906 | 8,000 / 15,453 | 1.5899 | 1.9 h |

| + 사후 로짓 보정 | 같은 식, τ = 1.45 | — | — | 1.6362 | — |

- **행 균등:** 폴더 이름 `capmin` 은 "클래스당 행 수 상한(cap)을 가장 적은 클래스(min)에 맞춘다"는 뜻이다.
  - 클래스 안 출처 비율은 그대로 두고, 출처 안에서는 화자를 번갈아 뽑았다(`scripts/data/make_capped_manifest.py --cap min`).
  - 최대 스텝은 대조군과 같다(79 epoch). 그런데 epoch 이 짧아 epoch 끝 평가가 잦았다.
  - 그래서 같은 "10번" 조기 종료가 대조군(≈18k 스텝)보다 짧은 ≈7.5k 스텝이었다.
- **사후 보정:** 학습은 그대로 두고 추론 로짓만 바꾼다. τ 는 valid 기준으로 0 ~ 1.5(0.05 간격)에서 골랐다. 두 백본 모두 같은 격자다.
  - valid 기준은 τ 에 대해 평탄하다. 2B 는 격자를 3.0 까지 넓히면 τ 2.5 가 +0.006(1.6421) 높을 뿐이다.
  - τ 를 키울수록 국가 평균을 더 얻고 전체를 더 잃는다. 2B τ 2.5 의 test 결과: 국가 평균 0.723 · 꼬리 0.182 · 중간 0.761, 대신 웹 전체 0.856 · 단어 0.576(`compare_2b_tau_sensitivity.md`).
- **속도 · 메모리(A100 80GB):**
  - 300m: 약 94발화/초, 9.0 GB
  - 2B: 약 30발화/초, 41.9 GB. 300m 의 1/3 속도다.
  - 2B 학습 손실은 첫 8k 스텝 동안 가끔 튀었다(200배치 구간 최대 17.7). 그 뒤 사라졌고 valid 에는 영향이 없었다.

### 3.3 run_zeroth (비교 기준, 학습 방식이 다르다)

- **학습 방식:** `experiments/webmic_kd_train.py`
  - 배포 전 모델을 교사로 지식 증류했다(α 0.3 · T 2.0).
  - 12층부터만 풀었고 학습률은 7e-6 이다.
  - run1 → … → run4 → run_zeroth 순으로 이어 학습했다.
- **학습 목록이 더 크다:** 우리 train 보다 크다(774,819행).
  - 우리가 valid 로 옮긴 697명이 들어 있다.
  - 뺀 Kspon 이웃 묶음도 들어 있다.
- **출발 모델:** `0705_country41_sent043_300m` 이다(7월, 다른 사람이 학습). 학습 목록이 서버에 없어서 test 화자를 봤는지 확인할 수 없다.
  - 이어 학습한 run1~run_zeroth 의 목록에는 test 화자가 0명이다.

## 5. 해석

### 5.1 병목은 화자 수다

- **꼬리 8개국:** 학습 화자가 5~15명뿐이지만, 행은 이미 1,600~3,800개씩 있다.
  - 행 수를 1,008 로 맞추거나(행 균등) 손실 무게를 17배까지 줘도(손실 가중) 새 화자는 생기지 않는다.
  - 2B 로 키워도 마찬가지다.
  - 꼬리 top-5 는 어떤 방법으로도 0.02 ~ 0.14 에 머문다(무작위 5개 찍기 ≈ 0.12). 2B 사후 보정 τ 를 2.5 로 키워도 0.18 이다.
- **중간 국가(16~100명):** 방법에 따라 0.59 → 0.74 까지 움직인다. 화자가 어느 정도 있으면 보정이 통한다.
- **같은 결론의 이전 기록:** 다운샘플링과 재가중에 대한 이전 기록(`26_다운샘플링_정리.md`)과 같은 결론이다. 그때는 동결 헤드나 부분 학습이었고, 이번에는 인코더 전체 학습에서 깨끗하게 다시 잰 것이다.

### 5.2 2B vs 300m (같은 레시피)

- **전체:** 같다. 웹 전체, 웹 문장, 131, 머리 모두 구간이 0 을 포함하고, 웹 전체 top-5 −0.005 는 경계선이다.
- **나은 곳:**
  - 중간 국가 top-5 +0.068 [+0.002, +0.124]: 미얀마 0.50 → 0.79, 말레이시아 0.45 → 0.57, 우크라이나 0.25 → 0.46, 인도 0.53 → 0.63.
    - 경계선이다. 같이 비교하는 모델 묶음이 바뀌면 부트스트랩 표본이 달라져 하한이 −0.004 까지 내려간다(`compare_frozen_20261020.md`).
    - fp32 로 재면 +0.095 [+0.027, +0.146] 이다.
  - 머리 중에서는 top-1 이 우즈베키스탄 0.38 → 0.52, 영국 0.42 → 0.51.
- **못한 곳:** 단어 한 개 발화(top-5 −0.028 [−0.041, −0.014])와 꼬리(−0.036, 구간이 0 포함).
- **비용:** 학습이 3배 느리고(13.3 h vs 4.4 h), 추론 파라미터가 약 6배다. 지금 배포처럼 CPU(ONNX)로 서빙하기엔 부담이다.
  - 사후 보정을 더하면 국가 평균이 가장 좋다(0.701). 하지만 300m + 보정(0.688)과의 차이(+0.013)를 이 비용과 견줘야 한다.

### 5.3 불균형 보정 세 가지

- **행 균등:** 중간 국가는 가장 크게 오르지만(+0.147) 대가가 크다.
  - 머리 top-1 이 −0.104 다. 예: 미국 0.56 → 0.27, 러시아 0.78 → 0.50.
  - 웹 전체 top-5 는 −0.050 이다.
  - 학습 acc 0.978 로 줄인 4만 행을 외우고 있었다.
- **손실 가중:** 국가 평균이 그대로이고 꼬리는 오히려 떨어졌다(−0.068).
- **사후 보정:** 재학습 없이 τ 하나로 웹 전체 −0.013 을 내주고 국가 평균 +0.027, 중간 +0.065 를 얻는다. 손실 대비 가장 싸다.
  - 단어 발화는 −0.049 로 많이 잃는다. 짧은 발화는 로짓 차이가 작아서, 사전 확률을 빼는 보정이 큰 국가의 정답을 더 많이 밀어내는 것으로 보인다.

### 5.4 run_zeroth 의 꼬리 성적은 믿기 어렵다

- **꼬리 성적:** run_zeroth 는 꼬리 0.453, 131 국가 평균 0.972 로 다른 모든 모델보다 훨씬 높다.
- **의심스러운 국가:**
  - 학습 화자 7명인 타지키스탄: 웹 1.00, 131 1.00
  - 3명인 에티오피아: 131 1.00
  - 12명인 캄보디아 · 투르크메니스탄: 0.92 · 0.75
  - 학습 화자 수로 설명하기 어렵다.
- **확인할 수 없는 이유:** run_zeroth 의 출발 모델은 학습 목록이 남아 있지 않다. 이 test 화자를 봤을 가능성을 배제할 수 없다.
- **머리 · 전체:** 우리 300m 이 run_zeroth 와 같거나 앞선다(웹 전체 top-5 +0.025).

## 6. 주의

- **꼬리 구간은 작다(9명 · 108발화).** 국가당 test 화자가 1명이라 구간이 넓다(예: 2B + 보정 꼬리 +0.036 [+0.000, +0.117]).
- **시드 1개 · 단일 시험지다.** 0.01 안팎의 차이는 학습을 다시 돌리면 뒤집힐 수 있다.
- **사후 보정은 한 점이 아니라 교환 곡선이다(§3.2).** valid 기준이 τ 에 대해 평탄해서, τ 를 조금만 바꿔도 국가 평균과 전체가 0.01~0.02 씩 맞바뀐다.
- **bf16 평가는 발화 단위로 흔들린다.** 학습 · 평가 모두 bf16 autocast 다.
  - 2B 는 같은 가중치라도 bf16 과 fp32 의 top-1 이 test 발화 5.8% 에서 다르다(2~4초 발화는 12%).
  - 맞던 것이 틀린 것 267건, 틀리던 것이 맞은 것 247건으로 거의 같아서 집계는 같다(top-1 0.707 vs 0.708).
  - 원인은 인코더 31층의 bf16 연산이다. 마지막 평균 풀링을 fp32 로 해도 차이가 그대로다. fp32 끼리는 배치로 돌리든 한 개씩 돌리든 같다(패딩 누수 없음).
  - bf16 은 배치 구성에도 흔들린다. 평가 배치만 240초 → 48초로 바꿔도 top-1 1.6% 가 바뀐다. 중간 평가(48초)와 최종 평가(240초)의 집계가 ±0.003 다른 이유다.
  - 300m 은 bf16 · fp32 의 top-1 이 1.9% 에서 다르다(2~4초 3.9%). 2B 의 1/3 이고, 역시 집계는 같다(맞음→틀림 93 · 틀림→맞음 96).
  - fp32 끼리 비교해도 결론은 같다(`compare_fp32_300m_vs_2b.md`). 2B − 300m top-5 는 다음과 같다.
    - 웹 전체 −0.004 [−0.009, +0.001], 단어 −0.026 [−0.039, −0.012]
    - 중간 +0.095 [+0.027, +0.146], 꼬리 −0.047 [−0.083, +0.017]
  - 작은 구간은 정밀도만으로도 움직인다. 2B 중간 국가 평균이 bf16 0.659, fp32 0.685 다.
  - 그래서 ±0.005 안의 차이는 수치 잡음만으로도 생길 수 있다. 화자 부트스트랩 구간에는 이 잡음이 들어가지 않는다.
- **test 는 38클래스로 채점한다.** 방글라데시 · 르완다 · 잠비아 3개 클래스는 학습만 하고 채점하지 않는다.

- **2B 를 학습 중에 평가할 때:** 학습 중인 GPU 에서 2B 를 평가하면 평가 프로세스가 12 GB(`--eval_batch_sec 48`) ~ 18 GB(기본 240) 를 잡는다.
  - 학습 · 다른 서비스와 GPU 를 나눠 쓸 땐 배치를 줄인다.
  - 프로세스 메모리 상한(`torch.cuda.set_per_process_memory_fraction`)도 건다.
  - 단 bf16 은 배치에 따라 발화 단위 예측이 바뀐다(§6). 문서에 넣을 숫자는 기본 배치(240초)로 다시 잰다.
- **fp32 평가(`--eval_fp32`):** bf16 autocast 와 TF32 를 끈다. 2B test 한 번에 약 40분(bf16 은 약 5분, 학습과 GPU 를 나눠 쓴 조건)이 걸린다.
- **사후 보정 · 국가별 표:** 로짓 위에서 CPU 로 몇 초면 다시 낼 수 있지만, 스크립트가 아직 저장소에 없다.
  - 사후 보정: `z' = z − τ·log(train 클래스 행 비율)`. τ 는 valid 의 웹 top-5 + 웹 국가 평균 top-5 로 고른다.
- **커밋 상태:** 위 스크립트들(복원 · 분할 · 행 줄이기 · 학습 · 비교 · 체인)은 아직 커밋하지 않았다.
