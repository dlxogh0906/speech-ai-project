# 37 — 언어 식별(LID) 모델로 국적을 가리면 (2026-10-22)

질문: fairseq XLS-R README 의 "XLS-R 300M + ft Voxlingua107"(`xlsr_300m_voxlingua107_ft.pt`)은 무엇이고, 우리 test 에 넣으면 어떻게 나오나.
학습했을 때(인코더 고정 + 선형 헤드, 인코더까지 전체학습)는 어떤가.

**결론: 그대로 쓰면 외국인의 한국어를 대부분 "한국어"라고 한다. 인코더 고정 + 선형 헤드로 바꿔 끼우면 사전학습 300m 과 거의 같다.
인코더까지 학습해도 LID 에서 출발한 이득은 없다 — 웹 · 단어는 낮아지고 꼬리는 같은 오경보율에서 낫지 않다(§5).**

- **우리 백본은 이 LID 모델이 아니다.** 우리는 사전학습만 한 `xlsr2_300m.pt` · `xlsr2_2B_1000k.pt` 를 쓴다(모델 `wav2vec2`, 태스크 `audio_pretraining`, 분류 헤드 없음).
  - LID 모델은 바로 그 300m 에서 출발했다. CNN 가중치 28개는 우리 파일과 똑같고, 나머지 394개 텐서(트랜스포머 등)가 바뀌었다.
  - 하는 일은 107개 언어 중 지금 들리는 말이 무슨 언어인지 맞히기다. 말하는 사람의 모국어가 아니다.
- **그대로 쓰면 외국인의 한국어 대부분을 한국어라고 한다.** 웹 문장 75.8% · 131 외국인 97.9% 다.
  - 단어처럼 짧은 발화는 16.6% 만 한국어이고, 자바어 · 말레이어 · 타갈로그어 등으로 흩어진다.
  - 원어민은 Zeroth 100% · Kspon 89.3% 를 한국어라고 한다.
- **한국어를 빼고 다음 언어를 보면 모국어는 조금 나온다.** 모국어가 107개 목록에 있는 35개국 평균으로 1위 0.116 · 3위 안 0.209 다.
  - 일본 0.661 · 중국 0.464 · 인도네시아 0.403 · 인도 0.350 정도다. 영어 · 러시아어 · 유럽어 화자는 거의 0 이다.
  - 한국어 같지 않은 소리를 누구에게나 주로 일본어 · 중국어 · 티베트어 · 자바어로 부른다. 그 위에서 일본어 · 중국어 화자가 조금 더 자주 맞는 정도다.
- **41개국 표로 옮기면 학습 안 함 300m 보다 훨씬 낮다.** 언어를 나라로 옮겨(§1) 웹 top-5 0.404, 한국어를 빼면 0.437 이다. 학습 안 함 300m 은 0.640 이다.
- **인코더 고정 + 선형 헤드로 바꿔 끼우면(LID 학습 안 함) 사전학습 300m 과 거의 같다.** 웹 top-5 0.616 vs 0.640 (−0.024 [−0.035, −0.014]) 이다.
  - 131 외국인 국가 평균은 0.545 → 0.657 (+0.112 [+0.034, +0.133]) 로 올랐다.
  - 꼬리 top-5 는 0.016 → 0.146 (+0.130 [+0.067, +0.200]) 로 올랐지만, 꼬리 오경보가 28.8% → 44.0% 로 같이 올랐다.
    같은 오경보율에서는 +0.010 ~ +0.062 이고 구간이 0 에 닿는다. 대부분 꼬리 국가를 더 자주 찍은 몫이다(29 · 31 과 같은 패턴).
  - 원어민은 엇갈린다. Kspon 오답 80 → 207 로 늘고, Zeroth 51 → 33 · 증강 67 → 49 로 줄었다.
- **인코더까지 학습해도(LID 전체학습 · 그 위 LoRA VC 50%) 이득이 없다.** 원래 모델과 같은 설정으로 출발점만 바꿨다(§5).
  - 웹 top-1 은 −0.023 ~ −0.051, 단어 top-5 는 −0.042 ~ −0.087 낮다. 네 짝(valid 선택 · 마지막 EMA × 전체학습 · LoRA) 모두 구간이 0 아래다.
  - 꼬리는 같은 오경보율에서 네 짝 중 세 짝이 더 낮고(−0.021 ~ −0.073), 남은 한 짝도 0 에 걸친다.
  - 중간은 원래 값이 오르지만 오경보도 함께 올라, 같은 오경보율에서는 대부분 0 에 걸친다.

- **LID 그대로:** 마지막 층(층 정규화 뒤) → Linear(1024) → 시간 평균 → Linear(107) 이다. 활성 함수는 linear 다.
  - 공개 fairseq 의 `wav2vec2_classification` 은 이 체크포인트의 pooling(`mean_fast`)을 만들지 못한다(assert). 그래서 같은 계산을 직접 했다.
  - README 가 가리키는 추론 스크립트는 Meta 내부 저장소(fairinternal)에 있어 공개돼 있지 않다.
- **언어 → 나라 (41개국 표에 넣을 때만):** 나라 점수 = 그 나라 모국어 묶음 언어 로짓의 최댓값, Korea = ko 다.
  - 묶음은 내가 정했다(`lid_zeroshot.py` 의 `L1`). 예: 스페인 {es, ca, gl, eu} · 인도 {hi, ta, te, ml, kn, mr, bn, gu, pa, ur} · 카자흐스탄 {kk, ru}.
  - 키르기스스탄 · 르완다 · 잠비아는 모국어가 목록에 없어 고를 수 없다.
  - 같은 언어를 쓰는 나라(스페인어 4개국 · 영어 2개국 · 중국어 여러 곳)는 점수가 같다. 학습 행이 많은 나라를 앞에 뒀다.
    그래서 top-5 는 같은 언어 나라들이 함께 들어가 부풀어 있다. **이 줄은 참고용이다.**
- **LID 학습 안 함:** LID 인코더를 사전학습 300m 형식으로 옮겨 담아(`xlsr2_300m_voxlingua107_ft_w2v.pt`) `--xlsr` 로만 바꿨다.
  - 나머지는 300m 학습 안 함과 같다. 17층 · 같은 2만 행 · 같은 시드 · L-BFGS 다. 헤드의 학습 정확도는 0.917 이다(300m 은 0.927).

## 4. 주의

- **입력 정규화가 두 줄에서 다르다.** LID 그대로는 LID 학습과 같게 파형을 정규화했다. LID 학습 안 함은 300m 학습 안 함과 같게 정규화 없이 넣었다.
  - 사전학습 · LID 설정은 둘 다 `normalize: True` 인데 우리 로더는 정규화하지 않는다. 300m 고정 특징에서 정규화 유무만으로 같은 발화의 코사인이 0.46 까지 떨어졌다(표준화 공간, 12발화).
  - 그래서 두 "학습 안 함" 줄은 사전학습 모델에게 낯선 입력으로 잰 값이다. 정규화를 맞춘 비교는 아직 안 했다.
- **언어 → 나라 대응은 내가 정한 것이다.** 묶음을 바꾸면 "LID 그대로" 줄의 41개국 수치가 바뀐다. 언어 수준 표(§3)가 원래 출력이다.
- **꼬리 표본이 작다.** 웹 문장 꼬리는 test 9명 · 108발화다.
- **시드 1개다.** §2 는 헤드만 학습했고, 인코더까지 학습한 비교는 §5 에 있다.

## 5. LID 인코더에서 출발해 학습하면 (2026-10-22 밤)

질문: 인코더까지 학습할 때 LID 인코더에서 출발하면 나은가. 특히 꼬리가 나아지나.

### 5.3 읽기

- **웹 전체 · 단어 · 머리는 LID 판이 낮다.** 웹 top-1 −0.023 ~ −0.051 · 단어 top-5 −0.042 ~ −0.087 로 네 짝 모두 구간이 0 아래다.
  머리도 멈춘 시점 EMA 짝을 빼면 −0.02 ~ −0.03 이다.
- **꼬리 이득은 없다.** 같은 오경보율에서 네 짝 중 세 짝이 더 낮다(−0.021 ~ −0.073, 대부분 구간이 0 아래).
  남은 한 짝(멈춘 시점 EMA)도 +0.005 ~ +0.026 이고 구간이 0 에 걸친다.
- **중간은 원래 값이 오르지만 오경보도 같이 오른다.** 네 짝 모두 LID 판의 중간 오경보가 높다(+3.6 ~ +10.6%p).
  같은 오경보율에서 0 을 넘는 칸은 오경보 5% 두 칸(+0.048 · +0.069)뿐이고, 나머지는 0 에 걸친다.
- **131 국가 평균은 +0.007 ~ +0.035 로 모두 0 에 걸친다.** 학습 안 함에서 보였던 +0.112 는 인코더까지 학습하면 거의 사라진다.
- **원어민 오답이 조금 늘었다.** 멈춘 시점 EMA 짝을 빼면 Zeroth 오답이 2 → 10 · 0 → 11 · 0 → 15 다(457발화 중). Kspon 도 0 → 4 · 3 → 8 · 3 → 9 다(670발화 중).
  멈춘 시점 EMA 짝은 Zeroth 2 → 1 · Kspon 0 → 2 다.
- **고른 스텝 탓만은 아니다.** 멈춘 시점 EMA 끼리도 웹 · 단어는 낮다. valid 곡선에서도 4k 이후 매 시점 낮다.
- 왜 그런지는 확인하지 않았다. LID 학습은 억양이 섞여도 같은 언어로 묶도록 인코더를 맞춘 것이라, 억양 차이를 지우는 쪽으로 출발했을 수 있다(가설).
