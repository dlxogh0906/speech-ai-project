# 15 — NPU vs GPU vs CPU 서빙 성능 비교 (2026-09-26)

같은 서빙 구성(주 모델 zeroth + 확인 모델 + 무음 정규화 + 재요청 규칙)을 세 가지 하드웨어에서 돌려 **정확도 · 지연 · 동시 처리량 · 전력**을 비교했다.

## 1. 결론

- **정확도는 같다.** NPU 와 GPU 의 1위 판정이 97.5% 일치하고, 다른 판정 15개는 전부 외국인 경계 사례다(GPU 가 맞힌 것 6, NPU 가 맞힌 것 7). 한국인 판정은 하나도 다르지 않다.
- **한 명씩 쓸 때는 GPU 가 가장 빠르다.** 요청 1건 0.10초(GPU) · 0.18초(NPU, 길이 버킷) · 0.23초(NPU, 12초 고정) · 1.6초(CPU).
- **동시 처리량은 튜닝한 NPU 가 가장 높다.** NPU 길이 버킷 + 16프로세스 57.2건/초 · GPU 51.8건/초 · 지금 운영 중인 NPU(12초 고정 · 8프로세스) 35.4건/초 · CPU 1.7건/초.
- **요청당 에너지는 GPU 가 낫다.** 최대 처리량에서 GPU 4.7 J/건 · NPU 7.2 J/건 (가속기 보드 전력만).
- **CPU 만으로는 서비스가 안 된다.** 동시 4명이면 요청이 2초, 32명이면 24초 걸린다.
- **권장**: NPU 서버를 **길이 버킷(4·8·12초) + 16프로세스**로 바꾼다. 한 명 지연 0.23 → 0.18초, 처리량 35 → 57건/초. 정확도 변화 없음.

## 2. 실험 설정

| 구성 | 하드웨어 | 실행 방식 |
|---|---|---|
| GPU A100 · 1프로세스 | NVIDIA A100-SXM4-80GB (GPU 서버, CPU 16코어) | onnxruntime CUDA, 세션 4개(스레드) |
| GPU A100 · 4프로세스 | 같음 | 프로세스 4개 × 세션 2 |
| GPU 서버 CPU | 같은 서버의 CPU 16코어 | onnxruntime CPU, 세션 4개 × 스레드 4 |
| NPU · 12초 고정 · 8프로세스 (현재 운영) | Rebellions RBLN-CA25 ×8 (NPU 서버, CPU 32코어) | rebel 0.10.2, 모든 입력을 12초로 채움 |
| NPU · 길이 버킷 · 8프로세스 | 같음 | 4·8·12초 중 입력보다 긴 가장 작은 크기로 채움 |
| NPU · 길이 버킷 · 16프로세스 | 같음 | 프로세스 16개 |

- 모델·판정 규칙·전처리는 모두 같다(`KD_GATE_TAU=0.9 · KD_GATE_INPUT=raw · KD_SILENCE_NORM=1 · KD_GATE_MIN_SEC=1.0 · KD_LOWCONF=0.45`).
- 시험 음성 617개(학습에 없던 화자): 웹마이크 외국인 300 · 505 외국인 100 · 한국인 대화(Kspon) 100 · 한국인 낭독(Zeroth) 100 · 사내 아이폰 녹음 17.
  길이 중앙값 6.8초, 4초 이하 18% · 8초 이하 61% · 12초 초과 17%.
- 측정 클라이언트를 **서버와 같은 기계**에서 돌려 네트워크 시간을 뺐다(`/data/speech-ai/out/novelty/bench/bench_client.py`).
  1) 617개를 한 건씩 순서대로 보내 판정·지연을 기록, 2) 동시 1·4·8·16·32·64명으로 부하를 주며 처리량·지연·전력을 기록.
- CPU 는 너무 느려 정확도를 5개마다 1개(124개)만 쟀다. CPU 와 GPU 는 같은 ONNX 파일이라 판정이 100% 같다.

## 3. 정확도 (617개)

| 구간 | GPU A100 | NPU 12초 고정 | NPU 버킷 |
|---|---|---|---|
| 한국인 대화(Kspon) Korea | 1.000 | 1.000 | 1.000 |
| 한국인 낭독(Zeroth) Korea | 1.000 | 1.000 | 1.000 |
| 사내 아이폰 Korea (나머지는 재요청) | 0.882 | 0.882 | 0.882 |
| 웹마이크 외국인 top-1 / top-5 | 0.712 / 0.930 | 0.726 / 0.933 | 0.716 / 0.933 |
| 웹마이크 외국인 → Korea 오판 | 2.0% | 1.7% | 1.7% |
| 505 외국인 top-1 / top-5 | 0.850 / 0.990 | 0.860 / 0.990 | 0.860 / 0.990 |

- top-1 은 "재요청 없이 1위가 정답"인 비율이다. 재요청은 웹마이크 외국인 약 9%, 505 외국인 3~5%.
- 한국인 대화(Kspon)의 **13%는 말소리가 1초 미만이라 거절**된다(`no_speech`). 세 구성 모두 같다. 짧은 대답을 받는 화면이면 "조금 더 길게" 안내가 필요하다.
- GPU 와의 1위 일치: GPU 4프로세스·CPU 100% · NPU 97.3~97.5%. NPU 의 1위 확률 차이는 평균 0.010.
- NPU 와 GPU 가 다르게 판정한 15개는 전부 외국인이고, 14개는 GPU 1위 확률이 0.6 미만인 경계 사례다(9개는 둘 다 재요청). 한쪽이 체계적으로 틀리지 않는다.

## 4. 지연 (한 명씩)

| 구성 | 요청 p50 | p95 | 모델 계산 p50 | 길이별 p50 (≤4초 · 4~8 · 8~12 · >12초) |
|---|---|---|---|---|
| GPU A100 · 1프로세스 | **105 ms** | 119 ms | 13 ms | 96 · 104 · 112 · 117 ms |
| GPU A100 · 4프로세스 | 106 ms | 120 ms | 13 ms | 98 · 104 · 113 · 118 ms |
| GPU 서버 CPU | 1,617 ms | 2,914 ms | 776 ms | 916 · 1,428 · 2,332 · 2,897 ms |
| NPU · 12초 고정 | 231 ms | 247 ms | 105 ms | 228 · 230 · 234 · 237 ms |
| NPU · 버킷 · 8프로세스 | 180 ms | 246 ms | 83 ms | **134** · 170 · 235 · 237 ms |
| NPU · 버킷 · 16프로세스 | 179 ms | 244 ms | 81 ms | **133** · 170 · 233 · 237 ms |

- "모델 계산"은 주 모델 한 번의 시간이다. 요청에는 디코딩(ffmpeg), 무음 정규화, 확인 모델이 더해진다.
- NPU 는 입력 크기가 컴파일 때 고정된다. 12초 고정이면 1초짜리 음성도 12초만큼 계산한다. 길이 버킷을 쓰면 NPU 계산이 4초 20 ms · 8초 39 ms · 12초 59 ms 로 줄어, 짧은 발화가 0.23초 → 0.13초가 된다.
- GPU·CPU 는 실제 길이만큼만 계산한다(동적 길이).

| NPU · 12초 고정 · 8 | 4.3 · 0.23/0.24s | 15.1 · 0.24/0.45s | 29.2 · 0.20/0.49s | 35.4 · 0.41/0.85s | 35.4 · 0.73/1.62s | 34.9 · 1.47/3.49s |
| NPU · 버킷 · 8 | 5.5 · 0.17/0.24s | 20.3 · 0.17/0.29s | 36.4 · 0.15/0.43s | 44.8 · 0.29/0.68s | 44.2 · 0.56/1.08s | 43.4 · 1.28/2.42s |

- **GPU 는 한 프로세스가 낫다.** onnxruntime CUDA 는 스레드끼리 병렬로 돌고, 프로세스를 나누면 GPU 를 번갈아 써서 오히려 느려진다(동시 8명 44.7 → 29.5건/초).
- **NPU 는 프로세스를 늘려야 한다.** rebel 런타임 호출은 한 프로세스 안에서 병렬로 돌지 않는다. 8 → 16프로세스로 처리량 44 → 57건/초. 부하 중 NPU 서버 CPU 사용률은 약 57% 였다.
- 동시 64명에서 1건씩 실패한 것은 말소리 1초 미만 파일의 `no_speech` 응답이다(오류 아님).

## 6. 전력 · 에너지 (가속기 보드만, 호스트 CPU 제외)

| 구성 | 대기 | 동시 1명 | 최대 처리량 시 | 요청당 에너지 (최대 처리량) |
|---|---|---|---|---|
| GPU A100 · 1프로세스 | 76 W | 99 W | 242 W (동시 32) | **4.7 J** |
| GPU A100 · 4프로세스 | 80 W | 101 W | 242 W | 5.1 J |
| NPU · 12초 고정 · 8 | 115 W | 171 W | 409 W | 11.6 J |
| NPU · 버킷 · 8 | 137 W | 223 W | 408 W | 9.1 J |
| NPU · 버킷 · 16 | 133 W | 212 W | 411 W | 7.2 J |

- GPU 는 `nvidia-smi` 보드 전력, NPU 는 `rbln-stat` 의 카드 2장 합이다. NPU 대기 전력은 서버 두 개(8905·8906)가 올라가 있는 상태에서 쟀다(서버 없을 때 약 88 W).
- 이 구성에서는 GPU 의 요청당 에너지가 약 1.5배 낮다. NPU 는 모델 두 개를 매번 따로 부르고, 요청마다 1개씩만 보낸다(배치 없음). 여러 요청을 묶어 보내면 달라질 수 있다.

## 7. 해석할 때 주의

- **호스트 CPU 가 다르다.** GPU 서버는 16코어, NPU 서버는 32코어다. 디코딩·전처리는 호스트 CPU 에서 돌아 처리량에 영향을 준다.
- **GPU 서버는 다른 서비스와 같이 쓴다.** 측정 중 GPU 사용률은 0% 였지만 메모리는 다른 서비스가 약 40 GB 를 쓰고 있었다.
- **전력은 가속기만이다.** 호스트 CPU·메모리·팬 전력은 빠져 있다.
- **네트워크 시간은 빠져 있다.** 실제 사용자는 여기에 업로드 시간이 더해진다(예: 폰 → Tailscale Funnel → NPU 서버).
- **NPU 정밀도**: NPU 는 낮은 정밀도로 계산해 확률이 조금 다르다(평균 0.010). 판정 결과에는 영향이 없었다.

## 8. 권장

1. **NPU 운영 서버를 길이 버킷 + 16프로세스로 바꾼다.** 실험용 서버(포트 8906)에서 검증을 마쳤고, 바꾸는 법은 아래와 같다. 모델 파일은 `encoder_pure_l17_bucket4_8_12.rbln`(모델당 1.5 GB, 장치 메모리 여유 충분).
2. **GPU 를 쓸 수 있으면 GPU 가 한 명 지연과 전력 효율에서 앞선다.** 다만 GPU 서버는 다른 서비스와 공유 중이라, 전용 NPU 서버를 쓰는 지금 구성이 운영상 단순하다.
3. **CPU 만으로는 운영하지 않는다.**

```bash
# NPU 서버: 버킷 모델 컴파일 (이미 해 둠)

python /root/nat_serve/compile_buckets.py bundle/models/deployed_gate 4,8,12
# 버킷 서버 기동 (실험 스크립트, 포트 8906 · 프로세스 수 인자)
bash /root/nat_serve/start_bucket.sh 16
```

## 10. 실제 저장 녹음으로 비교 (추가, 2026-09-26)

데모·낭독 페이지에 **실제로 저장된 녹음**만 모았다. 서버가 다시 보낸 테스트 파일과 데이터셋 음성은 형식(ffmpeg 태그)과 내용 해시로 걸러 냈다.
58개 · 아이폰(사파리 m4a) 45 · 크롬(webm) 13 · **녹음자는 모두 한국인**(사내). 그래서 이 절은 "한국인이 한국인으로 나오는가"만 잰다.
비교 대상에 **기존 서비스(옛 모델 · 옛 설정: 무음 정규화·확인 모델·재요청 없음)** 를 넣었다. 운영 중인 서비스는 건드리지 않고 같은 설정의 복사본을 따로 띄워 쟀다.

- 새 구성은 모델을 두 번 부르고 무음 정규화를 해서 기존 서비스보다 느리다(GPU 기준 +15 ms).
- 실제 녹음은 짧아서(대부분 3~5초) NPU 길이 버킷의 효과가 더 크다(0.23 → 0.17초, 처리량 37 → 65건/초).

### 10.4 한계
- 58개, 녹음자 1~2명(사내)이다. 사람이 늘면 숫자가 달라질 수 있다.
- 외국인 실제 녹음은 없다. 외국인 성능은 표준 시험지(3·4절) 숫자만 있다.
