# 07 — 모델 크기별 재평가 (2026-08-05)

백본 크기(2B vs 300m)와 양자화(fp32 vs int8)가 정확도·용량·지연에 얼마를 쓰는지.

---

## ① 백본 크기 — 기존 수치, 같은 test 셋으로 짝을 맞춤

**주의 — 크기 비교에 `0702` 를 쓰면 안 된다.** 그 실험의 test 셋은 043 아시아가 빠진
133,509발화이고, `0704`·`0705` 는 043 을 포함한 135,770발화다. 자주 인용되는 2B top-5
`0.9496` 은 앞쪽 값이라 300m 의 `0.9331` 과 나란히 놓으면 크기 손실이 과장된다.

같은 셋(135,770)에서의 값:

| | XLS-R 2B (`0704`) | XLS-R 300m (`0705`) | 차이 |
|---|--:|--:|--:|
| top-1 | 0.7838 | 0.7510 | −0.0328 |
| top-5 | 0.9410 | 0.9331 | −0.0079 |
| macro top-5 | 0.6294 | 0.6170 | −0.0124 |
| 사용 층 | 31 | 17 | |
| 백본 용량 | 25 GB | 3.6 GB | **7분의 1** |

top-5 를 0.8%p 내주고 백본을 7분의 1로 줄인다. 배포는 300m.

test 구성: 505 국내 92,999 / 041 유럽 25,163 / 043 아시아 2,609 / 한국어 14,999.

## ② int8 양자화 — 신규 실측

지금까지 int8 검증은 `quantize_onnx_300m.py` 의 클래스별 샘플 wav **41개**뿐이었다.
실제 test 오디오로 잰 건 이번이 처음이다.

`scripts/eval/eval_size_tradeoff.py --n 1000` · `aihub_country41_811/test.csv` · 4스레드 CPU

| | fp32 ONNX | int8 ONNX |
|---|--:|--:|
| 용량 | 960 MB | **279 MB** (3.4배 작음) |
| 발화 1건 지연 | 1,255 ms | 1,180 ms (**1.06배**) |
| top-1 일치율 | — | **91.8%** |
| top-5 집합 일치율 | — | **38.2%** |
| 특징 최대절대차 중앙 | — | 0.4889 |

**용량 3.4배를 얻는 대신 top-1 예측의 8.2%가 바뀌고, 속도는 사실상 그대로다.**

속도가 안 오르는 이유 — 동적 양자화가 MatMul 만 int8 로 바꾸고 앞단 conv 는 fp32 로
남긴다(`op_types_to_quantize=["MatMul"]`, ConvInteger 회피). 이 모델은 conv 특징
추출기가 시간을 잡아먹어서 Transformer 쪽만 줄여봐야 벽시계가 안 줄어든다.

top-5 집합 일치 38.2% 는 5개 중 하나만 달라도 불일치로 세는 엄격한 기준이라 낮게 보인다.
다만 top-1 이 8.2% 바뀐다는 사실은 그것과 별개다.

**권고 — 정확도가 중요한 경로에는 int8 을 쓰지 않는다.** 디스크·메모리가 정말 빠듯한
환경에서만 고려하고, 그때도 위 8.2% 를 감안한다.
