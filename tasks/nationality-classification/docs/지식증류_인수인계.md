## 0. 30초 요약

2B 교사(layer31)를 300m 학생(layer17)에 증류했다. 3단계를 거쳤고 **단계마다 상한의 정체를
규명하고 다음 단계로 넘어갔다**:

| 단계 | 무엇 | test top1 | macro5 | 결론 |
|---|---|--:|--:|---|
| 0. baseline (출하본 0705) | CE만 | 0.7510 | 0.6170 | 비교 기준 |
| 1. **헤드 KD** | 로짓 증류 (인코더 동결) | 0.7696 | 0.6356 | +1.9%p, 대신 꼬리 희생 |
| 2. **기법 변형 9종** | LS·DKD·게이팅·앙상블·특징KD | 0.7665 | 0.6251 | 꼬리 손실 −0.4%p까지 축소가 동결의 한계 |
| 3. **인코더 KD** ★최종 | 층12–17 학습 (75.6M) | **0.8245** | **0.7124** | 트레이드오프 소멸, **교사 추월** |

최종 모델은 **교사(2B, 오염 포함 0.7992)를 전 지표에서 추월**했고, ONNX로 수출해
**CPU 전용 데모 사이트**(포트 8905)까지 배포돼 있다.

## 2. 어떻게 했나 — 단계별 핵심

### 1단계: 헤드 KD (GPU 불필요, 43분)

두 인코더가 **동결**이라 캐시된 특징으로만 학습 가능. 교사 로짓 = 캐시 X31 →
(x−mu_t)/sd_t → 교사 헤드. 학생 헤드를 `(1−α)CE + α·T²·KL` 로 학습.

- **파이프라인 검증**: CE baseline이 출하본 재현 (micro5 0.9333 vs 0.9331)
- 스윕 15조합 → **α=0.3, T=2** (α 클수록 단조 악화 — 교사를 너무 믿으면 손해)
- clean 분해 결과: 교사가 아는 도메인 +1.8%p 진짜 이득, **043·꼬리는 하락**

### 2단계: 변형 9종 — 꼬리 하락의 원인 규명 (GPU 15분)

| 변형 | 판정 | 배운 것 |
|---|---|---|
| Label Smoothing | 대조군 | KD 이득은 smoothing이 아니라 **교사 지식** (LS는 +0.2~0.6%p뿐) |
| DKD (target/non-target 분리) | ❌ | 분리로는 교사 무지를 못 거름 — 043 반토막 |
| **마진 게이팅** | ✅ 채택 | 교사 확신도(margin)로 행별 KD 강도 조절 — 도메인 마스크의 원리적 대체 |
| **앙상블 교사** (2B+자기) | ✅ 균형 최적 | 학생 자신이 교사 맹점 희석 — 꼬리 손실 −0.4%p까지 |
| 특징 KD (ridge 투영) | ❌ | 동결 인코더에선 같은 가설공간 — **인코더를 열면 부활** |

결론: **동결 헤드로는 꼬리 동률이 상한.** → 3단계로.

### 3단계: 인코더 KD (GPU ~4.5h 총)

```
손실 = (1 − α·margin_i)·CE                    ← hard label
     + α·margin_i·T²·KL(z_s/T ‖ z_t/T)        ← 로짓 증류 (α=0.3, T=2)
     + β·(1 − cos(proj(pool17), 교사 L31))     ← 특징 증류 (β=0.5)
학습: 300m 층 12–17만 해동(75.6M), 18층+ 절단, 헤드는 CE-baseline 초기화
데이터: 서브셋 169,145행 (클래스당 cap 6000, 꼬리 전량), 8s 크롭, 6 epoch
```

핵심 설계 결정 두 개:

**① 교사 신호를 캐시가 아니라 재추출** — 특징 캐시와 현재 CSV의 행 순서가 어긋나 있어서
(CSV가 추출 후 재생성됨, 505는 1,868조각) 조각 매칭 대신 2B를 서브셋 오디오에 직접
forward(73분). 모든 신호가 행번호로 키가 잡혀 정렬 문제가 원천 소멸.

**② 화자 split을 JSON으로 고정** — `assign_speakers(seed42)`는 해시가 아니라
**인덱스 구성·순서 의존**이라, 같은 시드여도 데이터를 더하면 배정이 바뀐다(실측: 043 추가로
750명 이동). 캐시 인덱스 기준 배정을 `speaker_split.json`으로 박제해 전 단계가 같은
시험지를 쓰게 했다.

결과: **전 도메인·전 지표·clean에서 개선.** 교사가 모르는 043마저 +4.3%p —
교사 로짓이 아니라 **표현 개선의 전이**다 (마진 게이팅이 무지 전이를 차단).

## 5. 함정 목록 (우리가 실제로 밟은 것들)

1. **`assign_speakers(seed42)`는 순서 의존** — 인덱스가 다르면 배정이 다르다. "같은 시드 =
   같은 split" 아님. → `speaker_split.json` 고정으로 해결. 이걸 모르면 **오염된 비교**를 한다
   (교사-train 화자가 학생 test의 14.2%였다).
2. **캐시 행 ↔ CSV 순서 불일치** — CSV가 재생성되면 순서가 바뀐다. 유럽은 6조각 순열로 복구
   가능했지만(`recover_euro_sent_perm.py`, 발화 지문 cos 0.9993으로 검증), 505는 1,868조각이라
   재추출이 정답이었다.
3. **`kd_domains` 손실 배합 버그** — 마스크가 KD만 꺼야 하는데 CE까지 (1−α)배 감쇠시켰다
   (α=1이면 해당 행이 학습에서 소멸). 행별 배합 `(1−α·K_i)·CE_i + α·K_i·T²·KL_i` 로 수정.
4. **teacher_on_test는 오염 수치** — 교사 학습 발화가 test에 섞여 있어 "교사 상한"으로 인용
   금지. clean 부분집합 병기가 정본.
5. **ONNX 수출 순서** — `load_state_dict` **후에** `remove_weight_norm` (학습이 weight_norm
   유지 상태로 저장돼 있어 순서 바꾸면 파라미터 이름 불일치).
6. **수출 후 패리티 검증 필수** — pooled max|Δ| < 1e-2 assert + 실발화 top1 대조 10/10.
7. **디스크** — `/`는 3.5GB 남음. 대용량은 전부 `/data/tta`로 (kd_encoder가 심링크인 이유).
   `/data`도 21GB까지 줄었다 — 체크포인트 정리 필요 시점.
8. **행마다 `assign_speakers` 호출 금지** — 이차 폭발로 48분 헛돈 적 있다. 1회 계산 후 dict 참조.

- int8 양자화(ONNX)는 미실측 — 하면 266MB·더 빠르지만 정확도 영향 재야 함.
