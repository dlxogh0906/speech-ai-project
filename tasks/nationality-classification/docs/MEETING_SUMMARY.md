# 외국인 한국어 발화 → 국적(모국어) 분류 — 회의 요약

작성 기준: 현재까지의 전체 진행. 상세는 `EXPERIMENTS.md`, `AUGMENTATION_EXPERIMENT.md` 참조.

---

## 0. 한 줄 요약 (TL;DR)
- **XLS-R 2B(음성 인코더) + 분류 헤드**로 한국어 발화에서 화자의 **모국어(=국적 프록시) 61개**를 분류.
- **현재 최고 성능(test): top-5 정확도 95.3% (micro), 57.8% (macro)** — 인코더의 **중간 레이어(31층) 선택**으로 달성.
- **불균형·샘플링·fine-tuning·오디오증강은 전부 효과 없었고**, 원인은 구조적(**소수 국적의 *화자 수* 부족**)임을 실측·시각화로 규명.
- **배포 준비 완료**(HF 기반 추론 서버 + GCP 가이드). 웹/앱 공용 API 1개로 서빙 가능.

---

## 1. 프로젝트 / 데이터
- **목표**: 사용자가 한국어를 발화하면 그 사람의 **국적을 분류하는 웹/앱**.
- **데이터**: AIHub "외국인 한국어 발화 음성"(datasetkey 505). 약 **104만 발화, 화자 1,910명**.
- **라벨**: JSON의 `skill_info.motherTongue`(모국어). 검증 결과 거주국(country) 필드는 오염(거주 외국인 KR 12%)이라 **모국어가 가장 정확한 국적 신호**.
- **클래스**: **61개 모국어**(중국어/일본어/베트남어/… 타밀어). 단일언어 국가는 모국어=국적 1:1, 다언어권(중국어권/영어 등)은 악센트로 국가 구분 불가 → 언어 단위가 한계.

## 2. 평가 방식 (중요)
- **화자 분리(speaker-disjoint) 8:1:1 split** — train/valid/test 화자가 전혀 안 겹침. **실서비스(처음 보는 사용자)를 반영.**
- **micro vs macro top-5 구분**:
  - **micro** = 전체 발화 평균 (다수 국적이 좌우 → 높게 나옴)
  - **macro** = 국적마다 동일 가중 (**실제 "임의 국적 사용자" 체감** → 진짜 지표)

## 3. 성능 결과

| 모델 | micro top-5 | **macro top-5** | top-1 |
|---|--:|--:|--:|
| 초기 baseline (frozen, 최상위 레이어) | 0.937 | 0.498 | 0.731 |
| **현재 최고 (frozen, 31층 선택)** | **0.953** | **0.578** | — |

- **데이터 분포**: 상위 4개국(중/일/베/태)이 발화의 ~73%, 상위 13개국이 ~95%.
- **신뢰 가능한 국적 ~8~13개**(중국/일본/베트남/태국/몽골/러시아/영어/미얀마/인니…)는 top-5 ≥ 0.8.
- 소수 국적(화자 1~4명, 37개)은 거의 0 — 데이터 한계.

## 4. 시도한 기법 & 결과 (핵심 표)

| # | 기법 | 결과 (macro top-5) | 판정 |
|---|---|---|---|
| 1 | Frozen + linear probe (baseline) | 0.498 | 기준 |
| 2 | class-balanced / focal / logit-adjust | ≤ 0.498 | ❌ |
| 3 | 오버샘플링 / 균등 샘플링 | ↓ | ❌ |
| 4 | 부분 fine-tuning (×2, 인코더 학습) | 0.42~0.44 | ❌ (과적합) |
| 5 | **오디오 증강**(speed/noise/mask, 11.6만 샘플) | 0.490 (−0.007) | ❌ |
| 6 | TTS/생성모델 (리서치) | 불가 | ❌ |
| 7 | **레이어 선택 (31층)** | **0.578 (+0.080)** | ✅ **첫 성공** |

## 5. 핵심 인사이트 — 왜 어려운가
- **일반화의 단위는 "발화"가 아니라 "화자"** (평가가 화자 분리라).
- 소수 국적은 화자가 1~4명뿐 → **기존 화자에서 파생되는 모든 기법(복제·증강·합성·FT)은 새 화자를 못 만들어 전부 실패.**
- 시각화로 증명:
  - `runs/viz/B_by_speaker.png` — 특징공간이 국적이 아니라 **화자별로 뭉침**.
  - `runs/viz/C_augmentation.png` — 증강점이 **원본 화자 위에만** 쌓이고, 처음 보는 test 화자엔 못 닿음.
- → **소수 국적을 실제로 살리는 유일한 길 = 그 국적의 진짜 화자 추가 수집.**

## 6. 핵심 돌파구 — 레이어 선택
- XLS-R 48개 층 중 **악센트 정보는 중간층(~31)에, 화자 정체성은 초기층에** 분포(리서치 + 실측 일치).
- 지금까지 쓰던 **최상위(47층)는 ASR-내용 위주**라 손해 → **31층으로 바꾸니 macro 0.498→0.578, micro 0.937→0.953 동시 상승.**
- **데이터·학습 추가 0**, 게다가 **31층까지만 forward → 추론 ~35% 빨라짐**(정확도·속도 동시 이득).

## 7. 제품용 테스트 문장 (실측 기반)
- **낭독(정형 문장)이 자유발화보다 정확**(top-1 0.74 vs 0.69) → **대본 낭독 방식 권장.**
- 모델이 가장 잘 맞히는(모든 국적 top-5 적중) 추천 문장:
  1. "음악도 매력적이고 드라마 내용도 너무 좋았어요 이 드라마를 보고 한국어를 배워야겠다고 생각했어요"
  2. "추석은 음력 팔 월 십오 일로 설날과 함께 한국을 대표하는 명절이며 송편과 햇과일 등을 먹습니다"
- **top-5(5개 후보) 보여주는 UX**면 다수 사용자가 정답을 봄.

## 8. 배포 현황 & 계획
- **추론은 fairseq 불필요** — HuggingFace `facebook/wav2vec2-xls-r-2b` 기반(깔끔). 학습용 환경과 분리.
- 준비된 산출물: `xlsr_nationality_inference_bundle/` (포터블 헤드 + `app.py` FastAPI 서버 + `DEPLOY_GCP.md` 초보자 가이드).
- **웹/앱 공용 API 1개**로 서빙 가능 (모델은 클라이언트 무관) — 포맷변환(ffmpeg)+CORS만 추가.
- **추론 속도 실측**: GPU(T4) ~1초/요청, **CPU ~20초/요청**(인터랙티브 웹엔 부담 → GPU 권장, 또는 31층-cut+양자화로 단축).
- 비용: T4 VM 월 ~$250~350(미사용 시 정지하면 과금 중단).

## 9. 결론 & 다음 단계
**결론**: 주요 국적(~8~13개)은 잘 분류(top-5 0.95), 소수 국적은 데이터 한계로 어려움. **레이어 선택이 첫 확정 성능 향상**(macro +16%).

**다음 단계 (우선순위)**:
1. **layer 31을 새 baseline으로 확정** + 추론코드/테스트문장 재측정 (정확도·속도 동시 개선)
2. **소수 국적 대응**: ① 신뢰 클래스만 출력 + "불확실/기타" abstain(정직한 배포) ② 표현 disentangle(음색 제거)
3. **근본 해결**: 소수 국적 **실화자 데이터 수집**(다른 AIHub L2-한국어 코퍼스 흡수 등) — macro를 실제로 올리는 유일한 길
4. **제품화**: GPU VM 서빙 + 웹/앱 공용 API + 대본 낭독 UX
