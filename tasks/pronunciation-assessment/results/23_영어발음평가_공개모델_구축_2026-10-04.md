# 한국인 영어 발음 평가 — 공개 모델 조사·구축 (2026-10-04~05)

> 요청(이윤구, 카톡): "영어 발음은 이미 있는 모델이 많을 테니 찾아보고, 기존 모델처럼 입력·출력이 나와야
> 앱에 바로 탑재되니 그 작업을 해 보라."
> 범위: ① 공개 모델 조사 ② 지금 API 형식으로 감싼 영어 엔드포인트 ③ 품질 확인(SpeechSuper 영어와 비교).
> **한국어 API(8932)는 건드리지 않았다.** 영어는 별도 서버(8952)·별도 패키지(`mdd_en`)다.
> 아래 수치는 모두 **코드 리뷰 수정 뒤(v1)** 다. 수정 전(v0) 수치는 §6.

## 결론

1. **그대로 가져다 쓸 수 있는 공개 "발음 평가 모델"은 없다.**
   - 우리 응답(음소 점수, 들린 소리, 단어·문장 점수, 유창성)을 한 번에 내는 공개 가중치가 없다.
     - GOPT: Kaldi 특징이 필요하다.
     - MultiPA: 음소 점수가 없다.
     - CTC-GOP: 라이선스가 없다.
   - 상용 API(SpeechSuper, Azure)는 클라우드 전용이다.
   - 그래서 **공개 음소 인식기**를 가져와 한국어 엔진과 같은 구조로 감쌌다.
     - 인식기: `facebook/wav2vec2-lv-60-espeak-cv-ft`(Apache-2.0, Common Voice CC0)
     - 구조: 표준발음 → CTC → GOP → 점수 보정
     - 점수 보정: 공개 데이터 **speechocean762**(CC BY 4.0, 사람이 매긴 음소·단어·문장 점수)
2. **API 완성 — 요청·응답 형식이 한국어 API와 같다.** 차이는 음소 기호(ARPAbet/IPA)뿐이다.
   - 위치: `deploy/pronunciation-en`(포트 8952, 규격은 `API.md`)
   - 처리 시간: **GPU 중앙값 42 ms**
3. **문장 점수는 중국인 화자 데이터(speechocean762 test)에서 공개 모델(GOPT)과 같은 수준이다**(오차 ±0.05 — §11).
   한국인(037) 기준으로는 낮았는데(발음 0.41, 96±3에 몰림) **§12에서 037 사람 점수로 재보정했다** — 발음 0.61, 화자 5문장 평균 0.83.

   | | 우리 | GOPT |
   |---|---:|---:|
   | 종합 | 0.752 | 0.742 |
   | 유창성 | 0.786 | 0.753 |
   | 운율 | 0.774 | 0.760 |
   | 단어 | 0.573 | 0.533 |
   | 음소 | 0.598 | 0.612 |

   음소만 GOPT보다 약간 낮다.
4. **약점: 한국인의 오류를 잡는 비율이 낮다.**
   - L2-ARCTIC 한국인 4명, 단어 단위로 쟀다.
   - **정밀도 0.60 · 재현율 0.14 · 맞게 읽은 단어 오지적 4.0%.**
   - "틀렸다"고 할 때는 대체로 맞지만, 놓치는 게 많다. 원인은 둘이다(§3).
     - 상업적으로 쓸 수 있는 공개 인식기가 전부 **표준발음 라벨로 학습**됐다.
     - 점수 라벨(speechocean762, 중국어 화자)이 **억양 수준 오류에 관대하다.**
   - 해결에는 **한국인 데이터**가 필요하다. AIHub 037 신청, 또는 사내 녹음과 사람 전사.
5. **SpeechSuper 영어 비교는 아직 못 했다.**
   - 우리 키로 영어 coreType 3종(`sent.eval`, `sent.eval.promax`, `word.eval`)을 1번씩 호출했다.
   - 셋 다 `errId 41030 invalid coreType`이었다. **키에 영어 권한이 없다.**
   - 비교 스크립트는 준비해 두었다(`scripts/eval/compare_speechsuper_en.py`).

**상업적으로 쓸 수 있으면서 실제 L2 발음 전사로 학습한 영어 인식기는 하나도 없다.** 이것이 아래 결과 전체를 좌우한다.

G2P는 CMUdict(BSD)와 g2p_en(Apache, 사전에 없는 단어용)이다.
espeak(GPL)은 쓰지 않는다.
g2p_en이 끌어오는 `distance`(GPL)는 실제로 import되지 않아 설치에서 뺐다.

## 2. 음소 인식기 비교 (같은 조건)

`scripts/eval/en_phone_bakeoff.py` → `scripts/score/en_fit_phone_scorer.py`. 원본은 `$MDD_OUTPUTS/english/{bakeoff,scorer}/`.

| 모델 | 받아쓰기만으로 오류 판별(L2 한국인 음소) P / R / F1 · 오지적 | 음소 점수 PCC(so762) | 단어 PCC | 한국인 오류 AUC | 상업 |
|---|---|---:|---:|---:|---|
| **lv60-espeak** | 0.232 / 0.231 / 0.232 · 7.9% | 0.598 | 0.577 | 0.711 | ○ |
| xlsr53-espeak | 0.236 / 0.331 / 0.276 · 11.2% | **0.622** | **0.599** | 0.736 | △ |
| charsiu-ctc | 0.220 / 0.199 / 0.209 · 7.3% | 0.608 | 0.577 | 0.748 | △ |
| huper | 0.228 / 0.492 / 0.311 · 17.4% | 0.565 | 0.542 | 0.739 | ✕ |
| slplab-l2(한국인 학습) | 0.217 / 0.272 / 0.241 · 10.2% | 0.599 | 0.556 | **0.769** | ✕ |

- **받아쓰기만으로는 다 비슷하게 약하다**(F1 0.21~0.31).
  - 비교: 문헌의 L2-ARCTIC 학습 모델은 F1 0.57~0.72다(L2 데이터로 학습, 비상업).
  - 한국어 엔진에서 본 "표준발음으로 되돌려 적기"와 같은 현상이다.
- **점수(GOP + 회귀)는 모델 간 차이가 작다**(음소 PCC 0.57~0.62).
  - 상업적으로 깨끗한 lv60을 기본으로 했다.
  - xlsr53은 BABEL 라이선스가, charsiu는 가중치 라이선스가 확인되면 교체 후보다. 서버는 `--model`로 바꿀 수 있다.
- 한국인 학습 모델(slplab)이 한국인 AUC가 가장 높다(0.769). **한국인 데이터가 효과가 있다**는 간접 증거다.

## 3. 점수기 — 무엇으로 학습하느냐가 한국인 판별력을 바꿨다

음소 특징 15종은 다음 셋에 문맥(모음, 강세, 단어 안 위치, 기능어)을 더한 것이다(`mdd_en.gop`, `mdd_en.scorer`).
- 강제정렬 GOP 3종
- 정렬 없는 CTC-GOP 3종(Cao et al. 2024)
- 받아쓰기 불일치

이 특징에 HistGradientBoosting을 붙였다. 학습은 speechocean762 train(음소 4.7만 개)으로 했다. 아래는 lv60이다.

| 학습 목표 | so762 음소 PCC | so762 오류 AUC | **한국인 오류 AUC** |
|---|---:|---:|---:|
| 오류 분류: 사람 점수 < 1.0 | 0.587 | 0.928 | 0.633 |
| 오류 분류: < 1.5 | 0.596 | 0.930 | 0.711 |
| **사람 점수(0~2) 회귀 — 채택** | **0.598** | 0.926 | **0.711** |
| 로지스틱(< 1.0) | 0.554 | 0.921 | 0.564 |
| (학습 없이 p_af 하나만) | 0.384 | — | 0.679 |

- **이유: speechocean762 평가자는 "억양은 있지만 맞음"(1점)을 오류로 안 친다.**
  반면 L2-ARCTIC 주석자는 z→s, ð→d, ɛ→æ 같은 억양 수준 대치를 오류로 적는다.
  그래서 엄격한 라벨일수록 한국인 판별력이 오른다.
  - 수정 전(v0)의 추가 실험에서도 같았다: 라벨 < 1.9로 분류하면 한국인 AUC 0.756, 대신 so762 PCC 0.518.
- 회귀는 둘 사이의 균형점이다. GOPT와 같은 학습 목표이기도 하다.
- ⚠️ 이 표의 "한국인 AUC"는 L2-ARCTIC으로 쟀다.
  - 라벨 정의를 고를 때 이 값을 봤으므로 **완전한 미사용 평가는 아니다.** 비교한 후보는 5개였다.
  - 지적 문턱은 so762 train에서만 정했다(아래).

**지적 문턱.** 맞게 발음한 소리(점수 2.0) 중 몇 %가 걸리게 할지로 정한다.
- so762 train의 **화자 단위 5겹 교차 예측** 점수로 잡는다. 학습에 쓴 자리의 점수로 잡으면 실제 오지적이 목표보다 커진다.
- 후보 중 train F1(라벨 < 1.5)이 가장 높은 **5% 문턱(T = 81.7)** 을 골랐다.

| 규칙 | 문턱 | so762 test P / R / F1 · 오지적(점수 2.0 자리) | L2 한국인(음소) P / R / F1 · 오지적 |
|---|---:|---|---|
| 점수 < T, 3% | 75.0 | 0.473 / 0.503 / 0.488 · 3.2% | 0.363 / 0.073 / 0.122 · 1.3% |
| **점수 < T, 5% (채택)** | 81.7 | 0.398 / 0.605 / 0.481 · 5.3% | 0.340 / 0.105 / 0.161 · 2.1% |
| 점수 < T, 10% | 89.2 | 0.305 / 0.752 / 0.434 · 10.4% | 0.278 / 0.151 / 0.196 · 4.1% |
| 점수 < T, 20% | 94.3 | 0.204 / 0.863 / 0.330 · 20.5% | 0.267 / 0.359 / 0.306 · 10.2% |
| 받아쓰기 불일치 + 점수 < 60 (한국어 API 규칙) | 60 | 0.644 / 0.296 / 0.405 · 0.9% | 0.478 / 0.036 / 0.066 · 0.4% |

- so762 라벨은 점수 < 1.5다.
- 한국인 재현율을 올리려면 문턱을 올려야 하고, 그만큼 오지적이 늘어난다.
- **문턱은 제품이 정할 값이다.** 한국인 데이터로 다시 맞추기 전까지는 5%로 둔다.

- 앞뒤 무음을 0.5초로 맞추고, 응답 JSON으로 변환한다.

| 항목 | 값 |
|---|---|
| so762 `overall` vs 사람 종합 | 0.752 |

## 6. 코드 리뷰와 수정 (2026-10-05)

방법: 4개 관점(파이프라인 정확성, 학습·서빙 일치, API 계약, 견고성·규칙)으로 리뷰했다.
나온 지적마다 따로 재현을 시도해 반박되지 않은 26건을 고쳤다. 주요 수정은 다음과 같다.

| 문제 | 영향 | 수정 |
|---|---|---|
| espeak의 두 음소 토큰(ɔːɹ, ɑːɹ, əl …)이 **한 프레임**에만 나옴 | 맞게 읽은 for, or, are가 "모음오류"로 지적됐다. 맞게 발음한 R 앞 모음의 오지적이 11.4%(다른 모음 1.2%) | 구성 음소마다 토큰 확률을 그대로 주고 프레임을 2배로 늘렸다. **R 앞 모음 오지적 11.4% → 2.7%**(다른 모음 3.4%), **모음 뒤 R 10.9% → 3.7%** |
| 녹음이 문장보다 너무 짧으면 특징이 전부 상수 | 읽은 게 적을수록 점수가 **올라갔다**(44 → 64) | 정렬이 불가능하면 400 `too_short`. 가능하면 안 읽은 단어가 '누락'이 된다(점수 94 → 47 → 32) |
| 긴 refText | 정렬 없는 GOP가 음소 수의 제곱으로 커져 GPU 메모리가 터질 수 있다 | 단어 60개 · 음소 240개 상한(400 `reftext_too_long`) + 메모리 예산 단위로 나눠 계산 |
| 강세 있는 IH→IY(ship→sheep)를 맞음으로 처리 | 한국인 대표 오류를 놓침 | 약모음에서만 봐준다 |
| 숫자·악센트·특수 아포스트로피 토큰화 | '1,000' → one zero, café → caf | 숫자는 한 토큰으로(3.14 → three point one four), 유니코드 글자 허용 |

| API | 말소리 비율을 자르기 전 녹음으로 잼(늦게 끈 녹음 거절) · 한글 토큰 → 500 · 오독 단어 점수가 한국어 API와 다름 · `decode_failed` 코드 없음 · 깨진 JSON → 500 · span이 잘린 녹음 기준 | 모두 한국어 API와 같게, 또는 오류 코드로 |

## 9. AIHub 037로 추가 학습 (2026-10-06) — `en037-v1`

**무엇을 했나**
- 출발점: lv60-espeak의 몸통. 출력층은 ARPAbet 39 + blank로 바꿨다.
- 학습 데이터: AIHub 037 PRN(한국인 842명, 7만 1,889발화, 123시간)
- 정답: 라벨의 **phonemeText**. AIHub 자동 인식기가 만든 "들린 소리"이고 사람 전사가 아니다.
- 학습량: 8,000걸음(약 3바퀴, A100 40분)
- 검증: 037에서 화자 40명을 따로 뗐다. 037 공식 검증 세트는 학습과 화자가 같아서 쓰지 않았다.
- 재현: `scripts/data/build_037_ctc_manifest.py` → `scripts/train/en_finetune_ctc.py`
- 체크포인트: `$SPEECH_AI_DATA/checkpoints/en_ctc_037_v1/best`(→ step_8000)

**받아쓰기(CTC 출력) 자체는 "들린 그대로"가 되지 않았다**

L2-ARCTIC 한국인 600문장(사람 주석)에서 받아쓰기만으로 판별한 결과다.

| | 정밀도 | 재현율 | F1 | 오지적 | 사람 전사 대비 PER |
|---|---:|---:|---:|---:|---:|
| lv60(원래) | 0.232 | 0.231 | 0.232 | 7.9% | 0.179 |
| en037-v1 | 0.232 | 0.239 | 0.235 | 8.2% | 0.169 |

- 037 기계 라벨과의 오류율은 0.38 → 0.15로 내려갔다. 그 라벨은 잘 배웠다.
- 원인: 기계 라벨의 "틀림"은 사람이 듣는 한국인 오류와 종류가 다르다.

  | | 많은 오류 |
  |---|---|
  | 사람(L2-ARCTIC 한국인) | ð→d 18%, z→s 15%, ɪ→iː 6% |
  | 037 기계 라벨 | ɪ↔i, ɪ↔ə 같은 모음 혼동이 흩어져 있다. z→s 1.2%와 **s→z 1.2%가 같은 비율**이다 |

  반대 방향 오류가 같은 비율로 나온다는 것은, 기계 라벨의 "틀림"이 대부분 인식 잡음이라는 뜻이다.

**그런데 점수(확신도) 쪽은 확실히 좋아졌다**

학습 후 모델의 음소 사후확률로 GOP 특징을 다시 만들고, 점수기를 다시 학습했다.

| | lv60 | **en037-v1** | 참고 |
|---|---:|---:|---|
| 음소 PCC(so762) | 0.598 | **0.641** | GOPT 0.612 |
| 단어 PCC(so762) | 0.577 | **0.623** | 서비스 경로 0.573 → 0.622 |
| **한국인 오류 AUC**(L2, 음소) | 0.711 | **0.769** | 한국인 학습 모델 slplab(상업 불가) 0.769와 같다 |
| 문장 종합 · 유창성 · 운율(서비스 경로) | 0.752 · 0.786 · 0.774 | 0.756 · 0.785 · 0.768 | 그대로 |

같은 오지적 수준에서 더 많이 찾는다(L2 한국인, 음소 단위).

| 문턱 | lv60 정밀도 / 재현율 · 오지적 | en037-v1 정밀도 / 재현율 · 오지적 |
|---|---|---|
| 5% (기본) | 0.340 / 0.105 · 2.1% | 0.385 / 0.092 · **1.5%** |
| 10% | 0.278 / 0.151 · 4.1% | 0.343 / 0.154 · **3.1%** |
| 20% | 0.267 / 0.359 · 10.2% | **0.345 / 0.398 · 7.8%** |

서비스 경로, 단어 단위, 기본 문턱: **정밀도 0.596 → 0.709, 오지적 4.0% → 1.8%**, 재현율 0.143 → 0.108.
같은 문턱에서는 더 보수적으로 짚는다. 재현율을 원하면 문턱을 올리면 되고, 그래도 lv60보다 오지적이 적다.

**결정**
- 서버(8952) 기본 모델을 `en037-v1`로 바꿨다. lv60보다 모든 점수 지표가 같거나 좋다.
  - 라이선스: lv60(Apache-2.0) + AIHub 037. 학습 이용은 가능하고, 서비스에는 출처 표기가 필요하다.
- **"들린 그대로" 받아쓰기는 여전히 안 된다.** 이 부분을 고치려면 사람이 들린 대로 적은 한국인 영어 라벨이 필요하다(§7-2 사람 전사).

## 10. 합성 데이터 + 자가 학습으로 "들린 그대로" 받아쓰기 (2026-10-06)

**문제.** 037 기계 라벨은 자동으로 만든 것이다. 037 논문(LREC 2024)에 이렇게 적혀 있다.
> "음성학 전문가를 구하기 어렵고 사람 전사 오류율이 높아, 음성인식(STT) 결과에서 음소를 뽑아 자동 태깅했다."

그래서 한국인 특유의 오류가 거의 들어 있지 않다.
게다가 공개 모델은 **문맥으로 단어를 짐작해 사전 발음을 적는다.**
- 확인: TTS로 "I **s**ink **d**e we**dd**er is **b**ery nice"를 읽혔다.
- 문장 전체를 넣으면 "think the weather is very"로 고쳐 적었다.
- 같은 녹음의 앞 1초만 넣으면 "S … T"로 제대로 들었다.

**방법**
1. **합성:** 한국인 대표 오류를 일부러 넣어 TTS로 읽힌 녹음 3만 4,371개(40.8시간)를 만들었다.
   - TTS: Kokoro-82M(Apache-2.0, 음소 입력)
   - 규칙: ð→d · z→s/ʤ · θ→s/t · f→p · v→b · r↔l · s→ʃ · 어두 무성화 · ɪ↔iː · ɛ↔æ · oʊ→ɔ · ʊ→u · ɝ→ʌ · 끝소리 모음 삽입·탈락
     (문헌 기반, `mdd_en.l1_ko_errors`)
   - 목소리: 영어 28개
   - 문장: 037과 speechocean762 문장 1만 1,797개
   - 정답: 실제로 읽힌 소리
   - 스크립트: `scripts/data/build_synth_texts.py` · `synth_ko_errors_kokoro.py`
2. **학습 비교**(모두 en037-v1에서 이어 3,000걸음):
   - A = 합성만
   - B = 합성 + 037 기계 라벨(0.3배)
   - D = 합성 + **037 자가 학습 의사라벨**
3. **D의 의사라벨**(`scripts/data/pseudo_label_037.py`):
   - A(1,000걸음)가 037 실제 녹음 2만 개의 대표 오류 자리마다 "표준 / 한국인식"을 CTC 우도로 비교한다.
   - 문턱은 **사람 라벨 없이** 정했다. 037에서 사람 조음 점수가 4.5점 이상인 화자에게 규칙마다 5%만 걸리게 했다
     (`scripts/score/en_calibrate_pair_margins.py`).
   - 후보 자리의 10%가 "한국인식"으로 판정됐다.

**결과 — 받아쓰기(들린 그대로)**

평가 기준은 L2-ARCTIC 한국인 600문장(사람 주석)이다.

| | en037-v1(전) | **A** 합성만 | B 합성+037 | **D** 합성+자가학습 |
|---|---:|---:|---:|---:|
| 오류 재현율 | 0.239 | **0.597** | 0.318 | 0.277 |
| 정밀도 | 0.232 | **0.324** | 0.284 | 0.312 |
| F1 | 0.235 | **0.419** | 0.300 | 0.293 |
| 오지적(맞게 읽은 소리) | 8.2% | 13.0% | 8.3% | **6.3%** |
| 사람 전사 대비 PER | 0.169 | 0.184 | 0.162 | **0.144** |
| 한국인 대표 오류 재현 / 헛지적 | 0.109 / 2.2% | **0.607** / 12.1% | 0.214 / 3.2% | 0.270 / 3.9% |
| 합성 검증: 넣은 오류를 그대로 적은 비율 | 0.42 | 0.94 | 0.88 | 0.90 |

- **A:** 대표 오류를 5.5배 더 그대로 적는다. 정밀도는 학습 전과 같다(대표 오류 기준 0.39 vs 0.38).
  - 잘 되는 오류(재현 / 헛지적): f→p 0.43~0.71 / 2%, v→b 0.79 / 12%, θ→s 0.67 / 9%, r→l 0.50 / 0.5%, l→r 0.67 / 1%
  - ð·z는 맞게 읽은 소리까지 틀렸다고 한다(ð 74%, z 33%).
- **D:** 사람 전사에 가장 가깝다(PER 0.144). 오지적은 학습 전보다 적은데, 대표 오류는 2.5배 더 찾는다.

**ð→d는 아직 안 된다.**
- 오류별 구분력(AUC, 문턱과 무관)을 쟀다(`scripts/eval/en_pair_auc_l2.py`).

  | 오류 | 학습 전 → 합성 학습 후(A) |
  |---|---|
  | ð→d | **0.50 → 0.50** |
  | z→s | 0.59 → 0.66 |
  | v→b | 0.77 → 0.91 |
  | oʊ→ɔ | 0.72 → 0.81 |
  | 전체 | 0.73 → 0.82 |

- ð→d는 학습 전후 모두 동전 던지기 수준이다.
  - L2-ARCTIC에서 한국인 화자의 ð 623개 중 357개(57%)가 d로 주석됐다.
  - 모델이 보기에 두 그룹의 소리 차이가 없다. 사람 판정이 미세하거나 일관되지 않은 것으로 보인다.

**결과 — 서비스 경로**(점수기 + 지적 문턱. 단어 단위, L2 한국인)

| 같은 오지적에서 | en037-v1 | A | B | D |
|---|---|---|---|---|
| 오지적 ≈ 4.5% | 재현 0.19 · 정밀 0.63 | **0.21 · 0.66** | 0.19~0.24 · 0.65 | 0.19 · 0.63 |
| 오지적 ≈ 8% | 0.27 · 0.62(6.9%) | **0.32 · 0.61**(8.5%) | 0.31 · 0.62(7.8%) | 0.26 · 0.61(6.8%) |

- 점수기를 거친 "틀린 단어 표시"는 조금만 좋아졌다.
- 음소 단위 한국인 오류 AUC: en037 0.769 → A **0.812** · B 0.793 · D 0.789
- 문장 종합 PCC(so762): en037 0.754 → A **0.772**(GOPT 0.742)

**결정과 남은 일**
- 서버 기본 모델을 **D**(`synth-d`)로 바꿨다. 사람 전사에 가장 가깝고 오지적이 가장 적다.
  - 대표 오류를 더 많이 잡는 **A**(`synth-a`)는 `--model synth-a`로 쓸 수 있다.
- ⚠️ 평가는 L2-ARCTIC 한국인 **4명(대학원생, 상급)** 뿐이다. 앱 사용자(10대·초급 포함)에서는 달라질 수 있다.
- **다음 단계:** 사람이 "예/아니오"로 확인한 한국인 라벨을 소량(오류 종류마다 수백 개) 만든다.
  - 쓰임 1: ð·z 같은 애매한 오류의 판정 문턱을 우리 사용자 기준으로 맞춘다.
  - 쓰임 2: 그 라벨로 자가 학습을 한 번 더 돌린다.
- SpeechSuper 영어 비교는 권한을 받은 뒤 진행한다.

## 11. 전문가 리뷰와 수정 (2026-10-06)

리뷰는 5개 분야(음성학·L2 습득, 평가 방법론, 음성인식·ML, 발음평가 점수 체계, 제품·거버넌스)에서 했다.
지적마다 검증자가 코드·데이터로 다시 확인했고, 반박된 것은 뺐다.

**가장 크게 놓친 것:** 받아쓰기(들린 소리)만 고쳤고, 앱이 받는 "틀린 곳 표시"와 점수는 한국인 기준으로 재지 않았다.

**바로잡은 수치**

## 12. 문장 점수를 한국인 사람 점수로 재보정 (2026-10-10) — `scorer/synth-d-ko037`

§11 리뷰 1순위. speechocean762(중국인 학습자) 기준 문장 점수기는 한국인 037에서 `pronunciation`이 96±3에 몰려 사람을 거의 가르지 못했다.

**방법** (`mdd_en.sent_score` — 학습 스크립트와 서버가 같은 특징 함수를 쓴다)
- 데이터: 037 PRN(낭독) 882명 × 화자당 30발화 = **26,444발화**(문장 1,946개).
  - 서버와 같은 경로(앞뒤 무음 맞추기 → synth-d 엔진, 지적 규칙 v2)로 채점해 특징을 뽑았다(`en_extract_037_feats.py`, GPU 3조각 27분).
  - 037에서 읽은 칸은 녹음, 문장, 화자 번호(분할용), 사람 점수뿐이다. 나이·수준은 읽지 않았다.
- 특징 34개: 문장 특징 23개, speechocean762 문장 예측 5개, 음소 점수 기반 발음, 지적·한국인 대표 오류 비율 5개.
- 목표: 사람 조음 → `pronunciation`, 사람 운율 → `rhythm`.
  - 회귀기는 부스팅(HGB), 선형, 둘의 평균 중 화자 5겹 상관이 가장 높은 것을 골랐다.
  - 조음 기준 0.614 / 0.595 / 0.613 → **HGB**.
- `fluency`: 037에 유창성 라벨이 없어 speechocean762 예측(×10) 그대로다.
- `overall` = 0.6·발음 + 0.2·유창 + 0.2·운율. 한국어 API와 같은 비율이다.
- 눈금
  - 회귀 예측은 평균 쪽으로 오그라든다. 예측 분포를 **사람 점수 분포의 평균·폭으로 되편 뒤 ×20**으로 바꿨다(사람 4점 ≈ 80).
  - 백분위(한국어 API 유창·이해 방식)는 쓰지 않았다. 037 사람 점수는 평균 3.8/5로 높아서, 사람이 4점 준 발화가 45 근처로 내려간다.
  - `--scale pct`로 바꿀 수 있고, 두 눈금은 모두 점수기 파일에 들어 있다.

**결과** — 사람 점수와의 상관. 모두 학습에 없던 화자에서 쟀다.

- SPK는 자유 발화이고 사람 점수도 말하기 전반 1개라 잣대가 다르다. 그래서 이전 대 지금으로 읽는다.
  - 다섯 과제 모두 올랐다.
  - SPK03은 205건이고 −0.31 → −0.01이다.

- 단어·음소 점수와 지적은 바뀌지 않았다. speechocean762 단어 상관 0.618, L2-ARCTIC 단어 정밀도·재현율 0.656 / 0.157 그대로다.

**한계**
