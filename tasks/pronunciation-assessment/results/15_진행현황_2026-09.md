TAG(사람이 들은 실제 발음)를 CTC 정답으로 쓴다. **표준발음(KoG2P·LAB)은 정답으로 쓰지 않는다.**
쓰는 순간 모델이 "고쳐 적기"를 배우기 때문이다.

### 3-2. 학습 (2단계)

```
1단계  한국인 발화(KsponSpeech 691h)로 한국어 자모 CTC 를 먼저 익힌다
2단계  외국인 TAG 전체로 적응 — 오발음 40% · 한국인 10% 섞기(망각 방지) · lr 1e-5 · 2천 스텝마다 저장
```

체크포인트 20개를 모두 평가해 **제품 지표 순서**(헛지적 → JER → 보존 → 되돌림)로 하나를 골랐다.

### 3-3. 백본 비교

| 백본 | 크기 | 1단계 스텝 | 한국인 dev PER |
|---|--:|--:|--:|
| XLS-R 300m | 300M | 10,000 | 10.91% |
| XLS-R 300m | 300M | 40,000 | 6.55% |
| XLS-R 1B | 965M | 20,000 | 6.05% |
| **w2v-BERT 2.0** | 581M | **10,000** | **6.42%** |

- XLS-R 1B 는 한국인 발화만 좋아졌고 **외국인 발화에서는 오히려 나빴다**(안 본 문항 JER 18.1%).
- w2v-BERT 2.0 은 **1/4 스텝으로 XLS-R 300m 4만 스텝을 따라잡았고**, 2단계 후 모든 지표에서 앞섰다.
- 학습은 fairseq 이 아니라 HuggingFace 로 했다(구조가 달라 필터뱅크 입력). 레시피는 옮겼으나 **마스킹(SpecAugment)은
  꺼진 채로 학습됐다** — w2v-BERT 원본 config 가 `apply_spec_augment=False` 이고 학습 스크립트가 이를 켜지 않았다
  (2026-09-28 확인). XLS-R(fairseq, mask 0.5)과 이 점이 다르다.

한국인 dev PER 은 w2v-BERT 6.57%, FINAL v2 7.17%.

#### 이 표의 조건 — 「안 본 문항」이 아니다 (2026-09-26 정정)

이 23,562발화는 `manifest_foreign_clean_v2` 의 `test_unseen` 이다. **그 이름은 예전 fcv2 레시피에서
문항 30종을 학습에서 뺐을 때 붙은 것이고, 위 표의 모델들에는 해당하지 않는다.** 확인한 사실:

| 확인 | 결과 |
|---|---|
| 그 30문항이 Stage 2 학습셋(`manifest_full_tag_replay10` train)에 있나 | **30/30 전부 있다 · 해당 발화 233,312건** |
| 화자는 겹치나 | **0명** (test_unseen 1,168명 ↔ train 9,656명) |
| 기존 서비스 모델(OLD)은 안 봤나 | 그쪽도 287문항을 모두 학습했다(`08_문장암기_일반화.md` §3) |

따라서 실질 조건은 **「본 문항 · 안 본 화자」의 30문항 부분집합**이고, 184,074발화 표와 같은 종류다.
두 표의 수치가 거의 같은 것(F1 0.4964 ↔ 0.4928)도 이 때문이다 — 문항이 정말 처음이라면
`08_문장암기_일반화.md` 처럼 가중 F1 0.9509 → 0.8218 수준으로 떨어진다.

**w2v-BERT 의 안 본 문장 성능은 아직 측정하지 않았다.** 측정하려면 문항을 뺀 매니페스트로
다시 학습해야 한다(`build_sentence_holdout.py`). 대외 자료에 「안 본 문항」으로 쓰지 말 것.

### 4-2. 외부 공개 모델 검증

`slplab/wav2vec2-XLSR-300m_KoreanPhonene_spoken_by_foreigners`(모델 카드 PER 3.15%)를 같은 잣대로 평가했다.

- 안 본 문항 PER 5.10% 로 낮아 보이지만 **오발음의 78.9% 를 표준발음으로 덮는다**(MDD F1 0.268).
- 처음 보는 문장(한국인 dev)에서는 **PER 63.7%** 로 무너진다 → 학습 문장을 외운 모델.

**결론: 대안으로 쓸 수 없다.** PER 만 보면 좋아 보이는 전형적인 사례다.

### 4-4. 음소별 점수 (신규)

"초성 ㅊ 54점 · 받침 ㅇ 66점" 같은 화면을 만들기 위한 것. 기존 GOP 정의는 **95.8% 가 0 으로 뭉쳐** 쓸 수 없었다.

| | 기존(maxnorm) | **신규(margin)** |
|---|--:|--:|
| 같은 값으로 뭉치는 비율 | 95.8% | 0% |
| 오류 판별력(AUC, 자리 단위) | 0.7397 | **0.9370** |

- 자리를 **초성/받침/모음 × 자모**(43묶음)로 나누고, 전체 화자 분포로 **백분위 → 0~100** 환산한다.
- 어려운 소리: 모음 ㅢ · 초성 ㅉ ㅃ ㄲ ㅋ ㄸ ㅌ ㅍ · 받침 ㄷ / 쉬운 소리: 모음 ㅏ ㅣ ㅐ ㅔ · 초성 ㅁ ㄹ.
- **한계**: 사람·소리 단위로 묶으면 실제 오류율과의 상관이 **-0.24** 로 약하다.
  점수 30 미만 묶음의 실제 오류율 7.6% vs 70 초과 3.4% — 방향은 맞지만 숫자를 실력으로 읽으면 안 된다.
  화면에서는 "주의할 소리" 순위 정도로 쓰는 것이 안전하다.

## 5. API · 데모 (2026-09-27 기준)

### 5-1. 발음 평가 API — 포트 8932 (SpeechSuper `sent.eval.kr` 호환)

외부 API(SpeechSuper)를 쓰던 코드가 **주소만 바꿔** 우리 엔진을 부를 수 있게 만든 것이다.
요청·응답·오류 코드·점수 읽는 법은 `deploy/pronunciation-demo/API.md` 에 있다.

| 항목 | 값 |
|---|---|
| 주소 | `POST http://<서버>:8932/sent.eval.kr` (multipart: 오디오 + JSON) |
| 요청 | SpeechSuper 형식 그대로(`start.param.request.refText` · `tokenId`) 또는 간편형(`refText` · `audio`) |
| 인증 | 토큰 — `Authorization: Bearer` · `X-API-Key` · 폼 `token` · `?token` 중 하나. 값은 저장소 `.env` 의 `MDD_API_TOKEN`(git 제외). **채팅·문서에 적지 않고 따로 전달한다** |
| 공개 범위 | `0.0.0.0` 바인딩 + 토큰. **사내망까지만** — AIHub 로 학습한 모델이라 외부 공개 금지 |
| 응답 | `result.{overall, pronunciation, fluency, rhythm, comprehensibility, words[]}`. 음소마다 `alpha`(KoG2P 기호, 예 `k0`) · `alpha_jamo` · `actual`/`actual_jamo`(실제로 낸 소리) · `errorType` |
| 그 밖의 경로 | `GET /health` · `/speechsuper.html`(API 확인 화면) · `/`(통합 데모) · `/session` · `/reset` · `/sentences` · `/countries` |
| 녹음 저장 | `$MDD_OUTPUTS/webmic_takes/` — 요청마다 wav + 점수 원값 |

SpeechSuper 와 다른 점(실측 대조, `16_SpeechSuper_API_비교_2026-09-25.md`): 글자 점수 위치(`words[].score` vs
`words[].scores.pronunciation`), 음소 표기(`alpha` 가 우리는 **내야 할 소리**의 KoG2P 기호, 그쪽은 한글이며 낸 소리가 섞임).

**점수 규칙** (근거는 API.md §6)

| 칸 | 계산 | 파일 |
|---|---|---|
| 음소 `pronunciation` | (1 − 그 소리가 틀렸을 확률) × 100 | `score_phoneme/calibration.json` |
| `pronunciation` | 글자 점수 평균(= 음소 점수 평균) | — |
| `fluency` | 말 속도·쉼만 보는 규칙(발음과 독립) | `score_phoneme/fluency_rule.json` |
| `rhythm` · `comprehensibility` | 발화 1개에서는 `null`(신뢰도 낮음). 세션(5발화+)에서만 | — |
| `overall` | 0.6·발음 + 0.2·유창 + 0.2·이해(없는 칸은 빼고 비율 유지) | — |
| 사람 점수 예측 원값 | `_meta` 로 함께 보냄. 학습자 분포 백분위로 환산 | `score_phoneme/utt_percentile.json` |
| 0점 | `null` 로 보낸다(평균은 0 을 넣고 계산한 뒤 바꾼다) | — |
| 지적(`errorType`) | 전사가 표준발음과 달라도 그 자리 점수가 60 이상이면 지적하지 않고 `uncertain: true` | — |
| 입력 거절 | 말소리 1초 미만 또는 30% 미만 → HTTP 400 `low_speech` | — |

## 8. 남은 한계

1. **학습 문장이 226종뿐이다.** 문장 다양성이 유일하게 검증된 처방인데(격차 −43%), 실제 발음 라벨이 달린
   다양한 문장이 없다. AIHub `Speech`(65만 발화·39.8만 문장)와 131번 데이터는 **철자 전사뿐**이라 그대로 쓸 수 없다.
2. **오발음의 절반을 놓친다.** Recall 0.50. 사용자가 틀렸는데 "잘했어요"가 나올 수 있다.
3. **헛지적 2.21%** — 10문장 읽으면 두 번쯤 억울한 지적이 난다. 허용 발음('의'→[에]) 처리는 아직 안 했다.
4. **음소별 점수의 근거가 약하다**(상관 −0.24). 숫자보다 순위로 쓰는 편이 안전하다.
5. **억양·강세는 평가하지 못한다.** 자모 단위 소리만 본다.
6. **어휘·문법 점수는 범위 밖이다.** 공식 팩에 모델과 가중치가 있으나 TensorFlow 환경과 한국어 음성인식기가 따로 필요하다.
7. **서비스 운영 요소 미비** — 순차 처리, 세션이 메모리에만 존재, CPU 추론 속도 미측정.
   (토큰 인증과 SpeechSuper 호환 형식은 2026-09-27 기준 8932 에 적용됐다 — §5-1)
