# 실험 기록 — 발음 진단·평가

**아래 대표 성능표는 과거 XLS-R `tag_all_lar` 실험 기준이다.** 현재 NPU 서비스 모델은 M3 `w2vbert_synth_tense_v2/step_3000`이다(마지막 원격 확인 2026-10-25 KST, 문서 갱신 10월 29일). [현재 서비스 모델](../../../docs/발음평가_현재_서비스_모델.md)과 [최신 진단·후속 실험](../../../docs/발음평가_진단누락정보_감사_2026-10-26.md)을 구분해 참고한다.

문서에 쓰인 수치가 **어느 실험에서 나왔는지** 여기서 확인한다.
원본 JSON 87개 중 당시 보고 근거를 찾기 쉽도록 **주제별로 5개 파일에 병합**했다.
각 항목은 `source` 키에 원본 파일명을 남겨 두었다.

## 한눈에 — 과거 XLS-R 보고 수치

| 무엇 | 값 | 요건 | 파일 |
|---|--:|--:|---|
| **MDD weighted F1** (공식 채점 지표) | **0.9547** | 0.70 | `01_mdd_모델별성능.json` → `tag_all_lar` |
| 오류 클래스 F1 | 0.4319 | – | 동일 |
| 전사 PER | 0.0471 | – | `02_mdd_보조검증.json` |
| **발음숙달 PCC** (전체 발화) | **0.6622** | 0.60 | `03_점수_3종.json` |
| **이해가능 PCC** (전체 발화) | **0.6825** | 0.60 | 동일 |
| **유창성 PCC** (전체 발화) | **0.7618** | 0.60 | 동일 |
| 〃 **30발화 집계** (제품 운영 조건) | **0.6455 / 0.6707 / 0.7615** | 0.60 | 동일 |

> **PCC 는 집계 기준을 반드시 함께 적는다.** 대표값 0.6622/0.6825/0.7618 은 화자의
> **전체 발화**(`spk_all`, ~150발화) 기준이다. 제품은 20~30문장을 모아 점수를 내므로
> 운영 조건은 **30발화 집계**(`spk30`) = 0.6455 / 0.6707 / 0.7615 이다.
> **어느 기준이든 3개 차원 모두 0.60 을 넘는다.**
> ⚠️ `03_점수_3종.json` 의 `채택_화자단위` 는 메타데이터에 `max_utts: 30` 이라 적혀 있으나
> 그 안의 `v2_gbm_utt` 값은 실제로 **`spk_all`** 이다 (`gop_calibrate_v2.py` 가 상한을
> 적용하지 않는다 → 아래 "알려진 결함"). 두 실행(`채택_화자단위` cap 30 /
> `전체_변형비교` cap 100000)에서 `v2_gbm_utt` 가 **똑같이 0.6622** 인 것이 그 증거다.
> 집계 기준별 정확한 값은 `발화단위` 항목(`utt` / `spk30` / `spk_all`)을 볼 것.

> **[교차감사 통과분] 고정 정답지 재채점** (2026-07-30, 감사 판정은 `07_감사_고정정답지.md`).
> 기존 채점기는 정답을 만들 때 모델 예측까지 함께 정렬해, 같은 test 셋인데도 채점 위치가
> 모델마다 최대 2,014개, 정답 오류 개수가 43개 달랐다. 정답지를 canonical 축에 고정하면
> (`scripts/eval/mdd_eval_fixedref.py`) 이 의존이 사라진다.
>
> **성립하는 것** — 같은 매니페스트(`manifest_tag_all_lar`)를 쓰는 **6개** 변형에서
> 채점 위치·정답 개수 편차 **0**(1,787,938 / 67,982). 비교 가능한 어떤 쌍도 순위가 뒤집히지
> 않았고, 게이트 0.70 은 그대로 통과한다. 결과는 `outputs/fixedref_*.json`.
>
> **성립하지 않는 것** — ① `tag_combined` 은 **다른 매니페스트**(104,211발화 / 42,407오류)라
> "7개 편차 0" 은 거짓이다. ② "옛 방식이 특정 모델을 편들지 않았다" 는 순위 무역전에서
> 따라 나오지 않는다(모델별 이동폭이 0.0024 만큼 다르다). ③ 이 축은 **삽입을 채점하지 않아**
> 참조 편집연산의 91.5% 만 덮는다(치환 57,082 + 삭제 10,900 = 67,982, 삽입 6,311 제외).
> ④ 정확한 값 67,982 는 edlib 타이브레이크 산물이다(등가 최적 경로 범위 67,977~68,279).
> 모델 간 동일성만 진짜 불변량이다.
>
> 대외 수치는 기존 0.9547 을 유지한다 — 잣대가 다르므로 직접 비교 대상이 아니다.

> **weighted F1 0.9547 과 오류 F1 0.4319 는 둘 다 사실이다.** 공식 지표는 정상 위치
> (전체의 **95.86%** — 1,725,286 / 1,799,725)를 포함해 계산한다.
> 그래서 전부 "정상"으로 찍기만 해도 weighted F1 **0.9384** 가 나온다.
> **0.9547 의 실제 개선폭은 +0.0163 이다.** 제품 관점의 "지적 능력"은 0.43 이다.
> 보고에는 공식 지표를 쓰되, 질문이 오면 0.43 과 이 베이스라인을 숨기지 않는다.

> **점수는 화자 단위로만 유효하다.** 발화 1개 PCC 는 발음·이해도 **≈0.43**,
> 유창성 **0.607** 이고 20~30문장 모아야 포화한다.

## 파일별 안내

### `01_mdd_모델별성능.json` — 모델 계보 비교

TAG(전문가 음소 전사) 잣대 weighted F1. 같은 test 셋으로 잰 7개 변형.

```
xlsr2_300m (공개 사전학습)
   └─ tag_all           밑바닥 학습 50k 스텝
        └─ tag_all_lar  LAR 이어학습 15k 스텝   ← 이 성능표의 기준 모델
```

`tag_all_native` / `errup` / `omniw2v` / `omniw2v_46k` 는 개선 시도 변형이고,
`tag_combined` 는 초기 결합 실험이다. **채택된 건 `tag_all_lar` 하나다.**

### `02_mdd_보조검증.json` — 숫자 뒤에 붙는 조건들

| 항목 | 왜 봐야 하나 |
|---|---|
| `오발음_보존율` | **0.514** — 오발음의 절반만 보존되고 나머지는 표준으로 복원된다. 오류 F1 0.43 의 직접 원인 |
| `화자누출_영향` | train↔test 화자 502명이 겹치지만 실측 영향 **+0.0000**. 누출 없는 모델에서도 같은 격차가 나온다 |
| `단어누락_검출` | F1 0.682, 267,662발화 전수 |

### `03_점수_3종.json` — PCC

동결된 MDD 모델의 **부산물 특징 41종 + 보정기(GBM)만** 학습했다. 추가 모델 0개.
`전체_변형비교` 에 v1-ridge → v2-ridge → v2-gbm → v2-gbm-utt 개선 과정이 다 들어 있다.

### `04_공식팩_검증.json` — 공식 팩을 왜 안 썼나

액면 PCC 0.94 로 우리(0.66)보다 훨씬 높다. 그런데 **학습 화자 명단이 공개되지 않아**
우리 test 화자가 거기 포함됐는지 확인할 수 없다. 검증 가능한 조건에서 재보면:

```
자기 언어권 (화자 중복 의심)   0.938
가중치 4개 평균(수프)           0.565
다른 언어권 (미학습 보장)       0.330   ← 우리 0.662 보다 낮다
```

화자를 외울 여지를 뺄수록 정확히 그만큼 떨어진다.

gold 잣대로 재면 **공식 모델도 F1 0.42 로 떨어진다** — 모델이 아니라 잣대가 틀린 것.
같은 조건(데이터셋 041, 52,948발화, 교정 스크립트 `mdd_eval_official2.py`, `tol0`)에서:

```
공식  checkpoint_mdd_eu.pt   gold core/tol0  F1 0.4196   ← TAG 로는 0.965
우리  checkpoint_best.pt     gold core/tol0  F1 0.2235
```

⚠️ **이 번들에는 위 공식 수치가 아직 없다.** 근거 파일은 저장소 밖
`$MDD_OUTPUTS/eval_official2_041.json` 이고, `04_공식팩_검증.json` 에 병합되지 않았다.

번들의 `gold잣대_대조` 항목은 **공식 모델이 아니라 우리 `checkpoint_best.pt`**(0.2235)이므로
"공식 0.96 → 0.42" 의 근거로 인용하면 안 된다. 번들의 `공식MDD_041`(F1 `.3077`)은 같은 공식
모델을 **교정 전 스크립트로** 잰 별개 수치다. → 조치: 교정본을 번들에 병합할 것.

### `05_GOP_진단.json` — 음소별 점수의 한계와 여지

| 항목 | 결론 |
|---|---|

| `성능_상한` | 진짜 오류의 **59.2%를 인식기가 자동 교정**해 버린다. GOP 수식 문제가 아니다 |
| `재학습_여지` | 놓친 오류에서 전문가가 들은 음소의 **중앙값 순위 2위, top-3 90.2%**(top-1 은 0.4%). 음향 정보는 있고 결정 경계가 문제 |
| `디코딩_편향` | 경계 문제인지 표현 문제인지 가르는 스윕 |

### `06_실험감사.md/json` · `07_감사_고정정답지.md` — 교차모델 무결성 감사

Codex(`gpt-5.6-sol`)가 평가 코드와 결과 파일을 직접 읽고 판정한 기록.
실행자는 경로만 넘기고 판정에 참여하지 않는다(self-acquittal 방지).
06 은 발음 트랙 전체, 07 은 2026-07-30 에 새로 만든 채점기 두 개가 대상이다.

### `08_문장암기_일반화.md` — ⭐ 근본 원인 규명

**학습셋이 287문장뿐이고 문장당 5,398회 반복되어, 모델이 음향을 듣는 대신
문장을 식별해 외운 표준발음을 출력한다.** 오발음 되돌림(59.0%)의 주원인.

```
홀드아웃 실험 — 30문장을 학습에서 빼고 재학습
  본 문장 231종    되돌림 61.8%  오탐  1.93%  weighted F1 0.9509
  안 본 문장 30종  되돌림 22.1%  오탐 25.31%  weighted F1 0.8218

처방 — 문장당 상한 + 원어민 병합 (287종 → 25,507종)
  일반화 격차 −43% · 안 본 문장 오탐 −33% · 본 문장 되돌림 61.8% → 54.8%
```

**`weighted F1 0.9547` 은 학습에 사용한 287문장 범위 안의 값이다.**
후처리·재가중·디코딩 편향은 이 문제를 못 고친다(전부 실측으로 실패 확인).
같은 문서에 "MDD 개선 → 점수(PCC) 전달률 약 1/8" 실측도 있다.

## 재생성

```bash
cd <저장소 루트> && source tools/env.sh
T=tasks/pronunciation-assessment

# MDD 주 평가 (예측 캐시 있으면 CPU 몇 분)
python $T/scripts/eval/mdd_eval_tag71.py \
    --manifest $MDD_OUTPUTS/manifest_tag_all_lar \
    --preds    $MDD_OUTPUTS/eval_tag_all_lar_preds.jsonl \
    --out      $MDD_OUTPUTS/eval_tag71_all_lar.json

python $T/scripts/eval/check_b2_preservation.py     # 보존율
python $T/scripts/score/gop_calibrate_v2.py         # 점수 3종
```

원본 JSON 87개는 `$MDD_OUTPUTS/` 에 보존한 기록이다. **여기 5개는 그중 당시 보고에 사용한 결과를 추린 사본이다.**
예측 캐시(`*_preds.jsonl`, 311 MB)와 GOP 특징 캐시(317 MB)는 저장소에 넣지 않는다 —
기록이 아니라 데이터이고, 지우면 GPU 재디코드에 수시간이 든다.
