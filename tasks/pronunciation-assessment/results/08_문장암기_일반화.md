# 문장 암기와 일반화 — 근본 원인 규명

> **2026년 7~8월 XLS-R 실험 기록이다.** 본문의 운영·성능·원인 해석은 당시 조건을 따른다. 현재 M3 운영 모델은 [서비스 모델 명세](../../../docs/발음평가_현재_서비스_모델.md), 후속 일반화 진단은 [10월 감사·통제 실험](../../../docs/발음평가_진단누락정보_감사_2026-10-26.md)을 참고한다. 문서 안내 갱신: 2026-10-29.

**기간**: 2026-07-30 ~ 08-01
**결론**: 학습셋이 **287개 문장뿐**이고 문장당 5,398회 반복되어, 모델이 음향을 듣는 대신
**문장을 식별해 외운 표준발음을 출력하는 지름길**을 배웠다. 이것이 오발음 되돌림의 주원인이다.

---

## 1. 시작 — 데모에서의 위화감

일부러 틀리게 발음했는데 모델이 표준발음으로 받아쓰는 현상. 실측하니:

```
치환·삭제형 오발음 67,982자리에서 당시 모델(tag_all_lar)은
  표준으로 되돌림(놓침)   40,113   59.0%
  전문가와 같게 포착      23,397   34.4%
  제3의 반응              4,472    6.6%
```

`05_GOP_진단.json` 의 `auto_correct_rate 0.5922` 와 독립적으로 일치.

**되돌림률 = 1 − recall** 이다(recall 0.4099 ↔ 0.5901). 새 지표가 아니라 FN 을 쪼갠 것이다.

## 2. 원인 규명 — 네 가지 증거

### 2-1. 같은 소리인데 표준발음에 따라 답이 25배 갈린다

화자가 **실제로 `ㅃ` 라고 발음한** 자리에서:

| 표준발음 | n | 모델이 `ㅃ` 라고 맞힘 |
|---|--:|--:|
| `ㅃ` (정상 발음) | 6,490 | **89.9%** |
| `ㅂ` (오발음) | 366 | **3.6%** |

`ㄲ` 92.1% vs 4.9% · `ㅉ` 92.0% vs 9.2% · `ㄸ` 94.9% vs 10.9% 로 전부 동일한 패턴.

**음향은 같은데 출력이 25배 다르다.** 모델은 소리를 못 듣는 게 아니라
어떤 단어인지 알고 그 단어의 표준발음을 낸다.

### 2-2. 학습셋 문장 다양성

```
train 발화 1,549,180  /  서로 다른 표준발음열  287종
→ 한 문장이 평균 5,398회 반복
```

### 2-3. 문장 안에서 뒤로 갈수록 안 듣는다

20음소 이상 발화만, 위치별:

```
앞 20%  되돌림 62.2%
뒤 20%  되돌림 74.2%      (+11.9%p)
정상자리 오탐률은 위치와 무관하게 1.3~1.9% 로 평평
```

오탐이 평평하다는 것은 "뒤로 갈수록 어려워서"가 아님을 뜻한다.
앞부분은 문장 식별 전이라 들어야 하고, 특정된 뒤로는 외운 것을 읊는 게 손실이 낮다.

### 2-4. test 에 미학습 문장이 0개

```
train 287종 / valid 256종 / test 256종
test 문장 중 train 에 없는 것  0종
test 발화 178,049 중 미학습 문장 발화  0 (0.00%)
```

**지금까지의 모든 평가가 외운 문장 위에서 이뤄졌다.**

### 2-5. 데이터 양은 원인이 아니다 (반증)

| 추가한 것 | 문장 종류 | 되돌림 |
|---|--:|--:|
| 없음 (`tag_all`) | 287 | 58.9% |
| record/LAR 214,642발화 | +30 | **59.0%** |
| 원어민 54,327발화 | +25,250 | **56.0%** |

21만 발화를 넣어도 문장이 30종이면 효과 0. 5.4만이라도 문장이 2.5만 종이면 −3%p.
**움직이는 것은 발화 수가 아니라 문장 종류다.**

또한 대비별 학습 노출 횟수와 되돌림률의 상관은 **−0.38**(설명력 14%)에 불과하다.
`ㄴ→ㅅ` 은 2,402회 노출에 되돌림 10.3%, `ㅂ→ㅃ` 은 2,768회에 96.2% —
**노출량으로 설명되지 않는다.**

## 3. 홀드아웃 실험 — 일반화 격차 실측

### 설계

287종 중 **30종을 학습에서 완전히 제외**하고 그 문장만으로 test 를 구성.
**화자는 일부러 겹치게 두어 문장 변수만 분리**했다.

```
train  1,383,088발화 / 257문장 / 화자 10,707
test     203,826발화 /  30문장 / 화자 11,627 (train 과 10,289명 겹침 — 의도된 것)
       오류 포함 발화 53,948 (26.5%) · 누수 검증 통과
```

기존 `tag_all_lar` 체크포인트는 287종을 모두 학습했으므로 이 실험에 쓸 수 없다.
**밑바닥부터 20,000스텝 축약 학습**(`configs/mdd_ctc_300m_holdout30.yaml`).

### 결과 (1차)

| | 본 문장 231종 | 안 본 문장 30종 |
|---|--:|--:|
| 되돌림 (놓침) | **61.8%** | **22.1%** |
| 포착 | 30.8% | 45.2% |
| 제3의 반응 | 7.4% | 32.7% |
| 정상자리 오탐 | 1.93% | **25.31%** |
| weighted F1 | **0.9509** | **0.8218** |
| 오류 F1 | 0.3912 | 0.1568 |
| precision | 0.4075 | 0.0874 |
| recall | 0.3762 | 0.7641 |

**본 문장에서는 안 듣고 읊는다** — 오탐 1.93% 로 깔끔한 대신 오류의 61.8% 를 놓친다.
**안 본 문장에서는 실제로 듣는다** — 되돌림이 22.1% 로 급락하지만 전사 실력이 드러나 오탐이 폭발한다.

`weighted F1 0.9509` 는 실력이 아니라 암기가 만든 숫자다. 문장을 바꾸자 0.8218 로 무너진다.

난이도 차이가 아니다: 진짜 오류 비율 3.77%(본) vs 3.05%(안 본).

## 4. 처방 검증 — 문장 다양성

### 설계 (2차)

**데이터를 더 모으지 않고 있는 것을 다르게 썼다.**

```
문장당 발화 상한 1,000 (화자 라운드로빈으로 화자 다양성 유지)
  + 원어민 데이터 병합 (25,854문장, KoG2P 71음소 → 자모 46 변환)

결과: 297,874발화 / 25,507문장 / 화자 8,592
      문장당 평균 11.7회   (현행 5,398회 → 461배 감소)
```

스크립트 `scripts/data/build_diverse_manifest.py`.
테스트셋은 1차와 **동일하게 유지**해 직접 비교 가능.

### 결과 (2차)

| | 1차 본 | 1차 안 본 | 2차 본 | 2차 안 본 |
|---|--:|--:|--:|--:|
| 되돌림 | 61.8% | 22.1% | **54.8%** | 23.7% |
| 포착 | 30.8% | 45.2% | **35.4%** | **50.0%** |
| 오탐 | 1.93% | 25.31% | 2.84% | **16.92%** |
| weighted F1 | 0.9509 | 0.8218 | 0.9460 | **0.8734** |
| 오류 F1 | 0.3912 | 0.1568 | 0.3908 | **0.2069** |

```
일반화 격차(weighted F1)   −0.129  →  −0.073     (−43%)
안 본 문장 오탐            25.31%  →  16.92%     (−33%)
안 본 문장 포착            45.2%   →  50.0%
본 문장 되돌림             61.8%   →  54.8%      ← 외울 게 줄자 본 문장에서도 듣기 시작
```

train loss 가 4.9 → 14.0 으로 3배 올랐다. **외우지 못하고 있다는 직접 증거**다.

대가는 본 문장 weighted F1 0.9509 → 0.9460. 잃은 것은 실력이 아니라 부풀림이다.

## 5. 부수 실험 — MDD 개선이 점수(PCC)로 전달되는가

`errup`(오류 F1 0.5035, 되돌림 42.2%)으로 GOP 특징을 다시 뽑아 PCC 재측정.

| 차원 | tag_all_lar | errup | 차이 |
|---|--:|--:|--:|
| 발음숙달 | 0.6622 | 0.6759 | +0.0137 |
| 이해가능 | 0.6825 | 0.6943 | +0.0118 |
| 유창성 | 0.7618 | 0.7696 | +0.0078 |

**전달률 약 1/8** — MDD 오류 F1 이 16.6% 올랐는데 PCC 는 2.1% 올랐다.

비교하면:

```
집계 단위      발화1개 0.4251 → 전체 0.6622    +0.2371   ← 가장 큼
특징·보정기    v1 0.5235 → v2gbm-utt 0.6622    +0.1387
MDD 모델       tag_all_lar → errup             +0.0137   ← 가장 작음
```

**"MDD 개선 → 점수 개선"을 자원 배분 근거로 쓰면 안 된다.**
점수를 올리려면 특징·집계·보정기 쪽이 효율이 훨씬 높다.

산출물 `$MDD_OUTPUTS/eval_score_v2_errup.json`, 특징 캐시 `gop_feats_v2_errup_{train,test}.jsonl`.

## 6. 문헌 대조

- **[arXiv:2011.01991]** Internal Language Model Estimation — E2E 모델은 학습 도메인을 특징짓는
  내부 LM 을 암묵적으로 배운다. 추정해 빼면 도메인 적응이 개선된다.
- **[arXiv:2305.03837]** Mask The Bias — **CTC 전용 ILM 추정**. 오디오를 반복 마스킹해 내부 LM 을
  노출·제거. zero-shot 도메인에서 WER 9.3%, OOV F1 24.6% 개선. **재학습 불필요.**
- **[arXiv:2604.22133]** Beyond Acoustic Sparsity and Linguistic Bias — 이 현상을
  **"linguistic bias"** 로 명명. *"canonical information can easily override the subtle
  acoustic information"*. 단 이들이 지목한 것은 표준발음을 **입력으로 넣는** 시스템이고,
  우리는 넣지 않는다. 우리 것은 **학습 데이터 분포에서 온 암묵적 편향**이다.
  이 논문은 코퍼스 문장 다양성이나 프롬프트 암기를 다루지 않는다.

**CTC 는 조건부 독립이라 내부 LM 이 없다는 통념은 틀렸다.** 트랜스포머 인코더의 self-attention 이
발화 전체를 보므로 조건부 독립이 실질적으로 완화되고, 내부 LM 이 **디코더가 아니라 인코더에** 생긴다.
위 2-3 의 위치 효과가 그 메커니즘의 직접 증거다.

## 8. 한계

- 1·2차 모델은 **20,000스텝 축약본**(운영 레시피는 50k+15k)이고 `freeze_finetune_updates` 를
  10,000 → 2,000 으로 줄였다. valid WER 29.6%/33.9% 로 운영 모델보다 낮다.
  **확정된 것은 격차의 존재와 방향이지 운영 모델의 절대 수치가 아니다.**
- 되돌림 측정은 **삽입을 채점하지 않는다**(치환·삭제만, 참조 편집연산의 91.5%).
  자세한 것은 `07_감사_고정정답지.md`.
- 홀드아웃 30종은 시드 42 로 뽑은 무작위 표본이다. 다른 표본에서 격차 크기는 달라질 수 있다.
- **당시 운영 모델(`tag_all_lar`) 자체의 미학습 문장 성능은 이 축약 실험에서 측정하지 않았다.**
