## 0. 먼저 — 이 프로젝트의 데이터는 왜 헷갈리는가

**코퍼스는 하나인데, 그 위에 세 팀이 각자 다른 방식으로 정답을 적어놨기 때문이다.**
AIHub 「교육용 외국인 한국어 음성」(040 영어권 / 041 유럽 / 042 중·일 / 043 아시아)에서
같은 화자들이 여러 종류의 과제를 수행했고, 과제마다 라벨링 팀과 라벨 형식이 다르다.

```
AIHub 교육용 외국인 한국어 음성 (040 / 041 / 042 / 043)
│
├─ 발음 평가 과제 (RW 단어 · RS 문장 · RP 문단)  ── 오디오: mdd_gold_wav16k (187.8만)
│    ├─ TAG  = TextGrid  : 전문가가 "들리는 대로" 적은 음소 (실현형)   ← 학습·채점 정답
│    └─ LAB  = JSON      : 표준발음 + 오류 위치·유형 태그 + 사람 점수  ← 통칭 "gold"
│
└─ 낭독/발화 과제 (LAR 문장낭독 외)              ── 오디오: mdd_wav16k (26.8만)
     └─ Speech_lab JSON  : 맞춤법 전사 → G2P 기계변환               ← 통칭 "record"
```

**핵심: TAG와 LAB(gold)은 같은 발화에 붙은 두 장의 라벨이고, record는 아예 다른 발화다.**
이걸 몰라서 "gold로 채점" 같은 계획이 나왔다가 실측으로 폐기됐다.

### 0-1. 라벨 3종 한눈에 (실측 근거는 각 장 참조)

화자가 "빨리"를 **[팔리]** 로 잘못 발음한 경우, 각 라벨에 남는 것:

| | TAG | record | gold(LAB) |
|---|---|---|---|
| **정체** | 전문가 음소 전사 (TextGrid) | 맞춤법 전사 → KoG2P 기계변환 | 표준발음 + 오류 태그 + 사람 점수 |
| **남는 것** | `ㅍㅏㄹㄹㅣ` — 오류가 소리 그대로 | `"빨리"` → `ㅃㅏㄹㄹㅣ` — **오류 증발** | "0.3~0.5초에 경음화" — 위치·유형만 |
| **실현형 있나** | ✅ 유일하게 있음 | △ 단어 수준까지만 | ❌ **필드 자체가 없음** (전수 확인) |
| **오디오 관여** | 사람이 듣고 적음 | ❌ **오디오 안 씀** (텍스트끼리 G2P 비교) | 사람이 듣고 태깅 |
| **규모** | 181.5만 TextGrid | 26.8만 발화 | 188.2만 발화 |
| **과제** | RW / RS / RP | LAR | RW / RS / RP |
| **현재 용도** | **CTC 학습·평가 정답** | 단어누락 검증 + LAR 적응 오디오 | L1-prior 통계 + 점수기 정답 |
| **폐기된 용도** | — | 음소 MDD 학습(0.80 천장) | 음소 MDD 채점(공식 0.96 모델도 0.40) |

##### 1.3 포맷 구조 (트리)

```
TextGrid (Praat 텍스트 포맷, "ooTextFile", long form)
├─ File type = "ooTextFile"            (str, 고정)
├─ Object class = "TextGrid"           (str, 고정)
├─ xmin / xmax                         (float, 초 단위. 파일 전체 구간.
│                                       xmin이 0이 아닌 경우가 많음 = 앞쪽 무음을 잘라낸 시작시각)
├─ tiers? <exists>
├─ size                                (int, tier 개수 — 값 분포는 아래)
└─ item [1..size]:
     ├─ class = "IntervalTier"         (str, 관측된 값은 IntervalTier 뿐. PointTier 미관측)
     ├─ name = "words" | "phones" | "tags"
     ├─ xmin / xmax                    (float, tier 구간 = 파일 구간과 동일)
     ├─ intervals: size = N            (int)
     └─ intervals [1..N]:
          ├─ xmin  (float, 초)
          ├─ xmax  (float, 초)
          └─ text  (str; 빈 문자열 ""이 무음/휴지 구간)
```

##### 1.4 tier에 들어가는 값의 정체

- **`words` tier** — 어절(띄어쓰기 단위) 한글 표기. 예: `"가족이"`, `"몇"`, `"명이에요"`, `"의사소통"`, `"아이스크림"`. 빈 문자열 `""`이 어절 사이 휴지.
- **`phones` tier** — **한글 호환 자모(U+3131~U+3163) 낱자**. IPA도 아니고 유니코드 조합형 자모(U+1100대)도 아님. 즉 `ㄱ ㅏ ㅈ ㅗ ㄱ ㅣ` 처럼 초성/중성/종성을 낱개 자모로 푼 것. **전사자가 실제로 들린 대로** 적은 실현형.
  - 정상 심볼은 45개 내외지만, 실제 값에는 **오염(dirty) 토큰이 섞여 있다**. 각 3,000개 샘플에서 발견된 distinct `text` 값 개수: 040=112, 042=129, 041=148, 043=120. 그 중 정상 자모 1글자가 아닌 것들:
    - 특수 토큰: `"spn"`(spoken noise), `"-"`, `"_"`, `"."`, `"X"`, `""`(무음)
    - **한 interval에 여러 자모가 붙은 것**: `"ㄱㅏ"`, `"ㄴㅡㄴ"`, `"ㅎㅜㅊㅜ"`, `"ㅇㅗ ㅏ ㅇ ㄱㅣ"`, `"ㅂㅐㄱㅊㅓㅁ"`
    - **공백이 섞인 것**: `"ㄱ ㅓ"`, `"ㅆ  ㅡ"`, `"ㅎ ㅏ ㄴ ㅡ"`
    - **한글 음절/숫자 혼입**: `"ㄹ프"`, `"100점"`
    - 겹받침: `"ㄻ"`
  - → manifest 빌더가 `is_jamo()` 필터로 **자모만 뽑아 flatten** 하는 이유가 이것이다 (§2.6).
- **`tags` tier** — 오류 유형 한글 라벨. 값의 전수 종류(4개 디렉토리 3,000개 샘플씩 합산, 실측):
  `초성`, `종성`, `모음오류`, `경음화`, `기타`, `비음화`, `반복`, `격음화`, `연음규칙`, `유음화`, `경계억양 오류`, `ㄴ-첨가`, `구개음화`, `강세 오류`, `음운탈락`, `모음삽입`, `간투사` (총 17종). 나머지 interval은 `""`.
  - LAB JSON의 `error_tags[].error_tag`와 **동일한 17종 집합**이고, start/end도 일치 (§3).

##### 2.2 `{split}.tsv` — fairseq audio manifest

첫 3줄 실물 (`manifest_tag_all/train.tsv`):

```
/
data/tta/mdd_gold_wav16k/02/02482-M-97-DE-B-RW121-0596668.wav	25942
data/tta/mdd_gold_wav16k/04/04074-F-2-IT-B-RS075-0905717.wav	65536
```

- **1행 = 오디오 루트**. 여기서는 문자열 `/` (루트). 따라서 실제 경로는 `/` + `data/tta/mdd_gold_wav16k/...`. (빌더가 `wp.lstrip('/')`로 앞 슬래시를 떼고 루트를 `/`로 둔 것)
- **2행부터**: `상대경로<TAB>프레임수`
- **숫자 단위 = 샘플 개수(프레임), 16 kHz mono int16 기준**. 빌더 정의는 `frames_of(wp) = (os.path.getsize(wp) - 44) // 2` (44바이트 WAV 헤더 제외 / 2바이트 per sample). 실측 검증:
  - `data/tta/mdd_gold_wav16k/00/00793-F-99-ET-B-RW086-0196186.wav` → 선언 43,691 / 파일크기 87,426 → `(87426-44)//2 = 43691` ✅ (= 2.73초)
- **행 수 = tsv 줄 수 − 1** 이며, `.ltr`/`.canon`의 n번째 줄이 tsv의 (n+1)번째 줄에 대응.

**프레임 범위 / 길이 (실측)**

| split | 행 수 | 화자 수 | frames min/max | 초 min/max | 총 시간 |
|---|---|---|---|---|---|
| train | 1,432,243 | 9,667 | 8,192 / 239,259 | 0.51 / 14.95 | **1,301.6 h** |
| valid | 188,570 | 1,279 | 8,192 / 237,568 | 0.51 / 14.85 | 173.1 h |

```python
def parse_lab(lab):
    d = json.load(open(lab, encoding="utf-8"))
    ph = d.get("RecordingMetadata", {}).get("phonemic", {})

    toks = []
    for x in ph["phones"]:
```

```python
def parse_tag(tg):
```

#### (3) 핵심 확인 — 이 라벨이 왜 "약라벨"인가

##### 3-1. 생성 파이프라인 (코드 실물, `s1_speechlab_mdd.py:151-235`)

```
prompt              --KoG2P(규칙 전체)-->  target_phones
orthographic_raw --간투사/반복 제거-->  orthographic_clean --KoG2P-->  actual_phones
target_phones  vs  actual_phones  --Needleman-Wunsch(match=0,mismatch=1,gap=1)-->  errors[]
```
```python
target = list(text_to_phones(prompt))            # line 161
actual = list(text_to_phones(ortho_clean))       # line 162
ops    = _nw(target, actual)                     # line 163
```
**오디오는 이 경로 어디에도 들어오지 않는다.** 라벨은 전적으로 "제시문 텍스트"와 "전사문 텍스트" 두 문자열의 G2P 결과 차이다.

##### 3-2. 실증 검증 (실제로 KoG2P 재실행)

`$MDD_WORKDIR/00_scripts/s0_kog2p_wrapper.py`의 `text_to_phones()`를 그대로 import해 파일 전역에서 700줄 간격으로 뽑은 **384개 레코드**를 재계산:

```

actual_phones == KoG2P(orthographic_clean)  : 384 / 384   (100%)
불일치 사례: 0건
```

→ **가설 확정.** `target_phones`는 `prompt`에서, `actual_phones`는 `orthographic_clean`에서 나온다.

**추가 확인**

- 즉 `n_errors == 0` 116,612건 = (텍스트 완전 동일 105,439) + (띄어쓰기만 다름 11,173).

##### 3-4. "미묘하게 틀렸는데 전사자가 같은 단어로 알아들으면 오류가 사라지는가?" → **예. 완전히 사라진다.**

구조적 근거: 라벨 생성에 오디오가 들어가지 않으므로, 전사자가 정답 어절로 받아 적는 순간 문자열이 일치하고 → G2P 결과가 일치하고 → NW 정렬이 전부 `match`가 되어 → `errors: []`, `n_errors: 0`이 된다. 발음의 미세 이탈(VOT, 모음 포먼트, 억양, 어색한 유기성)은 라벨에 남을 자리가 없다.

#### 3. 핵심 판정 — 왜 이 라벨로 MDD 채점이 불가능한가

##### (a) 실현형(“화자가 실제로 뭐라고 발음했는지”) 필드는 **존재하지 않는다** — 확정

- LAB JSON 15,000개의 raw 문자열에 대해 `actual` / `realiz` / `produced` / `hyp` / `transcri` / `utter` / `실현` / `발음형` 키워드가 필드명으로 등장하는지 검사 → **0건**. 위 트리가 필드의 전부다.
- 집계본 전수(1,881,760줄): `actual_phones` 가 **null 1,881,760 / 1,881,760 = 100.0%**.
- 집계본 오류 객체 전수(946,132개): `actual_phone` **null 946,132 / 946,132 = 100.0%**, `op`(삽입/삭제/치환 연산) 도 **null 100.0%**.

##### (b) `phones` tier 는 **표준 발음(정답/타깃)** 이다 — 실현형 아님 (결정적 실측)

같은 prompt를 읽은 화자들의 phone 시퀀스를 비교했다 (040에서 40,000개 표본):

| prompt | 발화 수 | 서로 다른 phone 시퀀스 종류 | 오류태그 있는 발화의 modal 시퀀스 일치율 |
|---|---|---|---|
| 싱싱하다 | 287 | **1종** (`ㅅㅣㅇㅅㅣㅇㅎㅏㄷㅏ`) | **1.0000** (n=26) |
| 노력 | 282 | **1종** (`ㄴㅗㄹㅕㄱ`) | **1.0000** (n=52) |
| 글씨 | 265 | **1종** (`ㄱㅡㄹㅆㅣ`) | **1.0000** (n=43) |

오류 태그가 달린 발화조차 phone 열이 **한 글자도 다르지 않다**. 인덱스별로 봐도 태그가 붙은 위치의 phone 은 항상 모든 화자 공통의 표준 phone 이다 (예: `노력` idx4 = `ㄱ`, 여기에 `종성` 태그가 20건 붙었지만 phone 값은 전원 `ㄱ`).

→ **phones tier = 표준 발음의 강제정렬 결과. error_tags 는 “이 구간을 잘못 발음했다”만 말하고, “무엇으로 잘못 발음했는지”는 어디에도 없다.** MDD의 (canonical, perceived) 쌍에서 **perceived 쪽이 통째로 비어 있다** → 이 라벨만으로는 삽입/삭제/치환 판정도, 음소 단위 채점도 불가능.

문장(RS) 프롬프트에서는 시퀀스가 갈리는 경우가 있으나(≥5회 등장 229개 프롬프트 중 25개), 내용을 보면 **선택적 음운규칙을 주석자가 적용했는지 여부**의 흔들림이다:
- `이것 좀 드세요.` → `…ㄷㅈㅗㅁ…`(n=93) vs `…ㄷㅉㅗㅁ…`(n=50) — **양쪽 다 error_tags=0**
- `여기 물하고…` → `ㅁㅜㄹㅎㅏㄱㅗ` vs `ㅁㅜㄹㅏㄱㅗ`(ㅎ 탈락)
- `좋은` → `ㅈㅗㅡㄴ`(n=125) vs `ㅈㅗㅡ`(n=21)

무오류 발화들 사이에서도 갈리므로 실현형 전사가 아니라 **레퍼런스 표기 흔들림(주석자 간 편차)** 이다. 즉 정답조차 완전히 일관되지 않는다.

##### (c) error_tags 가 가리키는 것 = **시간 구간**. 음소 인덱스는 아니다

표본 24,000 파일 / 12,237 태그 기준:
- 태그 (start,end) 가 **어떤 phone 구간과 완전 일치**: 12,073건 = **98.7%**
- 어떤 words 구간과 일치: 0건
- 일치도 포함도 안 됨(내부 phone 0개): 210건 = 1.7%; 2~3개 phone 을 걸침: 4건

즉 **사실상 1태그 = 1 표준음소**지만, JSON에는 인덱스가 없고 float 시간으로만 표현되므로 매핑을 직접 해야 한다(집계본이 그 일을 했다).

##### 5-3. 가공/추가된 것 vs 버려진 것

**추가·가공**

## 6. 함정 모음 — 이 데이터를 만질 때 반드시 알아야 할 것

조사 중 실측으로 확인된 것만. 코드를 짜기 전에 해당 절을 읽을 것.

### 6-1. TAG 계열 — 전문가 음소 전사 + 학습 manifest

1. 파일명 3번째 토큰은 나이가 아니라 출생연도 뒤 2자리다. `04074-F-2-IT-...`의 LAB JSON은 birth_year="02"(2002년생), `00060-F-84-...`는 1984년생. 앞의 0이 제거되어 있어서("02"→"2", "00"→"0") 자릿수가 가변이므로 정규식을 `\d{2}`로 짜면 깨진다.
2. 파일명 5번째 토큰(A/B)은 `proficiency`가 아니라 `recording_level`이다. proficiency는 Advance/Beginner/Intermediate/Fluent 4종이고 recording_level은 Advanced/Beginner 2종인데, 파일명은 후자만 반영한다. 실제로 `00042-F-0-ZH-A-...`는 proficiency=Intermediate지만 recording_level=Advanced라 'A'.
3. LAB JSON의 canonical은 `RecordingMetadata.phonemic.phones[].phone`이다. G2P로 만든 게 아니다. 반면 Speech_lab(LAR/ATQ/...) JSON에는 `phonemic` 자체가 없고 `orthographic`만 있어서, LAR 라벨은 프롬프트→KoG2P로 만들어야 한다. 두 스키마를 같은 파서로 읽으면 안 된다.
4. LAB의 `error_tags[]`에는 실현형(actual phone)이 없다. 위치(start/end) + 유형만 있다. "뭐라고 발음했는가"는 오직 TAG TextGrid의 `phones` tier에만 존재한다. 이것이 gold(LAB)로 MDD F1을 재면 안 되는 이유.
5. TextGrid의 tier 개수가 가변이다. `(words, phones)` 2개가 다수(67~78%), 오류 태깅된 발화만 `tags` tier가 추가되어 3개. 042에는 words tier만 있는 파일도 1개 존재(`01514-F-98-ZH-A-RW076-0507203.TextGrid`). `size = 3`을 가정한 파서는 깨진다.
6. TextGrid의 `phones` tier 값은 자모 1글자라는 보장이 없다. 실측 distinct 값이 112~148종이며 `"ㄱ ㅓ"`(공백 포함), `"ㅎㅜㅊㅜ"`(여러 자모), `"spn"`, `"-"`, `"_"`, `"X"`, `"100점"`, `"ㄹ프"` 같은 것이 섞여 있다. 반드시 `0x3131<=ord(c)<=0x3163` 필터로 flatten해야 한다.
7. 자모는 한글 '호환 자모'(U+3131~U+3163)다. 조합형 초성/중성/종성 자모(U+1100~U+11FF)가 아니다. `unicodedata.normalize('NFD')` 결과와 코드포인트가 다르므로 섞어 쓰면 조용히 vocab이 어긋난다.
8. TextGrid 파일은 전부 BOM 없는 UTF-8이다. `build_tag_manifest_combined.py`의 `parse_tag()`는 `encoding='utf-16'`을 먼저 시도하는데, 실측 300개 전부 UnicodeDecodeError로 실패해 utf-8 fallback을 타므로 결과는 정상이다(가비지 디코딩 위험은 없음). 다만 파일당 예외 2회를 던지는 비용이 있고, 의도와 다르게 동작하는 죽은 코드다.
9. `{split}.tsv`의 1행은 `/` 한 글자다(오디오 루트). 실제 경로는 `/` + 상대경로. `.ltr`/`.canon`의 n번째 줄은 tsv의 (n+1)번째 줄에 대응하므로 zip할 때 헤더 한 줄을 반드시 버려야 한다.
10. tsv 두 번째 컬럼은 초가 아니라 **샘플 수**(16kHz mono int16 기준 `(filesize-44)//2`)다. 초로 쓰려면 16000으로 나눠야 한다.
11. `.ltr`에는 word separator(`|`)가 없다. fairseq wav2vec letter CTC 예제의 관례와 다르므로, 표준 레시피의 후처리(`|`→공백)를 그대로 적용하면 안 된다.
12. `dict.ltr.txt`는 46줄이지만 실제 vocab은 50이다. fairseq이 로드 시 `<s> <pad> </s> <unk>` 4개를 앞에 자동 추가한다. 두 번째 컬럼 숫자는 train.ltr에서의 등장 빈도이며(실측 정확히 일치), 인덱싱에는 순서만 쓰인다.
13. `.canon`은 37종 심볼만 쓰지만 dict은 46종이다. ltr에만 있는 9종(ㅙ ㅞ ㅒ + 겹받침 ㄻ ㄼ ㄺ ㅄ ㄵ ㄳ, 합계 1,167 토큰 = 0.008%)은 전사자 잔여물/오염에 가깝다. 겹받침 6종이 자모 CTC vocab에 들어간 것은 의도된 설계가 아닐 가능성이 높다.
14. `manifest_tag_all_lar`의 LAR 116,937행은 `.ltr`과 `.canon`이 100% 동일하다(차이 0건). 무오류 발화만 골라 canonical을 그대로 라벨로 썼기 때문. 따라서 이 행들은 MDD 오류 신호를 전혀 제공하지 않는 도메인 적응용 데이터다. `.ltr != .canon`을 오류 존재의 지표로 쓰는 분석에서 LAR 행을 섞으면 오류율이 희석된다(train 차이율이 26.9%→24.9%로 떨어지는 것이 그 효과).
15. LAR 116,937행은 고유 38,979발화의 **3배 업샘플**이다. 같은 wav 경로가 정확히 3번 반복된다. 발화 수를 셀 때 줄 수를 그대로 쓰면 3배 과대계상된다.
16. LAR 화자 5,287명 중 502명이 test 화자, 562명이 valid 화자와 겹친다. tag_all 자체는 train/valid/test 화자 겹침 0이지만, all_lar의 train에는 test 화자의 LAR 발화가 들어간다. 발화는 안 겹치지만(LAR vs RW/RS는 서로 다른 과제) 엄밀한 화자 분리는 아니다.
17. RP(문단 낭독)는 manifest에서 사실상 사라졌다. 15초(240,000 프레임) 상한 때문에 train에 단 1개만 살아남았고 valid/test에는 0개다. 즉 학습·평가 도메인은 RW+RS뿐이다.
18. `manifest_tag_all_lar`가 참조하는 `$SPEECH_AI_DATA/mdd_lar_wav16k`(6.9G)는 `$SPEECH_AI_DATA/mdd_wav16k`(record LAR 전량 268,533개)의 부분집합 중복이다. DATA_MAP에 "manifest 경로 수정 후 삭제 가능"으로 표시되어 있으므로, 이 manifest를 재사용할 때 경로가 이미 정리되었는지 먼저 확인해야 한다.

### 6-2. record 계열 — 맞춤법 전사 기반 약라벨

1. 라벨 생성에 오디오가 전혀 쓰이지 않는다. target_phones=KoG2P(prompt), actual_phones=KoG2P(orthographic_clean) 두 텍스트의 G2P 차이를 Needleman-Wunsch로 정렬한 것이 errors[] 전부다. 384개 표본으로 KoG2P를 재실행해 384/384 완전 일치 검증했다.
2. n_errors==0 이 43.43%(116,612건). 그중 105,439건은 prompt와 orthographic_clean이 글자까지 동일한 경우다. 'prompt == orthographic_clean 이면서 n_errors != 0'인 레코드는 0건 — 전사자가 정답대로 받아 적으면 오류는 무조건 사라진다.
3. errors[].t_start / t_end 는 1,057,960건 100% null 이다. 시간 정렬 정보가 전혀 없으므로 프레임 단위 MDD 학습에는 그대로 못 쓴다.
4. errors[].confidence 는 사람의 확신도가 아니라 s0_taxonomy.classify_op()가 규칙으로 박아넣은 상수다. error_type만 알면 confidence가 거의 결정된다(격음화·비음화만 2값으로 갈림). 독립 신호로 취급하면 안 된다.
5. error_type '음운탈락'은 del 425,297건 + ins 53,493건에 붙는다. 자음 삽입인데도 이름이 '탈락'이다(rationale은 '자음 X 삽입(미분류)', confidence=low). 이름만 보고 op을 추론하면 틀린다.
6. taxonomy에 정의된 '구개음화'는 실제 데이터에 0건이다. 관측 error_type은 11종뿐(구개음화·연음규칙·강세 오류·경계억양 오류는 없음).
7. err_ratio는 1.0을 넘을 수 있다(max 3.053, 158건). 분자 n_errors는 삽입을 포함하는데 분모는 len(target_phones) 고정이기 때문이다.

12. orthographic_raw != orthographic_clean 인 레코드는 12,604건인데 disfluencies가 실제로 기록된 건 3,118건뿐이다. 나머지 ~9,486건은 clean이 ' '.join(words)라서 후행 공백/중복 공백만 정규화된 차이다.
13. KoG2P가 어절 경계를 버리므로 띄어쓰기 차이는 음소열에서 소멸한다('없 다' vs '없다', '돌봐 준다' vs '돌봐준다'). 텍스트는 다른데 n_errors==0인 케이스가 11,173건이다.
14. actual_phones에 정상 KoG2P 심볼 46종 외에 파편 심볼 25종(0x, k, x, is, hx, mv 등, 총 ~90회)이 섞여 있다. orthographic에 독립된 마침표 토큰(' . ')이 문장 중간에 있을 때 KoG2P가 깨진 출력을 내기 때문이다(재현 확인: text_to_phones('했다 . 있다.') -> [...,'i','is','s','t0','aa']). 음소 vocab을 데이터에서 자동 유도하면 이 쓰레기 심볼이 들어간다.
15. prompt는 단 30종이다. 화자 11,074명이 같은 30문장을 읽은 구조라 텍스트 다양성이 없다. 모델이 프롬프트를 외우는 leakage에 주의해야 하고, 화자 분리 split이 필수다.

17. errors[].pos 는 target 인덱스다(op['tpos']). ins인 경우 삽입 지점의 target 인덱스라서 값이 n_target과 같아질 수 있고(최대 42), 같은 pos에 여러 오류가 중복될 수 있다. actual_phones 인덱스로 착각하면 안 된다.
18. 오디오는 268,533/268,533 = 100% 존재하며 뱅크에 여분도 없다. 다만 파일명 매칭 시 file 필드의 .json 확장자를 .wav로 바꿔야 하고, 샤드는 파일명 앞 2글자(=user_id 앞 2자리)다. 샤드 번호가 00~72 사이에서 연속이 아니라 61개만 존재한다(ls로 세면 README.txt 때문에 62개로 보인다).
19. $SPEECH_AI_DATA/mdd_wav16k 는 040/042 LAR의 서버 유일본이다(원본 48k 삭제됨). README.txt와 DATA_MAP.md에 '삭제 금지' 명시.
20. utterance_id는 268,533개 전부 유니크하지만 7자리 숫자 '문자열'이다(예 '0007295'). int로 파싱하면 선행 0이 날아가 file 필드와 조인이 깨진다.
21. file의 3번째 토큰(2자리 숫자, 0~99)은 출생연도 뒤 2자리로 보이지만 정의를 명시한 문서를 찾지 못했다 — 미확인. 값이 '0'인 레코드가 28,924건 있어 미기입/2000년생 구분도 미확인이다.

### 6-3. gold 계열 — 오류 위치·유형 태그 + 사람 평가 점수

1. 실현형 필드가 아예 없다 — LAB에 actual_phone류 키 자체가 존재하지 않고(15,000개 raw 문자열 키워드 검색 0건), 집계본에서도 actual_phones / errors[].actual_phone / errors[].op 가 전량 null(1,881,760·946,132 전수 100%). 'null이 채워질 때도 있겠지'라고 가정하면 안 된다.
2. phones tier를 '실제 발음'으로 착각하기 쉽다. 실측: 같은 단어를 읽은 287/282/265명의 phone 시퀀스가 오류태그 유무와 무관하게 100% 동일. 태그가 붙은 위치의 phone도 전원 표준 phone 그대로다 → phones = 표준발음 강제정렬.
3. 다만 문장(RS)에서는 같은 prompt의 phone 시퀀스가 갈린다(≥5회 등장 프롬프트 229개 중 25개). 이것도 실현형이 아니라 선택적 음운규칙(경음화·ㅎ탈락 등)을 주석자가 적용했는지의 편차다 — 무오류 발화들 사이에서도 갈린다. 즉 '정답' 자체가 일관되지 않는다.

### 6-4. 오디오 뱅크 + 파생 산출물 (캐시·가중치·체크포인트)

1. `sort | uniq -c`로 한글 필드를 집계하면 en_US.UTF-8 로케일 collation 때문에 같은 문자열이 여러 그룹으로 쪼개진다 — native 지역 필드가 실제 7종인데 148그룹으로 나왔다. 반드시 `LC_ALL=C sort` 또는 파이썬으로 집계할 것.
2. `eval_tag_all_preds.jsonl` / `eval_tag_all_lar_preds.jsonl`의 `i`는 `manifest_tag_all/test.tsv`의 **헤더(1행 `/`) 제외 0-based 행 인덱스**다. 파일 안에서 `i`가 정렬돼 있지 않으므로 zip으로 순서 매칭하면 전부 어긋난다. 반드시 `i`로 인덱싱할 것. (두 manifest의 test.tsv/test.ltr은 md5 동일이라 `i`는 상호 비교 가능)
3. `gop_feats_test.jsonl`의 stem 집합은 `test.tsv`와 완전히 같지만 **줄 순서가 다르다**. 줄 번호로 조인하면 안 되고 stem으로 조인해야 한다.
4. `mdd_lar_wav16k`는 `mdd_wav16k`의 100% 바이트 동일 부분집합(고유 파일 0). 두 뱅크를 함께 스캔하면 38,979개 발화가 이중 집계된다.
5. `manifest_tag_all_lar/train.tsv`에서 mdd_lar_wav16k 경로는 38,979개가 **각각 정확히 3번씩** 등장한다(116,937행). 경로만 mdd_wav16k로 치환하는 건 안전하지만 중복 제거까지 하면 3배 오버샘플링 설계가 깨진다.
6. gold 뱅크의 RP(문단) 16,500개는 평균 44.3초·최대 102초로 RW/RS(중앙값 2.8초)와 스케일이 완전히 다르고 총 203시간을 차지한다. 게다가 manifest_tag_all에는 RP가 train에 단 1행뿐(valid/test 0)이라 학습·평가 대상이 아니다. '뱅크 전체를 읽는' 스크립트는 RP 때문에 메모리/시간이 폭증한다.
7. gold에는 RW인데 307.9초짜리 이상치 파일이 있고, 1초 미만 파일도 11,354개 있다. 길이 필터 없이 배치를 만들면 터진다.
8. 파일명 3번째 필드(예: `-99-`, `-22-`)는 화자별 상수지만 값이 0~99에 걸쳐 있고 분포가 0~4와 93~99 양끝에 몰려 있어 나이로 단정할 수 없다 — 의미 미확인.
9. `mdd_lar_wav16k`에는 EN·ZH·JA가 한 건도 없다(61 L1코드만, ID·VI 편중). '무오류 LAR'을 언어 균형 잡힌 표본으로 가정하면 안 된다.
10. `l1_prior_weights.json`의 키는 영문 **국가명 81개**인데, 오디오 파일명·manifest는 **L1 2글자 코드 70종**을 쓴다. 둘을 잇는 매핑 테이블은 이번 조사에서 확인하지 못했다(미확인). 국가와 L1은 1:1도 아니다(예: United States/United Kingdom/Australia가 모두 EN 계열).
11. `prior_weight`는 확률이 아니라 곱하는 배수이고 [0.2, 5.0]으로 클립돼 있다. 클립된 엔트리는 1,134개 중 17개뿐이지만, 그 경우 `lift`(원값)와 `prior_weight`(클립값)가 다르다. 상한 5.0인 4건은 실제 lift가 그보다 컸다는 뜻.
12. `weights[*].speech_lift`는 1,134개 중 **324개가 null**이다(구개음화·연음규칙·강세 오류·경계억양 오류에 집중). null을 0이나 1로 대체하면 의미가 달라진다.
13. `signal_strength`는 파일 수 임계가 아니다 — strong의 최소 n_files는 703(Panama), moderate의 최대는 75,437(Spain)로 구간이 겹친다. 잔차 크기 기준이다.
14. `l1_prior_weights_long.csv`는 **BOM(﻿)** 으로 시작한다. `encoding='utf-8'`로 읽으면 첫 컬럼명이 `﻿L1`이 된다 — `utf-8-sig` 필요.

### 6-5. 평가 설계에서 실제로 터진 함정 (2026-07-25 추가)

이 절은 파일 스키마가 아니라 **그 스키마를 잘못 읽어서 생긴 실측 사고** 기록이다. 같은 실수 재발 방지용.

1. **`quality_flag != 'ok'` 를 평가에서 제외하면 안 된다.** record의 `usable_for_aggregation=false`(= `quality_flag`가
   `collapsed`/`restart_suspect`)는 **"오류 *통계 집계*에 쓰지 말 것"** 이라는 뜻이지 "평가에 쓰지 말 것"이 아니다.
   단어누락 평가에서 이걸 제외했더니 **전체 실제 누락 단어의 69.6%가 평가에서 빠졌다**
   (제외집단 누락률 19.76% vs 채점집단 0.96% — 20.6배). `collapsed`는 정의상 "말을 많이 빠뜨린 발화"라
   검출 대상 그 자체이기 때문. 전수로 바로잡자 정밀도 0.639→**0.677**, 재현율 0.648→**0.687**로 **올랐다**
   (희귀사건 페널티 해소). 반대로 record식 MDD F1은 0.9505→**0.9377**로 내려갔다(난이도 상승).
   → 평가 스크립트에서 품질 플래그로 거르기 전에, **그 플래그가 무엇을 위한 것인지** 먼저 확인할 것.
2. **양성률이 지표를 지배한다.** 같은 모델·같은 임계값인데 양성률 0.96%(필터본) vs 2.8%(전수)에서
   정밀도가 0.04 차이 났다. 부분집합 수치를 전수 수치처럼 인용하면 안 된다.
3. **제외 사유는 반드시 사유별로 세어볼 것.** "25,146건 제외"만 보면 문제가 안 보이고,
   `collapsed 16,972 / restart_suspect 7,412 / 비한글 762`로 쪼개야 첫 두 개가 부당하다는 게 드러난다.
4. **정당한 제외는 871건뿐이었다** — 프롬프트/전사에 숫자·영문이 섞여 KoG2P가 canonical을 생성하지 못하는 경우
   (예: "열한 시" → 전사 "11시"). 비교 기준 자체가 없으므로 채점식이 성립하지 않는다. 전체의 0.3%.
5. **무오류 집단(115,844)의 수치를 인용하지 말 것.** record식 F1 0.9972가 나오지만, 이 발화들은
   LAR 도메인 적응 학습에 그대로 쓰인 것들이라 자기 학습 데이터를 채점한 셈이다.
   공정한 값은 **오류 포함 발화(151,804)의 0.9008**.
