# GPU 필요 작업 상세 · 완료 체크리스트 · 전체 과업 체크리스트

_작성: 2026-07-06 · 근거: 비버톡 AI 개발 로드맵 **v3**, 발음오류 데이터구축 작업지시서, 공식 AI모델 환경 설치 가이드 5종, 본 프로젝트 산출물_

> **🆕 v3 갱신**: 공식 설치가이드 5종 = **사전학습 체크포인트 + 실행 스크립트가 담긴 Docker 팩**, 전부 목표 초과. 이로써 **1-A 백본은 300M 확정으로 사실상 종결**, **1-B는 밑바닥 학습이 아니라 공식 팩 재현→파인튜닝(warm start)**, **1-C 점수는 GOP vs 공식 회귀(PCC 0.72) 대조 후 결정**. 런타임은 발음=fairseq / 말하기(옵션)=NVIDIA NeMo 2스택.

## 0. 큰 그림 — 지금 어디까지 왔나

로드맵은 **두 갈래 병렬**이다.
- **갈래 A · MDD 즉시 분석 (알고리즘, GPU 불필요)** → **본 프로젝트에서 전체 데이터로 완결.**
- **갈래 B · XLS-R+CTC 인식기 (모델 학습, GPU 필수)** → **미착수.** 이하 1절이 그 상세.

> 지능(AI 학습)은 **XLS-R + CTC 한 곳**에만 몰려 있다. 나머지(KoG2P·MDD·L1 prior·GOP 계산·UI)는 학습 없는 알고리즘이거나 인식기 출력의 재사용이다.
> 즉 **남은 GPU 작업의 심장은 '음소 인식기(갈래 B)' 하나**이며, GOP·실시간화는 그 인식기에 의존한다.

## 1. GPU가 필요한 작업 — 상세

### 1-A. Sprint 0.3 — backbone 크기 확정 (🟢 v3: 300M 확정, 재현 확인만)

| 항목 | 내용 |
|---|---|
| **무엇** | ~~300M vs 1B vs MMS 벤치~~ → **공식 MDD 팩이 xls-r-300m에서 F1 0.96** → 300M 채택 |
| **남은 일** | 공식 팩을 우리 환경에서 **1회 재현해 F1 재측**(300M 확정). 3종 벤치가 1회 재현으로 축소 |
| **왜 GPU** | 재현·추론 자체가 GPU 연산(소규모) |
| **완료기준** | 공식 팩 재현 F1 ≈0.96 확인 |
| **정정** | 기존 "음소 인식은 1B급 필요 가능"은 **하향 종결**. 1B/MMS는 L1조건화·실시간이 300M로 부족할 때만 조건부 |
| **개략 규모** | 단일 GPU, 재현 수준 |

### 1-B. Sprint 1-B — XLS-R + CTC 음소 인식기 ★핵심 (대 GPU)

로드맵 전체에서 **유일하게 '학습(지능)'이 일어나는 부품.** wav 를 오발음까지 그대로 듣는 "귀".

| 항목 | 내용 |
|---|---|
| **무엇** | `wav → XLS-R-300m(재활용) + CTC 헤드 → 실제 음소열(오발음 보존)` — v3: **밑바닥 아님, 공식 팩 재현→파인튜닝** |
| **v3 3단계** | **B-0** 공식 MDD Docker 재현(F1 재측) → **B-1** 공식 `train.sh`로 L1 특화 파인튜닝(warm start) → **B-2** 오발음 보존 검증 |
| **왜 GPU** | backbone+CTC **파인튜닝**(백지 아님 → 데이터·시간 절감). 분류보다 무거운 음소 단위 정밀도. |
| **CTC 원리** | blank 삽입 → 가능한 모든 정렬 합산 → **프레임 단위 라벨 없이** 음소열 학습 |
| **완료기준** | 외국인 발화에서 **오발음이 실제 오발음으로 전사됨**(STT식 정답복원 제거) + **PER 목표 달성** |

**학습 라벨 (이미 확보/생성 가능 — 병목 해소됨):**
| 라벨 | 소스 | 생성법 | 상태 |
|---|---|---|---|
| A. 원어민 (오디오, 정답 음소열) | 원어민 낭독 | prompt → **KoG2P**(본 프로젝트 `s0`) 자동 | 도구 준비됨 |
| B. 외국인 (오디오, **실현형** 음소열) | **Speech_lab**(들리는 대로 전사) | orthographic → **KoG2P**(본 프로젝트 `s1`) | **실현형 26.8만건 이미 산출** |
| (참고) gold 위치·유형 | pronunciation_lab error_tags | 본 프로젝트 `s2`(188만) | **평가 정답셋으로 준비됨** |

> **핵심 연결**: 본 프로젝트가 만든 **Speech_lab 실현형(B 라벨)** 과 **KoG2P(A 라벨 도구)** 가 그대로 CTC 학습 입력이 된다. 갈래 A 산출물 = 갈래 B 입력.

**검증(v3 격상):** 노선 일치를 넘어 — 데이터 원저자(엔에스데블)의 **XLS-R-300m + CTC 팩이 실행 가능한 사전학습 체크포인트로 제공되고 F1 0.9601 실측**. 즉 "외부 검증"이 아니라 **재현·이식 대상 그 자체**. 이식 파일: `get_text.py`·`data_prep.sh`·`fairseq_files.py`·`align_result.py`·`calculate_f1.py` (fairseq `run.sh`/`train.sh`). ⚠️ 재현 착수 전 팩 **LICENSE.md(상용 이용 범위)** 확인 필수.

**개략 규모(참고, Sprint 0에서 확정):** XLS-R(300M~1B) 파인튜닝, 자매셋 오디오(EN 1,000h + EU 1,500h + 中日) 규모 → **다중 GPU·수일~수주** 단위. 프레임 라벨 불필요(CTC)라 라벨링 병목은 없음.

**의존 관계:** 1-A(backbone 확정) 선행 → 1-B 완료 시 아래 GOP·실시간화가 열림.

### 1-C. Sprint 2 ① — 발음 점수 (중 GPU) · v3: **GOP vs 공식 회귀 결정**

| 항목 | 내용 |
|---|---|
| **A안 GOP** | 인식기 **음소별 사후확률 재사용** → 음소별 0~100점. 추가 학습 거의 불필요 |

| **권고** | 두 방식을 **인간평가 PCC로 직접 대조 후 채택/앙상블**. GOP 조기 확정 금지 |
| **완료기준** | 두 방식 PCC 비교표 + 1개(또는 앙상블) 확정 · **PCC ≥ 0.60** |
| **의존** | 1-B 인식기(GOP) · 공식 회귀 팩(B안) |

## 4. 한 장 요약

- **코드(알고리즘) 트랙 = 완결.** 국적별 발음오류 패턴(두 소스)·L1 prior·진단 가중치·전체 벤치마크·시각화가 **전체 데이터**로 산출됨.
- **남은 것 = GPU 트랙 하나의 축**: `1-A 300M 확정(재현) → 1-B 공식 팩 재현→파인튜닝 → 2-① 점수(GOP vs 회귀) → 상시 경량화`. UI(2-②)는 인식기 출력에 의존하는 프론트엔드.
- **v3 순변화**: "인식기를 만들 수 있나" 최대 리스크가 **검증 팩(F1 0.96)의 존재**로 소거. 1-B는 밑바닥이 아니라 **재현→파인튜닝**이라 리스크·기간 대폭 축소. 무게중심이 base 개발 → **L1 특화·UI·실시간**으로 이동.
- **착수 준비 완료**: 인식기 학습 라벨(원어민 KoG2P + 외국인 실현형)·평가 정답셋(gold 188만)·채점 하네스·L1 prior 통합까지 갈래 A가 이미 깔아놓음. 여기에 **공식 팩(warm start)**까지 더해져, GPU만 붙이면 갈래 B가 바로 돈다. (재현 전 팩 LICENSE.md 확인)
