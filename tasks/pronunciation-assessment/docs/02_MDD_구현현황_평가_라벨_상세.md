## 1. 한 줄 요약

외국인 한국어 학습자의 발화에서 **어느 소리를 어떻게 잘못 발음했는지(위치+유형) 짚어주는 음소 인식기**를

| 항목 | 내용 |

- **규모** (`_mdd_train/manifest_tag_combined/`):

| split | 발화 수 |
|---|--:|
| train | 872k |
| valid | 116k |
| **test** | **104,211** |

- 0.5초 미만 클립은 제외(frames≥8000 필터; XLS-R 마스킹 크래시 방지)

### 라벨 — 이 프로젝트의 핵심 (3종을 구분해야 함)

같은 AIHub 코퍼스에 라벨 체계가 3개 있고, **어떤 라벨로 학습·평가하느냐가 성능을 결정**했다:

| 이름 | 정체 | 예: 화자가 "빨리"를 [팔리]로 발음하면 | 용도 |
|---|---|---|---|
| **TAG** ✅ | **전문가가 들리는 대로 적은 음소 전사** (TextGrid, 강라벨) | 라벨 = `ㅍㅏㄹㄹㅣ` (오류가 라벨에 그대로) | **학습·평가 정답** |
| record | 전사자가 **맞춤법으로** 받아적은 문장 → G2P 기계 변환 (약라벨, LAR 낭독 과제) | 전사 "빨리" → 라벨 = `ㅃㅏㄹㄹㅣ` (오류가 지워짐) | 구 트랙 학습(폐기) |
| gold | 오류 위치·유형 태그만 있고 실현형 음소가 없음 (`actual_phone=null`) | 채점 불가 | L1-prior 통계 전용 |

- **학습 입력 라벨(`train.ltr`)** = TAG 전사자 자모열 (실현형 = "실제로 낸 소리")
- **표준음(`train.canon`)** = LAB 표준 발음 (채점 시 기준)
- manifest 빌더: `scripts/build_tag_manifest_combined.py` (TAG TextGrid phones→자모, LAB→canonical)

## 3. 평가 지표는 어떻게 나온 것인가

### 채점 방식 (공식 AIHub `calculate_f1.py` 방식 그대로)
1. 발화별로 3개 시퀀스: **canonical**(표준음) / **전사자**(TAG, 사람 정답) / **인식기 출력**
2. edlib로 3자 정렬 (`scripts/mdd_reproduce_official.py`의 `align()`/`fixup()` — 공식 `align_result.py`와 동일 알고리즘)
3. 각 정렬 위치에서 이진 판정: 정답 오류 = (canonical ≠ 전사자), 예측 오류 = (canonical ≠ 인식기)
4. 전체 위치 풀링 → **weighted binary F1** (sklearn, 공식과 동일)

### 평가 데이터셋
- **TAG combined test = 104,211 발화** (041 유럽 + 043 아시아, 화자 분리 test split)
- 정렬 위치 수 약 107만 개

### 결과 (전부 실측)

| 모델 × 평가 | weighted F1 | 비고 |
|---|--:|---|
| **자체 CTC(TAG 전 언어권) → TAG test 178k** | **0.9547** | ★**현역·대표 수치**★ `tag_all_lar`. 040~043 전부를 단일 모델로 (`eval_tag71_all_lar.json`) |
| 자체 CTC(TAG 041+043) → TAG test 104k | 0.9558 | 구세대 `tag_combined` (2개 코퍼스). 전 언어권 확장 전 값 |
| 자체 CTC(TAG 041) → TAG 041 test 52k | 0.958 | 유럽 단독 |
| 공식 AIHub 배포 모델 → TAG 평가 | 0.965 | 기준선. 우리 채점법으로 0.96 재현 성공 = 채점 타당성 검증 |
| (참고) 오류 클래스 단독 F1 | 0.4319 | precision 0.466 / recall 0.402 — "위치 하나하나"의 검출 성능. 공식 weighted 지표는 정상 위치(**95.86%**)를 포함하며, 전부 "정상"으로 찍는 자명한 베이스라인이 이미 **0.9384** 다 |

> ⚠️ 이전 기록에 0.9607이 있으나 당시 평가 스크립트가 유실되어 재현 불가.
> **발표·보고에는 `tag_all_lar`의 0.9547을 쓸 것** — 040~043 전 언어권을 단일 모델로 처리한 현역 수치이고,
> 평가셋도 가장 크다(178,049발화 / 1,196화자). 0.9558은 041+043만 학습한 구세대 값이므로
> "전 언어권"이라는 서술과 함께 쓰면 사실과 어긋난다.
>
> **오류 클래스 F1(0.4319)의 원인**: 모델이 오발음의 절반가량을 표준발음으로 되돌린다.
> 오발음 보존율 **0.514** — 학습자가 표준에서 11.56% 벗어났는데 모델 출력은 5.94%만 벗어남.
> 전사 자체는 정확하다(전문가가 들은 음소의 95.3% 일치). 근거: `scripts/check_b2_preservation.py`,
> `check_b2_preservation.json`. 이것이 계획서의 **B-2(오발음 보존 검증)** 항목에 대한 답이며,
> 공식 모델을 같은 잣대로 재보기 전까지는 "우리 방식의 특성"인지 "과제 특성"인지 단정할 수 없다.

### record로도 평가했는가? — 했고, 그 결과가 방향 전환의 근거
초기 트랙은 record(약라벨)로 학습했다. 결과:

| 조합 | F1 | 해석 |
|---|--:|---|
| record 학습 → record 평가 (in-domain) | 0.80 | 약라벨 천장. **0.96 공식 모델을 warm-start해서 record로 이어 학습해도 0.82** → 데이터가 아니라 라벨이 병목이라는 증거 |
| record 학습 → gold 평가 | 0.21 | gold는 실현형이 없어 MDD 채점 자체가 성립 안 함 |
| 공식 0.96 모델 → gold 평가 | 0.40 | 강한 모델도 gold로 재면 낮음 = gold가 잘못된 자(尺)라는 실측 증거 |
| **현재 모델(tag_all_lar) → gold 평가** (2026-07-22) | 0.22~0.28 (tol0~±2) | 대칭성 확인용 실측 — TAG 0.95급 두 모델(공식·자체)이 gold에선 나란히 0.2~0.5로 붕괴. 잣대 불량 최종 확정. 공식(0.42)보다 낮은 것은 우리 모델이 gold가 태깅하지 않은 실현 편차까지 전사(→FP 처리)하는 민감도 차이로 추정 |

**교훈**: record는 맞춤법 전사→G2P라 발음 오류가 라벨에서 지워짐 → 모델이 오류를 "자동 교정"하도록 학습됨 → MDD에 부적합.
TAG(전문가 실현형 전사)로 전환하자 0.80 → 0.958.

## 4. 라벨 후처리 — 자모 → KoG2P 71음소 (2026-07-18 검증 완료)

납품/API 포맷은 KoG2P 로마자 음소(p0, ph, kf, aa, ...)를 요구하므로, 모델의 자모 출력을 **후처리로 변환**한다 (재학습 없음).

- **변환기**: `scripts/jamo_to_kog2p.py`
  - 규칙: 자음은 "다음 토큰이 모음이면 초성, 아니면 종성" (ㄱ→k0/kf). 예외: **ㅇ은 위치 무관 종성 ng**
    (병원=ㅂㅕㅇㅝㄴ처럼 연음 안 되는 종성 — 실데이터 10.7만 건 확인), 겹받침은 항상 종성,
    모음 없이 적힌 경음 ㅃㅉㄸ(더듬기 전사, 109건)은 초성 심볼 폴백
  - **검증**: 전체 manifest 2,183,836라인 100% 변환 + 왕복(자모→음소→자모) 무손실 + 1:1 길이 보존
- **F1 보존 검증** (`scripts/mdd_eval_tag71.py`, 동일 예측·동일 채점 코드·라벨 공간만 교체):

| | 자모 채점 | 71음소 변환 후 채점 |
|---|--:|--:|
| weighted F1 | 0.9558 | 0.9550 |
| 오류 클래스 F1 | 0.4707 | 0.4708 |

→ **후처리 변환 확정**. 추론 시 `jamo_to_phones(pred)` 한 줄이면 71음소 출력.
- 테스트 104k 예측 저장: `_mdd_train/eval_tag_combined_preds.jsonl` (재채점은 GPU 불필요)

## 5. 진단 파이프라인·데모 (구현 완료)

```
제시 문장 ──KoG2P(rulebook)──→ 표준 음소열 ┐
                                          ├─ NW 정렬 → sub/del/ins → 유형 규칙
사용자 오디오 ──CTC 디코드──→ 실제 자모열   ┘   (경음화·격음화·비음화·유음화·구개음화·탈락·첨가·초성/종성)
                                          → × L1-prior[국적] (81개국, gold 통계 기반) → 진단 JSON
```

- 유형 규칙 + 예시 추출: `scripts/mdd_demo_pipeline.py` (실제 test 발화에서 모델이 오류를 정확히 잡은 사례 확보:
  줄넘기[줄럼끼]→[줄넘기] 유음화, 괜찮다 ㅌ→ㄷ 격음화, 교육열 ㄴ첨가 누락 등)
- L1-prior: `_mdd_analysis/l1_prior_product/l1_prior_weights.json` — 국적별 오류유형 사전배수(>1 = 그 나라 전형 오류)
- **웹 데모**: `runs/demo/mdd_demo.py` + `mdd_demo.html` (port 8901)
  - 문장 선택(검증된 프리셋 + 자유 입력) → 마이크 녹음/파일 업로드 → 표준 vs 내 발음 정렬 시각화(자모+71음소 병기),
    오류 카드(유형 설명 + L1 배지), 무음 게이트
  - **단어 수준 진단** (2026-07-18 추가): 음운규칙이 음절 수를 바꾸지 않는 성질을 이용해 canonical을
    모음 기준 음절→단어 span으로 분할, 단어별 OK/오류/누락 판정 (음소 70%+ 삭제 = 누락).
    **학습 없이** 기존 인식기+정렬로 구현; record의 단어 누락 정답과 실발화 검증 일치
    (LAR007 "…잠을 잤다"→"…참을" 발화에서 잤다=누락, 잠을=오류, 나서=OK 재현)
  - 외부 공개: <배포 URL> (Tailscale Funnel, 국적 분류 데모와 같은 도메인)

## 7. 단어 누락 검출 정량평가 (2026-07-18) — ⚠️ 한계 발견 (중요한 음성 결과)

record LAR 2만 발화(단어 11.5만, 실제 누락률 1.3%)를 정답지로 데모의 단어 누락 판정을 대량 채점
(`scripts/eval_word_skip_record.py`, 예측 캐시 `word_skip_preds.jsonl`):

| 삭제율 임계 | precision | recall | F1 |
|--:|--:|--:|--:|
| 0.7 (데모 기본) | 0.072 | 0.831 | 0.133 |
| 0.9 (최선) | 0.116 | 0.708 | 0.200 |

- **재현율은 높으나(진짜 누락의 83%를 잡음) 정밀도가 낮음** — 누락 표시의 ~90%가 오탐.
- **원인 규명 완료**: 오디오 처리 버그 아님(ffmpeg 경로 동일 결과). **인식기의 도메인 갭** —
  RW/RS(짧고 또박또박한 발음문항)로 학습된 모델이 LAR(빠른 연결 발화 문장 낭독, 5초에 문장 전체)에서
  음소를 대량 누락함. 예: "나는 공연 보러 갔을 때가…"를 완벽히 읽은 발화에서 모델 출력이 절반 이하로 붕괴.
- **함의**: 짧은 프리셋 문항 진단(RW/RS 도메인)은 유효. **긴 자유 문장의 "누락" 판정은 현재 신뢰 불가.**
- **해결 방향**: LAR 오디오로 도메인 적응 (record 무오류 발화의 G2P 라벨 혼합 학습 또는 pseudo-label;
  RW/RS TAG 데이터와 혼합해 MDD 라벨 품질 유지) → 적응 후 본 평가 재실행으로 개선 확인.

## 9. 점수 트랙 — GOP + 초소형 보정 (2026-07-19)

발표자료 계획("점수 팩 vs **GOP** 비교 후 채택")의 GOP 쪽을 구현·측정. **인코더 학습 없음** —
동결 MDD 모델의 부산물 특징 6종(gop·nll·per + 말속도·blank비율·최장쉼) 위에 Ridge(7파라미터)만
train 화자 점수로 캘리브레이션. 정답 = lab JSON `EvaluationMetadata`(발음숙달/이해가능/유창성 1~5).
평가 = test 화자 1,180명(화자분리·겹침 0), 화자당 전체(~150발화) 집계.

| 차원 | −PER 단독 | **GOP+보정** | 목표 0.60 | 비고 |

### 9-1. 특징 확장 v2 (2026-07-25) — 게이트 3개 전부 통과 ✅

GOP 분위수, 화자 내 표준편차)하고 회귀기를 Ridge → GBM으로 교체. **인코더는 여전히 동결.**

| 차원 | v1-ridge | v2-ridge | v2-gbm | **v2-gbm-utt(채택)** | 목표 |
|---|--:|--:|--:|--:|:-:|
| 발음숙달 | 0.5235 | 0.6184 | 0.6487 | **0.6622** | ✅ |

### 9-2. 공식 점수 팩 재현 및 채택 판정 (2026-07-26) — **GOP 채택** ✅

체크포인트 12개(3과제 × 4언어권, 각 3.5G)를 받아 **우리 화자분리 test로 직접 채점**했다.

**팩의 실체**: 발표자료에 적힌 "XLS-R + 회귀(MSE)"가 아니라 **CTC로 점수 숫자를 받아쓰는 모델**.
출력층 `proj.weight (11, 1024)` = 특수토큰4 + `0~5` + `|`. 학습 라벨이 `"3 |"` 형태(`fairseq_files.py`),
추론은 greedy CTC 후 첫 숫자(`correlation.py`). 사전을 복원해 재현 성공.

| 차원 | 팩 발화단위 | 팩 화자단위 | 정확일치 | 우리 GOP(화자단위) |
|---|--:|--:|--:|--:|
| 발음숙달 | 0.804 | 0.943 | 72.5% | 0.662 |
| 이해가능 | **0.725** | 0.903 | 67.1% | 0.683 |
| 유창성 | 0.895 | 0.966 | 81.3% | 0.762 |

이해가능 발화단위 **0.725 ≈ 저자 보고 0.7228** — 재현은 정확했다. 그러나 이 수치는 채택 근거가 못 된다:

- **팩의 학습 화자 목록이 없고, 우리 test 화자가 거기 포함됐을 개연성이 높다.** 우리 화자분리는
  *우리* 모델만 보호한다. 1~5점 척도에서 정확일치 67~81%는 사람 채점자 간 일치도를 넘는다.
- **교차언어 테스트(`eval_pcc_crosslang.py`)로 검증**: 팩은 언어권별 모델 4개라 *다른 언어권 화자는
  구조적으로 미학습 화자*다. 여기서 성능이 무너진다.

| | 대각(학습 언어권) | 비대각(**미학습 화자 보장**) | 낙폭 |
|---|--:|--:|--:|
| 발음숙달 화자단위 | 0.938 | **0.330** | −0.608 |
| 유창성 화자단위 | 0.964 | **0.625** | −0.339 |

- 예측값 표준편차는 유지(0.98→0.81)되므로 "도메인 밖에서 상수 출력"으로 인한 착시가 아니다.
- 유창성(말속도·쉼)은 **모국어와 무관한 물리량**인데도 0.34 떨어진다 — "언어권 특화"만으로는
  설명되지 않는다.
- 화자 평균을 뺀 중심화 PCC는 0.42~0.55로, 팩이 발화 단위 변동도 잡긴 한다(순수 화자 조회는 아님).

**판정**: 미학습 화자임이 **보장된** 조건에서 팩은 0.330 / 0.625, 우리 GOP는 0.662 / 0.762다.
검증 가능한 유일한 비교에서 GOP가 앞선다. 게다가 GOP는 (a) 이미 배포하는 MDD 모델의 부산물이라
**추가 모델 0개·10.5G 절약**, (b) L1 라우팅 불필요, (c) 특징이 해석 가능(쉼 개수·오류 군집도)하다.
→ **점수 3종은 GOP+보정을 채택**하고, 팩 수치는 "검증 불가"로 각주 처리한다.
