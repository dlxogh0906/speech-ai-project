# 갈래 B 음소 인식기(MDD) — 학습·평가 파이프라인 & 아키텍처

_작성: 2026-07-11 · 대상: XLS-R-300m + CTC 음소 인식기 (발음오류 탐지·진단, MDD)_
_모델: `$SPEECH_AI_DATA/mdd_ckpt/checkpoint_best.pt` · 코드: `$REPO/scripts/`, `$MDD_OUTPUTS/`_

---

## 1. 목표 & 설계 원칙

외국인 한국어 학습자의 음성에서 **어디를·무엇을 잘못 발음했는지**를 짚어내는 인식기(갈래 B).

- **핵심 능력 = "오발음을 그대로 듣는 귀".** 일반 STT는 "칸"을 틀리게 말해도 정답 "칸"으로 복원해 오류가 사라진다. 우리 인식기는 **틀린 발음을 틀린 그대로**(`kh aa nf` → `k0 aa nf`) 전사해야 MDD가 `kh→k0` 오류를 잡는다.
- 이를 위해 **디코딩에 언어모델(LM) 미투입** → 순수 음소 CTC greedy 디코딩.
- 음소 심볼셋 = **KoG2P 71음소**(+ fairseq 특수토큰 4개 = vocab 75, blank=idx 0).
- 하드웨어 = 단일 **A100 80GB**.

## 2. 아키텍처

```
                    ┌─────────────────── 학습(파인튜닝) ───────────────────┐
  16kHz mono wav ─► │  XLS-R-300m 인코더  ─►  CTC head(wav2vec_ctc)        │ ─► 음소열
  (layer_norm)      │  warm-start          (71+4 vocab, blank=0)          │    k0 aa nf …
                    │  freeze 10k steps→해동                               │
                    └──────────────────────────────────────────────────────┘
                                          │  CTC greedy 디코드
                                          │  (argmax → unique_consecutive → blank 제거)
                                          ▼
        ┌──────────────── MDD 채점 (3자 정렬, 위치단위) ────────────────┐
        │   ① 표준(G2P)     target_phones   ← 읽을 문장 KoG2P 정답열      │
        │   ② 전사자(실현형) actual_phones   ← 사람 전사(정답 오발음)      │  Needleman-Wunsch
        │   ③ 인식기 예측    CTC 출력                                    │  정렬
        │                                                               │
        │   ②↔① sub/del = 진짜 오발음 위치(gold)                        │
        │   ③↔① sub/del = 예측 오발음 위치                              │
        │   → 위치단위 TP/FP/FN → P·R·F1·FAR·FRR   (탐지)               │
        │   → TP 위치에서 ③실현형 == ②실현형 ? → DER                    (진단) │
        └───────────────────────────────────────────────────────────────┘
```

- **인코더**: `xlsr2_300m.pt`(다국어 wav2vec 2.0 300M)에서 warm-start. 초기 10k step은 인코더 동결(CTC head만 학습), 이후 해동해 함께 파인튜닝.
- **헤드**: fairseq `wav2vec_ctc` (음소 vocab에 대한 선형 CTC head).
- **채점**: 학습 criterion과 동일한 greedy 디코드 → 3자 정렬. 공식 MDD 팩의 `align_result.py`/`calculate_f1.py`와 동일 알고리즘(우리 `s1._nw` + `s5` P/R/F1 정의로 재현).

## 3. 데이터

| 축 | 소스(트랙) | 라벨(음소열) | 규모 | split (train/valid/test) |
|---|---|---|--:|---|
| **B · 외국인** | Speech_lab **LAR**(고정 프롬프트 과제, target=prompt) | **실현형**(actual_phones, 들리는 대로 전사→KoG2P) | 268,533 | 214,642 / 26,693 / 27,198 |
| **A · 원어민** | 한국어 원어민 **자유대화 음성**(일반남여 일반통합·자유대화 코퍼스) | **정답**(전사→KoG2P, 원어민=정답=실현형이라 ltr==canon) | 67,682 | 54,327 / 6,711 / 6,644 |
| (참고) gold | pronunciation_lab **RW/RS/RP**(발음평가) | error_tags(위치·유형, **실현형 없음**) | 175,732(평가셋) | out-of-domain 참고평가(전체 error_tags 188만은 L1-prior 집계용) |

**핵심 제약 — 실현형은 LAR에만 있다.** 발음문항(RW/RS)의 phones 티어는 **표준음 혼입**(정답 참조)이라 "뭐라고 발음했는지"가 없다 → CTC 학습 타깃 불가 → **학습은 LAR로만**. 그래서 gold(RW/RS)는 학습 도메인과 다른 **out-of-domain 참고 평가셋**이 된다(§5·§6 참조).

- 전처리: **16kHz mono**, `wave` 표준라이브러리 로드, per-utterance **layer_norm**(config `normalize: true`).
- **화자분리**: 외국인(LAR)은 train/valid/test 화자 겹침 **0**(검증됨, 화자 8,864/1,098/1,112). ⚠️ **원어민 track은 발화단위 분할**이라 화자 일부 겹침(test 화자의 ~39%가 train에도 존재) — 엄격 화자분리 아님. 제품 핵심인 외국인 MDD 평가는 화자분리라 영향 없으나, 원어민 PER은 다소 낙관치.

### 4-1. 매니페스트 (fairseq audio_finetuning · labels=ltr)

  {train,valid}.ltr        행별 음소열(공백구분) = 학습 타깃(실현형/정답)

### 4-2. 학습 설정 (`_mdd_train/config/mdd_ctc_300m.yaml`)
| 항목 | 값 | 비고 |
|---|---|---|
| backbone | `xlsr2_300m.pt` | warm-start |
| criterion | `ctc` (zero_infinity) | 프레임 라벨 불요 |

| max_tokens | 2,400,000 (실행값; config파일엔 1.6M) | fp16, A100 80GB |

| best_checkpoint_metric | `loss` (valid) | 음소 CTC라 wer 대신 valid loss |
| save_dir | `$SPEECH_AI_DATA/mdd_ckpt` | 2k step마다 저장(PER 조기확인) |

## 5. 평가 파이프라인

### 5-1. 공통 디코드
학습 criterion과 **동일한** CTC greedy: `logits.argmax(-1).unique_consecutive()` → `blank(0)` 제거. `normalize=True`면 per-utterance layer_norm 후 인코더 입력.

### 5-2. 지표
| 지표 | 정의 | 스크립트 |
|---|---|---|
| **① PER** | 편집거리(pred, target)/len(target), 원어민/외국인 분리 | `scripts/mdd_eval.py` |
| **② MDD 탐지 F1** | 3자 정렬 위치단위 TP/FP/FN → P·R·F1·FAR·FRR | `scripts/mdd_eval_lar.py`(LAR), `mdd_eval_pos.py`(RW/RS) |
| **③ MDD 진단 DER** | TP 위치에서 인식기 실현형≠전사자 실현형 비율 | `mdd_eval_lar.py` |

- **FRR**(과지적)=FP/(TN+FP) · **FAR**(미검출)=FN/(TP+FN)=1−Recall.
- 정렬 = `s1_speechlab_mdd._nw`(Needleman-Wunsch), F1 정의 = `s5_benchmark.prf_at_threshold` 원문 재사용.

### 5-3. 평가셋 — **발표자료 지정 = gold(위치·유형)**
발표자료가 MDD F1 평가셋으로 **gold(pronunciation_lab)**를 지정함:
- HTML: *"gold는 **위치·유형(평가 정답셋)으로만 사용**"* · *"MDD F1 채점(**gold 188만**) → ≥70%"*
- PDF p.13: *"'위치·유형'은 error_tags[를], '실현형'은 LAR MDD를 각각 정답 소스로"* → **위치·유형(평가)=gold, 실현형(학습라벨)=LAR**

따라서:
- **목표 지표 = gold MDD F1** (인식기↔target_phones 정렬 → err_pos 탐지), **≥70%**. 학습은 LAR, 평가는 gold라 **out-of-domain**.
- **LAR MDD F1 = in-domain 진단용 곁수치**(목표 지표 아님). LAR 실현형은 **학습 라벨**이지 평가 정답셋이 아님.

## 6. 공식 평가수치 (2026-07-11)

### ① PER (음소오류율)
| 대상 | PER | 발화 |
|---|--:|--:|
| 외국인 (LAR test, in-domain, 화자분리) | **5.29%** | 27,198 |
| 원어민 (native test, ⚠️비-화자분리) | **7.35%** | 6,644 |

> ⚠️ 외국인 PER은 화자분리 test라 신뢰 가능. **원어민 PER은 화자 일부 겹침(§3)이라 다소 낙관치** — 원어민은 "정답 한국어 음소" 보조학습용이라 제품 핵심(외국인 MDD)엔 영향 없음.

### ② 목표 지표 — gold MDD F1 · 게이트 ≥70% → **0.208 미달 ❌**
발표자료 지정 평가셋(gold 위치·유형). 학습(LAR)과 다른 도메인이라 미달.
| 구분 | 지표 | 값 |
|---|---|--:|
| 탐지 | **F1 / P / R** | **0.208** / 0.124 / 0.658 |
| | FRR / FAR | 0.175 / 0.342 |
| 진단 | 유형정확도 / DER | 0.372 / 0.628 |
| 규모 | 발화 / 위치 | 175,732 / 2,284,640 |

> 미달 원인 = 도메인 갭(학습 LAR / 평가 gold RW/RS, PER 5.3%→21.9%). 해소 = gold 오디오 도메인 확장 재학습(필수).

### 곁수치 — LAR in-domain MDD F1 (목표 아님)
F1 **0.806** (P 0.857 · R 0.760 · FRR 0.015 · FAR 0.240 · DER 0.212). 인식기가 학습 도메인(LAR)에선 잘 됨을 보이는 진단용. 단 정답=학습라벨과 같은 Speech_lab 소스라 **반순환**(상한). **목표 지표는 gold이지 이게 아님.**

### ⚠️ 상태 & 남은 일
- **현재 = 게이트 미달**: 목표(gold MDD F1 ≥70%) 대비 **0.208**. 원인 = 학습(LAR)/평가(gold RW/RS) 도메인 갭.
- **필수 = 도메인 확장**: gold 오디오(비-held-out 화자)를 학습에 추가 → RW/RS PER↓ → gold F1↑. 정상발화 canonical 타깃부터가 안전(§ 오발음 보존 유지).
- (참고) LAR 곁수치 0.806의 반순환 여부 확인 = 전사자 일관성 점검(별개). 공식 팩 B-0 미실행.
