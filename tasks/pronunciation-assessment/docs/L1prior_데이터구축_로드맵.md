# 비버톡 L1 prior 데이터 구축 로드맵 (상세)

> 원천: 교육용 외국인 한국어 음성 데이터셋(발음 434k + 말하기 149k, EN/EU/中日 자매셋)
> 목표: 국적(L1)별 발음 오류 패턴 = **L1 prior**를 구축해 비버톡 진단의 국적-인지 차별화를 만든다.
> 이 로드맵은 대화에서 확정된 사실을 모두 반영한 최종본이며, 초기 가정(orthographic이 대량 본체)은 **폐기**되었다.

---

## 0. 한 줄 요약

> **1차 본체 = 발음 문항(434k)의 사람-태깅 `error_tags`를 국적별로 집계.**(G2P/MDD 불필요)
> **2차 보강 = LAR(따라말하기)만 G2P+MDD로 실현형 대치쌍을 추가.**
> ATQ 등 자유발화·운율/비유창 오류는 이 파이프라인에서 제외.

---

## 1. 소스 재정의 (물량 반전 반영)

| 소스 | 물량 | 역할 | 이유 |
|---|---|---|---|
| **발음 문항 error_tags** (RW/RS/RP) | 434,063 | **L1 prior 1차 본체** | 사람이 17종 유형을 이미 태깅 → 파생 불필요 |
| **LAR** (말하기 중 따라말하기) | 149k의 일부 | **실현형 대치쌍 2차 보강** | target=prompt 성립 → G2P+MDD 유효 |
| ATQ·SPT·PDT·EIG·SSO | 나머지 | **제외** | prompt=자극(정답 아님), 명세상 prompt 필수N |
| 자매셋 (EU·中日) | 별도 | **다국적 확장** | 동일 스키마 → 국적별 prior 통합 |

핵심 판단:
- 초기엔 "orthographic(말하기)이 대량, phonemic이 소량 gold"로 봤으나 **실제는 발음문항이 대량(434k)이고 사람 오류태그까지 있다.** 그러므로 **G2P/MDD는 본체가 아니라 LAR 전용 보강**으로 재배치.

## 2. 통합 오류 스키마 (목표 산출물)

레코드(발화) 단위 + 오류 단위 2계층.

```json
{
  "utterance_id": "0018185",
  "L1": "China",                 // nationality
  "language_region": "ZH",       // 파일명 4번째 필드
  "proficiency": "Intermediate",
  "recording_level": "Beginner",
  "task_code": "RS048",
  "source": "pronunciation_error_tag | lar_mdd",
  "target_phones": ["...KoG2P(prompt)..."],
  "errors": [
    {
      "pos": 12,
      "phone_context": "kh",         // 해당 위치 표준 음소(발음문항: phones/G2P 정렬)
      "actual_phone": "k0",          // ← LAR MDD만 채움 (실현형)
      "error_type": "격음화",         // 발음문항=사람 태그 직접 / LAR=지문규칙 자동
      "t_start": 3.25, "t_end": 3.69,// ← 발음문항만 (타임스탬프)
      "group": "G1|G2|G3",
      "confidence": "gold|derived"
    }
  ],
  "eval": { "PronunProf": 4, "Fluency": 0, "Comprehend": 4 },
  "quality_flag": null
}
```

- `source`로 두 파이프라인 출처를 반드시 구분.
- 발음문항은 `error_type`·`t_*`가 gold, `actual_phone`은 대개 null(표준음).
- LAR은 `actual_phone`이 채워지고 `error_type`은 지문규칙으로 파생(derived).

## 3. 파이프라인 A — 발음 문항 error_tags 집계 (1차 본체)

가장 값싸고 큰 성과. AI 없이 즉시 착수.

### A-0. 게이팅
- 파일명 6번째 코드가 **RW/RS/RP**인지 확인(발음 트랙).
- 자모→KoG2P 기호 매핑표 준비(phones 티어 정규화용).
- 17종 error_tag 라벨 표준화(오탈자·이형 통일).

### A-1. 파싱
- JSON `phonemic.error_tags` + TextGrid `tags` tier 로드.
- 각 오류를 (위치 phones-idx, 유형, t_start, t_end)로 추출.
- **phones 티어는 표준음 참조로만 사용**(위치·맥락). 실현형은 여기서 뽑지 않음.

### A-2. 3그룹 분류 (섹션 5)
- 유형을 G1/G2/G3로 태깅. G3(운율·비유창·기타)는 집계 본선에서 제외 또는 별도 트랙.

### A-3. 국적별 집계
- `nationality × error_type` 교차표 + 정규화(발화·음소 노출 대비 비율).
- 산출물: **L1별 상위 오류유형 표 = L1 prior 본체.**
- 완료기준: 국적별 17유형(또는 G1+G2 유효유형) 빈도·비율 표, 신뢰구간.

> 이 단계만으로 로드맵 갈래 A "L1별 상위 오류 유형 표"가 완성된다.

---

## 4. 파이프라인 B — LAR MDD 보강 (2차)

실현형(무엇으로 발음했나)이 필요할 때만.

### B-0. 게이팅
- 파일명 코드가 **LAR**인지 확인.
- `pron_error_pipeline.py`의 `READ_ALOUD_PREFIXES`에 LAR 포함(RS도 낭독이나 발음문항엔 orthographic이 없으므로 MDD 대상은 사실상 LAR).

### B-1. 정제 (정렬 전 필수)
- 간투사 제거(음/아/어/그/저…) + 인접 반복 축약 → `disfluency`에 위치 기록.
- (근거: 말하기 전사는 간투사·반복까지 다 적었으므로 반드시 걷어내야 가짜 오류가 안 생김.)

### B-2. G2P + MDD
- `prompt`, 정제된 `orthographic` 양쪽 KoG2P → Needleman-Wunsch 정렬.
- 대치·삭제·삽입 → (pos, target_phone, actual_phone).

### B-3. 유형 자동 태깅 (그룹2 지문)
- 섹션 5의 적용형/미적용형 지문으로 대치쌍에 error_type 부여.
- 발음문항 gold 태그로 이 자동분류 정확도를 검증.

### B-4. quality guard
- PER > 0.6 또는 길이비 이상 → 붕괴/오라우팅 의심 플래그.

> 코드 자산: `pron_error_pipeline.py` (파일명 라우팅 + 간투사/반복 정제 + G2P + MDD). LAR 검증 PER 2.6%, 실오류 1건(걸→거 ㄹ탈락) 확인 완료.

## 5. 오류유형 3그룹 처리 규칙

| 그룹 | 유형 | 처리 | 비고 |
|---|---|---|---|
| **G1 분절대치** | 초성·종성·모음오류 | G2P 슬롯 대치 비교 | 전체의 절반↑, 이미 처리 가능 |
| **G2 음운규칙** | 격음화·연음규칙·비음화·경음화·구개음화·유음화·음운탈락·ㄴ첨가·모음삽입 | **적용형(KoG2P) vs 미적용형(축자) 지문** 매칭 | 탈락/첨가/삽입은 MDD del/ins로 직접 |
| **G3 운율·비유창·기타** | 반복·간투사·경계억양·강세·기타 | G2P 불가 → 제외/오디오 트랙 | "기타" 24k는 샘플 검수 먼저 |

### G2 지문 예시(검증됨)
```
국물      적용형 …[ng]…   미적용형 …[kf]…   → 비음화 지문 kf→ng
파악하지  적용형 …[kh]…   미적용형 …[kf h0]… → 격음화 지문 kf+h0→kh
굳이      적용형 …[c0]…   미적용형 …[tf]…    → 구개음화 지문 tf→c0
무엇인지  적용형 …[s0]…   미적용형 …[sf]…    → 연음 지문 종성유지
```
발음문항 error_tag(유형 gold)와 이 지문을 매핑해 **두 소스를 같은 taxonomy로 통일**.

## 6. phones 티어 취급 원칙

- 발음문항 phones는 **표준음(정답 참조)일 수 있음**(가이드 지시와 무관하게 실측 확인).
- 따라서 **오류의 "위치·유형"은 error_tags를, "실현형"은 LAR MDD를** 각각 정답 소스로 삼는다.
- phones에서 실현형 대치쌍을 뽑으려는 시도는 금지(태거 편차로 오염).

---

## 7. 다국어 L1 통합

- EN / EU / 中日 자매셋은 **동일 스키마·동일 17종 taxonomy**.
- 파일명 4번째 코드(EN/ZH/…)와 `nationality`로 L1 축 정렬 → 하나의 `nationality × error_type` 통합 테이블.
- 산출물: **국적별 발음오류 prior 매트릭스** = 비버톡 진단의 국적-인지 가중치.
- 주의: 권역별 태깅 편차 가능 → 권역 간 비교 전 정규화(발화량·음소노출·태거 편차 보정).

## 8. 품질 게이팅

- **저품질 배제/다운웨이팅**: `LanguageUseEval`/`PronunProfEval`/`recording_level` 임계.
- **어절 붕괴 필터**: 한 어절 내 오류 비율 ≥ 임계 → 노이즈/극저숙련 별도 버킷.
- **오라우팅 방어**: LAR MDD의 PER·길이비 가드.
- **태거 일관성**: 동일 문항 교차검수 편차 점검(원천은 2회 교차 전수검수 되어 있으나 우리 재가공 단계에서도 스팟체크).

## 9. 벤치마크 & 검증 (공식 baseline 인용)

| 축 | 지표 | 공식 목표 | 용도 |
|---|---|---|---|
| 음소 인식(MDD) | F1 | ≥ 70% | 갈래 B 인식기 게이트 |
| 발음 점수(GOP) | PCC | ≥ 0.60 | 사람평가 상관 |
| MDD 진단 | P/R/F1·FAR·FRR·DER | — | error_tag를 정답셋으로 |
| 말하기 숙달도 | WCE | ≤ 30% | 분류 |
| 전달력 | CER | ≤ 12% | ASR 기반 |

- 발음문항 `error_tags` = **MDD 정확도 채점의 정답셋**.
- `PronunProfEval` 등 = **GOP PCC 벤치**.
- 엔에스데블 **오픈소스 레시피(XLS-R+CTC, fairseq)**를 warm-start/baseline으로 인용.

- [ ] G2 지문 테이블(9개 규칙) 작성
- **게이트**: 위 4개 미완이면 이후 정지.

### Sprint 1 — 두 파이프라인 병렬
- [ ] **A**: 발음문항 error_tags → 국적별 17유형 집계(즉시 성과, AI 불필요)
- [ ] **B**: LAR → 정제 → G2P+MDD → 실현형 대치쌍 + 지문 유형태깅
- **완료기준**: A=국적별 오류유형 표, B=LAR 대치쌍셋 + 자동유형 정확도(vs 발음문항 gold)

### Sprint 2 — 통합·다국어·검증
- [ ] 통합 스키마 적재(source·결측·quality flag)
- [ ] EN/EU/中日 통합 L1 prior 매트릭스
- [ ] MDD F1 / GOP PCC 벤치(원천 라벨 기준)
- **완료기준**: L1 prior 매트릭스 + 벤치 리포트
