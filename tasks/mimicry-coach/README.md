# 성대모사 교정 (mimicry-coach) — Phase 0

원본 대사와 내 녹음을 **음절 단위로** 비교해 *어느 글자에서, 어떻게 어긋났는지, 어떻게 고칠지* 짚는다.
계획서 「성대모사 교정 도구 v0.2」(2026-10-11)의 **Phase 0 기술 검증**이다. 학습은 없다 —
발음 task 의 원어민 정렬 모델 + Praat 신호처리 + 규칙이다.

```
원본 = 영화 「친구」 원작 발췌(목소리만 분리) · 녹음 = TTS 가 따라 한 것
대사: 니가 가라 하와이
  [니❸][가] [가❷][라] [하❶][와][이]
  ❶ '하' 앞에서 안 쉬었어요 → '하' 앞에서 한 박자 쉬어보세요   (쉼: 원본 1.69초 → 나 0.00초)
  ❷ '가'가 원본보다 높아요 → 힘을 빼고 조금 낮게 내보세요   (원본보다 4.2반음 높음)
  ❸ '니'를 너무 짧게 말했어요 → '니'를 원본처럼 길게 끌어보세요   (빠르기를 맞춘 뒤 원본의 0.6배 길이)
```

> 원작의 두 번째 '가'는 긁는 소리로 60 Hz 까지 떨어진다. 2026-10-18 전에는 ❷ 가 "'가'에서 끝이 내려갔어요(−7.1반음)"였는데,
> TTS 발성 시작 3프레임 음높이 튐이 부풀린 값이었다 — 서비스 점검에서 고쳤다([`results/08_서비스점검.md`](results/08_서비스점검.md) §8).

## 설계 결정과 근거

1. **원본과 녹음에 같은 추출기.** 계획서는 원본 RMVPE / 녹음 pYIN 이었다. 추출기 성향 차이가 그대로 "어긋남"이 된다.
   분석은 서버에서 한다 — 녹음 하나 0.06~0.24초(GPU, 다른 학습과 공유 상태)라 브라우저로 옮길 이유가 없다.
2. **경계는 녹음에 직접 강제 정렬 + 특징 DTW 교차 확인. MFCC-DTW(계획서 6.4)는 안 쓴다.**
   실제 다른 화자 60쌍에서 방법끼리 50 ms 안 일치율: 정렬↔특징 DTW **92.4%**, 정렬↔MFCC-DTW **85.0%**
   (음높이 차 ≥5반음 쌍 **80.2%**). 같은 사람 신호를 비튼 합성 쌍에선 MFCC-DTW 도 정확했다 — 화자가 바뀔 때만 무너진다.
   정렬도 혼자서는 안 된다: 잡음+음색 변화가 겹치면 토큰을 한쪽에 몰아 넣었다(합성 combo 경계 p90 440 ms).
   둘이 다르게 틀리므로, 맞는 음절만 재고 나머지는 "확신 없음"으로 넘긴다. 일치율 < 60% 면 재녹음 안내.
3. **교차 확인 DTW 는 쉼을 빼고 말소리끼리만 맞춘다.** 원작 「하와이」는 '하' 앞에 1.7초 쉬는데 TTS 는 안 쉰다 —
   가장 흔한 따라 하기 실수다. 쉼까지 넣은 DTW 는 그 침묵을 말소리에 짝지으며 경계를 끌고 가서 일치율 50% → "다시 녹음"이
   나왔다. 쉼을 빼니 **88%** 로 올라 "'하' 앞에서 한 박자 쉬어보세요"가 나온다. 쉼 차이는 compare 의 쉼 항목이 따로 본다.
4. **음절 경계는 앵커 가운데가 아니다.** CTC 는 초성을 음절 시작 근처에서, 앞 음절 마지막 토큰은 그 모음 앞쪽에서
   낸다 — 가운데는 앞 음절 모음 한복판이다. 첫 토큰 앞 80 ms 안의 에너지 골짜기(없으면 −20 ms)에 둔다.
5. **첫 음절은 앵커 앞 0.12초까지만 넓힌다.** 0.25초면 말 앞 숨소리가 첫 음절에 들어갔다(잡음을 섞으면 숨이 묻혀 길이 지적 오류).
6. **음높이 하한 0.6·Q1.** 낭독용 0.75·Q1 은 4반음 낮춘 음절을 무성으로 잘랐다 — 성대모사의 깊은 내림을 못 잰다.
7. **옥타브 오류: 급점프로 나눈 조각을 이웃 끝과 견줘 접는다 + 10반음 넘는 차는 안 짚는다.** 진짜 억양은 이어지고 오류는
   한 프레임에 ±12 반음 뛴다. TTS 견본에서 "12.6반음 높음" 같은 가짜 지적이 이걸로 사라졌다. 자연 낭독에선 유성 프레임의
   1.1% 를 접었고, 접은 곳을 눈으로 보니 모두 진짜 오류(약한 기본음 대신 2배음을 잡은 것 등)였다. 틈 건너 9.5반음 도약은 안 접는다.
   2026-10-18 서비스 점검에서 고친 것: 붙은 이웃(급점프)이 있는 조각부터 고친다(아직 안 고친 2배 이웃을 기준으로 맞는 90 Hz 를
   180 Hz 로 접었다) · 틈 건너 이웃과 이어지면 진짜 억양으로 본다(낭독의 맞는 332 Hz 를 붙은 오류 169 Hz 만 보고 접었다) ·
   양쪽 이웃이 다 옥타브 차이면 중앙값과 상관없이 접는다 · 이웃 없이 발화 중앙값보다 한 옥타브 위에 혼자 뜬 조각은 접지 않고
   버린다(진짜로 높게 시작한 낭독 조각도 같은 모양이다). 판정은 스펙트럼의 반 주파수 홀수 배음 유무로 했다.
8. **이웃한 같은 지적은 하나로.** '안'·'나'·'요' 셋 다 "높아요" → "'안 나요'가 원본보다 높아요" 한 번.
9. **원작 원본 자르기는 받아 적기 기준.** 대사 표기 후보(배우가 실제 한 말: "뭣이 중헌디"/"뭣이 중허냐고" 등, 계획서 6.9
   line_variants) 각각을 장면 받아 적기에서 근사 매칭 → 가장 잘 맞는 (장면, 표기)를 고르고 목소리 분리본을 우선(같은 표기면).
   자를 땐 받아 적은 토큰 시각 사이에서 끊는다 — 넓은 구간을 강제 정렬하면 남의 단어에 끌려갔다. 검사도 장면 전체 받아
   적기 안에서 한다 — 1~2초만 따로 받아 적으면 같은 소리도 JER 0.07 → 0.57 로 나빠진다(정렬 모델이 문맥을 본다).
10. **대사 확인 — 녹음 전체를 받아 적은 자모열이 대사와 너무 다르면 음절을 아예 안 잰다.** 강제 정렬은 무엇이 들어와도 대사에
   끼워 맞춰서, 다른 대사를 녹음해도 42%·잡음만 들어와도 12~25% 가 음절 지적을 받았다. 문턱 = max(0.6, 원본 자체 JER + 0.3):
   실제 말소리에서 다른 대사는 전부 0.6 을 넘고, 맞는 대사는 원작 최대 0.46(사투리 「뭣이 중허냐고」)·폰 조건 2% 만 넘었다.
   사투리 대사는 맞게 해도 높아서 원본 JER 에 여유를 더한다. 받아 적은 게 대사의 40% 도 안 되면 "말소리가 잘 안 들려요".
11. **음절 안 음높이가 10 ms 사이 3반음 넘게 튀면 튄 곳에서 끊은 가장 긴 조각(유성 프레임의 70% 이상)으로만 잰다.** 사람 억양은
   10 ms 에 1반음도 못 움직인다 — 튐은 긁는 소리·발성 시작·옥타브 오류다. 원작 ↔ TTS 첫 지적 가짜 3개 중 둘이 이것이었다.
   두 추적기(Praat·CREPE)의 끝 억양 불일치가 원작에서 15.6 → 6.9%, 낭독에서 5.2 → 3.8% 로 줄었다.
12. **녹음은 대사 부분만 본다 — 앞뒤 군말은 잘라 내고, 빠진 어절은 음절을 재지 않고 알려 준다.** 받아 적은 자모열에서 대사와
   가장 가까운 부분을 찾아(두 번 말하면 뒤엣것), 그 앞뒤에 받아 적힌 말이 있으면 사이의 가장 조용한 곳에서 자른다(조용한 틈이 없으면
   안 자른다 — 끝을 길게 끄는 끝 모음을 지키려고). 빠진 어절 = 음절의 절반 이상이 받아 적기에서도 안 나오고(토큰 2/3 이상)
   강제 정렬 확신도 낮으며(< 0.3) 확신 높은 음절(≥ 0.95)이 하나도 없는 어절. 그대로 재면 남은 음절이 빠진 어절 자리를 억지로
   나눠 가져 "'와'를 너무 짧게 말했어요" 같은 엉뚱한 지적이 나왔다(첫 어절 뺌 88%). 빠뜨린 녹음 78% 를 "'…'가 안 들려요"로,
   10% 를 "대사가 다르게 들려요"로 막고, 깨끗한 정상 녹음 70개는 하나도 안 막았다. phone 조건 낭독은 16% 가 걸려서 문구를
   "빠졌어요"가 아니라 "안 들려요 — 빠뜨렸거나 너무 작게 말했어요"로 했다.
13. **쉼은 무음 문턱만이 아니라 정렬 모델의 "말소리 없음"으로도 잰다.** 잔향·웅성거림이 쉼을 채우면 세기 분포로 정한 무음 문턱을
   못 넘어, phone 조건에서 넣은 쉼의 18% 만 잡았다. 정렬 모델(CTC)이 ±40 ms 안에서 대사 토큰 확률을 0.02 도 안 주고 세기도 말소리
   중앙값보다 6 dB 낮은 구간이 0.2초 이어지면 그것도 쉼이다(끝을 길게 끄는 모음은 세서 안 걸린다). 그리고 경계 교차 확인이 안 맞아
   "확신 없음"인 음절이라도 녹음 쪽 앞 쉼이 0.3초 이상이고 원본보다 길면 쉼만은 잰다 — 잡음 속에선 쉼 앞뒤 음절이 확신 없음으로 빠져
   쉼을 못 짚었다. "덜 쉬었다"는 그런 음절에서 안 짚는다: 잡음이 쉼을 채우면 녹음 쉼이 짧게 잡혀, 「하와이」 '하' 앞 1.69초 쉼을
   웅성거림·음악 속에서 0.2~0.37초로 재고 "짧게 쉬었어요"가 나왔다(녹음 조건 6개). phone 조건 넣은 쉼 검출 18 → 29%(목소리 바꿈
   7 → 18%) · 깨끗한 녹음 93% 그대로 · 쉼 안 넣은 녹음의 쉼 오지적 낭독 음절의 0.1% 이하 · 원작 0.
14. **주변 소리가 크면 알려만 주고 분석은 그대로 한다.** 말소리 구간 밖 세기 중앙값과 말소리 세기 중앙값의 차(추정 신호대잡음비)가
   20 dB 아래면 "주변 소리가 커서 쉼·세기는 확실히 못 잴 수 있어요 — 조용한 곳에서 녹음하면 더 정확해요". 추정값 중앙값: 깨끗 44 ·
   잔향 0.3초 43 · 자동 음량 37 · 웅성 20 dB 19 · 배경음악 10 dB 18 · phone 11 · 웅성 10 dB 9 dB. 막지 않는 건 phone 조건에서도
   넣은 어긋남의 절반은 맞게 짚어서다. 잔향은 이걸로 못 잡는다(말소리 밖이 조용하다).
15. **속삭이면 "목소리를 내서"부터.** 음절의 유성 프레임 비율을 길이로 가중한 값이 원본 ≥ 0.35 인데 녹음 < 0.25 이고 대사를 20% 이상
   받아 적었으면 속삭임이다 — 그 지적을 맨 앞에 두고 음높이 지적은 뺀다(남은 유성 조각에서 잰 값이라 「느그 서장」 속삭임에
   "'제'가 원본보다 높아요"가 나왔다). 받아 적기도 무너졌으면 "속삭이듯 말해서 대사를 잘 못 알아들었어요"로 다시 녹음. 분포: 원작
   0.40~0.92(숨 섞인 「밥은 먹고」·「어이가」 0.4) · 보통 녹음 0.70~0.95 · 속삭임 0.00~0.19. 잡음·음악만 들어와도 0 이라 받아 적기
   조건을 붙였다(잡음·음악 0.00 · 속삭임 0.38~1.00). 원본이 속삭인 대사(< 0.15)인데 녹음이 0.5 이상이면 거꾸로 "원본은 속삭이듯 말해요".
   녹음 조건 오인: 깨끗·phone 0/488, 배경음악 10 dB 를 분리하지 않으면 9/487(모두 「하와이」), 분리하면 0/58.
16. **대사 끝 음절은 높이보다 끝 억양.** 끝 음절에서 원본이 3반음 넘게 오르내리는데 녹음이 반대·평평하면 높이 차가 더 커도 끝
   억양을 짚는다 — 「밥은 먹고 다니냐」 '냐'의 의문 올림이 "'다니냐'가 원본보다 낮아요"에 묻혔다.
17. **허용치를 넘었다고 다 고칠 곳이 아니다.** 음높이·세기는 허용치의 1.5배, 길이는 1.25배를 넘어야 보여 주는 지적(고칠 곳)이고,
   그 아래는 다듬을 곳이다 — 고칠 곳이 없으면 "원본과 거의 같아요" + 작은 팁 최대 2개. 쉼·끝 억양·빠르기·목소리는 1배 그대로
   (드물고 귀에 잘 띈다). 평범한 두 낭독도 음절의 16~24% 가 이 세 종류에서 허용치를 넘고, 다시 녹음할 때마다 생기는 흔들림이 새
   지적을 만들어 교정 루프가 안 끝났다. 교환: 방해 변형에 보여 준 지적 0.62 → 0.37개/발화 · 넣은 어긋남이 1순위 66.7 → 64.3% ·
   3개 안 81.8 → 77.3%. 셋 다 1.5배면 0.26개지만 1.8배로 늘린 음절의 절반이 다듬을 곳으로 내려가(재면 1.6~1.7배) 길이만 1.25배.
   **보정 전 임시값이다** — 데모 `--labels` 로 모은 판단으로 다시 정한다(`summarize_labels.py`).
18. **검증 시뮬레이션은 재현돼야 한다.** Praat PSOLA 는 무성 구간을 늘릴 때 조각을 무작위로 골라, 같은 입력도 부를 때마다 파형이
   달랐다 — 같은 코드로 교정 루프 점검을 두 번 돌리면 통과 수가 2~4개씩 달랐다. Praat 난수를 고정하고(`synth._seed`), 루프 점검은
   쌍·방식마다 따로 난수를 쓴다. 흔들림 폭은 `--seed 0·1·2` 로 본다.

주입 크기가 허용치의 2배로 고정이라 ×2 에서 검출이 무너지는 건 당연하다 — 크기별 곡선(2.)과 같이 볼 것.

### 5. 경계 옮기는 방법 → [`results/05_경계방법비교.md`](results/05_경계방법비교.md)

합성(같은 사람)에선 MFCC-DTW 가 가장 정확했다(50 ms 넘는 오류 0~3%). 실제 다른 화자 40쌍에선 MFCC-DTW 만 다른
방법들과 어긋났다(정렬과 81.9%, 특징 DTW 들과 ~90%). 특징 DTW 는 6~24층·사후확률 모두 서로 99.4% 이상 같다 — 층은 크게 상관없다.

### 6. 견본 대사(TTS 10개) → [`results/06_견본대사_출력.md`](results/06_견본대사_출력.md)

TTS 끼리 비교(검증용). 다른 목소리로 따라 한 10개는 모두 1~3곳 지적, 같은 목소리 재시도 10개 중 2개는 "원본과 거의 같아요".

### 7. 원작 대사 (출처 · 클립 목록은 내부 보관 — 제3자 영상이라 공개 저장소에 넣지 않는다)

10개 중 **8개** 원본 확보(대사 찾기 JER 0.00~0.36). 탈락 2개: 「마이 묵었다 아이가」는 속삭임이라 성대 울림이 없어
받아 적기·음높이 둘 다 불가 — 계획서 skip_checks 대상이다. 「내가 니 시다바리가」는 받은 장면 6개 어디에도 그 대사가 없었다.
「곡성」 장면은 실제로 "뭣이 중허냐고"가 더 잘 맞아 그 표기로 썼다. 원작 ↔ TTS 비교에서 원작의 특징을 짚는다:

| 원작 | 짚은 것 |
|---|---|
| 친구 「니가 가라 … 하와이」 | "'하' 앞에서 한 박자 쉬어보세요" (원본 1.69초 쉼 → TTS 0초) |
| 범죄와의 전쟁 「살아있네」 | "'네'에서 끝이 안 내려갔어요 → 툭 떨어뜨려 보세요" (원본 −7.4반음) |
| 범죄와의 전쟁 「느그 서장 남천동 살제」 | "'남'에서 끝이 안 올라갔어요"(원본 +5.5) · "'동'에서 끝이 안 내려갔어요"(원본 −6.8) |
| 친절한 금자씨 「너나 잘하세요」 | "전체적으로 원본보다 빨라요" (TTS 가 원본의 0.65배 길이) |

### 8. 서비스 점검(2026-10-18) → [`results/08_서비스점검.md`](results/08_서비스점검.md)

## 한계 · 주의

- **실서비스 전 고칠 것(우선순위)은 [`results/08`](results/08_서비스점검.md) §7** — 남은 P0: 허용치 보정(모은 판단 0개 — 데모
  `--labels` 로 모은다) · 폰 조건 검출(넣은 어긋남 49%, 쉼 29%). P1: 긁는 소리·숨소리 · 원작 클립 귀 검수(페이지는 있다) · 1순위
  안정화(같은 녹음에 무음 0.15초만 붙여도 1순위가 25% 바뀐다 — 정렬 프레임 위상 문제라 순위 규칙으론 안 된다).
- **고칠 곳/다듬을 곳 문턱(음높이·세기 1.5배, 길이 1.25배)은 보정 전 임시값이다.** 허용치를 조금 넘은 것을 "원본과 거의 같아요"
  아래 팁으로 내린 것이라, 넣은 어긋남이 첫 지적인 비율은 67 → 65% 로 조금 줄었다.
- **속삭임 판정은 합성 속삭임(LPC 잡음 여기)과 녹음 조건 시뮬레이션으로만 확인했다** — 실제 사람 속삭임 녹음은 없다. 반주를
  분리하지 않은 배경음악 10 dB 녹음은 1.8%(「하와이」)가 속삭임으로 보인다. 주변 소리 알림은 잔향을 못 잡는다(말소리 밖이 조용하다).
- **대사 확인 문턱(max(0.6, 원본 JER + 0.3))은 TTS·낭독·원작 8개로 정했다.** 사투리·발음이 서툰 사용자 녹음, 시끄러운 방에서는
  맞게 말해도 "대사가 다르게 들려요"가 나올 수 있다(낭독 + phone 2%, 합성 변형 + phone 9~35%) — 실사용 로그로 다시 볼 것.

- **허용치는 계획서 초안 그대로다 — 보정 전.** 두 원어민이 같은 문장을 평범하게 읽어도 음절의 **47%** 가 허용치를 넘는다
  (같은 사람·같은 억양에서 잘못 짚는 측정 잡음은 2.3%). 즉 지적 대부분은 "실제로 다르다"이지 "틀렸다"가 아니다.
  무엇을 짚을지는 코치 라벨로 정할 일(계획서 8장). 허용치 ×1.5 면 실제 쌍 지적이 22% 로 줄지만 2.5반음 어긋남도 놓치기 시작한다.
- **원작 클립은 사람 검수 전이다**(계획서 7.1). 대사 위치·경계는 자동이고, 소리를 귀로 확인하진 않았다(스펙트로그램만 봤다).
  속삭임·절규 대사는 자동 처리가 어렵다 — 속삭임은 탈락, 절규(곡성)는 받아 적기 JER 0.31 로 겨우 통과.
- **원작 음성은 권리 확인 전 내부 시험용**(계획서 7.3) — 저장소에 안 넣었고(wav 는 .gitignore), 공개 주소로 내보내지 말 것.
- 합성 변형은 같은 사람 신호를 비튼 것이라 DTW·정렬 모두에 유리하다. 경계의 절대 정확도는 사람이 찍은 경계로 재야 한다.
- 정렬 모델은 잡음에 약하다(기존 실험과 같은 결론). 잡음 + 음색 변화가 겹치면 재녹음 판정으로 막는다.
- KoG2P 는 어절 경계에도 음운 규칙을 적용한다("나온 여자" → [나온녀자]). 정렬엔 영향이 작지만 빠진 글자 검출(Phase 1)엔 걸린다.
- 모음으로 시작하는 음절이 이어지면("어이가") 경계가 모호해 "확신 없음"이 잦다.
- **교차 의존 1곳**: `text.py` 가 `mdd.jamo_to_kog2p.INV`(발음 task)를 쓴다 — 정렬 모델이 그 표기로 학습됐기 때문. 그 표를 바꾸면 여기도 확인할 것.
